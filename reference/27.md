# 27. Sleep Consolidator

## 27.1 目的

Sleep Consolidator 是模型在「非即時學習階段」執行的內部整合程序，類似生物大腦的睡眠鞏固。

它的目的不是單純訓練，而是：

```text
1. 整理短期記憶
2. 合併重複記憶
3. 分離衝突記憶
4. 壓縮 adapter / LoRA expert
5. 用 dream replay 保持舊能力
6. 檢查是否產生遺忘
7. 將穩定知識慢慢蒸餾進核心模型
8. 更新重要性矩陣與可塑性狀態
9. 清除低價值或危險記憶
10. 建立可回滾版本
```

Sleep Consolidator 的核心思想是：

[
\text{白天快速學習，睡眠慢速整合}
]

也就是：

[
M_{fast}, A_{local}
\rightarrow
M_{semantic}, A_{compressed}, \theta_c
]

# 27.3 何時啟動 Sleep Consolidation

Sleep Consolidator 不應每次資料進來就執行，因為成本較高。
它應該由 controller 判斷是否啟動。

啟動分數：

[
s_{sleep}
=========

C_{sleep}
(
memory_pressure,
adapter_fragmentation,
conflict_density,
forgetting_risk,
idle_time
)
]

若：

[
s_{sleep} > \tau_{sleep}
]

則啟動 sleep consolidation。

---

## 啟動條件範例

| 條件               | 說明                        |
| ---------------- | ------------------------- |
| memory 太滿        | 記憶槽接近容量上限                 |
| adapter 太多       | expert bank 過度碎片化         |
| 衝突記憶太多           | 多個版本互相矛盾                  |
| replay loss 上升   | 舊知識有遺忘風險                  |
| sentinel loss 上升 | 哨兵測試顯示核心能力退化              |
| 系統閒置             | 可用計算資源足夠                  |
| 某類知識反覆出現         | 適合從 episodic 升級為 semantic |

# 27.4 Sleep Consolidator 總演算法

```text
Algorithm: SleepConsolidator(S_t)

Input:
    S_t = {
        θ_c, M_t, A_t, R_t, I_t, P_t,
        G_t, T_t, V_t, B_t
    }

Output:
    S_{t+1}

Steps:

1. 建立更新前快照
2. 從 memory 中選出需要整理的候選記憶
3. 生成 dream replay batch
4. 計算記憶相似度與衝突關係
5. 合併一致記憶
6. 版本化衝突記憶
7. 壓縮 adapter / expert
8. 用 replay + distillation 測試壓縮後模型
9. 若安全，將穩定知識慢速寫入 core
10. 更新 importance map
11. 更新 plasticity state
12. 刪除、抑制或降權低價值記憶
13. 更新 router
14. 執行 sentinel test
15. 若退化，rollback
16. 若通過，提交新狀態
```

# 27.5 Phase 0：建立快照與保護核心

在 sleep 開始前，先保存目前狀態：

[
B_t =
Snapshot(
\theta_c,
M_t,
A_t,
R_t,
I_t
)
]

目的：

```text
如果 consolidation 失敗，可以回滾。
```

對高風險區域加保護：

[
plasticity_{safety} = 0
]

[
plasticity_{core} \ll plasticity_{adapter}
]

也就是：

```text
安全核心不可更新
主核心極慢更新
adapter 可中速更新
memory 可快速整理
```

# 27.6 Phase 1：選擇要整理的記憶

不是所有 memory 都進入 sleep 處理，而是先計算每個 memory slot 的整理優先級。

對每個記憶槽 (m_i)，定義：

[
priority_i
==========

\alpha usage_i
+
\beta importance_i
+
\gamma conflict_i
+
\delta novelty_i
----------------

\lambda confidence_i
+
\mu age_i
]

其中：

| 項目             | 意義               |
| -------------- | ---------------- |
| (usage_i)      | 使用越頻繁，越值得整理      |
| (importance_i) | 越重要，越要保護         |
| (conflict_i)   | 衝突越多，越需要版本化      |
| (novelty_i)    | 新知識需要檢查          |
| (confidence_i) | 高信心者可穩定化，低信心者需驗證 |
| (age_i)        | 太舊者可能要衰減或壓縮      |

選出候選集合：

[
M_{cand}
========

{m_i \mid priority_i > \tau_p}
]

## 27.7.1 Dream Replay

由 Dream Generator 產生舊樣本：

[
\hat{x}_i, \hat{y}_i
====================

G_\psi(m_i, z_i)
]

也可以生成舊 logits：

[
\hat{p}_i(y|x)
==============

T_t(\hat{x}_i)
]

因此 replay item 可以是：

[
d_i =
[
\hat{x}_i,
\hat{y}_i,
\hat{p}_i,
task_i,
importance_i
]
]

---

## 27.7.2 Replay Sampling 權重

不是平均抽樣，而是根據重要性抽樣：

[
P(m_i)
======

\frac{
\exp(
\alpha importance_i
+
\beta usage_i
+
\gamma conflict_i
-----------------

\delta age_i
)
}{
\sum_j
\exp(
\alpha importance_j
+
\beta usage_j
+
\gamma conflict_j
-----------------

\delta age_j
)
}
]

也就是：

```text
重要的多 replay
常用的多 replay
有衝突的多 replay
太舊且低價值的少 replay
```

# 27.8 Phase 3：記憶聚類

把候選記憶根據 key 和 value 做聚類。

每個記憶：

[
m_i = [k_i, v_i, c_i, t_i, source_i]
]

定義記憶距離：

[
d(m_i, m_j)
===========

\alpha
\left(
1 - sim(k_i, k_j)
\right)
+
\beta
\left(
1 - sim(v_i, v_j)
\right)
+
\gamma
time_distance(t_i, t_j)
+
\delta
source_distance(source_i, source_j)
]

若：

[
d(m_i, m_j) < \tau_{merge}
]

則兩個 memory 可能屬於同一群。

產生記憶群：

[
\mathcal{C}
===========

{C_1, C_2, ..., C_K}
]

# 27.9 Phase 4：一致記憶合併

對於同一 cluster (C_k)，先判斷內部是否一致。

一致性分數：

[
consistency(C_k)
================

\frac{1}{|C_k|^2}
\sum_{i,j \in C_k}
sim(v_i, v_j)
]

若：

[
consistency(C_k) > \tau_{consistency}
]

則可以合併。

---

## 合併公式

新的 key：

[
k_{new}
=======

\frac{
\sum_i w_i k_i
}{
\sum_i w_i
}
]

新的 value：

[
v_{new}
=======

\frac{
\sum_i w_i v_i
}{
\sum_i w_i
}
]

權重：

[
w_i
===

confidence_i
\cdot
usage_i
\cdot
reliability_i
]

新的 confidence：

[
confidence_{new}
================

1 -
\prod_i
(1 - confidence_i)
]

新的 memory：

[
m_{new}
=======

[
k_{new},
v_{new},
confidence_{new},
source_summary,
time_range,
version
]
]

# 27.10 Phase 5：衝突記憶版本化

如果 cluster 內 key 相似，但 value 不一致：

[
sim(k_i, k_j) > \tau_k
]

但：

[
sim(v_i, v_j) < \tau_v
]

則代表：

```text
相同問題或相似情境下，有不同答案。
```

這時不能合併，也不能覆蓋。
必須版本化。

---

## 版本化形式

[
m_i =
[
k,
v_i,

time_i,
source_i,
confidence_i,
version_i
]
]

[
m_j =
[
k,

version_j
]
]

Router 之後根據 context 選擇：

[

===

q,
context,

source,
{v_1, v_2, ..., v_n}
)
]

---

## 衝突記憶處理規則

| 情況      | 處理                |
| ------- | ----------------- |
| 舊知識過期   | 舊版本 inhibited，不刪除 |
| 來源不可信   | 降低 confidence     |
| 不同情境皆有效 | 保留多版本             |
| 新知識高可信  | 提高新版 routing 權重   |
| 無法判斷    | 啟動 verifier 或保持並列 |

# 27.11 Phase 6：Adapter / Expert 壓縮

如果多個 adapter 學到相似能力，應該合併，避免 expert bank 無限成長。

每個 expert：

[
E_i(h) = B_i A_i h
]

其等效更新：

[
\Delta W_i = B_i A_i
]

多個 expert 合併：

[
\Delta W_{merge}
================

\sum_{i \in \mathcal{E}}
\alpha_i \Delta W_i
]

# [

\sum_{i \in \mathcal{E}}
\alpha_i B_i A_i
]

然後做低秩近似：

[
\Delta W_{merge}
\approx
B' A'
]

其中：

[
rank(B'A') \leq r
]

新的 expert：

[
E_{new}(h) = B'A'h
]

---

## Expert 合併條件

兩個 expert 可合併若：

[
sim(task_i, task_j) > \tau_{task}
]

[
sim(\Delta W_i, \Delta W_j) > \tau_W
]

[
interference(E_i, E_j) < \tau_I
]

其中 interference 可定義為：

[
interference(E_i, E_j)
======================

## L_{replay}(E_i + E_j)

## L_{replay}(E_i)

L_{replay}(E_j)
]

若 interference 很高，代表兩者不能合併。

+
\beta usage_i
+

+
\delta generality_i
-------------------

\mu temporal_decay_i

若：

[

]

[

# 27.14 Phase 9：更新 Plasticity State

Sleep 不只更新知識，也更新「哪些地方未來可以學得快」。

每個模組有 plasticity：

[
p_j \in [0, 1]
]

更新規則：

[
p_j^{t+1}
=========

\sigma(
a p_j^t
+
b novelty_j
-----------

## c importance_j

d forgetting_risk_j
+
e usefulness_j
)
]

解讀：

| 條件        | plasticity |
| --------- | ---------- |
| 常學新東西且低風險 | 上升         |
| 對舊知識重要    | 下降         |
| 容易造成遺忘    | 下降         |
| 很有用但不穩定   | 中等         |
| 安全核心      | 接近 0       |

# 27.15 Phase 10：更新 Router

Sleep 後 memory 和 expert 被合併、壓縮、版本化，因此 router 也要重新校準。

Router 訓練資料來自：

[
D_{router}
==========

D_{sleep}
\cup
D_{conflict}
\cup
D_{sentinel}
]

Router loss：

[
L_{router}
==========

L_{task}
+
\lambda_1 L_{load_balance}
+
\lambda_2 L_{conflict_routing}
+
\lambda_3 L_{expert_sparsity}
]

---

## Router 目標

```text
1. 正確選擇 memory version
2. 正確選擇 expert
3. 避免所有輸入都跑到同一個 expert
4. 對衝突知識做 context-aware routing
5. 保持 sparse activation
```

---

## Load Balance Loss

避免 expert collapse：

[
L_{load}
========

K
\sum_{i=1}^{K}
f_i p_i
]

其中：

* (f_i)：expert (i) 被選中的比例。
* (p_i)：router 給 expert (i) 的平均機率。

# 27.16 Phase 11：容量管理與 pruning

對 memory 和 expert 計算價值：

[
value_i
=======

\alpha usage_i
+
\beta confidence_i
+
\gamma generality_i
+
\delta importance_i
-------------------

## \lambda cost_i

## \mu conflict_i

\nu age_i
]

若：

[

則不一定直接刪除，而是依風險分級處理：

| 狀態       | 處理       |
| -------- | -------- |
| 低價值、低風險  | 刪除       |
| 低價值但可能有用 | 壓縮       |
| 舊但重要     | 降低讀取權重   |
| 與新版衝突    | inhibit  |
| 安全相關     | 不刪，改為封存  |
| 使用者偏好    | 保留版本與時間戳 |

# 27.20 更完整的偽代碼

```text
Algorithm: SleepConsolidator

Input:
    S_t = {
        θ_c, M_t, A_t, R_t, I_t, P_t,
        G_t, T_t, V_t, B_t
    }

Output:
    S_{t+1}

--------------------------------------------------
0. Snapshot
--------------------------------------------------

B_t ← Snapshot(S_t)

Freeze safety kernel
Set core plasticity to very low

--------------------------------------------------
1. Select candidate memories
--------------------------------------------------

for each memory slot m_i in M_t:

    priority_i =
        α usage_i
        + β importance_i
        + γ conflict_i
        + δ novelty_i
        - λ confidence_i
        + μ age_i

M_cand ← {m_i | priority_i > τ_p}

--------------------------------------------------
2. Build sleep replay batch
--------------------------------------------------

D_dream ← DreamGenerator(M_cand)
D_sentinel ← SentinelMemory()
D_recent ← RecentImportantExperiences()
D_conflict ← ConflictMemories(M_t)
D_proto ← PrototypeMemories(M_t)

D_sleep ←
    D_dream
    ∪ D_sentinel
    ∪ D_recent
    ∪ D_conflict
    ∪ D_proto

--------------------------------------------------
3. Cluster memories
--------------------------------------------------

C ← Cluster(M_cand, distance = d(m_i, m_j))

for each cluster C_k in C:

    consistency_k ← MeanPairwiseValueSimilarity(C_k)
    conflict_k ← ConflictScore(C_k)

    if consistency_k > τ_consistency:
        m_new ← MergeMemory(C_k)
        Replace C_k with m_new

    else if conflict_k > τ_conflict:
        Versionize(C_k)
        Train router to choose by context

--------------------------------------------------
4. Compress experts
--------------------------------------------------

E_groups ← ClusterExperts(A_t)

for each expert group E_g:

    if Interference(E_g) < τ_interference:

        ΔW_merge ← Σ_i α_i B_i A_i
        ΔW_lowrank ← LowRankCompress(ΔW_merge)

        E_new ← CreateExpert(ΔW_lowrank)

        Replace E_g with E_new

--------------------------------------------------
5. Distill stable knowledge into core
--------------------------------------------------

StableSet ← {
    m_i |
    stability_i > τ_core
    and conflict_i < τ_conflict
    and temporal_decay_i < τ_time
}

for each batch x from StableSet:

    p_teacher ← ModelWithMemoryAndExperts(x)
    p_core ← CoreOnlyModel(x)

    L_core_distill ← KL(p_teacher || p_core)

Update θ_c with very small learning rate
and strong importance protection

--------------------------------------------------
6. Update router
--------------------------------------------------

Train R_t on D_sleep to:

    minimize task loss
    choose correct memory version
    choose correct expert
    balance expert usage
    preserve sparse routing

--------------------------------------------------
7. Update importance and plasticity
--------------------------------------------------

for each parameter or module j:

    I_j ← UpdateImportance(
        old I_j,
        gradient_j,
        activation_j,
        replay_sensitivity_j,
        usage_j
    )

    P_j ← UpdatePlasticity(
        old P_j,
        novelty_j,
        usefulness_j,
        importance_j,
        forgetting_risk_j
    )

--------------------------------------------------
8. Capacity management
--------------------------------------------------

for each memory or expert u_i:

    value_i =
        α usage_i
        + β confidence_i
        + γ generality_i
        + δ importance_i
        - λ cost_i
        - μ conflict_i
        - ν age_i

    if value_i < τ_prune:
        if safe_to_delete:
            Delete(u_i)
        else:
            InhibitOrCompress(u_i)

--------------------------------------------------
9. Validation
--------------------------------------------------

L_before ← SentinelLoss(S_t)
L_after ← SentinelLoss(S_candidate)

risk =
    α forgetting
    + β locality_violation
    + γ safety_risk
    + δ confidence_drop

if L_after - L_before > ε:
    S_{t+1} ← Rollback(B_t)

else if risk > τ_risk:
    S_{t+1} ← Rollback(B_t)

else:
    S_{t+1} ← Commit(S_candidate)

return S_{t+1}
```

# 27.21 Sleep Consolidator 的重點

Sleep Consolidator 不是單純的「再訓練一次」。
它其實包含五個核心演算法：

```text
1. Memory Consolidation
   把短期、重複、一致的記憶合併成穩定記憶。

2. Conflict Versioning
   對衝突知識保留多版本，而不是覆蓋。

3. Expert Compression
   把相似 LoRA / adapter 壓縮成更少的 expert。

4. Core Distillation
   把長期穩定、低衝突、高泛化的知識慢慢寫入核心。

5. Safety Validation + Rollback
   用 sentinel、verifier、locality test 確認沒有退化，否則回滾。
```

[
\boxed{
SleepConsolidator
=================

Merge
+

+
Compress
+

+
Validate
+
Rollback
}
]

它是讓模型能夠「長期持續學習」的關鍵，因為它負責把快速學到的東西整理成穩定結構，同時避免舊知識被新知識覆蓋。
