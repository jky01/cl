你這四點的判斷是對的。
目前那份 spec 最大問題不是「模組不夠多」，而是有幾個地方把**可靠性問題誤寫成可學習問題**，尤其是：

1. safety 不該只靠 soft risk。
2. 512 維 memory value 不能先假設夠。
3. soft rollback 不能當可靠回滾。
4. dream replay 不能先假設品質與成本都可接受。

下面我用「全神經網路內部可實作」的角度，把這些地方改成更可驗證的設計。安全你說可以先放一邊，所以我先給最小修正，主力放在 2、3、4。

---

# 1. Safety Kernel：不能只是 soft risk，但可以先最小化處理

你指出的問題完全正確。

之前的設計裡：

```text
safety_risk
risk_vector[2]
safety_features
SafetyCritic
```

都只是可學的分數。
這種東西會 drift，不能保證：

[
P_{safety} \approx 0
]

如果要讓 safety 不被 (\Omega) 漂移，必須把它改成**結構性不可更新區域**，而不是一個可學 gate。

---

## 1.1 最小修正：Safety 不是 state，而是 immutable kernel

在 State Spec 裡，不應該有：

```text
safety_state: trainable tensor
```

而應該有：

```text
K_safety: immutable module
```

它可以是神經網路，但必須是：

```text
frozen
no_grad
not in Ω
not in S_t
not affected by SleepNet
not affected by CommitGate
not affected by PlasticityUpdateNet
```

也就是：

[
K_{safety}^{t+1}
================

K_{safety}^{t}
]

並且：

[
\nabla_\Omega K_{safety} = 0
]

---

## 1.2 Safety feature 從哪來？

`safety_features` 不應由可塑 memory 任意產生，而應來自 frozen safety encoder：

[
safety_features
===============

K_{safety}(x, y, update, state_summary)
]

形狀可以是：

```text
safety_features: [B, 128]
safety_block_mask: [B, 1]
safety_update_mask_memory: [B, N_mem, 1]
safety_update_mask_expert: [B, K_exp, 1]
safety_update_mask_core: [B, L, G, B_core, 1]
```

其中最重要的是 mask，而不是 risk score。

---

## 1.3 硬性保證 (P_{safety}=0)

不能讓 PlasticityNet 學出來。
要直接在 update path 上乘 hard mask：

[
\Delta S_{safe}
===============

mask_{safety}
\odot
\Delta S
]

對 safety-protected region：

[
mask_{safety} = 0
]

所以：

[
\Delta S_{protected}=0
]

這是架構保證，不是學出來的。

---

## 1.4 結論

如果要全神經化，安全最多只能說：

```text
Safety detector 可以是神經網路；
但 safety kernel、權限邊界、不可塑 mask 不應是可學 state。
```

所以完整系統應該是：

```text
神經調控內部學習系統
+
不可塑 safety kernel
+
不可塑 update mask
```

安全先放一邊的話，後面的核心改動是：**memory 表徵驗證、hard rollback、dream replay 降本與品質控制。**

# 2. 512 維 memory value 不能先假設夠

你指出最關鍵問題：

> 現在 spec 等於假設一條知識可以被 512 維 (v_i) 表示，然後用
> [
> R_m = A_{read}V_{mem}
> ]
> 加到 hidden state 裡。
> 但這不一定足夠。

這確實是整套系統的第一個實驗假設，不是可以直接假設成立。

---

# 2.1 原本設計的問題

原本是：

[
m_i = [k_i, v_i, aux_i]
]

其中：

[
v_i \in \mathbb{R}^{512}
]

讀取：

[
r_t = \sum_i a_i v_i
]

再投影：

[
h'_t = h_t + W_r r_t
]

這有三個問題。

---

## 問題 A：多筆知識會被平均掉

如果 top-k memory 裡有多筆相似但不同的 facts：

[
v_1, v_2, ..., v_k
]

soft attention 會得到：

[
r = \sum_i a_i v_i
]

這可能產生「混合知識」，尤其是衝突事實。

例如：

```text
A 的首都是 X
A 的首都是 Y
```

被平均後可能什麼都不是。

---

## 問題 B：512 維向量可能只能存提示，不是真正知識

512 維 residual 比較像：

```text
提醒模型往某方向回答
```

但不一定能可靠存：

```text
主詞
關係
受詞
時間
來源
版本
例外條件
```

---

## 問題 C：單一 hidden residual 太弱

把記憶只加到：

[
h'_t = h_t + r_t
]

可能不如讓記憶參與 attention、MLP 或 adapter 生成。

---

# 2.2 修正方向：memory value 不直接當知識，而是當「知識膠囊 latent」

把：

[
v_i \in \mathbb{R}^{512}
]

重新解釋為：

```text
value_latent，不是最終知識表示。
```

也就是：

[
v_i = latent_i
]

然後透過神經 decoder 產生更強的注入形式。

---

# 2.3 Memory Capsule Spec

原本 slot：

```text
key:   128
value: 512
...
```

改成：

```text
memory slot = retrieval key + value latent + control fields
```

其中 value latent 不直接加到 hidden，而是解碼成多種形式。

---

## 2.3.1 新 memory slot layout

建議改成：

```text
d_slot = 1024
```

| 區段              |  維度 | 說明                 |
| --------------- | --: | ------------------ |
| key             | 128 | 檢索 key             |
| value_latent    | 512 | 知識 latent          |
| relation_latent | 128 | 關係 / schema latent |
| context         |  64 | 適用情境               |
| source          |  32 | 來源                 |
| time            |  16 | 時間                 |
| version         |  32 | 版本                 |
| aux             | 112 | 控制欄位               |

所以：

[
d_{slot}
========

# 128 + 512 + 128 + 64 + 32 + 16 + 32 + 112

1024
]

這裡 `aux` 變大，是為了加入更多診斷欄位，例如：

```text
allocated
confidence
usage
freshness
conflict
inhibit
tombstone
schema_type
fact_type
arity
compression_level
write_generation
```

---

# 2.4 不再用單一 weighted sum，而是使用 Top-k Memory Cross-Attention

原本：

[
r = A_{read}V
]

改成：

1. 先取 top-k memory。
2. 保留每個 memory 的獨立表示。
3. 用 cross-attention 讓 hidden state 讀取這些 memory capsules。

---

## 2.4.1 Tensor interface

```text
H:        [B, T, d_model]
M_topk:   [B, T, K, d_slot]
K = 8 或 16
```

取出：

```text
value_latent_topk:   [B, T, K, 512]
relation_latent_topk:[B, T, K, 128]
context_topk:        [B, T, K, 64]
```

先用 MemoryValueDecoder 產生 memory tokens：

[
P_i = ValueDecoder(v_i, relation_i, context_i)
]

```text
P_i: [B, T, K, P, d_model]
```

例如：

```text
P = 4
d_model = 1024
```

也就是每個 memory slot 解碼成 4 個 prefix-like latent tokens。

---

## 2.4.2 Memory cross-attention

把所有 memory tokens 攤平：

```text
P_mem: [B, T, K * P, d_model]
```

然後：

[
R_t
===

CrossAttention(
Q = H_t,
K = P_{mem},
V = P_{mem}
)
]

輸出：

```text
R_t: [B, T, d_model]
```

最後：

[
H'_t
====

H_t
+
g_{mem}R_t
]

這比單純：

[
H + W_r(A_{read}V)
]

強很多，因為它保留 top-k memory 的個別性。

---

# 2.5 Memory 不只輸出 residual，還可以生成局部 adapter

對 facts / skills 更強的方式是：

[
value_latent
\rightarrow
small\ adapter
]

即：

[
\Delta W_i
==========

MemoryToLoRA(v_i)
]

對當前 token 啟用：

[
H'
==

H
+
\sum_i a_i \Delta W_i H
]

這樣 memory 不是只提醒模型，而是短暫產生一個局部轉換。

---

## 2.5.1 Tensor interface

MemoryToLoRA 輸入：

```text
value_latent_topk: [B, T, K, 512]
```

輸出低秩 adapter latent：

```text
mem_lora_A: [B, T, K, r, d_model]
mem_lora_B: [B, T, K, d_model, r]
```

實務上這太大，所以不直接生成 full A/B，而是生成低維 latent：

```text
mem_adapter_latent: [B, T, K, 64]
```

再由共享 HyperLoRA 產生小 rank adapter。

---

# 2.6 512 維是否足夠：第一階段必做實驗

這應該是 Stage 1 的第一個實驗，而不是等整套系統完成。

---

## 2.6.1 實驗 A：Atomic Fact Write/Read

資料格式：

```text
subject, relation, object
```

例如：

```text
(entity_392, born_in, city_71)
(entity_122, capital_of, country_55)
```

寫入 memory 後測試：

```text
What is relation(entity)?
Paraphrase query
Reverse query
Distractor query
```

指標：

```text
exact match
paraphrase generalization
collision rate
wrong-object rate
unrelated locality
```

---

## 2.6.2 實驗 B：容量掃描

測：

```text
d_value = 128, 256, 512, 1024
P prefix tokens = 1, 2, 4, 8
K top-k = 1, 4, 8, 16
```

觀察：

[
Accuracy(d_v, P, K)
]

以及：

[
Interference(d_v, P, K)
]

如果：

```text
512 維 + P=1 + K=1
```

不夠，就升級為：

```text
512 維 latent + P=4 memory tokens + K=8 cross-attention
```

---

## 2.6.3 實驗 C：Conflict Version Recall

寫入：

```text
A 在 t1 的值是 X
A 在 t2 的值是 Y
A 在 context1 是 X
A 在 context2 是 Y
```

測：

```text
指定時間
指定 context
未指定 context
```

如果模型把 X/Y 混合，代表 weighted sum 設計失敗，必須使用 version-aware top-k memory tokens。

---

# 2.7 結論：memory value 應改成 capsule，不是 residual

修正後：

```text
不要假設一個 512 維向量就是知識。
```

而是：

```text
512 維 value_latent
→ ValueDecoder
→ 多個 memory prefix tokens
→ cross-attention
→ optionally MemoryToAdapter
```

最小公式：

[
P_i
===

ValueDecoder(v_i)
]

[
R
=

CrossAttention(H, P_{topk}, P_{topk})
]

[
H'
==

H
+
g_{mem}R
]

這樣才有機會讓 memory 表徵足夠。

# 3. Soft rollback 不夠，要加入固定張量內的精確 hard rollback

你指出的問題也完全正確。

之前的：

```text
rollback_trace: [B, 128, 512]
inverse-delta latent
```

只能做近似回滾。
它不保證還原。

對安全或穩定性來說，這不夠。

---

# 3.1 正確設計：兩層 rollback

應該分成：

```text
1. Neural soft rollback
   用於一般低風險修正。

2. Exact hard rollback
   用於高風險、驗證失敗、核心更新失敗。
```

---

## 3.1.1 Soft rollback

[
S_{rollback}^{soft}
===================

S_{candidate}
+
RollbackNet(trace)
]

優點：

```text
省空間
可微
可學習
```

缺點：

```text
不可靠
不保證恢復
```

---

## 3.1.2 Hard rollback

保存精確舊值：

[
old_value
]

以及精確地址：

[
addr
]

回滾時直接 scatter 回去。

這是可靠的。

---

# 3.2 如何在固定張量裡做 hard rollback

重點是：

> hard rollback 不需要動態資料結構，也可以是固定形狀張量。

設計一個 rollback ring buffer。

---

## 3.2.1 Memory rollback trace

假設每次 online update 最多改：

```text
K_mem_write = 16
```

則 rollback trace 存：

```text
mem_trace_addr:  [B, H_trace, K_mem_write, N_mem]
mem_trace_value: [B, H_trace, K_mem_write, d_slot]
mem_trace_valid: [B, H_trace, K_mem_write, 1]
```

具體：

```text
mem_trace_addr:  [B, 128, 16, 4096]
mem_trace_value: [B, 128, 16, 1024]
mem_trace_valid: [B, 128, 16, 1]
```

`mem_trace_addr` 是 one-hot 或 straight-through one-hot。

回滾時：

[
M_{rollback}
============

ScatterRestore(
M_{candidate},
addr,
old_value
)
]

公式：

[
M_{rollback,j}
==============

(1-\sum_k addr_{k,j})M_{candidate,j}
+
\sum_k addr_{k,j}old_value_k
]

這是精確回滾。

---

# 3.3 Expert hard rollback

Expert state 是：

```text
expert_latents: [B, K_exp, d_exp]
expert_meta:    [B, K_exp, d_meta]
```

每次最多改：

```text
K_exp_write = 8
```

Trace：

```text
exp_trace_addr:    [B, H_trace, K_exp_write, K_exp]
exp_trace_latent:  [B, H_trace, K_exp_write, d_exp]
exp_trace_meta:    [B, H_trace, K_exp_write, d_meta]
exp_trace_valid:   [B, H_trace, K_exp_write, 1]
```

回滾：

[
E_{rollback}
============

ScatterRestore(E_{candidate}, addr, old_expert)
]

---

# 3.4 Core hard rollback

關鍵設計：**不要直接改 raw (\theta_0)**。

核心可塑部分只能是：

```text
core_delta_latents
core_delta_gates
```

所以 hard rollback 只需要保存這些 latent。

每次最多改：

```text
K_core_write = 16
```

核心 delta 總位置數：

[
N_{core}
========

L \times G \times B_{core}
]

例如：

[
24 \times 6 \times 4 = 576
]

Trace：

```text
core_trace_addr:   [B, H_trace, K_core_write, 576]
core_trace_latent: [B, H_trace, K_core_write, d_delta]
core_trace_gate:   [B, H_trace, K_core_write, 1]
core_trace_valid:  [B, H_trace, K_core_write, 1]
```

這樣回滾 core delta 是精確的。

---

# 3.5 Router hard rollback

Router state 也可回滾。

```text
router_contexts: [B, C_ctx, d_ctx]
router_expert_bias: [B, K_exp]
router_memory_bias: [B, N_mem]
```

但 router_memory_bias 太大，不一定每次全存。
可以限制每次最多改 top-k memory bias。

Trace：

```text
router_ctx_addr:   [B, H_trace, K_ctx_write, C_ctx]
router_ctx_value:  [B, H_trace, K_ctx_write, d_ctx]

router_exp_bias_old: [B, H_trace, K_exp]
router_mem_bias_addr:[B, H_trace, K_mem_bias_write, N_mem]
router_mem_bias_old: [B, H_trace, K_mem_bias_write, 1]
```

---

# 3.6 Commit 也要分成 soft training / hard deployment

訓練時：

[
S_{t+1}
=======

gS_{candidate}
+
(1-g)S_t
]

可微。

部署或 high-risk validation 時：

```text
if risk > threshold:
    hard rollback
else:
    hard commit
```

也就是：

```text
training:
    soft commit

deployment / safety-critical:
    hard commit + exact rollback
```

這不破壞全神經設計，因為 hard rollback trace 本身仍是固定張量 state。
只是可靠性上不再依賴可學 inverse latent。

---

# 3.7 修正後 rollback state spec

新增：

```text
hard_rollback_memory_addr:  [B, H_trace, K_mem_write, N_mem]
hard_rollback_memory_value: [B, H_trace, K_mem_write, d_slot]

hard_rollback_expert_addr:  [B, H_trace, K_exp_write, K_exp]
hard_rollback_expert_value: [B, H_trace, K_exp_write, d_exp + d_meta]

hard_rollback_core_addr:    [B, H_trace, K_core_write, N_core]
hard_rollback_core_latent:  [B, H_trace, K_core_write, d_delta]
hard_rollback_core_gate:    [B, H_trace, K_core_write, 1]
```

保留原本：

```text
rollback_trace_latent: [B, H_trace, 512]
```

但它只用於：

```text
風險預測
credit assignment
soft repair
```

不再承擔可靠回滾。

---

# 3.8 結論

修正後：

```text
soft rollback = 學習式修補
hard rollback = 精確還原
```

公式：

[
S_{rollback}
============

\begin{cases}
SoftRollbackNet(S), & low\ risk \
ScatterRestore(S), & high\ risk
\end{cases}
]

這是可靠性與全神經美學的折衷。
如果只能選一個，應該選 hard rollback。

# 4. Dream replay 是成本與品質熱點，必須改成「分層 replay」

你第四點也正確。

原本：

```text
dream_hidden: [B, 512, T_dream, 1024]
```

若：

```text
B = 16
N_dream = 512
T_dream = 8
d_model = 1024
```

float32 大約：

[
16 \times 512 \times 8 \times 1024 \times 4
\approx 268MB
]

float16 也約 134MB。
而這只是 dream hidden 本體，不含 autograd activation、attention、teacher、student forward。

所以 dream replay 不能一開始就做 full hidden trajectory。

---

# 4.1 正確方向：Dream Replay 分三層

不要一開始生成完整 hidden sequence。
改成：

```text
Level 1: Probe Replay
Level 2: Sketch Replay
Level 3: Full Hidden Replay
```

平常用 Level 1 / Level 2。
只有少量高風險樣本才用 Level 3。

---

# 4.2 Level 1：Probe Replay

最便宜。

DreamGenerator 不生成序列，而是生成 latent probe：

```text
dream_probe:  [B, N_dream, d_model]
dream_target: [B, N_dream, d_anchor]
dream_weight: [B, N_dream]
```

例如：

```text
N_dream = 128
d_model = 1024
d_anchor = 256
```

模型把 probe 當作 hidden state 測試：

[
z_{student}
===========

ProbeHead(f_\theta(dream_probe))
]

loss：

[
L_{probe}
=========

D(
z_{student},
dream_target
)
]

優點：

```text
不用生成 token sequence
不用跑完整 LM decoding
成本低
適合 sentinel / old behavior anchor
```

---

# 4.3 Level 2：Sketch Replay

中等成本。

生成短序列的壓縮 sketch，不是完整 hidden：

```text
dream_input_emb: [B, N_dream, T_dream, d_model]
dream_target_sketch: [B, N_dream, T_dream, d_sketch]
```

其中：

```text
d_sketch = 128 或 256
```

不是：

```text
d_model = 1024
```

用 projection head 對齊：

[
sketch_{student}
================

W_{sketch}h_{student}
]

loss：

[
L_{sketch}
==========

|sketch_{student} - dream_target|^2
]

這比 full hidden 省很多。

---

# 4.4 Level 3：Full Hidden Replay

只用於：

```text
高重要性
高遺忘風險
高衝突
sentinel failure
core distillation 前驗證
```

形狀：

```text
dream_hidden: [B, N_hard, T_dream, d_model]
```

其中：

```text
N_hard = 16 或 32
```

而不是 512。

---

# 4.5 Replay Budget Controller

新增一個 ReplayBudgetNet：

[
b_{replay}
==========

ReplayBudgetNet(
memory_pressure,
forgetting_risk,
compute_budget,
sleep_phase,
risk
)
]

輸出：

```text
N_probe
N_sketch
N_full
T_dream
d_sketch
```

例如：

```text
低風險：
    N_probe = 128
    N_sketch = 32
    N_full = 0

中風險：
    N_probe = 256
    N_sketch = 64
    N_full = 8

高風險：
    N_probe = 256
    N_sketch = 128
    N_full = 32
```

---

# 4.6 Dream 品質不能假設，要有 Dream Verifier

DreamGenerator 品質差會造成：

```text
錯誤 replay
錯誤 consolidation
錯誤 core distillation
```

所以每個 dream sample 要有 quality score：

[
q_i^{dream}
===========

DreamCritic(
m_i,
\hat{x}_i,
\hat{y}_i,
\hat{z}_i,
teacher_sketch
)
]

Replay loss 使用：

[
L_{dream}
=========

\sum_i
q_i^{dream}
w_i
L_i
]

低品質 dream：

[
q_i^{dream} \approx 0
]

不參與整合。

---

# 4.7 Dream coverage loss

DreamGenerator 不能只生成容易樣本。
要覆蓋高風險、高重要性記憶。

定義 memory coverage：

[
coverage_i
==========

\sum_j
A_{dream}(j,i)
]

其中 (A_{dream}) 表示 dream sample (j) 覆蓋 memory (i) 的程度。

Coverage loss：

[
L_{coverage}
============

\sum_i
importance_i
\cdot
\max(0, \tau - coverage_i)
]

這會逼 DreamGenerator 覆蓋重要 memory。

---

# 4.8 Dream diversity loss

避免 dream 全部長得一樣：

[
L_{diversity}
=============

*

\frac{1}{N^2}
\sum_{i,j}
(1 - sim(z_i,z_j))
]

也可以對同 cluster 內做 diversity，避免 replay 只覆蓋單一版本。

---

# 4.9 Dream replay 訓練策略

一開始不要讓 dream 參與核心更新。
訓練階段應該分層：

```text
Stage A:
    Dream 只做 behavior reconstruction。
    不允許改 core。

Stage B:
    Dream 用於 adapter replay。
    不允許 core distillation。

Stage C:
    Dream 通過 verifier 後，
    少量用於 core distillation。

Stage D:
    只有 high-quality + high-confidence dream
    才能影響核心。
```

# 6. 修正後的核心設計原則

你指出的四點，可以濃縮成這些原則。

---

## 原則 1：Safety 不能只是 risk score

```text
risk score 可以輔助；
不可塑 kernel 和 hard update mask 才是保證。
```

即使先放一邊，也不能把 safety 當成普通 trainable state。

---

## 原則 2：Memory 表徵能力要先驗證

不能假設：

[
v_i \in \mathbb{R}^{512}
]

足以表示一條 fact。

應改成：

```text
value_latent
→ memory capsule
→ prefix tokens / cross-attention / local adapter
```

並用 atomic fact、collision、conflict version 任務驗證。

---

## 原則 3：Rollback 必須有 hard path

```text
soft rollback 是修補；
hard rollback 是保證。
```

固定張量也能做 hard rollback：

```text
address one-hot + old value + scatter restore
```

---

## 原則 4：Dream replay 要分層

不要一開始生成：

```text
[B, 512, T, 1024]
```

應改成：

```text
probe replay
sketch replay
少量 full hidden replay
```

並加入：

```text
DreamCritic
coverage loss
diversity loss
budget controller
```

# 8. 最終建議

下一版 spec 應該不要先展開全部 30 個模組，而是先固定三個可驗證核心：

```text
1. Memory Capsule Interface
2. Exact Rollback Interface
3. Budgeted Dream Replay Interface
```

因為這三個如果不成立，後面的 SleepNet、CoreDistill、ExpertCompress、MetaTraining 都會建立在不穩定基礎上。

最小正確架構應該是：

[
S_t =
{
M_t^{capsule},
R_t,
I_t,
P_t,
DreamProbe_t,
Sentinel_t,
RollbackExact_t
}
]

暫時不要讓 core 大幅更新。

先證明：

[
write \rightarrow read \rightarrow conflict \rightarrow rollback \rightarrow replay
]

這條鏈能穩定工作，再談：

[
adapter compression
\rightarrow
core distillation
\rightarrow
long-horizon meta-learning
]

一句話總結：

> **全神經持續學習系統的第一版，不應追求模組完整，而應先證明三件事：memory latent 真的能存知識、rollback 真的能精確還原、dream replay 真的能提供低噪聲防遺忘訊號。這三個成立後，SleepNet(_\Omega) 才有資格往更完整的神經自我整合系統發展。**
