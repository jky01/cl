# 0. 先拍板：v0 採用哪種寫入？

[

# 3. key 分配：不能只靠語義相似度

你指出第二個核心問題：

> 如果 key 也來自 WriteNet，相似 entity / relation 會產生相似 key，碰撞大概率發生。

所以 key 必須拆成兩種：

```text
k_sem  = 用來查詢相似事實
k_addr = 用來分配寫入位置，避免碰撞
```

---

# 3.1 雙 key 設計

每個 slot 有：

```text
k_sem:  [128]
k_addr: [128]
```

查詢時用：

[
q_{sem}
=======

QueryEncoder(x_{query})
]

對：

[
k_{sem}
]

做 retrieval。

寫入時用：

[
k_{addr}
]

做 allocation。

也就是：

```text
semantic key 負責「找得到」
address key 負責「不撞位」
```

---

# 3.2 Product-key allocation

為了避免碰撞，`k_addr` 不直接是一個 dense vector，而是由 product code 產生。

設定兩組 codebook：

```text
C1: [N1, 64]
C2: [N2, 64]
```

例如：

```text
N1 = 64
N2 = 64
```

可形成：

[
64 \times 64 = 4096
]

個 address buckets。

WriteNet 輸出：

```text
logits_1: [B, 64]
logits_2: [B, 64]
```

用 Gumbel-softmax 訓練：

[
p_1 = GumbelSoftmax(logits_1)
]

[
p_2 = GumbelSoftmax(logits_2)
]

address key：

[
k_{addr}
========

[p_1 C_1,\ p_2 C_2]
]

所以：

```text
k_addr: [B, 128]
```

部署時可以 hard argmax：

```text
bucket_id = argmax(logits_1) * N2 + argmax(logits_2)
```

這樣 address 有明確分散機制，不只是希望 dense key 自己不要撞。

---

# 3.3 寫入槽位選擇

Memory 固定：

```text
M: [B, 4096, 1536]
```

每個 slot 對應一個 product bucket。

寫入時：

1. 先選 bucket。
2. 若 bucket 空，寫入。
3. 若 bucket 已用，選 bucket 內低 usage / 低 confidence / tombstone 的 slot。
4. 若真的滿，觸發 eviction / compression。

在完全固定 4096 slots 的 v0，可以簡化成：

```text
one bucket = one slot
```

也就是 product-key 直接對應 slot index。

---

# 3.4 key 去相關化 loss

只設計 product-key 還不夠，還要訓練 key 分散。

對一批 facts：

[
f_i = (s_i,r_i,o_i)
]

語義查詢 key：

[
q_i
]

slot semantic key：

[
k_i
]

正樣本：

[
sim(q_i,k_i)
]

負樣本：

[
sim(q_i,k_j),\quad j \neq i
]

contrastive retrieval loss：

[
L_{retrieve}
============

-\log
\frac{
\exp(sim(q_i,k_i)/\tau)
}{
\sum_j \exp(sim(q_i,k_j)/\tau)
}
]

---

## 3.5 same-relation hard negatives

最重要的是 hard negatives：

```text
entity_1 relation object_1
entity_2 relation object_2
entity_3 relation object_3
```

這些 relation 相同，entity 不同，最容易撞。

加入 margin loss：

[
L_{margin}
==========

\max
\left(
0,
m
+
sim(q_i,k_{neg})
----------------

sim(q_i,k_i)
\right)
]

其中 (k_{neg}) 來自：

```text
same relation, different subject
```

---

## 3.6 address balance loss

避免所有 facts 都集中到少數 product buckets：

[
L_{balance}
===========

\sum_b
\left(
p_b
---

\frac{1}{N_{bucket}}
\right)^2
]

其中 (p_b) 是 batch 內 bucket 使用率。

---

## 3.7 v0 key loss

總 key loss：

[
L_{key}
=======

L_{retrieve}
+
\lambda_1 L_{margin}
+
\lambda_2 L_{balance}
+
\lambda_3 L_{orth}
]

其中：

[
L_{orth}
========

\left|
\frac{K^\top K}{N}
------------------

I
\right|_F^2
]

這樣才是「主動避免碰撞」，不是只在實驗中觀察碰撞。

# 4. v0 寫入完整演算法

```text
Algorithm: AmortizedFactWriteV0

Input:
    x_write: [B, T]
    y_write: [B, T]
    M_t:     [B, 4096, 1536]

Output:
    M_{t+1}

Steps:

1. H_w = FrozenCore(x_write)

2. z_f = FactEncoderΩ(H_w, y_write)

3. WriteNetΩ(z_f) outputs:
       k_sem:      [B, 128]
       k_addr:     [B, 128]
       v_caps:     [B, 512]
       ans_prefix: [B, 512]
       ctx:        [B, 64]
       meta:       [B, 80]
       aux:        [B, 112]

4. ProductKeyAllocator chooses slot index:
       slot_id: [B]

5. Construct m_hat:
       m_hat = concat(k_sem, k_addr, v_caps, ans_prefix, ctx, meta, aux)

6. Hard write:
       M_{t+1}[slot_id] = m_hat

7. Store hard rollback entry:
       old_value = M_t[slot_id]
       addr = slot_id
```

注意：v0 寫入不是可微分 scatter 的美學版本，而是**部署合理的硬寫入**。
訓練時可以用 straight-through estimator 或 soft write 近似；但 v0 驗證時要用 hard write，因為這才是未來部署成本。

# 5. v0 讀取完整演算法

Algorithm: CapsuleReadV0

# 8. Hard rollback：要從 per-slot 修補升級成 transaction

你指出第三點也對。

單純：

```text
restore slot old value
```

只處理短程局部錯誤，不處理衍生效應。

正確設計應該是：

```text
transactional state update
```

---

# 8.1 每次 update 都是一個 transaction

定義 transaction：

[
\tau_j
======

{
id_j,
parent_j,
t_j,
writes_j,
derived_j,
status_j
}
]

狀態：

```text
pending
committed
invalidated
rolled_back
```

---

## 8.2 transaction log 使用整數索引，不用 one-hot

你說得對：

```text
[B, 128, 16, 4096] one-hot address
```

是設計味道。

hard rollback 不需要可微，應存整數：

```text
mem_log_idx:   int16 / int32 [B, H_trace, K_mem_write]
mem_log_value: fp16 / bf16   [B, H_trace, K_mem_write, d_slot]
mem_log_valid: bool          [B, H_trace, K_mem_write]
```

例如：

```text
mem_log_idx:   [B, 128, 16]
mem_log_value: [B, 128, 16, 1536]
mem_log_valid: [B, 128, 16]
```

比 one-hot 小非常多。

---

# 8.3 transaction 必須記錄衍生效應

如果一個壞 fact 後來被：

```text
merge
version
router update
importance update
dream replay
```

使用，那麼 rollback 原 slot 不夠。

所以每個 derived update 要記錄 parent transaction。

例如：

```text
memory slot i:
    origin_txn = 17
    parent_txns = [12, 14, 17]

router update:
    parent_txns = [17, 18]

importance update:
    parent_txns = [17]
```

用固定大小整數陣列：

```text
mem_parent_txn:    int16 [B, N_mem, K_parent]
expert_parent_txn: int16 [B, K_exp, K_parent]
router_parent_txn: int16 [B, C_ctx, K_parent]
```

例如：

```text
K_parent = 4 or 8
```

如果 transaction 17 被判定錯誤，所有依賴它的 derived state 都要：

```text
invalidate 或 rollback
```

---

# 8.4 rollback 應該是 transaction rollback

```text
Algorithm: RollbackTransaction(txn_id)

1. 找到 txn_id 的直接 writes
2. restore old values
3. 找到所有 descendant transactions
4. 將 descendant state 標記為 invalid
5. 對 invalid memory/expert/router 降低 read gate
6. 必要時 rollback 到最近 checkpoint
```

---

# 8.5 長程錯誤：需要 checkpoint，不只 ring buffer

你也指出：

> 最難的是 20+ 步後才發現錯。

如果 ring buffer 滿了，old value 消失，hard rollback 無法做。

所以需要兩層：

```text
short-term transaction log
+
periodic checkpoint
```

---

## 8.5.1 checkpoint 不是每步都存 full state

可以做 page-level copy-on-write。

Memory 分 page：

```text
N_mem = 4096
page_size = 64
N_page = 64
```

memory：

```text
M: [B, 64, 64, 1536]
```

如果 transaction 改了某個 page，先把整個 page 的 old value 存進 page log：

```text
page_log_idx:   int16 [B, H_page, K_page]
page_log_value: fp16  [B, H_page, K_page, 64, 1536]
```

這比存完整 memory 便宜，也比 per-slot 更能保持一致性。

---

## 8.5.2 checkpoint epoch

每次 sleep / validation 完成後建立 checkpoint：

```text
checkpoint_epoch += 1
```

只有通過 validation 的 transaction 才能進入 checkpoint。

未通過的 transaction 保持 pending。

---

# 8.6 對衍生效應的處理原則

```text
low-risk local write:
    per-slot rollback 可以

merge / router / importance / core update:
    必須 transaction group rollback

core distillation:
    必須 checkpoint 前置，不能只靠 slot restore

sleep consolidation:
    必須整批 transaction commit 或整批 abort
```

這代表 SleepNet 的更新不能是零散提交，而要是：

[
atomic\ transaction
]

要嘛整批 commit，要嘛整批 rollback。

# 12. Step 1 才測 collision

Step 0 成功後，才做：

```text

```

特別是 hard negatives：

```text

entity_3 capital_of city_3
```

測：

```text

是否 entity confusion
是否 relation collision
```

# 13. Step 2 才測 version

再加入：

```text
entity_1 capital_of city_old at t1
entity_1 capital_of city_new at t2
```

測：

```text
query with t1

query without time
```

如果沒有時間資訊時，模型要輸出：

```text

或選最新版本
```

# 14. Step 3 才加 hard rollback

先測單步錯誤寫入：

```text
1. 寫入 correct fact
2. 寫入 wrong fact
3. hard rollback wrong write
4. 測 correct fact 是否恢復
```

這一步只需要 transaction log，不需要 SleepNet。

# 15. Step 4 才加 dream

只有當：

```text

collision
version
rollback
```

都過關，才加 dream。

而且 dream 第一版只做：

```text
memory capsule → probe query / answer sketch
```

不要直接做 full hidden replay。

# 17. 最終修正後的核心結論

目前真正要先決定的是：

## 17.1 寫入模式

v0 選：

[
\boxed{
\text{amortized no-gradient write}
}
]

也就是：

[
m_{new}
=======

WriteNet_\Omega(x,y,H)
]

直接寫入 slot。

梯度式寫入先不放進 v0。

---

## 17.2 key 機制

使用：

[
\boxed{
semantic\ key + product\ address\ key
}
]

其中：

```text
k_sem  用於 retrieval
k_addr 用於 allocation
```

再加：

```text
contrastive retrieval loss
hard negative margin loss
bucket balance loss
orthogonality loss
```

---

## 17.3 rollback 機制

使用：

[
\boxed{
transaction log + integer index + old value + checkpoint
}
]

不要用 one-hot address。
不要只做 per-slot restore。
Sleep / merge / router / importance / core update 必須 transaction group commit。

---

## 17.4 dream 驗證順序

使用：

[
\boxed{
memory\ first,\ dream\ later
}
]

Dream 依賴 memory，所以不能和 memory 當獨立假設並行驗證。

---

## 17.5 baseline

至少比較：

```text
No memory
In-context fact
External KV retrieval
Oracle slot
Neural capsule memory
```

如果 neural capsule 連 in-context / KV 都打不過，就要重新評估它的價值。

---

## 17.6 真正 MVP

不是：

```text
capsule + version + rollback + dream + sentinel + commit
```

而是：

```text
single fact write → read → answer
```

完整公式：

[
x_{write},y_{write}
\rightarrow
WriteNet_\Omega
\rightarrow
m_i
\rightarrow
MemoryRead
\rightarrow
ValueDecoder
\rightarrow
answer
]

如果這條鏈不成立，後面全部暫停。

一句話總結：

> **下一步不是擴張 SleepNet，而是先證明無梯度 WriteNet 能把一條新 fact 編成可讀取、可解碼、可回答的 memory capsule；同時用 product-key address 避免碰撞，並用 baseline 驗證它是否比 prompt/KV 有存在價值。**
