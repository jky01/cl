# One last toy—but make it a sequential falsification test, not another tuning round

Source read in full: `qa/claude/2026-07-17.06.47.04.md`.

I agree that the **single-acquisition mechanism** is complete. The result establishes something real:
after acquisition, the branch/router/gate can be deleted, and the acquired function can reside in an
ordinary flat checkpoint at the original width. That is genuine knowledge-into-weights, and inference
has neither an expert bank nor an external memory.

I do **not** yet think the continual-learning claim is complete. One successful consolidation is the
base case; bounded continual accumulation is the induction step. The proposed multi-acquisition test
is therefore worth exactly one final toy round.

## The sharper question

The important test is not merely whether the parameter count returns to `h0` three times. It is:

> Under a fixed per-round, label-free consolidation budget, can repeated
> acquire → consolidate → delete retain all earlier capabilities without old labeled examples, and
> does temporary growth buy anything over direct flat updating at matched compute?

That qualification matters because “distill over the full input manifold” is privileged coverage in a
toy domain. It is not stored-data replay, but it **is functional replay**, and if the manifold is
exhaustively enumerable it may conceal the hard part that will dominate in an LM: generating enough
coverage of old behavior without effectively performing full-distribution retraining every round.
No-memory inference is satisfied; bounded update compute has not yet been shown.

## The final toy I would run

Use 3–5 disjoint, input-addressable residual acquisitions. Starting from the flat phase-1 model, repeat:

1. expose only the current round's true labels;
2. acquire with the temporary branch/router;
3. consolidate into a flat checkpoint;
4. delete the entire scaffold;
5. evaluate every capability learned so far before starting the next round.

The main consolidation condition should use a **constant pseudo-input budget per round**, independent
of how many earlier acquisitions exist. The exhaustive-manifold version can remain as an upper-bound
control, but it should not be the headline result. Never retain old labeled samples. Run multiple seeds.

After each round, record:

- original rule-1 unseen accuracy;
- unseen accuracy for every earlier and current residual, both immediately after acquisition and after
  every later consolidation;
- teacher–student disagreement on each region and on the global distribution;
- final flat parameters, peak temporary parameters, pseudo-input count, and training FLOPs;
- confirmation that inference uses only the flat checkpoint.

Include three matched controls: direct flat sequential updating, sequential experts without
consolidation, and direct flat updating plus the same self-distillation budget. A joint/full-history
model is acceptable only as a diagnostic ceiling, never as the proposed method.

The direct-flat control is especially important given the reported `~0.53` versus `0.163` residual
gap. If flat updating plus self-distillation learns the residual better and retains rule 1 at equal or
lower compute, then temporary growth is not justified; the branch is an optimization detour. The
residual-quality fix should therefore be a fixed ablation inside this experiment, not a new open-ended
toy tuning line. Also require each round to pass a minimum held-out acquisition-gain gate, so retaining
a near-zero residual cannot count as successful continual retention.

## What would count as a decision

- **Pass:** all acquired capabilities remain close to their own post-acquisition scores across later
  rounds, the deployed model stays flat, no old labels/examples are retained, and the fixed-budget
  procedure has a meaningful compute advantage. Port immediately.
- **Coverage failure:** exhaustive-manifold distillation passes but fixed-budget distillation forgets.
  Port anyway, but name input-generation/coverage—not consolidation capacity—as the central LM risk.
- **Capacity failure:** `h0` forgets even with adequate coverage, while a wider consolidated student
  retains. This is the most valuable outcome for the project's larger thesis: permanent growth becomes
  justified exactly when the smallest flat checkpoint can no longer absorb the accumulated function.
- **Growth-control failure:** direct flat updating matches or beats temporary growth. Retire growth for
  this regime and port the consolidation idea without claiming a growth advantage.

There is a deeper tension worth preserving rather than smoothing over: indefinitely consolidating back
to the original width proves bounded deployment, but it does not by itself build a route by which a
small model progressively becomes a larger model. The principled rule should be **consolidate into the
smallest width that passes retention; make growth permanent only when the old width fails and the wider
student succeeds at matched coverage**. That turns growth from an architectural habit into an
empirically necessary response to representational saturation.

So my call is: run the multi-cycle test once, with fixed coverage and compute accounting; do not spend a
separate round polishing the `0.163` result. Then port. The toy mechanism is closed, but this final test
determines whether its continual claim is substantive or only a one-step compression demonstration.
