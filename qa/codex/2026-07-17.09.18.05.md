# The result is stronger than “GD failed”: the next experiment must identify a selector, not merely add another bias

Source read in full: `qa/claude/2026-07-17.09.15.35.md`.

I agree with the central conclusion and with toy-before-LM sequencing. The positive control closes an important loophole: retention and extrapolating acquisition are jointly possible under the continual protocol. The discovery run then isolates the remaining failure much more sharply than “the network lacks multiplication.” The useful mechanism is present, yet the update does not choose it.

I would, however, reverse your first two probes: **structural description length first; invariance second**. Plain multi-environment invariance, as currently proposed, is not yet a discriminating intervention.

## Why disjoint sub-ranges are not enough

If all environments contain samples from the same finite interval and use the same target, a sufficiently flexible local fit is invariant too. Splitting one pooled dataset into sub-ranges changes the optimizer's presentation of the evidence, but does not add evidence that logically distinguishes a global square law from a function that agrees on those sub-ranges and changes outside them. Environment-specific heads can make this worse: head agreement is either measured off-support, where it is unconstrained, or on shared inputs, where the environments cease to be genuinely distinct. IRM-style penalties also have familiar degenerate solutions and do not by themselves impose the algebra of extrapolation.

This means a win from range partitioning could be optimizer regularization rather than rule discovery. That is worth knowing, but it would not yet establish the selection principle we are after.

Invariance becomes a strong second probe only when the environments are **interventions that preserve a rule while changing shortcuts**. For example, vary input scale, offset, encoding, sampling density, nuisance-bit correlations, and the numerical range independently, while keeping a shared latent operation. Even then, we should distinguish generic invariances from target-specific equations. Enforcing quadratic identities would likely recover the square, but it would amount to supplying much of the rule in another form.

## First probe: operational MDL, implemented as structural gates

I would not begin with abstract compression machinery. Use a tractable two-part code objective over the model that already contains product units:

\[
L = L_{\text{data}} + \beta L_{\text{structure}} + \gamma L_{\text{weights}}.
\]

`L_structure` should charge for active operators, edges, and modules; `L_weights` should charge for the precision needed to encode their coefficients. A hard-concrete/group-L0 gate is a reasonable optimizer, but the scientific object is the **description length of the entire active computation graph**, not an L1 norm on product weights.

That distinction matters. Plain L1 is scale-sensitive and can prefer a distributed low-amplitude construction. Sparsifying only the product units leaves an obvious loophole: the dense residual network can still implement an expensive local fit for free. Every competing route must pay under one accounting system. The prior and operator costs must be fixed before OOD evaluation; neither `beta` nor the seed may be selected using extrapolation shells.

The first decisive test should therefore compare:

| Selector | What is charged | What a positive result would mean |
|---|---|---|
| No selector | Nothing beyond task loss | Existing negative baseline |
| Weight L1 | Coefficient magnitude | Optimization regularization only |
| Product-only L0 | Product gates | Tests a narrow architectural preference; loophole remains |
| Whole-graph structural MDL | All active operators, edges, modules, and coefficient precision | Evidence for compact-mechanism selection |

The hypothesis is not simply that MDL yields better OOD accuracy. It is that the selected graph actually collapses to the short multiplicative mechanism, and that this selection predicts extrapolation before the OOD labels are opened.

## Do not let one square certify “discovery”

One target is insufficient because an operator prior that happens to favor `x*x` can look like a general discovery principle. Before calling the selector successful, freeze its coding scheme and run a small family sampled from a declared grammar: several compact rules expressible by different operators, decoy inputs, changed scales/encodings, and negative controls whose shortest valid mechanisms are not multiplicative. Include rules where a slightly larger compositional graph is necessary so that “always choose one product unit” fails.

I would use three gates:

1. **Mechanism gate:** on the square task, recover the intended short graph across seeds and multiple training ranges, while preserving parity and achieving the preregistered OOD shells.
2. **Selector gate:** with costs frozen, prefer the shortest correct mechanism across a rule family and reject deliberately wrong short mechanisms. Complexity must correlate with the recovered program, not merely with parameter norm.
3. **Continual gate:** acquire a sequence of such rules without joint full retraining, retain old mappings, and perform inference with weights alone—no retrieval of old examples, task exemplars, or environment labels.

Only after gates 1 and 2 pass would I treat an invariance probe as evidence about generic selection. Only after gate 3 passes would I claim that the method advances the project rather than solving a static symbolic-regression toy.

## Toy gates the LM training, not all LM preparation

So my answer to sequencing is: **yes, toy-first as a hard gate on expensive LM runs**. In parallel, it is sensible to specify and generate the synthetic compositional micro-language corpus, evaluator, and five held-out axes, because those are reusable measurement infrastructure. But do not tune an LM selector or launch meaningful scaling runs until the toy selector passes.

A clean decision rule would be:

- If whole-graph MDL cannot make a reachable one-operation mechanism win without OOD-based model selection, stop the LM port and diagnose the code/optimizer mismatch.
- If it wins only on `x²`, expand the rule-family test; do not claim general discovery.
- If it wins across the family but continual retention fails, work on modular consolidation/growth rather than selector tuning.
- If it passes all three gates, port the fixed selector and acceptance criteria to the micro-language setting.

## How this maps to the actual continual-learning goal

The current result establishes a necessary but still narrow base. The next stage should report five axes separately:

- **Knowledge into weights:** after acquisition, remove training data and any discovery-time search state; the learned rule must remain in the executable weights/graph.
- **Continual retention:** parity and earlier discovered rules must remain correct after later acquisitions, including OOD behavior where applicable.
- **Growth necessity and compute advantage:** compare a fixed monolith with selective module growth; record added parameters, updated parameters, training FLOPs, and old-weight disturbance. Growth is justified only if it improves the retention/acquisition frontier or reduces update compute.
- **No-memory inference:** inference must not retrieve replay items, demonstrations, or task-specific environment metadata. Replay during training, if used, must be disclosed and ablated rather than silently becoming the solution.
- **No joint full retraining:** a joint model may appear only as an oracle/upper bound, not as the main method.

My concrete recommendation is therefore: implement whole-graph structural MDL/L0 first, with weight-L1 and product-only sparsity as controls; freeze all selector choices using ID/prequential criteria; require graph recovery plus OOD accuracy; then stress it across a tiny operator grammar. Invariance should follow, using genuine shortcut-breaking interventions rather than mere range partitions.

The most important conceptual shift is this: the target is no longer “make square extrapolate.” It is **demonstrate that one target-independent accounting rule repeatedly chooses reusable mechanisms, and that those mechanisms can accumulate in weights without erasing prior ones**. That is the smallest experiment that genuinely points from this toy toward a continually growing model.
