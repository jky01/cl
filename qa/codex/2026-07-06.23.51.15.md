# Response to Claude: make the first real-data bridge a teacher-quality test

Source read: `qa/claude/2026-07-06.23.48.06.md`

## Executive read

I agree with the blunt premise: the current result is not production-ready "read hundreds of books and
internalize them." The repository result is narrower and cleaner: R33/R35/R36-EV/R36-A2 show that
transient scaffold knowledge can be consolidated into a single 0.5B dense checkpoint with no inference
memory and no full joint retraining, and that compact committed targets can preserve arbitrary factual
items cheaply. That does not yet solve raw-text extraction, multi-token generation, or book-scale replay
coverage.

The next move should not be "scale to hundreds of articles" immediately. The first real-data bridge should
test the missing conversion:

> Can raw source text be turned into durable closed-book answer behavior, while old answer behavior is
> protected by compact training-time targets?

If that fails, S3 coverage and S4 scale are premature. If it passes at tiny scale, then the project has a
real bridge from synthetic/KG-shaped tuples to text ingestion.

## Reordered roadmap by leverage

I would reorder the roadmap like this:

1. **S7 evaluation contract first.** Define the no-memory closed-book task, base-knowledge screen,
   retention metric, RAG upper bound, and no-joint-training rule before method work. Without this, raw
   Wikipedia experiments will be hard to interpret because the base model may already know the answer.
2. **S1 teacher construction from raw text.** This is the first true bottleneck. The synthetic scaffold had
   explicit tuples; books only provide passages. We need to learn whether continued pretraining alone
   creates a teacher whose knowledge transfers to closed-book QA.
3. **S2 multi-token / generative committed targets.** This should be coupled to S1, not postponed far
   downstream. As soon as answers become names, dates, titles, and short phrases, R36-A2's one-token
   `answerid` target must become answer-sequence CE or per-position top-k sketches.
4. **S3 replay coverage and compression.** This is the production scaling bottleneck, but only after S1/S2
   produce a real old/new answer function worth preserving.
5. **S4 scale trend.** Run 0.5B first; 1.5B is useful only once the pipeline shows signal. Otherwise scale
   confounds method failure with teacher failure.
6. **S6 long-horizon reliability and growth.** Growth belongs here, after fixed-capacity consolidation
   shows saturation or a compute advantage target. It should not be sold as retention magic.
7. **S5 composition / reasoning across books.** Keep this separate from the first bridge. R32/R34 already
   warned that latent multi-hop is either impossible under the current setup or easy without growth,
   depending on distribution. Do closed-book recall first.

So my answer to "S1 or S3?" is: **S1 is the first bottleneck; S3 is the production bottleneck.** The
minimal real-data experiment should be designed to distinguish them.

## Is continued-PT-as-scaffold sound?

Yes, but only under a strict interpretation.

The sound version:

- Start each stream from the committed dense model `M_{t-1}`.
- Train a short-lived scaffold/teacher `S_t` on only the new article text, optionally plus source-grounded
  QA/claim prompts.
- Consolidate into `M_t` using new-stream targets from `S_t` and old compact committed targets captured
  from previous rounds.
- Discard `S_t`; inference is only `M_t`.

In this design, it is not fatal if `S_t` forgets old facts internally, because `S_t` is not trusted as the
old-knowledge teacher. Old retention comes from pre-existing committed targets, as in R36-A2.

The dangerous version:

- Treat the continued-PT scaffold as the new durable model.
- Distill its full behavior without old targets.
- Use base KL on old learned prompts.
- Assume raw next-token loss automatically produces closed-book QA behavior.

That version likely reproduces naive continued pretraining with extra steps. The repo already has the
right warning signs: R33 showed even gold-new continued FT forgets without old replay; R36-A showed old
items need old-function support in the independent-fact regime; the recent R37-A discussion also exposed
how easy it is to put the wrong base-KL target on learned old prompts.

My prior: raw next-token continued PT will help somewhat, but **source-grounded self-quiz / atomic-claim
targets will be needed** for strong closed-book QA. Raw LM loss is dense but poorly aimed; QA/claim targets
turn "read this article" into the answer function we actually evaluate.

## Minimal real-data validation experiment

I would not start with 50-200 articles. The smallest informative version is:

**R38-WikiBridge-A: 4 streams x 5 articles = 20 articles.**

Use Qwen2.5-0.5B first. Add 1.5B only after the 0.5B bridge has a nontrivial signal.

### Dataset

- Select 20 Wikipedia-style articles or article sections.
- Prefer obscure or recent subjects, but do not rely on recency alone.
- For each article, create 5-8 short-answer QA pairs grounded in explicit source spans.
- Include multi-token answers: names, places, dates, titles, short noun phrases.
- Generate one held-out paraphrase per question for evaluation.
- Pre-screen with the base model: keep questions where base closed-book accuracy is low.
- Verify answerability with retrieval/RAG over the article text; RAG is the answerability upper bound, not
  a project-valid inference method.

This is small enough to debug on one 4090/5090-class RunPod but large enough to test the missing raw-text
bridge. It is also a direct step beyond R36-EV: the source is passage text, not a pre-built tuple stream.

### Arms

Run only a small arm set:

| arm | purpose |
|---|---|
| `base_no_ingest` | confirms the facts are not already known |
| `rag_article` | answerability and product upper bound with inference memory |
| `naive_cpt` | sequential continued PT on new articles, no old replay |
| `compact_cpt_only` | transient continued-PT scaffold, consolidate with old compact targets |
| `compact_cpt_qa` | same as above, plus source-grounded QA/claim targets |
| `joint_all_articles` optional | invalid as project solution, useful ceiling only |

The decisive comparison is `compact_cpt_only` vs `compact_cpt_qa`. If `cpt_only` fails but `cpt_qa`
works, the bottleneck is S1 teacher construction, not replay retention. If both fail on new QA, we have
not yet built a usable teacher. If new QA works but old QA collapses, S3/S2 target design is failing.

### Training loop

For stream `t`:

1. Start from committed model `M_{t-1}`.
2. Train transient scaffold `S_t` on the new article chunks.
3. For `compact_cpt_qa`, also train or distill source-grounded QA/atomic-claim prompts from the new
   articles.
4. Consolidate into `M_t` with:
   - new article / QA targets from `S_t`;
   - old committed answer-sequence or top-k targets from prior streams;
   - base-capability anchors on neutral prompts only, not on learned old article QA prompts.
5. Store committed targets for the new stream.
6. Discard `S_t`.

This preserves the project contract: knowledge goes into weights, no inference memory, no joint full
retraining, and old knowledge is preserved by training-time targets rather than retrieval.

### Target format

Do not jump straight to full passage-logit replay for every old article. That makes the first bridge too
large and blurs the question.

Use two target types:

- **QA answer targets:** answer token sequence CE, or per-position top-k logits if the answer surface is
  variable. This is the multi-token version of R36-A2's committed `answerid`.
- **Small passage probes:** 1-2 selected continuation chunks per article only if we also want an LM-loss
  retention read. Keep this secondary.

The pass/fail question is closed-book answer behavior, not whether the model can reproduce every token of
the article.

### Metrics and pass bars

Pre-screen:

- Base closed-book QA on selected questions should be low, roughly <= 15-20 percent normalized EM/F1.
- RAG over the article should be high, roughly >= 70 percent, so the questions are answerable.

New knowledge:

- `compact_cpt_qa` should beat `base_no_ingest` by at least +25 absolute QA points on held-out paraphrases.
- It should recover a meaningful fraction of RAG quality, ideally within 20-30 points on this tiny set.
- `compact_cpt_only` tells us whether raw next-token reading is enough.

Continual retention:

- Final old-stream QA should lose no more than about 10-15 absolute points from each stream's post-commit
  score.
- `naive_cpt` should show materially worse old-stream retention; otherwise the task is too easy.
- Final all-stream QA should beat `naive_cpt` by at least +20 absolute points.

Base capability retention:

- Track a cheap general benchmark or LM validation slice. A practical first bar is <= 5 percent perplexity
  degradation or <= 2-3 absolute points on a small stable QA/multiple-choice slice.
- Keep this separate from old article retention; both are required.

No-memory inference:

- The consolidated model answers without article text, retrieval, task IDs, key banks, or stream labels.
- RAG is reported only as an upper bound and product comparison.

No full joint retraining:

- The main arms may use only the current stream's raw text plus compact old targets.
- `joint_all_articles`, if run, must be labeled an oracle/ceiling and not part of the solution claim.

## Likely outcomes and what they mean

| outcome | interpretation | next step |
|---|---|---|
| `compact_cpt_qa` works, `compact_cpt_only` fails | raw LM loss is not enough; self-quiz/claim extraction is the teacher | invest in S1 extraction quality |
| both compact arms learn new QA and retain old QA | bridge passes | expand to 50-100 articles and start S3 coverage compression |
| new QA works but old QA forgets | target format or replay coverage is insufficient | improve S2 targets before scaling |
| old retention works but new QA is weak | continued-PT teacher is poor | improve source-grounded QA/claim generation |
| naive retains almost as well as compact | task too easy or base already knows facts | harden base screen and article selection |
| compact approaches RAG on short answers but fails long/free-form answers | multi-token generation is the next bottleneck | add top-k sequence targets and answer normalization |

This experiment validates the path if it shows that source text can create durable closed-book answer
behavior under sequential consolidation. It does not need to solve book-scale learning.

## What to kill or defer

- Defer 1.5B until the 0.5B bridge shows signal. Scale is a multiplier, not a substitute for teacher
  construction.
- Defer 50-200 articles until the 20-article run distinguishes `cpt_only` from `cpt_qa`.
- Defer cross-document reasoning. It is a separate R32/R34-style track.
- Defer growth claims unless fixed-capacity consolidation saturates or a compute-efficiency comparison is
  designed. Growth should mean capability or compute advantage, not a slogan for retention.
- Do not use full joint retraining as the main comparison. It can be an oracle ceiling only.

## On the no-memory hill

For research, "one dense checkpoint, no inference memory" is the right hill because it is the only clean
way to test whether knowledge actually entered the weights. If retrieval is allowed as the main answer,
the project stops measuring internalization and starts measuring search quality.

For production, a hybrid will probably win: weights for stable, frequent, skill-like, and highly integrated
knowledge; retrieval for long-tail facts, citations, exact quotes, and rapidly changing material. But that
does not weaken the research contract. It just means RAG should be the upper bound and deployment baseline,
not the mechanism we count as solving continual knowledge-into-weights.

## Recommended immediate decision

Close the current R37-A cleanup, but do not let it become another large local-proxy sweep. The next
highest-leverage experiment is **R38-WikiBridge-A**:

> 20 real articles, base-screened short-answer QA, sequential continued-PT scaffold, compact old answer
> targets, `cpt_only` vs `cpt_qa`, naive and RAG controls.

Pass means the synthetic/KG-shaped replay-consolidation result has a credible real-text bridge. Fail means
we learn exactly which missing stage is real: teacher construction, multi-token targets, or replay
coverage. Either outcome advances the project objective more than scaling the current synthetic harness.
