## Verdict

I agree with letting the R36-A sweep continue. The two immediate hygiene issues I raised are satisfied
for this run:

1. `PYTHONHASHSEED=0` is set by the sweep driver, so the current separate per-K processes should not
   be confounded by Python string-hash randomization.
2. The replay subsets are already nested prefixes, not independently drawn subsets.

That makes the running sweep valid as a storage-footprint probe. The one strict boundary remains:
the non-replayed result is provisional until small-K winners are checked against a full-ours
same-complement reference. Do not make a "minimal-footprint works" claim from the all-stream
full-ours number alone.

## Repository-grounded read

In `s2/lifecycle_bakeoff.py`, `run_consolidate` now implements the R36-A mechanism in the right
place. `BK_REPLAY_K=-1` keeps the established full replay path; `BK_REPLAY_K=0` creates an empty
prior pool; `BK_REPLAY_K>0` stores a fixed per-stream subset and replays only that subset during
later rounds. The final checkpoint is still a single dense model, inference uses no memory, and the
`ours` arm self-distills old streams from a pre-round snapshot rather than using old gold labels.
That is aligned with the project objective: the training scaffold can be transient, but the usable
knowledge must end in weights.

The subset implementation is indeed nested:

```python
sr = random.Random(seed * 100003 + j * 31 + 7)
idx = list(range(len(s)))
sr.shuffle(idx)
replay_subset.append([s[i] for i in idx[:REPLAY_K]])
```

So `K=4` is a prefix of `K=8` for the same seed and stream. This makes the K curve interpretable as
increasing retained coverage rather than a mixture of coverage and random subset luck. The follow-up
audit logging is still worth doing, but it is not a blocker for the run.

The remaining code hygiene issue is lower priority for this already-running sweep: `rng =
random.Random(seed * 13 + abs(hash(kind)) % 97)` is still brittle unless the driver pins
`PYTHONHASHSEED`. Because this run does pin it, the sweep is valid. Before any next sweep, replace
that with a stable explicit offset map so determinism is guaranteed by the script, not by the launch
environment.

## Non-replayed gate

Your provisional treatment of Q2 is the right compromise. The full-ours all-stream age curve can be
used to triage whether small K is even close, but it is not the final reference.

The reason is structural. The non-replayed metric for `K < PER` is evaluated only on old-stream
complement examples from streams `0..ROUNDS-2`. The full-ours all-stream average includes the newest
stream and the full old streams. Those are not the same distribution and can shift the bar in either
direction. A small-K run can look good against the wrong aggregate while still only protecting the
items it rehearsed; it can also be unfairly punished if the old-stream complement is harder than the
global average.

If `K<=8` clears the primary gates, the next run should be an eval-only or train-once full-ours
reference that emits, for the same nested complement:

- `full_ref_nonreplayed_seen_K4`
- `full_ref_nonreplayed_para_K4`
- `full_ref_nonreplayed_seen_K8`
- `full_ref_nonreplayed_para_K8`

Then the real gate is:

```text
smallK_nonreplayed_seen >= full_ref_nonreplayed_seen_K - 0.08
smallK_nonreplayed_para >= full_ref_nonreplayed_para_K - 0.08
```

alongside the already registered all-seen, all-para, oldest-forget, newest, and base-hop gates.

## Interpreting the running sweep

The result can support a storage-footprint claim, not a compute-footprint claim. For every `K>0`,
the training loop still samples `Bf` replay examples per step whenever prior streams exist. Small K
reduces stored committed examples and diversity, but not the replay branch frequency or nominal
old-prompt count. So the correct successful claim is:

```text
tiny committed training-time rehearsal can write broad old-stream protection into one dense
checkpoint with no inference memory
```

not:

```text
compute is reduced
```

and not:

```text
rehearsal-free continual learning is solved
```

The smoke result is already the main failure mode to watch: at `K=4`, replayed seen was high
(`0.75`) while non-replayed seen was near floor (`0.0625`). If the full 6x40x1000 sweep repeats that
pattern, R36-A is a clean negative: random tiny replay teaches the stored items but does not protect
the stream function. That would still move the project forward because it rules out a cheap random
subset story and points to a more structured preservation scaffold.

## Decision table

If `K<=8` passes the primary gates and the same-complement reference, call it a positive
minimal-storage replay-consolidation result. The claim should be narrow: "minimal-footprint
training-time rehearsal into weights, no inference memory." It is not a growth-necessity result.

If replayed metrics are high but non-replayed metrics lag, call it item rehearsal. The next branch is
coreset selection, key/relation-conditioned generated probes, or a learned preservation writer. Do
not continue by merely increasing random K unless the curve shows a clear knee.

If `K=16` or `K=40` is the first reliable point, replay remains load-bearing. That is still useful:
it quantifies the storage needed by the current consolidation recipe and prevents overclaiming.

If `K=0..8` stays near naive, stop the random-subset line. The next lever is not full joint
retraining and not another OGD patch; it is smarter selection or a writer objective that explicitly
preserves non-replayed old functions.

## Growth and project-objective lens

R36-A advances the main objective only if the old knowledge is recoverable from the final dense
weights without inference memory. The experiment is well-posed for that: all final metrics are on
the dense checkpoint, and the scaffold is training-time only.

It does not establish that growth is necessary. Growth is fixed in this lifecycle loop, while the
question being tested is replay footprint. Any positive R36-A result should be filed under
continual retention and knowledge-into-weights. A growth claim still needs separate evidence of
capacity saturation or compute advantage under matched controls.

Bottom line: keep the sweep running. Treat the non-replayed comparison as provisional until the
same-complement full-ours reference is run for any small-K candidate. If the smoke pattern persists,
take the negative seriously and pivot to structured probe selection rather than full-data joint
retraining or blind random-K scaling.
