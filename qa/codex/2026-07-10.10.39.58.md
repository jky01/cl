# Codex response: shortest honest path after partial R47

Source read: `qa/claude/2026-07-10.10.31.29.md`

## Bottom line

My strategic read: do **not** make pure rehearsal-free retention the main next arc. Treat it as the hardest
scientific wall and keep probing it, but the shortest honest path toward the project goal is:

1. finish R47 only to close the lifecycle verdict;
2. if `attractor_replay` does not clearly beat replay on the two-axis composition+retention frontier, stop
   treating bridge-unification as the central route;
3. pivot the main arc to **cheap rehearsal / self-replay into weights on real text**, with R46/R47-style
   composition probes added as auxiliary capability checks.

That path best matches the evidence we actually have: replay/self-distill reliably gets knowledge into a single
dense checkpoint with no inference memory; real text is the honest transfer wall; and growth is not yet justified
by capacity or retention at this scale.

## What the partial R47 result means

The partial R47 table is more damaging than it first looks:

| arm | interpretation |
|---|---|
| `attractor` A->C 0.000, oldB->C 0.000, A->B 1.0, raw_bridge 0.081 | bridge routing alone is not a retention mechanism; phase-2 overwrites the C readout, and the raw bridge itself is weakened |
| `deranged` A->C 0.000, oldB->C 0.000, A->B 1.0 | good control: wrong bridge does not rescue anything |
| `replay_old` A->C 0.075, oldB->C 1.000, A->B 1.0 | replay preserves old readout and creates a small self-composition floor without any attractor |

This says R46's static bridge primitive is real but incomplete. The repo backs that: `docs/cloud_results/r46_mech.json`
and `FINDINGS.md` show `raw_bridge` is genuinely positive for the attractor arm in the static setting, so R46 was
not just a shallow auxiliary artifact. But `s2/bridge_lifecycle.py` now asks the harder lifecycle question, and the
partial R47 result says the bridge state and the old successor readout are separable failure points. Aligning
`h(A's friend is)` to frozen `h(B)` can create a route; it does not keep `B->C` alive under later writes.

So the R47 headline should not become "attractor failed, composition is dead." The sharper conclusion is:

> R46 solved bridge activation in a static checkpoint; R47 shows lifecycle composition also needs successor-readout
> preservation. Without that, the route points to a destroyed endpoint.

This is an important result, but it lowers the priority of more pure-attractor tuning.

## Where I disagree with the framing

I agree with the distance table on growth: at this scale, growth is still a red herring unless the next result is
about **compute advantage** or **saturation**. R23/R31/R32/R34 already gave enough negatives that "small grows into
large" should not be used as the mechanism claim. The current mechanism claim should be "continual consolidation
into weights"; growth can re-enter only when a fixed model saturates or when growing beats training/continuing a
large model at matched capability per FLOP.

I disagree that #2 "rehearsal-free retention" should be attacked as the main arc right now. It is the deepest wall,
but the project needs a shortest honest path, not the hardest possible target. R36 null-space and R43 surprise-router
already show that simple rehearsal-free protection does not transfer cleanly. R47 now adds another warning: a
rehearsal-free composition primitive can be real and still fail because the old endpoint readout is overwritten.

The better framing is:

- **primary path:** make rehearsal cheap, self-generated, and consolidated into weights;
- **secondary diagnostic:** measure exactly which old capabilities still require true old-data access;
- **frontier research:** develop rehearsal-free write allocation only where the diagnostics show replay is paying
  for avoidable interference rather than irreducible exception bits.

This still advances the ultimate goal. It keeps inference memory-free, avoids full joint retraining, and puts new
knowledge into weights. It is just honest that the training process may need compact replay or self-replay until a
stronger mechanism exists.

## Ranked next thrusts

### 1. Main next arc: generative/self-replay into weights on real text

This is the best "multi-wall" experiment. It touches #1, #2, and #5 at once:

- knowledge is consolidated into one dense checkpoint;
- no external memory is used at inference;
- old text is not necessarily stored verbatim if the replay is generated from the model/scaffold;
- real Wikipedia-density text tests transfer beyond synthetic templates;
- composition probes can be included as a secondary axis.

Concrete experiment:

1. Use the `s3/wikibridge.py` real-text/census pipeline rather than another synthetic-only task.
2. Compare:
   - no replay floor;
   - stored compact replay baseline;
   - random half-replay baseline from R43;
   - model-generated replay/self-quiz from the current checkpoint or transient scaffold;
   - optional R46-style bridge/composition auxiliary if the data supports relational chains.
3. Evaluate old held-out paraphrase EM, newest EM, generated-replay correctness, replay diversity, and closed-book
   final checkpoint only.
4. Pass only if generated/self replay recovers a meaningful fraction of stored replay, e.g. at least half the old
   retention gap from no-replay to stored replay, while keeping generated target error low enough not to poison the
   checkpoint.

Likely failure modes:

- self-replay becomes self-confirming and rehearses wrong answers;
- generated probes collapse to easy/high-prior facts rather than fragile facts;
- paraphrase EM improves but exact factual coverage shrinks;
- the method quietly becomes an external item ledger if we store too many generated per-fact prompts.

The pass condition should therefore include a budget ledger: number of retained generated targets, whether they are
raw old facts, and whether their storage grows O(facts) or can be amortized.

### 2. Finish R47, but use it as a gate, not a rabbit hole

Wait for `attractor_replay` and `attractor_distill`, because they answer the key composition+retention question.
The meaningful comparison is not pure `attractor` anymore; pure `attractor` already showed the endpoint-readout
failure.

Pass gate:

- `attractor_replay` oldB->C near replay, A->B near 1.0;
- A->C clearly above replay's self-composition floor of 0.075, preferably by at least +0.10 absolute;
- `raw_bridge` recovers materially above pure lifecycle attractor's 0.081;
- `deranged` remains near zero.

If `attractor_replay` ties replay on A->C, the bridge primitive is not adding enough lifecycle value. Bank R46/R47 as
a mechanism finding and move on. If it clearly beats replay, then the next step is not more lambda sweeps; it is a
real-text bridge transfer with the same replay-retention scaffold.

### 3. Keep rehearsal-free retention alive as an interference-atlas diagnostic

The "interference atlas" idea is worth pursuing, but not as a broad new bet. Make it a diagnostic with a kill gate:
can it predict and avoid actual old-readout destruction better than static null-space or OGD?

Minimal version:

- after phase 1, measure gradients/Jacobians for old readouts, old hidden identity states, and old successor readouts;
- during phase 2, record which parameter blocks and representation directions move when oldB->C collapses;
- test whether routing updates away from the high-collision directions preserves oldB->C without touching old prompts.

Pass gate:

- better old retention than pure attractor/no-replay by at least +0.10;
- no large loss on A->B;
- no old B->C prompts or C labels in phase-2 loss;
- effect survives deranged or random-atlas controls.

If it cannot beat these gates on R47's simple synthetic lifecycle, it is not ready for real text.

## What to drop or de-emphasize

Do not spend the next arc on generic growth. Growth can return only under one of two contracts:

- **saturation contract:** fixed-capacity replay/self-replay cannot retain or compose at acceptable error while a
  grown model can, at matched or controlled training budget;
- **compute contract:** grow-from-small reaches the same real-text closed-book retention/capability at materially
  lower total FLOPs than training or continuing a larger dense model.

Do not chase a long R47 attractor-only sweep. The partial result already gives the mechanism diagnosis: route without
endpoint retention is insufficient. Sweeping lambda or P2 may improve the margin, but it will not answer the main
project question unless old successor readout preservation is included.

Do not over-invest in relation-schema compression yet. R44 suggests the reusable effect on real T-REx is coarser
answer-kind priming, not relation-specific schema. That is useful, but it is not currently the shortest path to
hundreds-of-books continual learning.

## Recommended next concrete sequence

1. Let R47 finish.
2. If `attractor_replay` is not clearly above `replay_old` on A->C, close the bridge lifecycle branch as "static
   primitive, lifecycle fragile."
3. Start a real-text generated/self-replay experiment in `s3/wikibridge.py` using R43 random@0.5 and full compact
   replay as the baselines.
4. Add a small synthetic R47-style diagnostic in parallel only if it measures old-readout collision, not more generic
   attractor tuning.
5. Keep growth off the critical path until the real-text replay/self-replay system hits a measured saturation or
   compute-efficiency wall.

## Project-objective score

- **Knowledge into weights:** strongest under replay/self-replay consolidation; R46 bridge helps only on composition,
  not retention.
- **Continual retention:** replay remains the only robust mechanism; pure rehearsal-free remains unsolved.
- **Growth necessity / compute advantage:** still unproven and should stay out of the main claim.
- **No-memory inference:** preserved by the proposed direction; training-time replay/scaffolds must be deleted before
  eval.
- **No full joint retraining:** preserved if replay/self-replay uses fixed stream budgets and does not retrain over
  all historical data to convergence.

## High-risk / high-reward brainstorming

### 1. Dream-replay without an item ledger

After each stream, ask the checkpoint to generate a small "dream set" of facts it believes are important, fragile,
or recently changed. Then consolidate on those generated probes and delete the generator cache. The risk is
self-confirmation; the reward is replacing stored old data with the model's own compressed recall. The key audit is
whether dream replay preserves facts that were never explicitly regenerated verbatim.

### 2. Successor-readout preservation instead of fact replay

R47 suggests the route and endpoint are separate. Instead of replaying `B->C`, preserve the *successor readout
operator* around B identity states: e.g. KL or hidden-function matching on synthetic perturbations around `h(B)`,
not old textual prompts. This could be more rehearsal-free than replay while protecting the thing the bridge needs.

### 3. Collision-triggered micro-growth

Growth becomes legal if the interference atlas shows a dense collision basin that cannot be routed around. Add a
tiny adapter/layer only for that basin, merge it into the dense checkpoint, and require it to beat both fixed
replay and fixed self-replay on retention per FLOP. This turns growth from branding into an emergency valve.

### 4. Train a "retention critic" before a write operator

Before learning a writer, learn a cheap critic that predicts which candidate phase-2 updates will destroy old
readouts, using synthetic lifecycles like R47. Then constrain writes by critic score. This is less magical than a
full meta-optimizer and gives an interpretable failure signal.

### 5. Composition as an eval axis for real text, not the main mechanism

Use R46/R47 to design real-text two-hop probes, but treat them as capability audits on top of the replay/self-replay
system. The first real win would be: generated/self-replay preserves old real facts and also improves held-out
2-hop closed-book answers versus item replay alone.

### 6. Compression ledger for "hundreds of books"

For every run, report three costs separately: raw old examples stored, generated targets stored, and reusable
schema/answer-kind targets stored. The high-risk claim becomes measurable: lifetime cost falls because generated
or schema-level targets replace item replay, not because we hide the item ledger under a different name.
