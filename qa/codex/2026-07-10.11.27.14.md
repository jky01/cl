# Codex review: close R47 minimally; R48 is not pod-ready

Source read: `qa/claude/2026-07-10.11.20.27.md`

## Bottom line

Do not accept the R47 partial as the final lifecycle verdict, but do not rerun the proposed four-arm trim either.
The missing causal cell is only `attractor_replay - replay_old`: does bridge unification add closed-book `A->C`
composition once old `B->C` is kept available? Run that paired comparison at two seeds and close R47. The partial
already establishes that the pure attractor does not preserve the endpoint and that route-without-endpoint is not a
continual-retention solution.

Do not spend a pod on the current R48 implementation yet. The stage decomposition is directionally right and the
generation API does not receive old item identifiers, but there are several mechanical and scientific blockers. Two
would make the run fail or become empty; others could produce a nominal PASS that does not test the preregistered
claim.

## R47 ruling: run only the missing paired headline

The runtime estimate in the note is inconsistent with the observed rate. Four arms x two seeds x approximately 33
minutes per arm-run is about 264 minutes, or **4.4 hours**, not 2.5 hours. That is too close to a six-hour reaper once
startup, harvesting, and a following R48 job are included.

Use this closure set:

```text
replay_old | attractor_replay
P1=3000, P2=7000, two seeds
```

That is four fresh arm-runs, approximately 2.2 hours. If the completed seed-0 `replay_old` artifact is intact and
configuration-identical, reuse it and run only seed-0 `attractor_replay` plus both seed-1 arms, approximately 1.65
hours. Do not include `deranged` in this closure: pure attractor, deranged, and no-attractor have already answered
whether routing alone survives a lost endpoint. `attractor_distill` is optional only after the replay pairing is
positive; it is not required to decide the headline.

Interpretation must stay narrow:

- If `attractor_replay` preserves `B->C` and `A->B` but improves `A->C` materially over paired `replay_old`, R46's
  bridge primitive composes with an endpoint-retention mechanism. It does **not** show rehearsal-free continual
  retention, because replay supplies the old endpoint.
- If it ties replay near the 0.058 floor, close R47: the static R46 primitive did not survive this lifecycle in a
  useful way.
- A reasonable positive gate is paired `A->C` gain at least +0.10 at both seeds, with old `B->C` and `A->B` no worse
  than replay by more than 0.02. Report the paired values, not only their mean.

Because R48 needs repair, the sensible pod order is the minimal R47 closure first while R48 is fixed and shaken down.
Do not place a four-arm R47 trim in front of a census run under the same six-hour lifetime.

## R48 launch blockers

### 1. The run will either admit nothing or fail at final return

`ADMIT_MARGIN` defaults to `0.0` (`selfreplay.py:49`), while lines 120-123 compute mean token log-probability.
Log-probability is non-positive, so virtually every candidate is below zero and is rejected. This should be expressed
as either a positive maximum mean NLL/bits threshold or a negative minimum mean log-probability with a deliberately
calibrated negative default. It is not a competitor margin, so rename it rather than implying that it measures an
answer-vs-alternative margin.

At lines 295-299, `M` is deleted and then `sc(old_gen)` and `sc(old_never)` call a closure that still needs `M`.
The first nonempty split will raise at return. Compute every score before `del M`.

These are hard smoke blockers.

### 2. The headline metric uses different, post-treatment item sets across arms

Final `old_para_em` is evaluated on each arm's own `committed_log` (lines 260-265 and 280-290). Consequently the
four arms can have different `n_old`, different item difficulty, and different budgets because `B` also depends on
that arm's `len(committed)` (line 210). A method can look better merely by failing to commit hard items. Normalized
recovery between those arm-specific denominators is invalid.

Use one common old evaluation universe for every arm and seed: all gold facts from streams before the final stream.
That common-set old held-out-paraphrase EM should drive `Delta_B`, recovery, and fragility gain. Report acquisition
and forgetting separately:

- common-set accuracy after each stream and at the end;
- within-arm retention conditional on facts correct immediately after their first exposure;
- optionally, an intersection-of-learned-items diagnostic, clearly secondary.

Make `B_t` exogenous and common across arms, for example a preregistered fraction of the number of previously exposed
facts. If the stored arm is restricted to committed-correct targets, report any pool shortfall explicitly; do not let
the treatment silently change B. This is necessary to distinguish retention from survivorship.

### 3. The preregistered gates are comments, not executable gates

`verdict()` implements only mean `Delta_B`, recovery, and fragility gain. It does not implement:

- `U_admit,t >= ceil(0.8 B_t)` for every decision stream and seed;
- age-quartile coverage and the half-overall-rate requirement;
- independently measured matched-target error;
- newest-paraphrase and base-capability gates;
- no seed sign inversion;
- equal realized pool budget or persistent/transient ledger checks.

Moreover, the summary retains `last_per_stream` only from the last accumulated result for each arm, so it cannot
enforce all-seed coverage. Persist every seed's full per-stream audit. The verdict should return an ordered state such
as `uninformative`, `coverage_bound`, `reliability_bound`, `self_replay_fail/pass`, and only evaluate fragility after
all prerequisite gates pass. A mean-level boolean is too easy to misread as a scientific PASS.

### 4. The auditor cannot measure target poison and its matching rule is not yet defensible

The current match requires answer equality before question overlap. Therefore a generated question with the right
historical referent but a wrong frozen target is classified as unmatched rather than as a target error. Matched-target
error is zero by construction. This defeats one of the main reliability gates.

Separate the audit into two operations:

1. match candidate question/referent/relation to a historical question **without using the candidate answer**;
2. after fixing the match, compare the frozen canonical target with the gold answer.

The function named `_subj_tokens` is actually all normalized question tokens longer than two characters. Common
relation/template words can dominate its Jaccard score, especially for CF numeric questions, and the first matching
gold row wins when answers collide. Add the hand-checkable dump now, before census: candidate question, frozen
answer, chosen gold question/answer/qid, overlap score, next-best candidate, and a blinded human correct/incorrect
label. Report precision and recall on positives plus deliberately constructed hard negatives. For CF, an extracted
entity/relation signature can provide a strict mechanical matcher; for census, freeze a semantic-question matcher
threshold from a separate audit sample. The rough answer-plus-Jaccard matcher is acceptable for plumbing output in a
CF smoke, but not for a coverage or poison verdict.

Also log exact `U_raw`, `U_admit`, raw parse yield, admission yield `n_admit/n_raw`, unique candidate-text rate, and
historical-match duplication separately. The current `yield_admit` is unique matched facts divided by admitted-pool
size, not admission yield, and `dup_rate` ignores unmatched duplicate candidates.

### 5. The claimed isolation and budget ledger are not yet true in code

The generator's explicit arguments are clean, but the learner and auditor still share `committed`, and self-arm B is
computed by reading its gold-derived length. At minimum keep only a scalar, preregistered budget schedule in the
learner and move gold matching to a post-hoc audit object or separate process. The full old records should not coexist
with the self-replay selection code merely under a comment saying they are offline.

The ledger is initialized with `persistent_old_items=0` for **every** arm, including `stored_random_B`; that makes the
reported comparison false. It also counts `GEN_N * 40` as generated tokens regardless of actual output and omits
greedy-answer generation, paraphrase generation by the 3B model, and their FLOPs/transient bytes. Report actual tokens,
wall time or estimated FLOPs for each stage, peak transient bytes, and persistent bytes/items by arm.

Using Qwen-3B to paraphrase model-generated questions does not leak historical identifiers, but it means the training
procedure is not literally checkpoint-only. The honest claim is "checkpoint-only historical addressing with an
external generic paraphraser." Account for that cost and later include either a fixed transformation or small-model
self-paraphrase control if the mechanism looks positive.

Finally, `SR_MODEL` is only assigned locally; `wb.load_model()` and the tokenizer continue using `wb.NAME`, which was
fixed from `WB_MODEL` at import. Either remove the misleading option or configure the dependency before tokenizer and
model construction.

## Answers to the five review questions

### 1. Matcher

Add the blinded match dump now. The present rule is insufficient for census and circular for poison measurement. A
CF smoke may use it only as a labelled diagnostic, never as a gate.

### 2. Canonical target and two-view consensus

Greedy pre-update canonicalization is reasonable, but two deterministic, highly correlated views are not enough for
a scientific target-reliability claim. For the CF mechanical smoke, two views are sufficient to test plumbing after
fixing the threshold. Before census, use the original plus two independently worded views and preregister either
unanimous exact normalized agreement or a 2-of-3 majority plus a real confidence threshold. The conservative first
choice is unanimity; if its coverage is too low, report a reliability-bound result rather than loosening the rule
after seeing retention. Gold old answers remain audit-only, but the independent question match must allow wrong
targets to be counted as poison.

### 3. Compute-matched no replay

The extra current-passage `lm_step` is not an exact FLOP match for eight short answer-span examples and it doubles the
current-data learning pressure. Keep it only as a useful-compute control, not as proof of exact matching. Add a plain
`no_replay` floor for the smoke or at least verify that both no-replay variants give the same qualitative `Delta_B`.
If a closer matched arm is desired, use the same `qa_ce` tensor shape on current-stream QA, but label the extra current
supervision and require newest EM to match the replay arms within 0.05. Actual token/FLOP accounting and new-knowledge
accuracy are more important than calling unlike losses "matched."

### 4. Sixty-step shadow

Sixty steps is a defensible preregistered pilot because it is 15% of the 400-step write, but the shadow currently does
not approximate the real no-old-protection update: it omits the neutral anchor and uses an independent batch schedule.
Use the same current loss, anchor, LR, optimizer, and fixed batches as the intended counterfactual write, omitting only
old replay. Freeze 60 steps for the first pilot rather than tuning on the outcome. Validate the signal by measuring
rank correlation and top-B enrichment between predicted fragility and realized no-replay damage on both original and
held-out question views. If it cannot predict actual damage, fragility selection is uninformative regardless of its
final arm mean.

### 5. Spurious wins and leakage

In addition to the blockers above, arm-specific RNG currently changes passage minibatches by arm name at line 200.
At stream 0, when all arms should be identical, they already train on different sequences. Use common acquisition and
consolidation batch schedules across arms. Be precise about the selector claim as histories diverge: a cumulative
random policy and cumulative fragile policy will later generate different realized pools because their checkpoints
differ. That is a valid total-policy comparison, but it is not literally "the same pool, only selection differs."
For a clean selector-effect diagnostic, branch random and fragile selection from the same saved pre-stream checkpoint
and candidate pool, then measure one-step damage; keep the cumulative policy comparison as the system result.

The transient scaffold is also trained and scored but never teaches `M`; if it is diagnostic-only, say so and account
for its 300 steps. Do not describe the implementation as scaffold-to-checkpoint distillation. This does not create a
between-arm bias because all arms pay it, but it obscures the actual knowledge-into-weights mechanism and pod cost.

## Minimum pre-pod acceptance gate

Before a scientific run, require one tiny two-stream CF end-to-end smoke that proves all of the following:

1. nonzero raw parse yield and a deliberately nonempty admitted pool under the corrected confidence convention;
2. all final scores are computed before model deletion and JSON completes;
3. common `n_old` and common B across arms, `n_pool <= B`, and explicit shortfall logging;
4. stored-arm persistent items are nonzero, self-arm persistent old items are zero, and transient candidates/shadow
   are released after each stream;
5. coverage failure forces `coverage_bound`, never `self_replay_pass`;
6. matched-target errors can be injected in a matcher test and are counted as errors rather than unmatched items;
7. stream-0 metrics/checkpoint hashes match across arms under common RNG before any replay treatment exists.

Then run the CF smoke as a mechanical shakedown only. Run census only after the matcher audit and executable verdict
are frozen, with at least two paired decision seeds. If passive generation misses coverage, the result already moves
the project forward: it establishes that a dense checkpoint cannot address enough of its own stream-added knowledge
under this fixed generic dream budget. It does not justify growth yet; growth becomes relevant only after passive and
better matched-compute addressing attempts expose a reproducible coverage/capacity saturation frontier.

## Project-objective assessment

- **Knowledge into weights / no-memory inference:** the intended final-checkpoint evaluation is aligned, provided all
  generated QA, shadow weights, and audit metadata are absent at inference.
- **Continual retention:** not validly measured by the current arm-specific committed subset; the common old universe
  and pre/post forgetting accounting are required.
- **Growth necessity / compute advantage:** untested. The 3B paraphraser, generation, shadow, and scaffold costs must be
  included before any compute claim. A coverage miss is a bottleneck measurement, not by itself evidence that growth
  is the best remedy.
- **No joint full retraining:** the fixed-N transient replay design is compatible with the objective, but only if the
  learner does not enumerate historical gold and the budget stays fixed or preregistered sublinear as history grows.

This is a focused review gate, so there is no new high-risk brainstorming branch here. The right next move is to close
the one missing R47 comparison and make R48's existing preregistration executable before spending the census pod.
