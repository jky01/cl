# 建議：小模型永續成長與新知識融入權重

閱讀文件：`FINDINGS.md`、`docs/memory/s0-step0-state.md`

## 核心判斷

我建議把目前專案主張收斂成這句話：

> 用暫時神經記憶吸收新知識，用 multi-view teacher 與 answer-recall guard 確認知識品質，再用 replay / self-distillation 把知識鞏固進單一 dense checkpoint；只有在固定模型出現可測量的能力或計算飽和時，才做 function-preserving growth。

這個說法和現有證據最一致。R19-R30 已經支持「新知識可以經由暫時 scaffold 進入 dense weights，推理時不依賴外部 memory」；R23 與 R31 同時也很清楚地指出，永續保留不是 growth 本身造成的，而是 replay / self-distillation 造成的。也就是說，「知識進權重」已經是強主線；「小模型長成大模型」還需要另外證明它帶來 compute 或能力上的必要性。

## 架構建議

建議採用四階段生命週期，而不是把 memory、growth、replay 混成單一概念。

1. **吸收新知識**
   新資料先進入 transient scaffold / capsule memory。這一層負責快速吸收、版本管理、admission/trust、衝突處理、多視角問法。

2. **驗證 scaffold 品質**
   健康檢查應以 teacher 的 answer-recall 為準，不要再用 retr@1 當主要 proxy。R27-R29 已經證明 retrieval 正常但 answer 錯時，student 會忠實蒸餾錯誤知識。建議每個 stream 都記錄 seen / paraphrase / reverse / temporal view 的 answer-recall，低於門檻就 restart、加步數，並保留 best scaffold。

3. **鞏固進權重**
   用 scaffold teacher distill 新 stream，同時對舊 stream 做 replay / self-distill，並保留 base task KL。這是目前最 load-bearing 的部分：anchor agreement 不夠，必須 replay 舊任務分布。

4. **丟棄 inference memory**
   每輪結束後，用無 memory 的 dense checkpoint 做評估。若最後仍需要外部 memory 才能答題，就不能宣稱「知識已融入既有權重」。

Growth 應該放在第 3 階段的容量工具，而不是保留機制。也就是：先判斷固定模型是否真的飽和，再用 identity-initialized deepening 或 MoE/expert expansion 擴張可訓練容量。

## 下一個最重要的實驗

現在最缺的是 growth 的正當性。建議優先做一個 canonical `growth_compute_advantage` 實驗，至少包含這些 arms：

- `fixed-small + replay/self-distill`
- `grow-from-small + replay/self-distill`
- `fixed-large from start`
- `large-from-scratch / offline oracle`，若成本允許
- `nogrow top-k trainable layers + replay`，作為 R23/R31 延伸 baseline

通過標準要先寫死：`grow-from-small` 必須在相同或更高 retention 下，用明顯更少 compute 達到 fixed-large 的能力，例如低於 large-from-scratch 30-50% 的訓練 FLOPs / GPU hours。若 fixed-small + replay 仍然追平，就不能說 growth 有必要。

另一條路是 capability-saturation，而不是單純加 facts。R31 顯示 800 facts 連固定 1 layer 都能記住，所以 facts 數量本身不是好壓力源。更好的壓力源是跨 stream composition：早期 stream 給 A->B，後期 stream 給 B->C，最後要求模型無 memory 回答 A->C，而且這個答案不能直接出現在 scaffold teacher 的單步訓練 view 裡。這能測到「知識融入權重後是否產生組合能力」。

## 評估指標

建議所有主結果固定報告：

- no-memory inference 的 final checkpoint 指標
- oldest-stream forgetting、all-stream seen / paraphrase / reverse
- base LM / hop task preservation
- teacher answer-recall，而不是只報 retr@1
- replay buffer 大小、teacher snapshot 數量、訓練 FLOPs、GPU hours、峰值顯存
- final parameter count 與每輪新增參數
- 固定模型 replay baseline 是否已經飽和

尤其要把「訓練期 scaffold」和「推理期依賴」分清楚。scaffold 可以存在於訓練期；但最後 headline 應以單一 dense checkpoint、無 external memory 的結果為準。

## 應避免的說法

- 不要說「growth 防止遺忘」。目前證據支持的是 replay 防止遺忘。
- 不要用「retrieval 很好」代表 scaffold 很好。必須看 answer-recall。
- 不要把 toy growth 的 positive result 直接外推到 pretrained Qwen；文件中已經顯示 Qwen-0.5B 的 growth capability gain 在多 seed 內接近 noise。
- 不要只和弱 RAG 比 accuracy。memory/scaffold 的價值應該主打 versioning、admission、no-context-cost、可鞏固進權重。

## 近期路線圖

1. 把 R30 reliable faithful loop 定為「知識進權重」的核心 baseline。
2. 把 answer-recall guard 抽成所有 scaffold 訓練共用的可靠性流程。
3. 做 `growth_compute_advantage`，用 compute、能力、retention 三個維度同時判斷 growth 是否值得。
4. 做跨 stream composition benchmark，逼出固定模型與純記憶回放的上限。
5. 再把 learned Ω controller 接上，但 reward 要包含 compute cost、growth 次數、final no-memory capability、old-stream retention。

總結：專案方向是可行的，但目前最強成果不是「模型變大所以不忘」，而是「新知識經 scaffold 驗證後，可透過 replay/self-distill 鞏固進單一權重」。下一步要讓「小模型長成大模型」站得住腳，必須證明 growth 在 compute 或 capability saturation 上有固定模型做不到的價值。
