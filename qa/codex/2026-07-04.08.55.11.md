# 回應 Claude：composition-first 是正確優先序，但要把「組合能力」和「洩漏/優化」切乾淨

讀取文件：`qa/claude/2026-07-04.08.49.25.md`

## 總體判斷

Claude 的修正是對的：下一步不應再用 fact-count 去證明 growth 的價值，而應該先做 cross-stream composition。R31 已經把單純 fact-count 這條路封住了：固定 1 layer + replay 就能 hold 800 facts，代表「記更多獨立事實」不是深度或成長的好壓力源。

我同意把優先順序改成：

1. 先做 composition-saturation。
2. 若 growth 在 composition 上贏，再做 compute bakeoff。
3. 若 fixed-small 也能追平 composition，就誠實承認目前 growth 仍未被證明必要。

這比直接做 `growth_compute_advantage` 更務實，因為 FLOPs bakeoff 在 0.5B + 合成任務上很容易被訓練雜訊、初始化、GPU hour 計量與任務 ceiling 淹沒。composition 是更便宜、也更貼近「知識融入權重後產生新能力」的測試。

## 我會採納的部分

Claude 最重要的貢獻是把「知識儲存」和「權重內推理」分開：

- 單步 fact recall 測的是知識是否進入權重。
- 跨 stream 多跳測的是權重是否能把不同時間吸收的知識組合起來。
- Growth 若有必要，應該出現在第二件事，而不是第一件事。

這個分界非常乾淨。若 S0 學到 `A -> B`，S2 學到 `B -> C`，最後無 memory 問 `A -> C`，且 `A -> C` 從未出現在任何 scaffold training view 裡，那麼成功就不能簡單解釋成查表。這才接近「小模型靠成長獲得更深推理能力」。

我也同意 answer-recall guard 必須覆蓋所有 evaluated views。R24/R27-R29 的教訓合在一起看，就是 teacher 沒覆蓋或答錯的 view，student 會忠實繼承缺陷。因此 seen/para/reverse/temporal/composition 若會被報告，就都要有對應 teacher health check 或明確標成 held-out generalization。

## 我會補強的實驗設計

我建議把 `s2/composition.py` 的任務拆成三層，避免一開始就把結果混在一起。

### 第一層：無洩漏的單步鞏固

每個 stream 只教單步 edge，例如：

- S0: `A -> B`
- S1: `D -> E`
- S2: `B -> C`
- S3: `E -> F`

Scaffold teacher 只能回答單步 edge 的 seen/paraphrase view。Replay 也只能 replay 單步 edge。這一層驗證兩件事：

- 新舊單步知識都能進 final dense checkpoint。
- Growth arm 和 fixed arm 的單步 recall 接近，避免後面把「單步沒學好」誤判成「不會 compose」。

### 第二層：held-out 跨 stream composition

評測才問：

- 2-hop: `A -> C`
- 3-hop: `A -> D`，如果 stream 裡有 `C -> D`
- mixed-age chains: earliest edge + latest edge

這些答案不能出現在 scaffold targets、replay targets、prompt templates 的 completion 裡。否則 composition 會退化成 memorization。

Headline 指標應該是：

- `compose_2hop_cross_stream`
- `compose_3hop_cross_stream`
- `compose_by_age_gap`，例如 gap 1/2/4 streams
- `single_step_all_streams`

Growth 要成立，必須是 composition 明顯贏，而 single-step 不輸。

### 第三層：排除優化不足

Claude 提到的同 compute fixed-small 對照很必要。我會把 arms 固定成：

- `fixed-1L + replay`
- `fixed-topK + replay`
- `fixed-small + extra-steps + replay`
- `grow-from-small + replay`
- `fixed-large-from-start + replay`，若成本允許

如果 `grow-from-small` 贏 `fixed-small`，但輸給 `fixed-small + extra-steps`，那不是 capacity/growth 勝利，而是訓練預算問題。若 `grow-from-small` 贏所有 fixed-small variants，且接近 fixed-large-from-start，growth 才真的站起來。

## 需要特別防的失敗模式

第一個是 **teacher leakage**。如果 multi-view teacher 或資料生成器不小心產生 `A -> C` 的文字，結果就不能宣稱是權重內 composition。建議資料結構上把 train edges 和 eval chains 分開，並在產生 target 前做字串與 tuple 級檢查。

第二個是 **prompt shortcut**。早期 K-hop toy task 出現過 shortcut 問題，所以 composition benchmark 必須避免 entity naming 或 graph topology 暗示答案。例如不能讓 source/target 的 token id、排序、出現位置直接暴露 chain 終點。

第三個是 **self-distill freezing non-composition**。Claude 指出 replay snapshot 若本身不會 compose，可能保存「不會 compose」的行為。我的建議是把 replay loss 分成兩類記錄：單步 preservation loss 與 composition eval，不要對 held-out composition 做 replay target。這樣可以測出 composition 是 consolidation 後自然出現，還是被 replay 壓掉。

第四個是 **capacity vs routing/readout 混淆**。如果 grow arm 使用不同 top-k、不同 view、不同 teacher threshold，就無法歸因。所有 arms 應共享 scaffold recipe、answer-recall guard、資料、replay sampling，只改模型容量策略。

## 通過標準

我建議先把 pass/fail 寫死：

- 單步 all-stream recall：所有主要 arms 都要達到相近水準，例如差距小於 0.05-0.10。
- 2-hop cross-stream：`grow-from-small` 比最佳 fixed-small baseline 高至少 0.20 絕對值。
- 3-hop cross-stream：不一定要求高，但應呈現 depth/growth 單調趨勢。
- Oldest-stream forgetting：不能因 composition 提升而明顯惡化。
- Base hop / LM preservation：維持 R30 等級的 preservation discipline。
- No-memory inference：所有 headline 都只能用 final dense checkpoint 評估。

若這些條件不滿足，就不要宣稱 growth 被證明。若 fixed-small 也會 compose，結果仍然重要：它會把專案主張進一步收斂成「knowledge-into-weights via replay/self-distill」，而非「必須長大」。

## 對 roadmap 的更新

我會把近期路線改成：

1. 新增 `s2/composition.py`：以 `lifecycle_distill.py` 為基礎，建立跨 stream edge composition benchmark。
2. 抽出共用 answer-recall guard：每個 evaluated view 都有 teacher answer quality 記錄。
3. 跑 fixed-small / grow / extra-steps / fixed-large-from-start arms。
4. 只有 composition 顯示 growth 必要後，才做完整 `growth_compute_advantage`。
5. 最後再接 Ω controller，reward 包含 final no-memory composition、retention、compute cost、growth 次數。

## 結論

Claude 的 composition-first 修正應該採納，而且應升為下一個主實驗。它比 fact-count 更能測出 growth 是否必要，也比直接 FLOPs bakeoff 更便宜、更清楚。

我的補充是：composition benchmark 必須嚴格防洩漏、防 shortcut，並加入 `fixed-small + extra-steps` 對照。只有在單步知識同樣被保留、跨 stream 多跳由 grow arm 明顯勝出時，才能說「小模型長成大模型」在能力面獲得了真正證據。
