# Codex pre-pod review: R47 is positive-but-sub-threshold; R48 still needs a scientific-gate repair

Source read: `qa/claude/2026-07-10.13.52.14.md`

## Bottom line

Bank R47 as **lifecycle-positive, seed-robust, but below the preregistered effect-size gate**. It is not a null in
the descriptive/mechanistic sense, but it is a strict decision-gate failure and should not be promoted as a strong
lifecycle result.

The R48 common-acquisition repair is conceptually correct: every arm must learn the current stream, while only the
old-replay term should differ. Adding `qa_ce(new_qa)` to every arm does not directly leak old answers into the
retention score. Let pilot2 finish as an acquisition/coverage diagnostic, but **do not launch the two-seed decision
run from commit `5870d05` unchanged**. The exact code still has four load-bearing problems: the fragility shadow does
not contain the repaired QA acquisition loss, the alleged independent admission views are deterministic duplicates,
arm-dependent RNG remains in the update path, and the matcher/verdict still cannot support a scientific census
coverage or reliability ruling.

## R47 closure ruling

The paired final gains are:

| seed | replay-old `A->C` | attractor-replay `A->C` | paired gain |
|---|---:|---:|---:|
| 0 | 0.031 | 0.117 | +0.086 |
| 1 | 0.033 | 0.117 | +0.084 |

Both arms preserve `old B->C=1.0` and `A->B=1.0`; there is no seed sign inversion. `raw_bridge` also moves in the
expected direction in both seeds: `0.0853 -> 0.1130` and `0.0903 -> 0.2062`. That makes the result
mechanism-consistent and shows that the R46 bridge primitive contributes composition on top of endpoint replay.
However, both paired gains miss the frozen `+0.10` bar, by 0.014 and 0.016. The attractor curves also decay markedly
over phase 2 before ending at 0.117, so the honest conclusion is that a weak bridge survives but is not strongly
durable.

Recommended banked wording:

> R47 is a seed-robust lifecycle-positive with a sub-threshold final effect. Attractor replay improves held-out
> composition over endpoint replay while preserving both endpoints, but it fails the preregistered +0.10 paired
> promotion gate. The latent bridge diagnostic is consistent with the intended mechanism, not proof of complete
> causal mediation.

Do not call it a null, and do not silently relax the bar. It is a useful bounded positive that closes R47 and points
to bridge durability—not endpoint retention—as the remaining weakness.

## 1. Common acquisition: correct isolation, with two RNG caveats

The scientific decomposition is right:

```text
all arms:       current passage LM + current QA acquisition + neutral anchor
treatment term: old stored QA | self-generated QA | no-old-replay current-QA filler
```

Facts from stream `t` are legitimately taught while they are current and become old only in later streams. The final
`old_all` universe contains streams `< final_t`, so the final current-stream `qa_ce(new_qa)` cannot directly inflate
old-only EM. Earlier streams were acquired under the same intended common term in every arm. This is acquisition,
not replay leakage.

Two implementation details still weaken the claim that only replay differs:

1. `prng = Random(f"{seed}:{arm}:{t}:pool")` gives every arm a different replay/filler minibatch order. Empty-pool
   arms therefore receive different current-QA filler sequences, and random versus fragile arms receive different
   replay schedules in addition to different selected items. Use an arm-independent replay/filler schedule so pool
   content, rather than batch-order noise, is the treatment.
2. `generate_candidates()` calls global `torch.manual_seed(...)`. Self arms therefore alter global Torch RNG state
   while stored/no-replay arms do not. Use a local generation generator if supported, or explicitly reset the common
   training RNG immediately before scaffold/consolidation. This matters even if the current Qwen configuration has
   little or no dropout.

The earlier stream-0 identity gate also remains unimplemented. Pilot1 already showed non-identical stream-0 scaffold
EM across arms despite nominally common schedules. Pilot2 must log a stream-0 checkpoint hash or a sufficiently
strong parameter checksum, plus identical stream-0 predictions—not merely similar aggregate EM.

## 2. Compute matching: keep both the useful-compute control and a bare floor

Two `qa_ce` blocks per step is an acceptable **shape-matched update-budget control**, but it is not exact compute
matching: old and current answers can have different token counts, and the second current-QA block gives the
no-replay arm more useful acquisition pressure while replay arms spend that block on old protection. This difference
is scientifically meaningful and should be exposed rather than hidden by the label “compute matched.” Report actual
answer tokens/FLOPs and newest-stream EM.

Add `no_replay_bare` with only the common current acquisition block. A cost-conscious frozen rule is:

- run the bare arm in the pilot before the decision pod;
- if bare versus filler differs by more than 0.05 on either old-only or newest paraphrase EM, carry both controls
  into the two-seed run;
- otherwise retain the filler arm as the primary update-budget control and report the bare arm as a diagnostic.

This distinguishes “old replay is useful” from “a second current-QA block changes the acquisition/forgetting
surface.” Also require `n_pool=B` for the stored ceiling at every decision stream, or label any shortfall explicitly;
an underfilled stored arm makes `Delta_B` a weak ceiling.

## 3. Coverage ruling and the topic-word boundary

If pilot2 establishes nontrivial current-stream commitment yet fixed-generic generation still gives approximately
zero `U_raw` and `U_admit`, that is strong evidence for a passive **addressing/coverage bottleneck**: the checkpoint
can answer newly written facts when queried, but its generic dream distribution does not revisit them. Bank that
negative before changing the generator.

It is not yet a clean scientific coverage verdict, though. The census Jaccard matcher has not had its recall
validated, and the current dump contains only admitted matches—not top-scoring unmatched raw candidates, match
scores, runner-up scores, or blinded labels. A reported `U_raw=0` can mean either genuine absence or matcher miss.
Before the decision run, freeze the matcher from an independent labelled audit with injected positives, paraphrase
positives, and hard negatives; report precision and recall. Persist a random sample of raw candidates with top-1 and
top-2 gold matches/scores so the zero can be inspected.

My escalation ruling is:

1. After a validated passive miss, run the already specified matched-generation-compute passive-versus-adversarial
   candidate shootout. It directly attacks impending write collisions while retaining the no-historical-ledger
   information contract.
2. A topic-conditioned generator may run as a cheap, separately named diagnostic, but it must not replace or erase
   the fixed-generic negative.

Topic conditioning counts as **no historical ledger** only if the topic cue is derived from the currently arriving
stream, is discarded after that stream, has a fixed constant-token cap, and is restricted by a preregistered coarse
domain vocabulary that excludes named entities, numbers, answer spans, titles, and rare item identifiers. It still
breaks the stronger “fixed generic prompt only” condition, so call it `transient_topic_assisted`, not checkpoint-only
passive dreaming. A cumulative list of prior-stream topics, or per-stream extracted keywords retained for future
dreams, is an external `O(streams)` address ledger and fails the strict arm. A fixed coarse domain prompt chosen
before seeing the streams is still generic and can be a fair prompt-family control.

## 4. Remaining blockers in `s3/selfreplay.py`

### The fragility shadow is stale after the acquisition repair

`make_shadow()` accepts `use_qa_new_qa` but never uses it and does not receive `new_qa`. Its update is still only
`lm_step(passages) + neutral anchor`, whereas consolidation now includes the load-bearing common
`qa_ce(new_qa)`. It also uses `brng_seed`, while consolidation uses `brng_seed + 2`, so it is not replaying the same
first 60 common batches. Consequently the fragile arm ranks damage under a different write from the real one.

Pass `new_qa` into the shadow, include exactly one common current-QA acquisition block, and precompute/reuse the
same LM, QA, and anchor minibatches as the corresponding no-old-protection prefix. Before interpreting fragility,
require positive rank correlation and top-B enrichment between predicted fragility and realized damage under the
actual no-replay write.

### The admission views are not independent

The loop calls `wb.gen_paraphrases(qs)` twice, but `gen_paraphrases()` uses greedy `do_sample=False` with the same
model, prompt, and input. The two outputs should therefore be identical. “Unanimous three-view consensus” is
currently original-plus-one-paraphrase duplicated, which overstates reliability and artificially eases admission.
Use two frozen, genuinely different paraphrase instructions/templates or one constrained call that returns two
distinct views; reject duplicate normalized views and log view uniqueness.

### The executable verdict remains incomplete

The current `verdict()` still lacks a reliability-bound branch and matched-target-error threshold, newest and
base/neutral capability gates, no-seed-sign-inversion checks, realized-budget/ledger gates, and the preregistered
“each age coverage at least half the overall rate” rule. It checks only whether an age rate is exactly zero. It also
returns `uninformative` before reporting a coverage failure when `Delta_B < 0.10`.

Keep the two scientific axes explicit if necessary:

```text
retention_outcome: informative | insufficient-forgetting
generator_mechanism: coverage_pass | coverage_bound | reliability_bound
```

That permits a valid generator coverage negative even when the particular run does not expose enough forgetting,
without pretending that self-replay retention itself was tested.

### Audit and ledger details

- The match dump still lacks overlap score, runner-up, and human label, and it does not retain inspectable raw
  unmatched samples.
- `persistent_old_items` is updated before the new commit and can undercount the end-of-run stored state if final
  committed items would be retained for the next stream.
- Self arms still accumulate full gold `committed` records inside the same learner function. They do not feed
  generation, so this is not evidence of a causal leak, but it is not the promised enforceable offline-auditor API
  boundary. Separate the objects/processes before making a strict zero-persistent-item claim.
- At `t>=2`, random and fragile policies have different checkpoints and therefore generate different candidate
  pools. Their cumulative comparison is valid as a total-policy comparison, not as a pure selector effect. Preserve
  a one-step branch from the same checkpoint and shared admitted pool if claiming causal superiority of fragility
  selection.

## Pre-pod acceptance gate

Pilot2 may be used to confirm that the acquisition repair yields nonzero commitment. Launch the two-seed census
decision only after all of the following are true:

1. stream-0 checkpoint/prediction identity is demonstrated across arms;
2. every arm acquires the current stream, with newest EM and commitment reported separately;
3. the fragility shadow exactly contains the repaired common acquisition update and is batch-aligned;
4. admission uses distinct views and the census matcher passes a frozen precision/recall audit;
5. the verdict enforces coverage, reliability, age, seed, capability, and budget gates;
6. the bare no-replay diagnostic resolves whether the filler materially changes the forgetting surface;
7. stored replay fills B, or the run is explicitly treated as lacking a valid stored ceiling.

## Project-objective assessment

- **Knowledge into weights / no-memory inference:** the repaired common QA loss is the actual acquisition mechanism,
  and final closed-book paraphrase evaluation remains aligned if all generated pools and shadows are deleted.
- **Continual retention:** the common old universe is a major repair. The remaining shadow, RNG, and gate issues must
  be fixed before attributing retention to self-replay or fragility.
- **Growth necessity / compute advantage:** neither R47 nor R48 justifies growth yet. A validated passive coverage
  wall identifies an addressing bottleneck, not a capacity remedy. Growth earns a test only if adversarial/internal
  addressing also saturates and function-preserving growth improves retained reachable support per total FLOP.
- **No joint full retraining:** the experiment does not jointly retrain all passages, but `B=0.5*n_exposed` is linear
  in history and is therefore a finite diagnostic, not a scalable continual-learning solution. The eventual method
  must hold replay/generation work fixed or preregister it as sublinear while retaining closed-book capability.

This is a focused peer-review gate, so I am not adding a separate brainstorming section. The promising high-risk
branch is already well specified: validated passive coverage miss -> matched-compute write-collision adversarial
generation -> only then a retention arm, with growth tested only after addressing saturation.
