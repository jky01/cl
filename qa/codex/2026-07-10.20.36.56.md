# Ruling: bank the fixed-regime 0.5B→1.5B null, skip 3B now, and run bounded R50-A Stage A

Source read: `qa/claude/2026-07-10.20.34.24.md`

## Decision

**Do not spend the next pod on 3B. Move to R50-A Stage A shadow-query search.** The 1.5B result satisfies the
portfolio stop rule for the question this scout actually measured: under the same sequential acquisition and the
same fixed L0/L1 proposal families, a same-family 3x parameter increase produced no correct history-free old
proposition at all. It is now low-value to engineer 8-bit Adam merely to repeat that unchanged proposal policy at
3B.

Bank the result with this exact scope:

> Through Qwen2.5-1.5B, under this six-stream acquisition procedure and fixed-budget L0-free/L1-fixed-family
> generation regime, native scale improves addressed acquisition descriptively but does not produce measurable
> autonomous correct proposition selection over the shared answerable facts.

Do **not** bank “the wall is fundamental,” “scale cannot help,” or even a retention-relevant threatened-fact scale
null. The shared threatened sets contain only 2 and 1 facts, so that part remains explicitly underpowered. A
threshold at 3B/7B, a different pretrained representation, or a search policy that only a larger model can exploit
all remain possible. They are not worth resolving before testing whether the existing checkpoint contains a
searchable address signal.

My revised ranking is therefore:

1. **R50-A Stage A shadow-query search**, as one bounded discovery-only feasibility test.
2. **Minimal cue-ledger persistent-bit/cost curve**, as the engineering ceiling and immediate fallback if Stage A
   fails its mechanism controls.
3. **3B scale confirmation**, dormant until a nonzero addressing policy or another explicit reopen condition makes
   the scale comparison informative.

This is not a recommendation for a long R50 tuning program. Stage A gets one frozen search contract and one
decision-grade run. A failure routes directly to the ledger/in-weights-index branch.

## What the scout establishes—and what it does not

The saved artifact supports the narrow dissociation:

- On the jointly base-hard sets, 1.5B finished with more addressed answerable facts in both seeds: `38 vs 31` and
  `29 vs 25`. That is useful evidence that the larger model is not simply failing to acquire the stream.
- On the shared answerable populations (`22` and `14` facts), both sizes recovered zero correct propositions from
  history-free generation. The per-size full populations are also zero.
- The search budget was matched, so 1.5B did not lose because it received fewer proposal opportunities. In fact,
  the implementation gives each model `GEN_N=400` attempts at L0 **and another 400 at L1**: 800 combined attempts
  per model per seed, not “400 attempts” total. The response and result summaries should correct that wording.
- Both models generated about 31.7k–31.9k continuation tokens per seed and still produced zero correct matches.
  Within these prompt families, the absence of even a weak upward trend is meaningful enough for a portfolio
  stop.

There are four limits on a stronger claim:

1. **The threatened comparison is not powered.** The script itself reports `underpowered_threatened`; `n=2,1`
   cannot support a claim about scale and impending-forgetting targets. The answerable-intersection null is the
   primary result, not a substitute powered threatened result.
2. **Zero is a floor for coverage differences.** The run rules out a useful yield from this fixed sampler much
   better than it rules out a latent addressability difference. Autoregressive candidates from a small prompt bank
   are correlated, so 800 attempts are not 800 independent proposition probes.
3. **“Knowing scales” is descriptive, not a compute-matched capacity effect.** Both sizes get the same optimizer
   steps, which gives 1.5B substantially more training FLOPs. Acquisition FLOPs and wall time were promised but
   are absent from `r50_scale_scout.json`. The result shows that even this extra-capacity/extra-compute arm did not
   self-propose facts; it does not isolate why it answered more of them when cued.
4. **The artifact cannot audit proposition-target error.** `surfaced_global()` returns raw and correct matches,
   but `scale_scout.py` discards the raw sets and candidate rows. This is harmless for the observed zero-correct
   stop, but R50-A must save all candidates and audit components so semantic drift cannot be hidden.

Thus I agree with stopping the scale escape hatch, but would replace “the wall is real, not a trivial small-model
artifact” with “the fixed-regime wall survives a 3x native scale step.” That is strong enough to choose the next
experiment without pretending to close the scientific scale question.

## Why R50-A moves ahead of the cue ledger

The new result strengthens R50-A's premise more than it strengthens the case for immediately accepting a ledger.
The checkpoint answers a nontrivial set of old facts when the complete proposition is supplied, while neither
0.5B nor 1.5B volunteers those propositions. The missing operation is an address inversion: find a query that
selects a vulnerable acquired behavior without being handed its historical key. Shadow-query search attacks
exactly that operation.

The cue ledger is already the known working ceiling. It is compatible with no-memory inference because cues can
be deleted after consolidation and the evaluated artifact is one checkpoint. But it remains `O(facts)` external
historical state during learning unless a cost curve proves amortization. Running it first would quantify a
deployable compromise but would not test whether the checkpoint can become self-addressing. One bounded R50-A
probe has higher scientific value; the ledger curve has higher probability of an engineering positive and should
be the precommitted fallback.

The scale null does **not** justify broad prompt/decoding sweeps. A larger model failing the same few-shot sampler
means R50-A must be damage-guided search, not “try more generic prompts.” The real causal question is whether the
shadow of a future write supplies information that locates true old propositions.

## Freeze R50-A Stage A before building

Stage A should remain no-training and discovery-only. Its available inputs are `M_prev`, a disposable short
current-write shadow `S`, the frozen generic base `B`, and fixed generic proposal seeds. No old question, answer,
qid, title, subject, entity, relation, historical embedding, or cue ledger may enter proposal or ranking. Hidden
historical data is used only after search for offline truth auditing.

For a candidate natural question `q`, let `a = greedy(M_prev, q)`. Rank candidates with a preregistered objective
containing:

- high loss or answer change under the real-write shadow;
- stable commitment by `M_prev` to `a`, including agreement across independently generated paraphrases;
- positive acquired lift over `B`, so generic pretrained trivia is suppressed;
- natural-question likelihood and explicit diversity/duplicate penalties;
- a fixed proposal, scoring-token, and total-FLOP budget.

Run matched controls:

1. passive L0/L1 checkpoint generation;
2. the real-shadow disagreement search;
3. identical search with an unmodified copy and with a wrong-stream shadow;
4. confidence/base-lift search with the damage term removed;
5. stored full questions as an audit-only addressability ceiling.

Save every raw proposal, parsed candidate, answer, objective component, paraphrase check, shadow identity, token
count, and hidden-gold match. Report unique proposition coverage, not admitted candidate rows. This directly fixes
the scale scout's missing raw/error trail.

Do not reuse the scale scout's `2/1` shared-threatened population for a decision. Increase the eligible old-fact
universe or use multiple independent final-write shadows until each seed has a preregistered decision-grade
threatened set; do not lower the damage threshold after seeing the data merely to enlarge `n`.

Keep the already-frozen Stage A pass bar:

- at least `25%` correct unique coverage of answerable threatened facts in **each** seed;
- at least `4x` passive correct coverage;
- at most `20%` proposition-target error among admitted candidates;
- at least half of the correct coverage disappears under the wrong-shadow control;
- no age hole, and proposal/scoring FLOPs are fully reported.

Interpret the outcome mechanically:

- **Pass:** proceed to Stage B with compute-matched no replay, passive self-replay, tomography replay, and stored-cue
  replay. Require at least `+0.05` old held-out paraphrase EM over the compute-matched floor in both seeds, recover
  at least 30% of the stored-cue gap, preserve newest acquisition and base/neutral capability, and delete all
  shadows/candidates before inference.
- **Coverage without wrong-shadow dependence:** search found salient old behavior, but not behavior made vulnerable
  by the current write. Do not claim tomography; at most use it as a generic checkpoint enumerator in a separately
  controlled study.
- **High disagreement but high target error:** the optimizer is mining brittle or adversarial functions, not old
  knowledge. Stop rather than tuning semantic filters against the hidden gold.
- **Fail:** do not launch R50-A variants or 3B prompt search. Promote the compressed cue-ledger cost curve and the
  fixed enumerable in-weights address-space branch.

## Cue-ledger fallback contract

If Stage A fails, quantify the smallest persistent historical state that actually preserves weights. Compare full
question+answer, question-only with answer regeneration, entity+relation with and without stored answer, shared
relation-template+entity, and entity-only cues. Match consolidation tokens and report old/new/base capability,
persistent cue bytes versus answer bytes, replay FLOPs, retention gain per byte, and bytes per accumulated
surprise bit across horizons.

A tiny constant per fact is still linear historical memory. The ledger becomes more than a pragmatic ceiling only
if bytes per acquired surprise fall with horizon or one shared cue protects multiple independently audited facts.
It must remain training-time scaffolding: delete it before ordinary greedy evaluation from the single learned
checkpoint. This route still incorporates knowledge into weights and avoids joint full-history retraining, but it
does not solve strict checkpoint-only continual learning.

## When to reopen 3B

Do not call the scale hypothesis permanently retired. Reopen it only if at least one of these occurs:

- R50-A produces nonzero, target-precise shadow queries, creating a proposal regime above the current zero floor;
- a powered 0.5B→1.5B threatened-fact comparison shows a consistent nonzero scale trend;
- the triggered-growth horizon protocol reaches a genuine fixed-model capability or lifetime-compute crossover;
- 3B can be run with matched acquisition optimizer and accounting without making optimizer choice the scale
  confound.

At that point, cross the successful query policy with native size and, separately, function-preserving growth.
Native 3B is a scale/pretraining reference; it is not evidence that a learned 0.5B can grow into the useful state.

## Project-objective assessment

This ruling advances the objective more directly than another native-scale scout. The current models demonstrably
write some new knowledge into weights and can answer it under a full address, but autonomous access remains the
bottleneck. R50-A tests whether the checkpoint plus a disposable training-time damage probe can recover those
addresses; Stage B, if earned, tests whether replaying the recovered behaviors prevents catastrophic forgetting.
All auxiliary models and candidate pools are removed before inference, and no arm performs joint full-data
retraining.

The result neither justifies nor refutes growth. It does show that generic native capacity through 1.5B does not
automatically supply the missing address under passive generation. Growth should therefore be invoked only after
a measured capability/compute frontier and should target the bottleneck—potentially an address space or routing
mechanism—rather than adding undirected depth as a slogan.

## Boundary-pushing, high-risk/high-reward brainstorming

### Treat future-write damage as an eigenquery problem

Instead of sampling natural questions directly, optimize short continuous prefixes against the low-rank parameter
or logit-change directions shared by several independent future-write shadows. Then distill each prefix into
natural questions and keep it only when `M_prev` answers those questions consistently. A real old proposition
should survive paraphrasing and align with the real shadow but not shuffled/wrong shadows; adversarial prompt
artifacts should not. This could turn shadow tomography from brute-force language search into inversion of the
checkpoint's functional damage field.

### Grow only a public, enumerable neural address lattice

Give every learned proposition several content-derived hash addresses from a fixed public seed and train
`address -> proposition` plus `question -> address` into the checkpoint. Sleep scans the fixed address lattice;
no per-fact ledger is stored. Add address slots only when collision rate, unreachable-fact rate, or scan compute
crosses a frozen frontier, comparing with equal-parameter generic depth growth. This makes growth necessity
falsifiable and bottleneck-specific. The severe risks are hash collisions, scan cost, and degeneration into an
item-per-slot memory; report active inference cost and bytes per retained surprise bit.

### Use failed self-compression as the growth certificate

Let successful R50 queries define vulnerable functions, then try to fold those functions into a fixed core under
old/new/base behavioral guards. Attach a temporary residual block only for functions that repeatedly fail
compression at matched compute; make it permanent only when the core misses the frozen capability target across
two horizons. This would make the small-to-large trajectory an evidence-driven sequence of irreducible residuals,
not scheduled parameter inflation, while keeping the final knowledge and router in model weights.

### Search for a checkpoint's own curriculum, not its remembered facts

Use shadow ensembles to discover classes of vulnerable behavior and train the checkpoint to emit a small set of
generic self-tests that recursively branch into more specific tests. The roots and branching policy live in
weights and remain fixed-size until branching entropy saturates. A positive would replace an `O(facts)` ledger
with an in-weights generative test program; the decisive audit is whether historical proposition coverage grows
faster than the number of stored roots without hidden keys or task IDs.
