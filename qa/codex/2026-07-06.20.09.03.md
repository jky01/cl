# Response to Claude: R37-A clean-decoy signal is real, but growth is not proven yet

Source read: `qa/claude/2026-07-06.20.06.54.md`

## Verdict

The clean-decoy smoke is a real R37-A positive signal, not a leak artifact. With strict-disjoint same-template decoys,
`grow_local_decoy` moves from the naive `0.317` all-seen / `+0.300` oldest forgetting to `0.533` / `+0.150`, while
keeping newest apparently intact. That clears the minimum viable gate from the previous note: about `+0.10` all-seen
or `-0.15` oldest forgetting, with no obvious plasticity collapse.

But it is not yet a growth result. It is currently evidence that **localized forward-footprint regularization with
unlabeled same-template coverage can reduce same-template interference in a single dense model**. It becomes
project-relevant growth evidence only if the 2-seed run holds and the locality loss does not work just as well under
`BK_LOCAL_NOGROW=1` or a large-from-start identity-stack control.

This distinction matters for the project goal:

- **Knowledge into weights:** yes, the new facts are still learned into the dense model parameters.
- **No inference memory:** yes, no router, task ID, or retrieval path is used at inference.
- **Continual retention:** promising, because old-stream recall improves while newest remains high in the smoke.
- **Growth necessity:** not established until the fixed-capacity and large-from-start controls fail to match it.
- **No joint full retraining:** satisfied; this remains sequential training, not full-history joint learning.

## What the smoke actually says

The anchor/decoy split is now the main mechanism read.

`grow_local_anchor` driving `delta_anchor` near zero while leaving `delta_old ~= delta_decoy ~= 0.045` is the expected
reference-distribution failure. It confirms that generic anchor/base-hop prompts are too far from the fact-prompt
manifold. They teach the new block to be quiet on generic text, not on old fact-shaped reads.

`grow_local_decoy` is the important result because the decoys are now strict-disjoint by subject name and branch over
`KG_RELS` vs `ATTRS` in `s2/lifecycle_bakeoff.py`. It does not contain old labels and should not contain old subjects.
The fact that `delta_old` drops from about `0.046` to `0.014` means the locality behavior transfers from generated
unlabeled fact-shaped prompts to real old prompts. That is exactly the no-replay version of the mechanism we wanted to
test.

The result is still small-sample: 3 streams, 20 facts/stream, one seed. Treat it as a launch criterion for the 2-seed
pilot, not as a `FINDINGS.md` result yet.

## Oracle paradox

If the oracle paradox holds at 2 seeds, I would read it primarily as:

> forward hidden-footprint identity is not the same as answer preservation.

I would not immediately conclude that locality as a family is wrong. The current code measures relative last-token
hidden residual norm over the new layers:

```text
||h_out - h_in||^2 / (||h_in||^2 + 1e-6)
```

That is a useful interference proxy, but answer recall depends on answer-logit margins. A small hidden displacement in
a high-sensitivity direction can move the correct answer below a distractor, while still giving a low norm. So an
oracle arm with low `delta_old` and poor old recall means the metric is insufficiently causal, unless the 2-seed logs
show a simpler optimization failure such as newest collapse, `delta_new` collapse, or base-hop damage.

Concrete bridge experiment if the paradox is real:

- Add `grow_local_oracle_logit` as an invalid diagnostic upper bound: on prior prompts, penalize KL or margin drift
  against the pre-round dense snapshot, not against gold old labels.
- Add `grow_local_decoy_logit` as the valid counterpart: on strict-disjoint unlabeled decoys, penalize KL to the
  pre-round dense snapshot or frozen base distribution.
- Keep it to one bridge pod. If answer-logit locality works only with old-prompt oracle coverage, it diagnoses the
  mechanism but is not a valid no-replay solution. If clean decoy-logit locality works, then R37-A has a stronger
  candidate mechanism than hidden-norm locality.

So my answer to question 1: yes, if it reproduces, record it as a real sub-finding, but use it to justify the
answer-logit-drift bridge. The sub-finding should be phrased narrowly: **hidden-footprint identity on old prompts does
not guarantee old answer preservation**.

## Decoy data contract

The decoy distribution is within the current project contract if the implementation remains strict:

- generated after excluding every used stream subject name;
- no old labels and no old prompt storage;
- no inference-time memory or retrieval;
- same sequential lifecycle, no full-history joint training;
- reported honestly as **unlabeled same-template coverage**, not as pure data-free regularization.

It is not old replay. It is closer to generated coverage of the input manifold. That is acceptable because the project
does not require learning without any auxiliary unlabeled prompts; it requires new knowledge to enter weights, old
knowledge to survive, and inference to remain a single dense model without memory.

The hidden risk is distribution engineering: if the method only works because the benchmark template is known and easy
to generate, it may not scale to less synthetic streams. The right next control after this pilot is not more lambda
tuning; it is to test whether same-template coverage still helps on `BK_DATA=kg` and then on paraphrase-heavy reads.

## What must happen before a positive claim

For the ongoing 2-seed pilot, read `grow_local_decoy` against these gates:

- all-seen beats naive by at least `+0.10`, preferably moving toward the R36-C `nswrite` region;
- oldest forgetting improves by at least `0.15`;
- newest remains within about `0.05` of naive / `ours_tgt_answerid`;
- base-hop drop stays small;
- `delta_old` reduction tracks retention, not just `delta_decoy`;
- seed variance is not carrying the result.

If it passes, run the two growth controls before updating `FINDINGS.md`:

```text
BK_LOCAL_NOGROW=1 BK_ARMS=grow_local_decoy ...
```

and a large-from-start identity-stack control with the same locality loss and training budget.

Interpretation:

- If `NOGROW` matches grown `grow_local_decoy`, the result belongs to locality regularization, not growth.
- If large-from-start matches grown, the result is capacity/initialization, not lifecycle growth.
- If grown beats both while keeping compute/update cost reasonable, then R37 has a legitimate growth-oriented finding.

## Bottom line

Continue the 2-seed pilot exactly as launched. Do not spend more time on anchor. Do not promote the oracle arm to a
valid result. If clean `grow_local_decoy` holds and beats the fixed-capacity controls, then it is worth a standalone
finding: **no-replay retention via localized-write growth with strict-disjoint unlabeled same-template coverage**.
Until those controls are in, the honest claim is narrower: **strict-disjoint decoy locality materially reduces
same-template interference in the smoke and preserves the no-memory dense-inference contract**.
