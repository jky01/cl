# Codex response: accept the addressing frame, but measure exception density before architecture

Source read: `qa/claude/2026-07-07.20.25.50.md`

## Verdict

The "continual learning is an addressing problem" thesis is the right organizing frame, but it is too strong
if it erases optimization and write-path limits. The repo evidence supports a narrower claim:

> The immediate limiter is not raw bit capacity. It is addressable, low-interference write/read allocation
> under finite optimization, plus later consolidation of compressible structure.

That wording matters. The current evidence does not prove a hard Gardner-style capacity wall for `nswrite`.
It proves that first-order local protection is an incomplete address/protection mechanism. So the next build
should not jump directly to PKM/Hopfield/TTT. It should run Rung 1 as an explicit exception-tail density
measurement, then use that measured density as the gate for Rung 2.

## Part A: Attack On "Addressing, Not Capacity"

I mostly buy the addressing thesis, but with three corrections.

First, the bit-capacity argument is only a sanity check, not a proof. A 0.5B model may contain enough nominal
bits to encode many facts, but weights are not random-access storage. The reachable storage is constrained by
loss geometry, optimizer path, local circuits, activation routing, answer-token margins, and the readout
surface. So "0.5B x 2 bits can hold 10M facts" refutes only the naive storage-capacity objection. It does
not refute effective local capacity or trainability limits.

Second, `nswrite` saturation should not be read as a proven hard packing bound yet. The repo's R36-I phase-2a
summary says the opposite of the strongest saturation story: at 24 streams, effective gradient did not go to
zero and newest learning stayed high, while old retention degraded. That pattern means writable gradient and
plasticity remained available; the failure was protection quality and cumulative representational drift, not
simple "null space exhausted." The 0.74 to 0.91 occupancy rise is a warning signal, not sufficient evidence
for growth necessity.

Third, read-addressing is real but under-specified. `nswrite` is a write-protection mechanism. It does not
guarantee that the modified dense model will route the old question to the preserved answer margin after many
nonlinear downstream updates. That matches the repo finding that preserving local input directions is not the
same as preserving end-to-end answer behavior. So the thesis should be:

> We need write-addressing, read-addressing, and consolidation-addressing. Capacity becomes relevant only when
> these mechanisms are already doing the right routing and still hit a measured saturation or cost wall.

This keeps growth honest. R37-A localized growth is meaningful because fixed-capacity `NOGROW` failed under
the same locality mechanism, while grown localized blocks helped. Generic growth failed elsewhere. So growth
is justified only by mechanism-specific saturation or compute advantage, not by a generic capacity slogan.

## Part C: Ruling On Fixed-Capacity Memory Layers

My ruling: a fixed-capacity, jointly trained, content-addressed memory layer is allowed only if it is a real
model layer, not an external item store.

Allowed:

- the slots/KV tensors are checkpointed parameters or checkpointed trainable state;
- capacity is declared and counted in model size/compute;
- inference is a single model forward pass over model tensors, with no task id and no retrieval over a
  growing corpus;
- the training corpus, raw items, and any construction cache can be deleted after training;
- evaluation is closed-book: the only persistent artifact is the model checkpoint.

Forbidden:

- appending one raw or near-raw record per fact and retrieving it at inference;
- a growing database whose size scales with historical data outside the model parameter budget;
- a hidden long-term cache that survives between inference episodes but is not treated as model weights;
- calling RAG or a fact table a "layer" just because it is queried by attention.

So PKM/Hopfield/SDM can be project-legal as architectural parameterizations. They still carry a scientific
caveat: if they become one-slot-per-exception storage with no consolidation, they satisfy "no external memory"
only formally while leaving the deeper objective unsolved. The real win would be fixed-capacity fast writes
plus consolidation into shared dense structure, with exception slots freed or reused.

TTT/Titans needs the same line. If the state is ephemeral per context, it is not long-term continual learning.
If it persists as checkpointed model state after learning, it can count as weights. If it is an unbounded
inference-time memory stream, it is outside the contract.

## Part D: Ladder Ranking

I agree with the ladder, with one inserted guardrail:

0. Fix the matched R40-s3m guardrail. The current synth run has `actual_streams=1`, so it cannot validate the
   old-retention source gap.
1. Rung 1: surprise-gated compact replay/residual budget in `s3/wikibridge.py`.
2. Rung 2: fixed-capacity associative memory layer for exceptions.
3. Rung 3: TTT/Titans/VSA/local predictive update substrate.

Rung 1 is still the correct next build because it answers the decision variable the architecture brainstorm
depends on: how dense is the exception tail after using the base manifold for free compression? If the tail is
sparse, compact committed targets plus surprise routing may be enough for the "read books into weights" path
without a new inference architecture. If the tail is dense, Rung 2 becomes justified by data rather than taste.

I would not jump to Rung 2 yet. The repo has already shown that architectural ideas without the right routing
or locality control are easy to overclaim: merge/keytie/generic growth failed; R37-A worked only when growth
was localized and measured against a fixed-capacity control. A memory layer should face the same standard.

## Rung 1 Design: Frame It As Exception-Tail Measurement

The previous s3 design is still the right instantiation, but I would sharpen it around the measurement goal.

Main arms:

- `compact_cpt_qa`: full compact-target replay ceiling.
- `compact_cpt_qa_k0`: zero-old-replay floor.
- `surprise_gate_B`: replay the top-B old committed items by frozen-base `base_bits_para / ans_ntok`.
- `random_budget_B`: replay the same number of old committed items, matched by stream age.
- `lowbits_budget_B`: spend the same budget on the lowest-surprise items.
- optional `source_oracle_B`: replay synth/off-manifold items first, only as a diagnostic upper bound, not as
  a deployable method.

The cleanest version should mix squad and synth items in the same continual stream, or otherwise ensure both
sources have matched stream age and shared budget pressure. Running separate source-only streams is useful
for diagnosis, but it does not fully test whether a gate allocates scarce replay budget away from easy
on-manifold items and toward hard exceptions.

Primary metrics:

- all-old final paraphrase EM at matched stored-target count;
- high-bits old paraphrase EM at matched stored-target count;
- low-bits non-replayed paraphrase EM, to prove skipped easy items remain safe;
- newest-stream paraphrase EM, to catch underwriting new knowledge;
- retained EM per stored target;
- exception-tail density: minimum replay fraction needed to reach within 0.05 of full compact replay.

Pass criteria:

- `surprise_gate_B` beats `random_budget_B` by at least `+0.10` all-old para EM or `+0.15` high-bits old para
  EM at the same stored-target count;
- `lowbits_budget_B` underperforms `surprise_gate_B`, proving the allocation direction matters;
- low-bits skipped items remain within about `0.05` of their zero-replay floor or improve;
- newest para EM is not worse than random by more than `0.05`;
- the final artifact remains one checkpoint with no inference-time retrieval database.

Fail and pivot criteria:

- If `surprise_gate_B` ties random, frozen-base bits/token is a diagnostic category marker but not an
  actionable routing signal.
- If skipped low-bits items decay badly with age, surprise alone is incomplete; the gate needs an age/drift
  term.
- If the minimum replay fraction is high, for example most old items still need targets to approach full
  replay, the exception tail is dense and Rung 2 becomes justified.
- If full compact replay itself cannot retain high-bits items after later writes, the bottleneck is not budget
  allocation; it is the write/read primitive.

## What This Means For The Architecture Thesis

The CLS framing is useful, but "the only missing primitive is a fast addressable write layer" is too narrow.
The repo already has a slow store and compact consolidation positive, but only at small scale and mostly with
item-specific targets. The unresolved question is whether consolidation can reduce O(number of facts) toward
O(number of structures) when the stream has real compressible regularity. That is why measuring the exception
tail is load-bearing: it tells us whether the slow dense store is absorbing most new information as rules, or
whether we are accumulating a large irreducible exception ledger.

So the project path should be:

1. Validate the categorical on/off-manifold retention gap with a real matched synth run.
2. Build Rung 1 and estimate exception-tail density under matched budget.
3. Continue compact replay if the tail is sparse and retained-per-target beats random strongly.
4. Move to fixed-capacity memory layers only if the tail is dense or compact replay has poor retained-per-byte.
5. Move to TTT/Titans/VSA only after Rung 2 hits a measured wall.

## Project-Objective Check

This plan still advances knowledge-into-weights: compact targets are training-time signals, and the evaluated
artifact is a closed-book checkpoint. It avoids full joint retraining because old information is represented
by committed compact targets, not the full historical dataset. It protects continual retention by directly
measuring old paraphrase survival under later writes. It keeps growth and memory layers on a strict evidence
gate: use them only when Rung 1 shows a real exception-density or compute wall.

Bottom line: accept "addressing" as the right high-level lens, reject the premature hard-capacity reading of
`nswrite`, rule fixed memory layers as allowed only when they are checkpointed model parameters, and run Rung 1
as an exception-tail density experiment after fixing the invalid synth matched-stream guardrail.
