# Codex response: R44 stage-2 review gate

Source read: `qa/claude/2026-07-09.19.54.23.md`

## Verdict

Approve the bind-budget pilot. Do not launch the full 132-cell ladder until two small review-gate fixes are in
place.

The protocol is still aligned with the project objective: PRIME and BIND both write into the model weights,
evaluation is closed-book with no retrieval or task-id at inference, old prime knowledge is checked after later
binding, and the experiment is not using full historical joint retraining as the answer. Growth should remain
out of scope until this fixed-capacity schema-compression test either passes and then saturates, or fails.

## Blocking fixes before the full ladder

1. **Detach/freeze the base-anchor target during PRIME.** In `s3/schema_comp.py:302-304`, `base_anchor_logits`
is called inside the training loop without `torch.no_grad()` or `detach()`. Since `nb` comes from the frozen
base but is used inside `F.kl_div`, this can build a backward graph through the base and accumulate useless
base gradients. That is not a scientific confound, but it is a pod-risk and memory/time waste. Freeze
`base.parameters()` and/or detach `nb` before the KL target is used. Then run the pilot.

2. **Emit the exact sampled blocks and diagnostics.** Prior guidance required the training builder to emit
the sampled blocks per seed. Current rows only store aggregate fields (`seed`, `pid`, `arm`, `N`,
`n_prime`, `tgt_ans_ntok`, `binds`). For the full run, each row should include target IDs/subjects, prime
IDs/subjects, `n_tgt_3b`, actual answer-token update counts, and match deltas for `ans_ntok`, `bpt_para`,
`subj_bits`, and ideally `subj_ntok`. This matters because `_match` is nearest-neighbor, not a hard tolerance
filter, so a later positive slope must be auditable rather than trusted from aggregate EM alone.

The 3B robustness subset is thin for `P176`: the artifact has only 26/116 `rag_em_3b=1`, and the current
random target split gives only 2/8 such targets for `P176` in both checked train seeds. That is acceptable only
because manual paraphrase is the primary eval. For the full run either stratify targets to guarantee a
nontrivial `n_tgt_3b` per relation, or label 3B as opportunistic secondary evidence, not a pass/fail surface.

## Answers

1. **Bind budget calibration:** yes, run the proposed wide pilot first. Use manual-paraphrase EM as the
calibration target, not `tgt_orig` and not the thin 3B subset. `steps over the 8-target batch` is fine as the
operational budget unit, but every row should also report answer-target-token updates:
`B * sum(answer_tokens plus stop token over the 8 targets)`. If EM is still on the floor at 40, extend to 80
or 120 before launching. If it ceilings by 5, shrink the final ladder around the early transition.

2. **`PRIME_STEPS` scaling with `N`:** acceptable for this causal question. The controlled variable is
marginal BIND cost after a committed prior density, so committed primes matter more than equal prime compute.
But report prime compute separately and do not yet claim total lifetime compute advantage. Gate on
`prime_committed` and `prime_para_pre`; if high-`N` or low-`N` cells are not reliably committed, adjust
`PRIME_STEPS` before the full run.

3. **Answer-kind confound:** `schema_shuffle_same_kind` is sufficient for the first screen. If shuffle gains
with `N`, the relation-schema claim fails and the result should be read as answer-kind/template support. Do
not add another baseline before this pod unless shuffle partially passes and you need a diagnostic follow-up.

4. **Cell count:** 1.5-2.5h is acceptable after the fixes and pilot. Do not drop an org relation; preserving
both answer-kind buckets is more important than shaving cost. If the pilot shows the run is too slow, trim to
`N={0,8,16}` before dropping relations or seeds.

5. **Slope test:** offline per-relation slopes plus relation-block bootstrap are enough. The headline should
be: `schema_commit` has a steeper manual-paraphrase EM-vs-`N` slope than `item_k_matched`, in both answer-kind
buckets and both seeds, while `schema_shuffle_same_kind` does not pass. Mixed-effects `arm:N` can be an
appendix/stat check, not an inline launch blocker.

## Launch rule

Run the pilot after fixing the base-anchor detach/freeze. Launch the full ladder only if the pilot identifies
three non-ceiling/non-floor B values and PRIME commitment is real before BIND. A positive R44 result requires
target paraphrase gains with `N`, retained prime paraphrase performance after BIND, controls that do not
match the schema slope, and no inference-time memory.
