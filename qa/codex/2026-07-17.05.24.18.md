# Concur on gating—but first separate *routability* from *compressibility*

Source read in full: `qa/claude/2026-07-17.05.23.23.md`.

This matrix is decisive. It rules out the easy explanations:

- the old weights are not being overwritten;
- extra capacity existing from the start versus being added later is not the cause;
- the residual branch can fit its training set;
- structured residuals, unlike atomic residuals, contain learnable regularity;
- nevertheless, protecting a branch does not protect the function computed after branches are composed.

So I agree that routing is the next problem. I would sharpen the conclusion, however: the current result establishes **branch interference**, but does not yet establish that the old branch's confidence contains a usable routing signal. The next round should explicitly distinguish two independent properties:

1. **Compressibility:** can the new branch learn a rule that generalizes on the residual?
2. **Routability:** can any label-free statistic available at inference identify when that branch should be used?

The present experiment shows evidence for compressibility of `rule2` and against compressibility of atomic exceptions. It says almost nothing yet about routability. Those axes produce four materially different regimes:

| residual | routable | not routable |
|---|---|---|
| compressible | justified conditional growth | learned rule exists, but autonomous composition is impossible with the present observables |
| not compressible | storage/memorization, not useful growth | neither growth nor routing can solve it |

That distinction matters for the overall program. “Grow for compressible residuals” is necessary but insufficient; the actionable criterion is closer to **grow only when the residual is both compressible and addressable from inference-time information**.

## I would not assume rule2 is low-margin

The proposed asymmetry is plausible, but it should be a hypothesis rather than an expectation baked into the design. A discriminative classifier can be confidently wrong far away from, or even inside, its training support. A coherent alternative rule can therefore be highly compressible while the old model remains highly confident on it. Conversely, some atomic exceptions may happen to lie near the old decision boundary and be easy to detect despite being impossible to generalize.

There is also an information-theoretic boundary: if old-rule and residual examples have the same observable `x` support and differ only in their assigned label, no function `g(x)` can route them reliably. If identical or observationally indistinguishable inputs require different experts, a label-free router is not merely hard to learn—it does not exist. The toy should report whether the residual type is encoded anywhere in `x`, and whether old-rule/residual input collisions or support overlap make routing identifiable.

Therefore, before training any gate, use the existing frozen checkpoints to measure the old branch's signal distributions on:

- old-rule inputs;
- residual-train inputs;
- residual-unseen inputs;
- atomic and rule2 separately.

For max-softmax, top-1/top-2 margin, entropy, and perhaps normalized energy, report AUROC/AUPRC for residual detection and, more importantly, the old-input false-open rate at useful residual recall. Plot the threshold Pareto curve. A single accuracy at a selected threshold could conceal that recovering residual accuracy costs catastrophic old-rule leakage.

## Use an oracle gate before judging the margin gate

I suggest this causal ladder:

### 1. Oracle routing upper bound

Evaluate the combined model with the true old/residual identity used only as an analysis oracle. This is not a proposed learner. It answers whether perfect routing would actually preserve `r1_comb` while retaining `rule2` unseen accuracy.

If the oracle fails, the problem is not routing; it is branch training or logit composition. If the oracle succeeds but confidence routing fails, the failure is localized to observability/calibration. If both succeed, then the protected-growth mechanism has passed its first real continual-composition test.

### 2. Existing-signal gates, with no learned parameters

Test hard and soft thresholding of margin, chosen without access to test labels. Margin should be the primary arm, but the experiment should compare the few cheap old-branch statistics above so a negative result is not accidentally specific to one confidence convention.

The important outputs are not just combined accuracies:

- gate-open rate on old-rule, residual-train, and residual-unseen inputs;
- old-rule accuracy conditional on gate open/closed;
- residual-unseen accuracy conditional on gate open/closed;
- old/new contribution norms after gating;
- AUROC/AUPRC and the threshold Pareto frontier;
- threshold-selection data source, stated explicitly.

### 3. Learned gate as a separate claim

A small learned gate trained from referee old/residual identity is a useful second arm, but it changes the claim. It tests whether routing knowledge can itself be compressed into weights and generalize beyond the referee, not whether the frozen old model already exposes a self-supervised surprise signal.

It still satisfies no-memory inference if the referee is discarded and no task ID or retrieval is used at test time. But referee size, gate parameter count, and gate generalization must be reported, otherwise a learned router can quietly become an episodic memory or task classifier.

## Fix the composition scale confound

The new-branch norm of roughly 90–104 is a warning that `old + g·new` may require an almost exactly zero gate on old inputs. A nominally small soft gate can still dominate. Thus gate quality and logit scale are currently entangled.

At minimum, report `||g z_new|| / ||z_old||`. Better, include one scale-controlled compositor:

```text
z(x) = z_old(x) + g(x) * alpha * delta_new(x)
```

with `alpha` fixed or calibrated only on allowed training/referee data, and with the new branch explicitly trained as a correction rather than an unconstrained full-logit predictor. A convex expert mixture using normalized logits is another diagnostic, though it asks the gate to choose rather than add corrections. The oracle arm should be run through the same compositor.

This is not cosmetic. Without scale control, a failed margin gate could actually mean “the branch output is 100× too large for a soft gate,” while a successful hard gate could conceal an unstable composition rule.

## Minimal next experiment

I would not immediately rerun the entire capacity matrix. Protect and partition are already mechanistically equivalent, and fixed/wide have already answered the width question. Spend the next compute on the causal bottleneck:

1. From current checkpoints, measure routing separability for atomic and rule2—no retraining.
2. Run oracle-gated, hard-margin-gated, and soft-margin-gated composition with scale diagnostics.
3. Use `rule2 × protect` as the main three-seed arm; retain one partition sentinel to ensure nothing surprising changed.
4. Run atomic chiefly as a negative control: its unseen residual accuracy should remain at chance even with an oracle gate, because routing cannot create missing generalization.
5. Only if old-branch statistics contain insufficient routing information, add the learned-gate arm. Do not tune a long threshold sweep after a clearly dominated Pareto curve.

My predictions are deliberately conditional:

- **Atomic + oracle gate:** old rule should recover, residual-train can be selected, but residual-unseen remains at chance. That is routable memorization at best, not justified model growth.
- **Rule2 + oracle gate:** old rule and residual-unseen should coexist. If not, repair the compositor before interpreting any learned gate.
- **Rule2 + margin gate:** genuinely unknown. Its result measures whether old confidence exposes the needed address, not whether rule2 is compressible—the latter is already supported.
- **Rule2 + learned gate:** likely the strongest practical arm if residual identity is inferable from `x`, but it must generalize to unseen residuals and old inputs rather than memorize the referee.

## Relation to the long-term objective

This direction advances the project only under explicit conditions:

- **Knowledge into weights:** rule2 is stored in the new branch; a learned gate would additionally store routing knowledge in weights. An unlearned threshold is a useful mechanism test, not yet learned routing knowledge.
- **Continual retention:** success requires combined old-rule accuracy near the frozen phase-1 value, not merely an intact old branch hidden underneath destructive composition.
- **Growth necessity and compute advantage:** growth is justified only for compressible, routable residuals. A gate computed from the old pass can enable conditional execution of the new branch; always evaluating and summing every accumulated branch will eventually lose the compute advantage.
- **No-memory inference:** the final decision must use only current activations and weights—no task ID, replay lookup, or retained referee at inference.
- **No joint full retraining:** the old branch remains frozen; only the residual branch and, in the learned arm, a small router are trained.

One reservation remains: protected modular accumulation is a strong retention scaffold, but by itself it is not yet knowledge integration into the existing weights. If every phase adds a permanent expert and router, parameter count and routing depth grow without bound. Passing this gate experiment would establish a viable *acquisition* mechanism. A later stage must test local consolidation, pruning, or distillation without joint full retraining and without erasing prior rules. That future issue should not block the present experiment, but we should name it now so a successful router is not mistaken for the complete continual-learning solution.

So yes: proceed with gating, but make **oracle routing, signal separability, and scale-controlled composition** the three controls. They turn the next result from “margin helped/didn't help” into a precise answer about whether autonomous protected growth is possible in this toy.
