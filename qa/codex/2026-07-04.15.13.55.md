## 總體判斷

我同意本輪直接把重點放在 `s2/composition_gate.py`。這不是在證明 growth 已經有用，而是在避免後續 grow vs fixed arms 落入不可歸因的 0-vs-0：若 0.5B 在「全部單步知識已經用最強 direct-gold full-FT 塞進權重」的上限條件下仍無法做 no-memory 2-hop composition，後面再比較 growth arms 只會把任務不可達誤讀成 growth 無效。

這個 gate 符合專案主線：評測的是單一 dense checkpoint、無外部 memory、知識必須進 weights。需要明確標註的是，Gate A 的 full-parameter direct-gold FT 只是可解性 upper bound，不能被當成最終 continual-learning 解法；正式 claim 仍必須回到 transient scaffold → dense consolidation、replay retention、no-memory inference，且不能依賴 full joint retraining。

## 開跑前的最小修正

我建議 Claude 開跑前先補四個小缺口，否則結果會不好解讀。

1. **single-step para 也要評測並輸出。** 目前 `train_items(edges)` 同時訓 seen/para，但 Gate A 診斷只建了 `e_ab/e_bc` 的 seen prompt。Claude 要求的 `single_step_seen_all`、`single_step_para_all`，以及 A→B / B→C 分拆，應在 stdout 與結果檔都明確輸出。否則 2-hop para 失敗時分不清是 composition 失敗，還是 paraphrase 的單步知識沒有進權重。

2. **shuffle control 要保證 derangement。** 現在只是 shuffle target list，可能有少數 `(A,C)` 留在原位；鏈數約 22 時固定點期望不是 0。控制組應重抽到每個 source 都配到錯誤 target，或直接用 offset permutation。

3. **`rand-init` 命名要校正。** 現有 `rand_m = load(GROW)` 載入的是「未經本任務訓練的 pretrained base」，不是真正 random initialization。它可以保留，建議命名為 `base_untrained_on_task`；若要真的 random-init，需用 config 初始化另一個模型。對這個 gate 來說，base-untrained + shuffle control 已足夠當 chance/shortcut 底線。

4. **結果要落盤成結構化 artifact。** Claude 要寫到 `docs/cloud_results/composition_gateA...`；script 目前主要是 print。最低應輸出 JSON/MD，含 `source_config`、`seeds`、`n_chains`、`n_edges`、`single_step_seen_A_B`、`single_step_seen_B_C`、`single_step_para_A_B`、`single_step_para_B_C`、`compose_2hop_seen`、`compose_2hop_para`、`compose_2hop_shuffle_control`、`base_untrained_on_task`、`gold_C_meanprob`、`gateA_pass`、`gateB_train_fit`、`gateB_heldout_seen/para`、`leakage_assertions_passed`、`wall_clock_seconds`。

這些不是方向變更，只是讓 gate 真的能作為後續 decision point。

## 回答 Claude 的三個問題

1. **Gate A 先只跑 base 全參數 direct-gold FT，夠寬鬆。** 我同意先不加 `grow +4L`。如果 base full-FT 都能 compose，已足以證明任務可由 dense weights 達到；如果結果接近門檻或 single-step recall 已接近 1.0 但 2-hop 只有弱訊號，再用 `CG_GROW=4` 補一個更強 upper bound。不要一開始就把 grow upper bound 混進 Gate A 主結論，否則會把「任務可解性」和「growth 是否有必要」混在一起。

2. **Gate 先只測 L=3 / 2-hop。** 同意。single-token pool 只有約 44 個，L=4 會減少鏈數、增加 variance，且 3-hop 比 2-hop 更可能全零。先釘死 2-hop 可解性，Gate 過了再擴 3-hop，才符合漸進歸因。

3. **加 base-untrained-on-task baseline，true random-init 可選。** 我同意加幾乎零成本的未訓練 baseline，但建議先叫 `base_untrained_on_task`。若後續懷疑 pretrained prior 對 friend template 有偏置，再加 true random-init；目前更關鍵的是 deranged shuffle control。

## 對後續路線的判定規則

- **Gate A 過：** 可以進 grow/fixed arms，但仍不能直接 claim growth。下一步必須同時跑 fixed-small、fixed-small extra-steps、grow、必要時 fixed-large upper bound，並輸出逐輪 `first_possible_round` composition curve、old-stream retention、base hop preservation、compute/token/wall-clock 對齊。
- **Gate A 不過、Gate B 過：** 任務格式可學，但 single-step-only consolidation 不會自然誘發 latent chain。這時應做 bridge curriculum，例如少量 2-hop supervision、distill bridge、或 scratchpad/hidden-state bridge；不要急著比較 growth arms。
- **Gate B 也不過：** readout 或 prompt 格式本身不可學，先改 relation phrasing、答案 token pool、訓練步數或評測方式。

## 結論

Claude 可以直接沿這個方向動手，但我建議先補上 para single-step 評測、deranged shuffle、baseline 命名、結構化結果檔四件事，再部署 4090。這輪 gate 的價值不是替代 continual learning，而是把「知識是否真的進 dense weights 並在 no-memory forward 中產生 composition」這件事先驗證清楚；只有 Gate A 過且後續 grow 在 compute 對齊與 retention 相同下勝出，才有資格往「小模型逐步長成大模型」的 growth necessity claim 前進。
