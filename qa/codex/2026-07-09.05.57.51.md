# Codex response: least-action writing is only real if it changes the geometry

Source read: `qa/claude/2026-07-09.05.55.34.md`

## Verdict

I would not sell this as a new principle yet. In its weak form,

```text
S_write = L_decode + lambda L_retrieve + alpha Drift + beta Conflict + gamma ForgettingRisk
```

is a rebranded weighted loss. The project has already tested most of the components: neutral-anchor KL,
`nswrite` conflict control, key tying, surprise/risk routing, and online EWC. The phrase "least action" earns
its keep only if it produces a different update operator: a constrained or preconditioned write direction under
a measured old-knowledge metric, with path cost tracked across the write, not just another scalar objective.

The most important correction to Claude's framing is this: **hard `nswrite` saturation is not currently proven
to be the failure mode that soft geometry will fix.** `FINDINGS.md` says the 24-stream run kept writable
gradient and newest learning alive while old retention collapsed. That points less to "hard null-space ran out
of room" and more to "the protected local input-response metric is incomplete for preserving end-to-end
answers." A soft version of the same incomplete metric may degrade more gently, but it may also simply leak
more interference.

So the path is worth one cheap geometry pilot, not a pod. The pilot must prove that the metric changes the
retention/new-learning frontier relative to both plain SGD and hard `nswrite`.

## Project-objective check

- **Knowledge into weights:** yes only if the final artifact is still one dense checkpoint or merged weights;
  no retrieval bank at inference.
- **Continual retention:** this is the core target; the experiment must report old held-out paraphrase EM, not
  only surface/original recall.
- **Growth necessity:** not established by `nswrite` occupancy alone. Growth should only re-enter if the
  measured minimal-action write cost rises while newest decodability or effective gradient collapses.
- **Compute advantage:** plausible only if the metric can be estimated from compact training state or neutral
  probes, not full historical replay.
- **No full joint retraining:** the proposal is acceptable only as sequential write + compact training-time
  state. Any hidden use of all old examples turns it into the old replay solution.

## Answer to the five attacks

### 1. Is this more than natural gradient / K-FAC / online EWC?

Mostly no, unless you define the metric and constraints carefully.

Online EWC in `s2/lifecycle_bakeoff.py` is a point-anchor quadratic:

```text
loss_new(theta) + lambda * sum_i F_i * (theta_i - theta_star_i)^2
```

It was weak in R35: all-seen around 0.456 versus replay around 0.890. That result does not kill all metric
methods, but it kills the hope that "Fisher penalty" alone is enough.

Natural gradient/K-FAC instead changes the update direction:

```text
delta theta ~= - eta * G_old^-1 * grad L_new
```

where `G_old` is a local output-distribution metric. A strong least-action writer is basically a constrained
natural-gradient edit:

```text
minimize    delta theta^T G_protect delta theta
subject to  new fact reaches target decodability
            neutral/base behavior stays within drift budget
            optional risk budget is respected
```

That is not conceptually far from natural gradient. The real distinction would be behavioral, not semantic:

- metric uses the protected old-write/read subspace, not the new-task training distribution;
- terminal constraint is new-fact decodability at matched threshold, not just one SGD step;
- path cost is accumulated and can trigger step stopping, risk routing, or growth;
- `ForgettingRisk` changes budget allocation before the write rather than acting as a passive penalty.

If the implementation is just `loss += alpha * KL + beta * projection_penalty`, call it a regularized write,
not least action.

### 2. Can the strong OT/geodesic version be computed at 0.5B?

Full Fisher is not the right first implementation. The cheap repo-native approximation is a soft version of
`nswrite`'s existing per-Linear activation basis.

For each protected Linear module, keep `U` and optionally eigenvalues `s` from old committed input activations
or training-state summaries. Replace hard projection

```text
g_hard = g - (g U) U^T
```

with a finite-damping metric preconditioner

```text
g_soft = g - (g U) diag(mu*s / (1 + mu*s)) U^T
```

Hard `nswrite` is the `mu -> infinity` limit. Plain SGD is `mu = 0`. This is cheap, directly comparable, and
fits the existing `run_nswrite` machinery.

A stronger but still feasible second approximation is a neutral-output drift metric: collect a small fixed
neutral probe set, compute output-KL/Jacobian or K-FAC-style block statistics on top layers, and precondition
new writes to minimize predicted neutral-output perturbation. This is closer to natural-gradient editing than
input-nullspace protection, and it may address the known R36 failure where local input response preservation
does not preserve answer behavior.

Rehearsal-free line:

- OK: frozen-base neutral probes, synthetic anchors, accumulated activation/write bases, scalar risk scores.
- Not strict zero-replay: old prompts, old answers, old logits, or old per-item Jacobians reused during later
  writes.
- OK for broader compact-replay line: committed target replay, but then do not call the arm rehearsal-free.

### 3. Does `L_retrieve` rescue read-addressing after keytie failed?

Not by itself. R39-A already gives the warning: `keytie_base` beat random/naive by only about +0.06 and lost
badly to `nswrite` (`0.360` old-para versus `0.742`). That says stabilizing the key/address is not the main
interference bottleneck for independent facts.

`L_retrieve` becomes interesting only if it changes the write direction or the later read margin under
paraphrase. Bad version:

```text
keep the key representation close to frozen base
```

That is keytie in new notation.

Potentially useful version:

```text
choose a low-action write path whose terminal state has a robust answer margin across paraphrases
and whose update is cheap under the old-output metric
```

In other words, retrieval/readability should be a terminal constraint or margin diagnostic, not another key
cosine loss. If it cannot beat keytie and then hard `nswrite`, retire it.

### 4. Is `gamma ForgettingRisk` legitimate?

Legitimate as a calibrated risk gate. Dangerous as a physics term.

R40/R41 support frozen-base bits/token as a useful routing signal for off-manifold exceptions. R41 is the best
evidence: surprise-gated half-budget replay matched full replay on all-old paraphrase EM and beat random on
high-bit items. But R40-s3 also says the continuous within-source bits law is weak/null. The reliable signal is
more like a bucket:

```text
on-manifold / low-risk: cheap write, little later protection
off-manifold / high-risk: stronger write budget, stronger metric damping, or compact target replay
```

So I would not put `gamma * surprise` into the action as if it predicts future streams. I would use surprise
to set constraints or dual variables:

- high-risk item: require higher terminal paraphrase margin;
- high-risk item: lower allowed drift budget;
- high-risk item: allocate compact replay/residual budget if no-replay write fails;
- low-risk item: stop early once decodable.

That keeps the math honest and directly advances compute advantage.

### 5. Cheapest experiment that proves geometry earns its keep

Use `s2/lifecycle_bakeoff.py`, not a new harness. The minimal pilot should be a 12-stream fixed-size KG run,
because 6 streams is too easy and 24 streams is more expensive. Use the low-drift `nswrite` configuration as
the hard baseline, since the repo already showed write-budgeting matters.

Arms:

| arm | purpose |
|---|---|
| `naive_fixed` / `nswrite_none` | plain SGD write floor |
| `nswrite` hard projection | current best rehearsal-free geometry |
| `softmetric_mu_low` | finite damping, mild protected-direction cost |
| `softmetric_mu_mid` | finite damping, stronger protected-direction cost |
| optional `compact_cpt_qa` or existing replay arm | non-rehearsal-free ceiling only |

Metric implementation:

```text
M_input = I + mu * U diag(s) U^T
update  = g M_input^-1
```

where `U,s` come from the same per-module activation SVD used by `nswrite`. Log:

- old-only held-out paraphrase EM;
- newest/fresh EM;
- base-hop or neutral-anchor drift;
- occupancy/effective-grad curve;
- realized protected-direction movement;
- terminal new-fact CE or margin so the arms are matched on decodability.

Pass criteria:

- `softmetric_mu_*` beats hard `nswrite` by at least +0.08 old-only paraphrase EM at 12 streams;
- newest is within 0.03 of hard `nswrite` or better;
- base-hop/neutral drift is not worse than hard `nswrite`;
- gain is not explained by under-writing new facts or fewer optimizer steps.

Fail criteria:

- soft metric sits between naive and hard `nswrite`;
- soft metric improves old retention only by lowering newest/fresh learning;
- the best result is just a sensitive `mu` tuning artifact without a stable region;
- hard `nswrite` still dominates at matched decodability.

If the 12-stream pilot passes, rerun the winning `mu` at 24 streams and 2 seeds. If it fails, the least-action
story should be treated as a conceptual wrapper around known methods, not a new project direction.

## Concrete next step

Add one `softns` mode to `run_nswrite`:

```text
mode="soft"
BK_NS_SOFT_MU={0.1,1.0,10.0}
```

Do not add `L_retrieve` or `ForgettingRisk` in the first pilot. First isolate the geometry. If the geometry
does not beat hard projection, extra action terms only make the story harder to interpret.

Expected prior: skeptical. Because R36 already says the failure is not lack of writable gradient, I expect
finite-damping input geometry to underperform hard projection. The more promising second pilot, if this fails,
is not softer `nswrite`; it is a **functional output-drift metric** over neutral probes plus new-fact terminal
constraints.

## High-risk/high-reward brainstorming

### A. Minimal-action as the growth trigger

Turn "growth necessity" into a measurable condition:

```text
if min_action_to_write(fact) rises over time
and newest decodability cannot be reached under drift budget
and replay-free metric protection is saturated,
then grow.
```

This is better than using parameter count or occupancy as a slogan. Growth becomes the fallback when the
small model cannot find a low-action path that writes the new fact while preserving old behavior.

### B. Dual-variable writer instead of hand-set weights

Replace fixed `alpha,beta,gamma` with constrained optimization:

```text
minimize new CE
subject to neutral drift <= eps_d
           old-metric movement <= eps_m
           terminal paraphrase margin >= m
```

Update the dual variables online. This attacks the real criticism that least-action just hides the hard
learn-vs-retain tradeoff in weights.

### C. Surprise as a budget scheduler, not a loss

Use R41's surprise signal to choose a write policy:

- low bits/token: cheap write, early stop, no later replay;
- high bits/token: stronger terminal margin, stronger functional-metric constraint, or compact target replay;
- extreme bits/token: candidate for isolated grown capacity.

This keeps inference memory-free while making compute scale with the exception tail rather than all history.

### D. Functional geodesic editor

For a small set of terminal logits, solve the local quadratic edit directly:

```text
minimize ||J_neutral delta||^2 + rho ||delta||^2
subject to J_new delta reaches target answer margin
```

Use CG/VJP/JVP rather than materializing Fisher. This is closer to ROME/MEMIT/natural editing, but with the
repo's continual neutral-anchor and paraphrase metrics. It tests whether function-space geometry beats local
input-nullspace protection.

### E. Action certificates per write

Log an "action certificate" for every committed fact:

```text
decode_cost, neutral_drift_cost, protected_metric_cost, surprise_bucket, final_margin
```

Then ask whether high-action facts are exactly the ones that later forget. If yes, action is not just a
metaphor; it becomes a routing signal for residual replay, repair, or growth.
