# R49a logic ruling: keep the OR threat rule; L3 still needs a relation-level guard

Source read: `qa/claude/2026-07-10.16.22.09.md`

## Bottom line

Let the running seed-0 job finish as a **shakedown only**, but do not let its current L3 number authorize
`search_warranted`. I confirm the threatened-fact OR rule as the frozen primary definition. I do **not** confirm
provenance-lock plus correct answering as sufficient for decision-bearing L3: an explicit relation-addition guard
and a proposition-level audit are still required.

There are also several implementation gaps relative to the frozen contract: the shadow enrichment uses a
bits-only label rather than the OR-threatened label, `fixed_family_win` does not enforce age coverage or target
error, and the pooled/neutral parts of the shadow gate are absent. Hold seed 1 and every R49b branch until these
are corrected. This does not require stopping the current seed-0 diagnostic.

## 1. L3: require relation recovery, not merely the right answer

**Ruling: add the explicit relation-add check.** Provenance-lock prevents a candidate generated for fact A from
being credited to fact B, and correct-answer filtering is necessary. It is not sufficient to show that the
candidate recovered A's proposition. The same entity can participate in several relations, multiple questions
can share an answer, and the current Jaccard matcher can clear its threshold partly from entity tokens already
placed in the prompt. A generic or wrong-relation question can therefore receive the right short answer without
demonstrating that generation reconstructed the omitted relation.

Use a two-stage decision-bearing L3 audit:

1. With `E_i = _sig(entity_cue_i)`, define auditor-only target relation tokens
   `R_i = _sig(target_question_i) - E_i` and generated additions
   `A_i = _sig(generated_question_i) - E_i`. Require `A_i & R_i` to be non-empty after answer aliases, numbers,
   question words, and generic boilerplate are removed. This is a cheap necessary filter, not semantic proof.
2. For every seed-0 L3 apparent correct-threatened hit, inspect an audit row containing `qid`, entity cue,
   generated question, added tokens, target question, match score, frozen-model answer, and gold answer. Credit
   the hit only if the generated question asks the same relation/proposition. Freeze the resulting deterministic
   rule before seed 1. If that cannot be made reliable, label L3 confounded and forbid it from producing
   `search_warranted`.

Report both coverage over **all** threatened facts and coverage conditional on facts with a usable entity cue.
The all-threatened denominator remains the branch statistic; the eligible-only value diagnoses whether failure
comes from the model or from the capitalization-based entity extractor. Do not silently drop entity-less facts
from the decision denominator.

The current run does not retain candidate-level hit rows in its JSON, so a nonzero or branch-changing L3 result
will need either a saved audit sidecar or a rerun after this instrumentation. If L3 is zero, the missing relation
guard cannot create a false negative, but seed 0 still remains only a shakedown.

I agree with requiring L3, rather than L2 alone, for R49b. In this census L2 is just three coarse source labels;
if it works, first fold those constant-size domain prompts into the fixed-family control. It does not yet prove
that a write-conditioned item address is needed.

## 2. Threat: retain the frozen OR as primary

Keep

```text
threatened(i) = pre_eval_EM(i) == 1
                AND (damage_real_bits(i) >= 0.5 OR post_real_eval_EM(i) == 0)
```

as the primary universe for both seeds. Do not switch to EM-flip primary after seeing which component is larger.
The two components detect different useful failure stages: the bits threshold detects substantial confidence
erosion before a decoded answer flips, while the EM flip captures realized closed-book failure when bits/token is
unstable for short answers. If one-token answers make flips dominate, that is a property to report, not a reason
to change the preregistered rule.

Add `bits_only`, `flip_only`, and `both` counts and publish two sensitivity curves: EM-flip-only and
bits-threshold-only. They must not control the branch. If the union passes but both component curves separately
reverse the scientific conclusion, return `inconclusive` and replicate rather than redefining threat post hoc.

One blocking consistency fix is needed now. `dflag` in `run_seed()` currently marks only
`damage_real >= DAMAGE_MIN`, while coverage uses the OR union. Thus top-quartile enrichment is not testing whether
the shadow predicts the facts R49b would target. Gate on enrichment of the OR-threatened label, and report
bits-only and flip-only enrichment as diagnostics. Spearman on continuous shadow-versus-real bits can remain the
rank statistic.

## 3. Remaining decision-logic corrections before seed 1

1. **Enforce the whole L1 gate.** `decide()` currently checks only per-seed `L1-L0 >= 0.20`.
   `record()` gives global levels `target_err=None`, and the per-age output contains answerable counts but not
   threatened denominators or correct-threatened counts. Record L1 matched-target error and per-age threatened
   coverage, then require target error `<=0.10` and no zero-coverage supported age bin in each seed. Define the
   minimum support for an age bin before seed 1; tiny bins should be reported with intervals rather than silently
   treated as evidence of coverage.
2. **Block positive decisions on a weak-availability seed.** The code declares `availability_fail` only when
   *both* seeds are below `0.20`. Require every seed to meet the availability floor before any positive branch.
   If both fail, return `availability_fail`; if only one fails, return `availability_unstable`/`inconclusive`, not
   `fixed_family_win` or `search_warranted`.
3. **Complete the shadow gate.** Preserve per-fact pairs so pooled Spearman can be computed; require the frozen
   per-seed and pooled correlation criteria and per-seed enrichment. Add neutral/base-capability sanity alongside
   new-stream EM, and make the sanity test an explicit pass/fail condition. At present `new_shadow/new_real` is
   only printed, neutral behavior is not measured, and `shadow_ok` ignores both.
4. **Make one-seed status unambiguous.** Keep `phase="shakedown_only"` separate from
   `power="underpowered|adequate"`. The current one-seed function can return `underpowered` instead of the claimed
   `shakedown_only`; this is harmless scientifically only if neither is presented as a final branch.
5. **Finish compute accounting.** L1 currently performs `6 * floor(400/6) = 396` attempts. Distribute the
   remainder to make L0/L1 exactly equal. The ledger still omits answer-evaluation tokens and model-token
   evaluations, whose cost varies with the number of matches. Add them before making any compute-advantage claim.
6. **Harden missing-value logic.** `both()` can return true when one of two values is `None`, because it filters
   missing values before `all()` but checks only the original list length. Require two finite values explicitly.

The separation between `addressability` and `build_r49b` is otherwise correct: a valid cue-ladder result may say
`search_warranted`, but a failed shadow must leave `build_r49b=false` and send the work back to proxy repair.

## Execution decision

- Finish seed 0 and use it to check availability, power, curve shape, entity-cue eligibility, and whether the
  shadow metrics are non-degenerate.
- Apply the schema and gate fixes above. If seed-0 L3 has any apparent hits, save and audit them and rerun the
  affected measurement before freezing seed 1.
- Run seed 1 only after all branch inputs and thresholds are fixed. Do not lower `DAMAGE_MIN`.
- Build R49b only if both seeds show low L0/L1, relation-valid L3 coverage at least half the reachable ceiling,
  adequate power/availability, and a fully passing shadow proxy.

R49a remains an auditor-only addressing diagnostic. It neither demonstrates continual retention nor justifies
growth. The project advances only if a later learner uses checkpoint-plus-current-write signals to generate
reliable old targets, consolidates them into weights, deletes all temporary cues/shadows/pools, and improves
closed-book multi-age retention under a compute-matched no-replay control. No historical oracle cue may enter that
learner path, and no full-history joint retraining is introduced here.
