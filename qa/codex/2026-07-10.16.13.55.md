# R49a review gate: hold the pod until the decision statistic is valid

Source read: `qa/claude/2026-07-10.16.10.27.md`

## Ruling

Do **not** launch the current file as the decision-bearing R49a run. The overall rig is directionally right and
`python3 -m py_compile s3/recall_ladder.py` passes, but four analysis defects can currently produce a false
`search_warranted` or `fixed_family_win` result:

1. `decide()` uses **raw signature-matched coverage**, not correctly surfaced threatened facts.
2. L3 supplies words from the same signature later used to declare a match.
3. L5 is exactly 1.0 inside the already-answerable universe, so the coded availability gate is vacuous.
4. The frozen ladder requires an L4 relation rung, per-seed confirmation, age coverage, target reliability, and a
   stronger shadow gate; none is enforced by the current decision function.

After the required corrections below, I approve a seed-0, latest-transition shakedown with `STREAMS=6`, followed
by seed 1 only if the output is non-degenerate. Do not lower `DAMAGE_MIN` in response to the observed count.

## Blocking corrections

### 1. Make correct threatened coverage the decision variable

At present `record()` computes `cov_threatened` from `raw`, while `correct` is reported only over all answerable
facts. `decide()` then reads the raw threatened rates. This lets a lexical match, including an L3 cue-induced
match, trigger a branch even when the generated question does not recover the gold answer.

For every level, record at least:

- `U_raw_answerable`, `U_correct_answerable`;
- `U_raw_threatened`, `U_correct_threatened`;
- `cov_correct_threatened` and matched-target error;
- the per-age versions of those counts.

Apply the frozen branch rules to `cov_correct_threatened`, not raw coverage. Raw coverage remains a useful matcher
diagnostic. For an oracle per-fact generation rung, preserve `target_qid` in each generated candidate and only let
that candidate recover its prompted target; do not remap it to whichever old question has the highest Jaccard.

Also restore the parts of the frozen fixed-family gate that are currently absent: L1 must improve by at least
0.20 in **each** seed, have no supported age bin with a hole, and have target error at most 0.10. A mean across
seeds cannot substitute for the per-seed requirement. Seed 0 should print `shakedown_only`, and no final branch
decision should be emitted until two seeds exist.

### 2. Replace the confounded L3 and restore L4

The current L3 is not safe for the branch decision. `_topic_words()` is derived from `_sig(gold_question)`, and
`surfaced()` declares success using Jaccard against that same signature. A model can echo cue words without
recovering the relation or proposition. Correct-answer filtering reduces this failure, but it does not make the
raw matcher interpretable.

Use the originally frozen ladder:

- `L2_oracle_domain`: the coarse `src` label only. In this census that is a genuinely broad three-way label
  (`news_gen`, `squad_human`, or `wiki_gen`).
- `L3_oracle_entity`: subject/entity only, with answers, aliases, dates, and numbers redacted.
- `L4_oracle_relation`: entity plus relation/question type, still answer-redacted.
- `L5_full_question`: the held-out paraphrased question.

For L3, require the candidate to add relation-bearing content absent from the entity cue, and require the frozen
pre-write model's answer to equal gold. For L4, target provenance plus correct answering should be primary, with a
small manual audit of every apparent hit in the shakedown. If a reliable entity-only manifest cannot be produced
without leaking most of the question, retain the current topic-word rung only as an explicitly confounded
`L4_like` diagnostic and forbid it from yielding `search_warranted`.

Do not replace L5 with an almost-complete question. That would remove the true closed-book answerability ceiling.
L4 is the proper place for the nearly complete, answer-redacted cue.

### 3. Separate global availability from the reachable-relative ceiling

`old_ans` is defined by a successful deterministic answer to `eval_question`. L5 then asks the same model the same
`eval_question` again. Therefore, whenever `old_ans` is nonempty, current L5 coverage within `old_ans` is 1.0 by
construction; it is not the global availability rate, and `L5 < 0.2` cannot diagnose anything except an empty
answerable set.

Report two quantities explicitly:

- `availability_rate = n_answerable / n_old`, using the held-out paraphrase;
- `reachable_relative_coverage(L)`, whose L5 ceiling is 1.0 by definition.

Use the former for `availability_fail` and the latter for the half-ceiling comparisons. Cache the initial L5/EM
answers instead of generating them twice.

Threat must be measured on the same evaluation surface as availability. The current code computes `avail_em` on
`eval_question` but computes all answer bits with `key="question"`. Compute pre-write, shadow, and real bits on
`eval_question`, and record the real and shadow post-write EM values there as well. Define threatened as pre-write
paraphrase-correct and either real damage at least 0.5 bits/token or a real EM 1-to-0 flip; report the two components
separately so the OR rule is auditable.

### 4. Do not let a failed shadow proxy authorize R49b

The 60-step and 400-step writes are correctly branched from the same checkpoint with aligned Python-random batch
prefixes. However, the implementation only reports a per-seed Spearman over all old items. It omits the required
top-quartile damage enrichment, pooled correlation, and neutral/new-stream checks, and `decide()` can still return
`search_warranted` when `shadow_gate_pass` is false.

Compute correlation on the answerable audit universe, use average ranks for ties, report per-seed and pooled
Spearman, and require at least 1.5x enrichment of real-damaged facts in the shadow top quartile. Also report the
60-step versus 400-step new-stream and neutral/base metrics so a malformed shadow is visible. Keep two separate
outputs:

- `addressability_result`: what cue strength reaches correct old facts;
- `shadow_proxy_result`: whether the proposed real-shadow search signal predicts realized damage.

`search_warranted` for the specific R49b real-shadow decoder requires both to pass. A useful cue ladder plus a
failed shadow instead warrants repairing or replacing the threat proxy, not launching contrastive decoding.

## Answers to the five review questions

1. **Power:** use `(c)+(a)`, but with an important division. Answerable coverage is the stable primary descriptive
   curve; correct threatened coverage remains the branch-decision statistic because R49b is supposed to target
   imminent interference. Use six streams first. If either seed has fewer than 20 threatened facts, report Wilson
   intervals/paired fact-bootstrap intervals and return `underpowered`, not a binary branch. Keep 0.5 bits/token
   frozen; optional 0.25 and 1.0 thresholds may be labeled sensitivity analyses only.
2. **L5:** keep the full held-out question. Express its ceiling as 1.0 relative to reachable facts and separately
   report global availability. Add L4 rather than weakening L5.
3. **Matcher:** yes, current L3 is circular. Restore entity-only L3, retain target provenance, require newly supplied
   relation evidence plus the correct gold answer, and manually audit shakedown hits. Do not make a branch decision
   from cue-overlapping raw Jaccard.
4. **Compute:** `n_cands` is insufficient because it is successful parse yield, not work performed. Record attempted
   continuations, input prompt tokens, generated tokens, answer-evaluation tokens, and model-token evaluations.
   Exact hardware FLOPs are unnecessary for R49a, but token-evaluation accounting is required. Make L0 and L1
   exactly 400 attempts by distributing the remainder rather than running 400 versus 396. Label L3/L4 as
   `O(answerable facts)` oracle audits.
5. **Transitions:** the latest transition is sufficient for the seed-0 shakedown and already permits age-stratified
   slices across all prior streams. Add per-age denominators and correct coverage now. If a two-seed result passes
   but an age bin is empty, tiny, or anomalous, add the penultimate transition before committing to R49b; do not
   pay for all transitions before the ladder is shown to be non-degenerate.

## Approved launch sequence after correction

1. Run a cheap CPU/import/one-batch preflight and verify the output schema and exact prompt-attempt ledgers.
2. Run seed 0 at the latest transition with six streams. Stop if availability is weak, threatened `n < 20`, the
   matcher audit fails, or the curve is flat until L5.
3. Freeze all thresholds and prompts, then run seed 1. Require the applicable rule in both seeds and report
   uncertainty rather than relying only on the mean.
4. Build R49b only if correct cue reachability and the shadow proxy both pass. R49a itself does not demonstrate
   retention: any later promotion must consolidate generated targets into weights, delete cues/shadows/pools, and
   improve closed-book paraphrase retention over the bare floor under a compute-matched control.

This keeps the experiment aligned with the project objective. Oracle historical information remains sealed in the
auditor, inference remains memory-free, and no full-history joint retraining is introduced. The result can justify
a weights-only self-replay mechanism, but it cannot yet justify model growth; growth remains off until addressing
works and then saturates under a fixed or sublinear lifetime-compute budget.
