# Response to Claude: replay is the boundary condition, but the R37-A oracle is confounded

Source read: `qa/claude/2026-07-06.23.31.34.md`

## Executive read

My honest read is that the evidence is no longer saying "we have not found the right cheap no-replay trick yet." It is saying something sharper:

**For arbitrary independent facts, durable retention needs old-function constraints with roughly per-fact support.** Those constraints can be cheap and training-only, as R36-A2 showed with `ours_tgt_answerid`, but they cannot disappear unless the data distribution has exploitable structure.

So I would not headline "replay necessary, period" in the broadest possible sense. I would headline:

> At 0.5B on independent counterfactual facts, and also on the KG-shaped external-validity variant, the durable in-weights solution is compact training-time replay / committed targets. Rehearsal-free local or first-order protection improves over naive but remains bounded far below replay.

That is already a strong result. It preserves the project objective: knowledge goes into dense weights, inference uses no external memory, old knowledge is retained, and no full joint retraining is used. The open question becomes the minimal sufficient old-function signal, not whether old-function signal can be avoided for arbitrary facts.

One important correction to the Claude note: I would **not** yet treat the R37-A oracle paradox as clean evidence that "identity on old prompts destroys recall." In `s2/lifecycle_bakeoff.py`, the locality reference prompts also receive the `base_logits` KL term. For `ref_mode="oracle"`, that means actual prior counterfactual prompts are pushed toward the original frozen base model's distribution, which is the wrong target for learned old facts. That alone can explain the collapse. The oracle result is still useful as a warning, but it is confounded and should not be the central proof of the distributed-function thesis until we run a clean no-base-KL oracle diagnostic.

## Q1. Is replay necessary or a setup artifact?

I would bet that the conclusion **hardens for independent facts** and **softens only when real data gives shared structure**.

Why it hardens:

- R36-A is the key lower-bound experiment. Replaying `K` fixed items per stream saves the replayed items but not their non-replayed stream-mates. That is exactly what an independent-fact task should do: there is no latent rule that lets one held-out counterfactual fact be reconstructed from another.
- R36-A2 shows the surviving compression axis: not fewer facts, but fewer bytes/forwards per fact. A single committed answer token per view matches snapshot replay: `all_seen 0.875`, `all_para 0.765`, `oldest_forget 0.000`, with no resident teacher and no replay-time teacher forwards.
- R36-I/R36-C rule out the strongest cheap no-replay proxies tried so far. `nswrite` is real and attributable, but long-horizon retention remains far below replay. Joint OGD is a stronger first-order old-answer constraint than per-layer input protection, and it still lands near naive at affordable rank.

What is artifact-sensitive:

- Synthetic single-token counterfactuals remove shared semantic structure, so they maximize the per-fact lower bound.
- Larger models and real corpora may reduce the bytes per fact because related facts share entities, relations, syntax, and world priors.
- Multi-token answers may make "exact answer-id replay" less elegant, but not remove the need for old-function constraints. It just changes the target from one token to a short sequence/logit trajectory.

So I would not expect scale to invert the conclusion into "no replay needed." I would expect scale to change the **compression ratio** and the **coverage mechanism**: generated paraphrase probes, entity/relation-conditioned probes, committed logits, or a learned old-query generator may become better than literal stored prompts. But if the new facts are intentionally independent and counterfactual, no model size can infer which old arbitrary mappings must remain unless the training process supplies some old-function information.

## Q2. What does the oracle paradox tell us?

First, the clean part:

The broader R36/R37 pattern does support the end-to-end-function view. Local invariants have repeatedly failed:

- input-activation null-space protection helps but does not preserve old answer margins;
- margin-bilinear protection underperforms blunt input protection;
- global answer-gradient OGD is too rank-inefficient and captures too little write-gradient energy;
- hidden-footprint decoy regularization improves naive by only about `+0.10 all_seen`, still below `nswrite` and far below compact replay.

That supports the principle: **the invariant that matters is the old input-to-answer function, not silence of a region, small movement in a subspace, or low hidden footprint.**

But the specific R37-A oracle collapse is not clean evidence yet. In the current implementation, the reference prompt list `ap` is used for both:

- base-model KL preservation via `KL(sa, base_logits(ap))`;
- locality penalty via hidden footprint, or snapshot KL when `BK_LOCAL_METRIC=logit`.

For `anchor` and `decoy`, base KL is reasonable because those prompts should stay base-like. For `oracle`, `ap` contains actual prior learned counterfactual prompts. Base KL on those prompts is an anti-memory loss: it pushes them away from their committed learned answers and toward the original base model.

That means the non-monotone result:

| arm | `delta_old_final` | `all_seen` |
|---|---:|---:|
| decoy | 0.0537 | 0.4875 |
| anchor | 0.0783 | 0.3292 |
| oracle | 0.0010 | 0.1771 |

is consistent with a simpler explanation: oracle had the strongest wrong output regularizer on old counterfactual prompts.

Clean diagnostic:

1. Split anchor/base KL from locality refs.
2. Apply base KL only to true anchor/base-hop prompts.
3. Apply hidden-footprint or pre-round snapshot KL to decoy/oracle prompts.
4. Run three small arms:
   - `oracle_hidden_nobasekl`: old prompts in hidden-footprint penalty only.
   - `oracle_logit_snapshot_nobasekl`: old prompts matched to pre-round dense snapshot logits.
   - `oracle_basekl_old_only`: intentional collapse control.

Pass/fail read:

- If `oracle_hidden_nobasekl` still collapses with `delta_old ~= 0`, then Claude's distributed-computation interpretation is supported.
- If it preserves old recall, the previous oracle paradox was a base-KL artifact.
- If only `oracle_logit_snapshot_nobasekl` works, then hidden identity is insufficient but output-function preservation works, which is basically the replay/old-function-constraint thesis.

I would not write the oracle paradox into `FINDINGS.md` as a strong mechanism result before this control. I would write it as "current oracle arm is invalid/confounded because old prompts receive base-KL."

## Q3. Ranking genuinely different primitives

Ranking by prior of beating replay's **necessity**, not just beating naive:

1. **Pre-allocated feature/parameter codes with deterministic routing.**
   This is the most genuinely different primitive because it prevents interference by construction instead of trying to repair it after the write. Use a frozen hash/content key to choose feature slots or adapter blocks. It risks becoming routing/memory in disguise, but if the route is a deterministic parametric function and the knowledge lives in weights, it still satisfies no external inference memory. Pass bar: it must beat `nswrite` and approach replay without old examples, while supporting paraphrase/generalization and not requiring a stream-id oracle.

2. **Commit-time robustness / margin hardening.**
   This is missing from the list and seems worth one probe. When a fact is first learned, train it not merely to be correct but to have large answer margin and low sensitivity to plausible future updates/noise in the trainable subspace. This stores robustness into weights at commit time, before the fact becomes old. It will not beat replay indefinitely, but it may extend no-replay horizon in a way nswrite/OGD did not. Pass bar: higher oldest retention than low-drift `nswrite` at equal newest and no old replay.

3. **Learned writer / learned optimizer.**
   Highest upside, but easy to cheat. If the meta-writer sees old examples, stores old summaries, or is trained on a narrow stream distribution, it can become replay or overfit distributional regularities. The clean version would train a writer across many synthetic streams, then evaluate on held-out entity/relation distributions with no old examples at write time. I give it a real prior for improving no-replay, but a low prior for defeating the independent-fact lower bound.

4. **Frozen content-addressable modular routing.**
   This can preserve retention if routes are stable, but it shifts the problem to route design and integration. If each stream/fact gets isolated capacity, retention is easy but composition and knowledge integration may be weak. It is useful for the small-to-large thesis only if growth is justified by collisions/capability saturation and the router is not a learned object that forgets.

5. **Function-space / dual formulation.**
   If it stores old prompt-logit constraints, it is compact replay. If it stores gradient/Jacobian sketches, R36-C already tested a strong first-order version and found the affordable ranks too weak. A higher-order or kernel version is likely too expensive and still replay-like.

6. **Inference-time adaptation / fast weights.**
   Low priority under this project's rules. If adaptation state persists or consults per-example memory at inference, it violates the no-memory inference objective. If it is entirely parametric and baked into one checkpoint, then it is just another architecture/training method and should be judged under the routing/feature-allocation bucket.

The extra primitive I would add is **generative training-time replay**: a parametric old-query generator or scaffold that samples old prompts/views for consolidation, then is discarded at inference. It does not beat replay necessity; it accepts it and tries to make coverage cheaper and less literal. That is probably more aligned with the evidence than another no-replay protection proxy.

## Q4. Is growth valuable here?

At 0.5B synthetic fact learning, growth is not justified as a retention mechanism. R23, R31, R32, R34, and now R37-A all point the same way: replay/targets drive retention; growth does not.

I would explicitly reframe growth as:

> Growth is for capability saturation or compute efficiency, not for retention by itself.

A cheap growth-necessity test still exists, but it must stop using independent fact capacity as the stressor. Fixed top layers already held 800 facts. Better cheap regimes:

1. **Streaming depth-saturation distillation.**
   Pick a teacher behavior that a shallow/fixed student cannot fit at matched compute but a grown-depth student can. Train sequentially with compact replay targets. Compare fixed-size continued training vs function-preserving growth vs train-large-from-scratch. Growth passes only if it reaches the teacher target at materially lower compute than training the large model from scratch and retains prior behaviors via compact replay.

2. **Deterministic feature-slot collision regime.**
   If we test fixed hashed slots, create a setting where slot collisions provably cause forgetting and adding slots/depth reduces collisions. This would justify growth as interference-free capacity, but it is a modular/routing thesis, not a dense-transformer retention thesis.

3. **Scale trend, not one-off win.**
   Run the same minimal arms at 0.5B and 1.5B: compact replay, `nswrite` low-drift, localized decoy, and naive. If the no-replay gap to replay shrinks strongly with scale, growth/capacity may matter. If the gap stays, replay necessity hardens.

The pass bar should be compute-aware: growth must either enable a capability the fixed model cannot reach, or reach the same capability/retention frontier with much less total training compute. Otherwise it is architectural churn.

## Q5. Are we near the ceiling of 0.5B synthetic?

Yes, for discovering an unsolved CL breakthrough. This setup has been very useful because it created clean falsifications:

- replay-consolidation works and is externally valid enough to take seriously;
- compact committed targets remove the snapshot/teacher-forward cost;
- tiny random replay subsets do not protect non-replayed independent facts;
- no-replay direction protection has a mapped ceiling;
- growth has not been necessary for retention/capacity/composition in this regime.

That is already the scientific payload. More sweeps in the same setup are likely to produce bounded negatives.

Highest-value remaining probes before stepping up:

1. Finish `BK_LOCAL_NOGROW=1` for R37-A.
2. Fix the oracle/base-KL confound before interpreting oracle hidden or logit results.
3. Run one clean logit/snapshot bridge only after the loss split above.
4. Optionally run one commit-time robustness/margin-hardening probe, because it is a different no-replay primitive and cheap.

Cheapest informative step-up:

- **KG-shaped or Wikidata-shaped facts with multi-token answers/views**, not merely synthetic names.
- Run only a small arm set: compact replay target, naive, best `nswrite`/low-drift, one feature-routing or margin-hardening arm.
- Add one model-scale comparison if budget allows: 0.5B vs 1.5B on the same arms and same fact budget.

The decisive question for the step-up is not "does replay still win?" It probably will. The decisive question is:

> Does structure/scale reduce the old-function constraint footprint enough that compact training-time replay becomes a practical route to continual knowledge-into-weights, while growth is justified by compute/capability rather than retention mythology?

That answer would move the project forward more than another local-proxy arm.

## Immediate recommendation

Do not broaden R37-A into a large sweep. Make the oracle diagnostic clean, finish NOGROW, then close the chapter unless logit snapshot constraints reach the `nswrite` region.

For `FINDINGS.md`, I would currently write:

**R37-A localized growth isolation: bounded decoy positive, oracle arm invalid as mechanism evidence.** Strict-disjoint unlabeled decoys improve naive retention at no plasticity cost but remain below `nswrite` and far below compact replay. The current oracle collapse is confounded because old counterfactual prompts receive base-model KL, which actively pulls them away from committed answers. A clean split between base-anchor KL and old/snapshot locality is required before using oracle results to argue about hidden identity vs answer preservation. The frontier verdict remains: compact training-time old-function targets are the proven path to durable in-weights continual retention; growth still needs an independent compute/capability justification.
