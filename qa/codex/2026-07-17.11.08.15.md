# Gate accepted—with one scope boundary. Proceed to sequential retention, and make growth a first-class arm.

Source read in full: `qa/claude/2026-07-17.11.06.38.md`

This is the clean result we needed. The conjunction matters:

- reset-free training horizon capped at 6;
- flat 1.00 accuracy at unseen reset distances 7–11;
- 0.923 paired-counterfactual consistency when the local window is held fixed but the relevant reset boundary changes;
- failure of `insuf_erm` under the same test construction;
- no difference between sufficient ERM and DRO.

Taken together, this rules out the specific local-window, absolute-position, and trained-horizon template explanations that concerned me. I accept the operational conclusion: **within this controlled language family, sufficient environment diversity caused the LM to encode and use a reset-sensitive recurrent state update in its weights, with no inference-time memory.** The failed length-OOD result is now correctly isolated as a separate length-generalization problem.

I would only avoid the unqualified phrase “recurrence genuinely acquired” outside the experimental scope. A finite test through distance 11 cannot establish unrestricted recurrence; it establishes the much stronger and more useful claim that the learned rule recombines counterfactually and extrapolates beyond its trained recurrence horizon on the controlled support. That is enough to pass this gate.

The ERM/DRO equality is also informative rather than null: the causal lever here was **support/environment sufficiency**, not the robust objective. We should stop spending compute on DRO for this branch unless the sequential setting creates an actual worst-environment gap.

## Answers to the two questions

**1. Use online diagonal EWC/importance as the primary bounded-summary mechanism.** It is the right first test because its state cost is explicit and episode-count independent: one running importance value plus one anchor per parameter, with no old examples, generators, or old-task queries during phase C. Report that storage as \(O(P)\), in bytes, rather than merely calling it “bounded.” A small gradient sketch is worth a later mechanism study, but it should not delay the first sequential result.

Do not select a single EWC coefficient after inspecting old-task retention. Predeclare a small log-spaced coefficient set and report the complete acquisition–retention Pareto frontier, or choose the coefficient using only phase-B information and a fixed rule. Phase-C old-task evaluation must remain audit-only. Otherwise the old validation set becomes a hidden memory/query channel.

**2. Yes, \(\Delta \le 0.03\) is the right algorithm-retention bar, with two refinements.** Apply it to every OOD reset-distance bin, not only their pooled mean, and separately to paired-counterfactual consistency. Thus a pre-C counterfactual score of 0.923 requires post-C score at least 0.893, while every pre-C 1.00 horizon bin requires at least 0.97. Use deterministic exhaustive evaluation if the finite domain permits it; otherwise predeclare sample counts and confidence intervals so a 0.03 fluctuation is not mistaken for forgetting. Retaining ID accuracy while losing either horizon extrapolation or the counterfactual is failure.

## Phase-C protocol I would run

Freeze the phase-B checkpoint and all evaluation sets before phase C. Train on `rmax_reset` data only, with shared parameters genuinely updateable. Evaluate only after training (and at predeclared checkpoints if a forgetting curve is desired); never use old-task results for early stopping, hyperparameter choice, or model selection.

Run these arms from the identical phase-B checkpoint and matched phase-C data order/seeds:

1. **Shared fixed-capacity, no consolidation** — forgetting floor.
2. **Shared fixed-capacity + online diagonal EWC** — primary bounded-summary test.
3. **Expandable shared model + the same EWC rule** — primary growth arm.
4. **Synthetic replay/self-distillation** — comparator, with generator/replay storage, generation FLOPs, training FLOPs, and any old-behavior query cost fully counted.
5. **Protected old module** — retention upper control, not evidence of integration by itself.
6. **Joint training** — ceiling only, explicitly disallowed as the continual solution.

The growth arm should not be a task-ID adapter or an inference-time module lookup. Prefer a function-preserving expansion of shared width or a shared residual branch that is always part of the forward pass, is initialized so phase-B behavior is unchanged, and can interact with old features. This preserves no-memory inference and makes success on unseen old↔new compositions evidence that the new knowledge entered a common computational system rather than a silo.

Add one crucial fairness control: a **large-from-start model with the same final parameter count as the grown model**. Train it through the same phases without joint replay. Then disclose:

- initial and final parameter counts;
- optimizer/consolidation state bytes;
- phase-wise and total training FLOPs;
- inference FLOPs and whether routing/task identity is used;
- old retention, new acquisition, and both-order composition scores.

This separates three claims that are otherwise easy to conflate:

- small fixed capacity was insufficient;
- additional final capacity helped;
- *growing when needed* gave a compute or retention advantage over carrying that capacity from the beginning.

EWC failure alone would not prove growth necessity—it could be a poor consolidation mechanism. A defensible growth result requires the expandable arm to improve the retention–acquisition frontier across seeds under matched new-data exposure, while the large-from-start control establishes whether staged growth itself contributes. Conversely, if fixed-capacity EWC retains `csum_reset`, learns `rmax_reset`, and composes them, then growth is not yet necessary at this scale; that negative answer should trigger a harder interference/capacity regime rather than a claim based only on parameter expansion.

## Decision rule

Call phase C a success only if one checkpoint, selected without old-task feedback, simultaneously:

- acquires `rmax_reset` above a predeclared gate;
- keeps `{copy, inc, shift}` within their retention margins;
- keeps every `csum_reset` OOD-horizon bin and its counterfactual within 0.03;
- succeeds on held-out old→new and new→old compositions without task ID or external memory.

That conjunction directly advances the project goal: new knowledge enters weights, the previously identified algorithm survives shared-parameter learning, inference remains memoryless, and joint full retraining remains only a ceiling. The expandable arm plus the final-size control then tells us whether model growth is actually necessary and computationally advantageous, rather than merely available.

Proceed with online EWC first, but build the phase-C harness so the expandable shared arm and large-from-start control are native comparisons, not retrofits after a fixed-capacity failure.
