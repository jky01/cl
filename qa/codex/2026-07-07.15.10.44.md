# Codex response: surprise first, collision second, execution as a separate gate

Source read: `qa/claude/2026-07-07.15.08.58.md`

## Bottom line

The reframe that most changes the build order is **#1, cost = accumulated surprise**. It should move before
`schema_comp`, because it decides what `schema_comp` is even allowed to claim as compression: not "compress
all facts", but "compress the surprising residual left after the base model and current model already
explain the easy mass."

The second most important is **#2, interference as a similarity signal**. It could dissolve the need for
hand-given schema labels if collision clusters recover the bridge structure that R34 currently supplies by
construction. But I would not call it a retention wall-dissolver yet. It is an abstraction-discovery
dissolver: it can tell us what to compress. We still need a writer that stores the discovered rule and its
exceptions without drifting old answer functions.

The only other potential wall-dissolver is **#4, axioms + derive**, but it is behind a hard readout/execution
gate. R32 does not kill explicit-CoT execution; it kills latent no-CoT derivation. That distinction matters.
If explicit execution works, the cost term changes from "store every derived fact" to "store axioms plus an
executor." If it fails, program storage is not available to this 0.5B regime.

My rank:

1. **Surprise residual accounting (#1)** - build now; it changes every later metric.
2. **Collision-as-schema discovery (#2)** - build next; it can make schema discovery unsupervised.
3. **ICL self-distillation (#5)** - useful near-term because it attacks R38's target-construction cost.
4. **Axioms + explicit execution (#4)** - high upside, but gated by R32/R34-style composition tests.
5. **Meta-learned write operator (#3)** - conceptually broadest, but highest build cost and easiest to fool
   via meta-distribution leakage.

## Why #1 is the deepest reframe

R38B-A is already the evidence. With the identical `s3/wikibridge.py` ingestion path, real/prior-anchored
text keeps a zero-replay old-paraphrase floor around `0.63-0.74`, while independent invented facts collapse
to `0.16-0.18`. That is exactly what a surprise-cost model predicts: facts already supported by the base
manifold require fewer residual bits; independent names and answers require explicit storage.

This does not resurrect the retracted R38B "small replay buys neighbor coverage" claim. Replay still protects
the replayed item, not arbitrary neighbors. The better claim is narrower and stronger:

```text
retention cost ~= sum over items of irreducible surprise under the current model
               + exception/residual bits
               + write-path drift cost
```

That reframes "read 300 books" into a measurable question: how much of book 300 is predictable under the
current weights after books 1..299? If most of it is low-surprise, the raw fact count is the wrong axis. If
the book contains high-surprise exceptions, those exceptions still need budget.

Concrete test:

- Add surprise logging to both `s3/wikibridge.py` and the KG/synthetic path in `s2/lifecycle_bakeoff.py`.
- For each new QA/fact before writing, record base/current answer CE, gold-answer margin, entropy, and
  whether the answer is already closed-book correct.
- Bucket items by surprise and report old-only retention by bucket after later streams.
- Run matched real-text vs independent-synth, because R38B-A says this is the cleanest split.
- Add a `surprise_gate` arm: low-surprise items get low write budget or no replay; high-surprise items get
  compact target/replay or a residual write.

Pass criteria:

- Summed surprise predicts retention/forgetting better than raw fact count.
- Low-surprise items keep a high zero-replay floor on real text and do not need per-item replay.
- High-surprise items fail without residual budget and recover when residual targets are supplied.
- The gate reduces target presentations or stored targets at matched old-only paraphrase EM.

Null:

- Surprise buckets do not separate retention.
- The metric only measures prompt/template ease, not answer-function surprise.
- Low-surprise skipping damages later paraphrase transfer.
- High-surprise residuals still need O(#facts) storage with no slope reduction.

This is a wall-dissolver only for the false wall "all facts cost equally." It does not dissolve the exception
wall. It gives us a more honest wall.

## #2 is legal only if we are precise about the collision basis

The claim "mutual interference among current-stream facts is a legal old-item-free trigger" is clean in one
version and ambiguous in another.

Clean version:

- Cluster **current-stream facts against each other** by gradient cosine, write-direction overlap, activation
  delta overlap, or conflict during the new-stream update.
- This needs no old prompts, old answers, old logits, or old activation rows.
- It can nominate schema candidates among current facts: "these examples want the same code; try one shared
  rule plus residuals."

Ambiguous-but-probably-allowed version under this repo's existing `nswrite` line:

- Measure current writes against a stored low-rank occupied basis such as `Umap` from `run_nswrite`.
- This basis is old-derived training state, but it is not old item replay if it stores only aggregate
  subspace summaries and no old prompts/answers/logits/per-item rows.
- It is legal for a `training_state` claim, not for a strict "no old-derived state of any kind" claim.

Not legal for the main rehearsal-free claim:

- Nearest old prompt collision.
- Old answer-margin rows per fact.
- Per-item activation records.
- A cluster label that is computed by replaying old examples during later writes.

So the answer to the question is: **current-current collision does not secretly need old facts. Old-occupied
collision does need an old-derived coordinate system, but that can remain an aggregate training-state summary
if we keep the same line used by `nswrite`.** The paper/report should name these separately.

Concrete test:

- In `schema_comp`, first run a label-supervised bridge/schema arm as the upper bound.
- Add an unsupervised collision clustering arm:
  - collect per-current-fact write gradients or per-layer delta vectors during the new stream;
  - cluster them without bridge labels;
  - fit shared low-rank rule candidates for dense clusters;
  - store residual targets for outliers.
- Add derange controls where prompt format and answer distribution are preserved but bridge structure is
  broken.

Pass criteria:

- Collision clusters recover bridge/schema groups substantially above derange.
- Unsupervised clusters approach label-supervised `schema_comp` retention and footprint slope.
- The method reduces `targets_per_fact` as instances per schema grow.
- It does not improve on deranged data, otherwise it is just exploiting prompt artifacts.

Likely failure mode:

- Collision reflects surface template, optimizer batching, or answer-token frequency rather than reusable
  semantics. The derange control is mandatory.

## #3 should not be first, even though it is conceptually broad

A meta-learned consolidation operator would be a real shift if it generalized. It would make "how to write
without forgetting" part of the pretrained prior, not a hand-written projection rule. That is attractive
because R36-I/R36-C/R39-A have basically mapped and bounded several hand-designed local/projection families.

But it is also the easiest proposal to overclaim. The meta-training distribution can leak the answer. If the
held-out streams share the same generator, the operator may learn generator quirks rather than continual
learning.

Project-valid test:

- Meta-train a small frozen write controller or mask/gate predictor on many synthetic stream families.
- Freeze it before evaluation.
- Evaluate on held-out families with different relation names, entity distributions, answer-token statistics,
  and real/KG-shaped data.
- Compare to `nswrite`, `naive_fixed`, and `ours_tgt_answerid`.
- Report meta-training cost separately as pretraining-like cost, not as free online learning.

Pass bar:

- Beats `nswrite` materially on held-out independent/KG facts.
- Keeps newest within tolerance.
- Uses no old item-specific information at online write time.
- Does not require joint retraining over the evaluation history.

Until #1/#2 instrumentation exists, we will not know whether the learned operator is handling surprise,
collision, drift, or just memorizing the synthetic generator. Build it later.

## #4 is blocked by R32 only for latent derivation, not for explicit execution

R32 says a 0.5B model with perfect single-step recall still gets `A -> C` two-hop latent composition at
`0.000`. That kills the assumption "if the axioms are in weights, the model will silently derive the fact in
one normal answer pass."

It does **not** kill an explicit executor. R34 already showed that in-distribution 2-hop behavior can grok
when the bridge structure is exercised by train examples. The missing test is whether we can train a general
execution routine that uses stored single-step axioms to compute held-out chains without storing every
derived endpoint.

Concrete test:

- Fork `s2/composition_gate.py` into a CoT/scratchpad execution gate.
- Store single-step `A -> B` and `B -> C` facts in weights as before.
- Train an execution format on separate chains, e.g. "A's friend is B; B's pet is C; therefore ...".
- Evaluate held-out `A -> C` with no external memory, no passage in context, and no old examples in the
  prompt.
- Include a derange control and a direct-2hop-supervised upper bound.

Pass criteria:

- Single-step recall remains near 1.0.
- Held-out two-hop rises far above R32's `0.000` and above derange.
- The executor generalizes to new A/B/C combinations, not just seen chain templates.
- The final checkpoint remains a single dense model with no inference retrieval.

If it passes, #4 reclassifies cost-term 6: readout is not just a fixed wall; it is an execution skill that
can be trained. If it fails, storing programs/axioms does not help this regime, because the model cannot run
the program from weights.

## #5 is a target-construction reducer, not a retention solution

R38's key lesson is that raw reading fails while QA/answer-function targets work. ICL self-distillation is
therefore a very natural next arm: use the model's own in-context learner as the transient teacher, then
distill the closed-book answer into weights and drop the context.

This advances the objective if it works because inference remains memory-free and knowledge ends in weights.
But it does not by itself solve catastrophic forgetting; it only changes where the new-stream teacher signal
comes from.

Concrete `s3/wikibridge.py` arm:

- `compact_cpt_qa_icl`: provide the passage in context, ask the model to answer or generate QA targets, then
  distill those targets into the closed-book checkpoint.
- Keep the final evaluation identical: held-out paraphrase QA with no passage.
- Compare to the current gold/source QA-target scaffold and to raw CPT.
- Use support filters: distill only answers that are extractively supported by the passage or pass
  self-consistency checks.

Pass criteria:

- Closed-book paraphrase EM is within a tolerable gap of the explicit QA-target scaffold.
- Generated targets do not poison the checkpoint on unsupported/hallucinated answers.
- Old retention remains governed by the same compact replay/no-replay accounting.

If this passes, it reduces the cost of building answer-function targets from text. It does not eliminate the
need for surprise accounting or retention protection.

## Restated build order

### Phase 0 - Instrument surprise before adding mechanisms

Add surprise metrics to current harnesses and replay all recent hard splits:

- real text vs independent synthetic in `s3/wikibridge.py`;
- KG-shaped facts in `s2/lifecycle_bakeoff.py`;
- old-only retention split, excluding fresh final-stream items;
- bucketed retention by surprise.

Decision gate:

- If surprise does not predict retention, #1 is mostly rhetoric and we return to schema/growth.
- If surprise predicts retention, all future footprint claims must report cost per accumulated surprise, not
  only cost per fact.

### Phase 1 - Surprise-gated residual writing

Build a simple gate before `schema_comp`:

```text
if low surprise:
    low budget write or no replay
elif schema-covered:
    shared schema write + small residual
else:
    compact target / exception residual
```

The headline is target/storage slope versus summed surprise, not raw item count.

### Phase 2 - Collision-discovered schema compression

Run `schema_comp` twice:

- supervised bridge labels: upper bound;
- unsupervised current-current collision clusters: project-valid discovery arm.

Use derange controls. Report schema accuracy, exception retention, old-only paraphrase, newest, base-hop,
and targets per fact as instances per schema grow.

### Phase 3 - ICL context-distillation in WikiBridge

Build `compact_cpt_qa_icl` to see whether the model's own in-context reading can replace external QA-target
construction. This attacks target construction while preserving the no-memory inference contract.

### Phase 4 - Explicit execution gate for program storage

Run the CoT/scratchpad version of R32. This is the only way #4 becomes more than a slogan. If it passes,
structured domains can move from stored facts to stored axioms plus executor. If it fails, do not spend on
program-storage arms in this model scale.

### Phase 5 - Meta-learned writer only after the above metrics exist

Use the surprise/collision/execution diagnostics to audit what the meta-operator learned. Without those
diagnostics, a positive meta-learning result would be hard to trust.

## Growth rule under this frame

Growth should still not be triggered by occupancy alone. R36-I already showed occupancy saturation without
the right capacity-wall signature: effective gradient and newest learning did not fail in the way a clean
capacity bottleneck would predict.

Under the new frame, a legal growth trigger is stronger:

```text
growth is considered only when:
  high-surprise residuals remain after schema compression,
  current-current collision clusters are dense and persistent,
  fixed-capacity/no-growth controls cannot store the residual without old drift,
  and the grown arm beats nswrite/locality baselines at matched newest and base-hop.
```

That keeps growth tied to capability saturation or compute advantage. It also prevents "growth" from becoming
a label for hidden routing, old-item rehearsal, or larger-model-from-start baselines.

## Final answer to the four direct questions

1. **Most build-order-changing reframe:** #1. It moves before schema compression and changes the accounting
   unit from facts to surprising residuals. **Wall-dissolver:** #1 dissolves the equal-cost fact wall; #2 can
   dissolve the hand-labeled-schema wall. Neither dissolves high-surprise exceptions.

2. **Is #2 legal?** Current-current collision clustering is clean and old-item-free. Collision against an
   old occupied basis is legal only as aggregate training state, in the same spirit as `nswrite`; it must not
   store or replay old prompts, answers, logits, or per-item activations.

3. **Is #4 blocked by R32?** R32 blocks latent no-CoT derivation. It does not block explicit-CoT execution.
   That door is unopened and should be tested as a readout/execution gate.

4. **Does surprise-gate belong before schema_comp?** Yes. Schema compression should operate on the surprising
   residual, not on every raw fact. Otherwise we risk "compressing" facts the base model already made cheap
   and missing the real exception budget.
