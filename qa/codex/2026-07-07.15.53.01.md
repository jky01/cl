## Interpretation constraints

Do not overclaim the current surprise summary. The code now reports surprise terciles, correlation,
retained-per-surprise-bit, and the important `excl_already_correct` variant. That is enough for the smoke.
However, it does not yet directly test "better than raw age/fact-count" inside the script. If the surprise
signal looks alive, the scaled run or offline sidecar analysis should compare:

- retention as a function of `surprise_bits`;
- retention as a function of stream age;
- retention with both predictors together, preferably with the already-correct facts excluded.

The KG base-recall screen is also part of validity. If frozen-base recall is above the intended low baseline
(the script prints `OK <=0.15`), then surprise and retention can be contaminated by facts the base already
knew. In that case, emphasize the exclude-already-correct analysis and do not treat full-pool numbers as
write-difficulty evidence.

## Pass/fail gates for the running smoke

The useful first readout is not "which arm won overall"; it is whether each mechanism answers a research
question tied to the project goal.

1. Surprise gate:
   - Pass only if higher base surprise predicts lower final paraphrase retention in a monotonic or near
     monotonic way, especially after excluding already-correct facts.
   - The signal should be stronger than a trivial age effect before it becomes a planning variable.
   - If buckets are flat or dominated by already-correct facts, retire surprise as a cost-unit for now.

2. Merge baseline gate:
   - `merge_ties > loramerge` means sequential LoRA merge was an unfairly weak merge baseline.
   - It does not make merge a frontier method by itself.
   - To become a live branch, `merge_ties` needs old-paraphrase retention at least `nswrite + 0.05`, newest
     stream retention within about `0.03`, and base-hop drop no worse than `0.03`.

3. Dense-weight objective:
   - The final artifact is a single dense checkpoint with no inference memory, so the arm is aligned at
     inference time.
   - The delta bank is training/merge-time state and must remain in storage/compute accounting. The current
     `delta_store_bytes` field is the right honesty hook.

4. Growth necessity:
   - R40 does not establish growth necessity. It tests fixed-base parallel merge and compact write-cost
     diagnostics.
   - If fixed-capacity merge works surprisingly well, growth becomes less justified until saturation is
     shown.
   - If fixed-capacity merge fails while replay/compact-target consolidation retains, that supports the
     existing direction: knowledge must be consolidated into weights, with growth considered only when
     capacity or compute limits are demonstrated.

## Likely failure modes to watch

- Merge improves `loramerge` but still trails `nswrite`: treat it as a corrected baseline, not a new main
  direction.
- `merge_sum` looks good only by boosting newest facts while old paraphrase retention collapses: reject it.
- TIES protects old facts but damages base-hop: reject or require a base-capability penalty before scaling.
- Surprise correlation is driven by base-already-correct examples: use the exclude-already-correct metrics as
  the main signal.
- Scaffold answer recall is weak for one or more streams: arm comparisons become teacher-quality limited,
  so do not infer much from merge failure.
- VRAM fails because base, scratch, and fresh PEFT are resident together: switch the base reference to CPU or
  reset scratch from CPU state dicts. This is an engineering issue, not a conceptual result.
