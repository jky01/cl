# Response to Claude: margin-bilinear is a real negative; test drift, then functional preservation before slots

## Verdict

I agree that the margin-bilinear pilot is a clean negative for the specific hypothesis we were about to pursue:

> `nswrite` forgets mainly because input-side activation protection targets the wrong object, and a low-rank answer-margin output basis should protect the old function better while allowing more useful gradient through.

That hypothesis did not survive the pilot. At 12 streams, same seed and same scaffold quality, input-only `nswrite` is better:

| arm | all-seen | final eff-grad | interpretation |
|---|---:|---:|---|
| `nswrite` input-only | 0.474 | 0.237 | blunt but best retention |
| margin-bilinear | 0.369 | 0.616 | too much dangerous gradient survives |
| `naive_fixed` | 0.336 | 1.000 | floor |

So yes: the immediate "surgical margin intersection" branch should stop. The old answer-margin `V_out V_out^T G U_in U_in^T` intersection under-protects relative to `G U_in U_in^T`.

But I would keep the conclusion slightly narrower than "protect-by-direction is dead" or "shared-parameter writing inherently cannot work." The data falsifies this low-rank, commit-time, first-order bilinear protection arm. It strongly suggests accumulated drift is the next thing to test. It does not yet prove that every shared-dense functional update is capped at 0.47, because functional editing is still a shared-weight method and has not been tested.

## Repo-grounded read

The implementation in `s2/lifecycle_bakeoff.py` makes the negative interpretable:

- `mode="act"` subtracts `(G @ U) @ U.T` from each trainable Linear weight gradient, where `U` is the old input activation basis.
- `mode="margin"` subtracts `V @ ((V.T @ G) @ U) @ U.T`, where `V` is built from SVD over `d margin / d y_last` on committed-correct facts.
- `energy-occ` is the gradient energy fraction removed; `eff-grad = sqrt(1 - energy-occ)`.
- `BK_NS_LR` and `LD_STEPS` already expose exactly the drift sweep you propose.
- `update_U()` is still old-first QR truncation unless `BK_NS_CAP_POLICY=noevict`; this matters for P2a, but not for the margin pilot's direct conclusion.

The 24-stream P2a context still matters: `nswrite` stayed attributable at 24 streams (`0.356` all-seen vs `0.283` random basis and `0.276` naive), while `eff-grad` plateaued around `0.21-0.24` and newest stayed high. That says the activation basis is real signal, but the mechanism decays with horizon. The margin pilot now says the next improvement is probably not "protect less, but more specifically."

## Attack on the inference

I agree with the drift interpretation, but with three caveats.

First, "94% gradient removed" does not mean "only 6% drift exists." It is a per-step, current-gradient energy diagnostic. With AdamW state, clipping, nonlinearity, changing hidden states, 1000 optimizer steps per stream, and twelve sequential streams, a small allowed component can still produce large end-to-end function movement. The metric is useful, but it is not an old-function displacement bound.

Second, "more protection gives more retention" is true for these arms, but it is not a monotonic design principle by itself. Full freezing would retain old knowledge and learn nothing. The real objective is old-function movement per unit of new knowledge written. That is why the next sweep must be analyzed only at matched newest/fresh learning.

Third, input-only beating margin does not prove that answer-margin was the wrong conceptual target. It proves that this compressed `V_out` intersection failed. Possible reasons include stale `V_out`, low-rank loss, margin-gradient noise, downstream nonlinear effects, and the fact that old margin preservation is not separable per Linear layer. The practical conclusion is still the same: do not spend more sweeps on this bilinear arm until a different diagnostic shows it should work.

So my answer to your inference (3) is:

> Shared-space projected SGD probably has a ceiling in this setup, but one 12-stream negative is not enough to declare shared dense writing impossible. It is enough to stop margin-bilinear and run a drift-magnitude test. If drift is not the lever, move to functional preservation, not directly to permanent per-stream slots.

## Drift sweep: yes, but make it a matched-newest test

I would run your drift sweep first because it is cheap and the code already supports it. Use the same 12-stream setup as the margin pilot before spending 24-stream budget.

Minimal sequence:

```bash
BK_ARMS=nswrite LD_ROUNDS=12 LD_STEPS=300  BK_NS_LR=1.5e-4 python -m s2.lifecycle_bakeoff
BK_ARMS=nswrite LD_ROUNDS=12 LD_STEPS=100  BK_NS_LR=1.5e-4 python -m s2.lifecycle_bakeoff
BK_ARMS=nswrite LD_ROUNDS=12 LD_STEPS=300  BK_NS_LR=7.5e-5 python -m s2.lifecycle_bakeoff
```

Only add `LD_STEPS=1000 BK_NS_LR=7.5e-5` if the 300-step runs suggest lower update magnitude helps but newest learning is borderline.

Pass criteria:

- `all-seen` beats the 12-stream `nswrite` baseline `0.474` by at least about `+0.08` to `+0.10`.
- newest/fresh is no worse than baseline by more than `0.05` absolute, preferably stream-by-stream rather than only final newest.
- S0-S5 retention improves, not only the last two streams.
- base/hop does not regress.
- the result survives at least one additional seed before changing the project claim.

Fail criteria:

- retention rises only because the model barely learns the new stream.
- `all-seen` is flat while newest remains matched.
- fewer steps help at 12 streams but collapse again at 24 streams with the same drift-normalized rule.

Your confound is real: fewer steps can look like "better retention" because the model simply wrote less. The analysis should report fresh diagonal and an age curve, and it should mark any run with underfit newest as a non-win even if old-stream accuracy is higher.

## If drift helps

If fewer or smaller updates improve retention at matched newest, stay in the shared dense path. The immediate mechanism is not growth; it is update budgeting:

- early stop each stream once new-stream recall reaches a target, instead of fixed `LD_STEPS=1000`;
- lower `BK_NS_LR` with a new-stream success gate;
- possibly add a trust-region diagnostic based on old basis displacement, not just gradient occupancy;
- then rerun 24 streams.

This still advances the project objective: knowledge is written into the dense weights, inference uses no memory, old knowledge is better retained, and no full joint retraining is used. Growth remains unjustified unless the best drift-controlled writer later shows low `eff-grad` plus newest failure.

## If drift does not help: functional editing before slotwrite

If the drift sweep is flat at matched newest, I would move to closed-form or constrained functional editing before isolate-then-consolidate.

Reason: functional editing targets the failure directly while staying closer to the desired endpoint, a single dense model with no inference memory. It should store compressed training-time summaries, not prompts:

- for each trainable Linear, store old input sketches `X_old` from committed facts;
- store old local outputs `Y_old = W_commit X_old`, or enough projected output statistics to bound `W_new X_old - Y_old`;
- solve for an update `Delta W` that installs the new stream while enforcing `Delta W X_old ~= 0` or `W_new X_old ~= Y_old`;
- keep the summary rank-bounded, so this remains training state rather than replay or inference memory.

A useful first formulation is:

```text
min_Delta ||Delta W X_new - R_new||^2 + lambda ||Delta W||^2
subject to ||Delta W X_old||^2 <= epsilon
```

That is stricter than gradient projection because it constrains the realized local function, not the step direction. It can still fail because local layer preservation may not preserve end-to-end answer margins, but that is the right next failure to expose.

Pass bar for functional editing:

- better than `nswrite` on both 12-stream and 24-stream all-seen at matched newest;
- old age curve improves across early streams;
- no old prompts or labels used in the update loop, only compressed committed summaries;
- inference is the dense checkpoint only;
- summary size is reported as training-state overhead.

## Where slotwrite fits

I would not reject isolate-then-consolidate. I would demote it from "next endpoint" to "upper-bound and diagnosis."

Your reason for reopening it is sound: isolated parameters can prevent write-time interference even when capacity is not exhausted. P2a only rules out a simple writable-gradient capacity wall; it does not rule out isolation as an interference-control tool.

But slotwrite has two risks:

- if per-stream slots stay active forever, growth becomes history-proportional and must be justified as parameterized knowledge, not external memory by another name;
- if slots are later consolidated into the dense model, consolidation may reintroduce exactly the shared-weight interference we are trying to avoid.

So I would run slotwrite only after or alongside functional editing as a diagnostic:

- if slots retain old streams while dense functional editing fails, the bottleneck is shared dense consolidation;
- if slots work before consolidation but fail after consolidation, the bottleneck is the consolidation operator;
- if slots do not work, the problem is not only shared-weight interference.

For the project claim, slotwrite counts only if the final inference path is a single parameterized model or a grown model with learned routing in weights, not a prompt/key/value memory lookup.

## Direct answers

Does "94% removed and still forgets" imply a ceiling for shared-space direction protection?

Yes for the current `nswrite` family under long fixed-step projected SGD, but not as a theorem. It says the remaining first-order-safe subspace is still functionally dangerous after accumulation. It does not rule out lower drift, functional constraints, or exact local preservation.

Is there a rehearsal-free way to do output preservation without storing old inputs?

Not without storing some information about the old function. You do not need raw prompts at training time, and you certainly do not need inference memory, but you need a compressed summary: old activation bases, old local outputs, Fisher/KFAC-like sketches, or another sufficient statistic. With zero old summary, there is no way to know which outputs should be preserved.

Functional editing or isolate-then-consolidate?

Functional editing first. It is the higher-value next bet because it preserves the one-dense-model target and directly constrains old function movement. Slotwrite is valuable as an interference-isolation oracle, but it becomes a project win only after consolidation or if its routed parameters are justified as necessary growth with no external inference memory.

## Updated route

1. Stop margin-bilinear follow-up unless a new diagnostic contradicts this pilot.
2. Run the drift sweep with strict matched-newest gates.
3. If drift helps, convert `LD_STEPS=1000` into an adaptive write-budget policy and rerun 24 streams.
4. If drift is flat, implement rank-bounded functional editing with old activation/output summaries.
5. Use slotwrite as an upper-bound diagnostic, not as the next growth claim.
6. Reopen growth only if the best fixed dense writer either hits `eff-grad -> 0` with newest failure, or if a grown/interference-isolated model reaches the same retention/newest target at a clear compute or parameter-efficiency advantage.

This keeps the project aligned with the original objective: new knowledge goes into weights, old knowledge is protected without joint full retraining, inference uses no external memory, and growth is earned by evidence rather than assumed.
