# Ruling: run 1.5B now; keep fixed-budget generation primary, but do not trust the coded verdict yet

Source read: `qa/claude/2026-07-10.19.07.26.md`

## Decision

**Approve the current 0.5B→1.5B run as the cheap scale scout. Do not stop it to make 3B fit.** A same-family
3x parameter step is large enough to answer the immediate portfolio question: is the 0.5B history-free
self-addressing null already beginning to move with native model scale? It is not, however, a substitute for the
original 3B confirmation and it cannot establish that a trained 0.5B model can grow into the useful larger state.

Use the 1.5B result to trigger 3B as follows:

- **Confirm at 3B** if the intersection gain is in the same direction in both seeds and is either the frozen
  `+0.15` absolute effect or a credible large relative lift from the near-zero floor, while the token-normalized
  result also favors 1.5B. Do not use “ANY upward trend” literally: one additional recovered fact in a small
  denominator is not a scale signal.
- **Do not invest in 3B immediately** if 1.5B is flat in both seeds with adequate joint-answerable and
  joint-threatened denominators. That is a valid portfolio stop for this branch, but the scientific conclusion
  must remain “no scale effect through 1.5B under this protocol,” not “3B would also fail.” Threshold behavior
  between 1.5B and 3B remains possible.
- **Do not interpret an underpowered or acquisition-limited run as flat.** If either shared threatened set is
  small, or one size learns too few joint-hard facts, repair the population/power problem rather than escalating
  model size.

This is useful for the project objective only as a diagnosis. Both models acquire knowledge into weights and the
audit is checkpoint-only at inference, with no retrieval memory or task ID. But native 1.5B superiority would not
yet demonstrate continual retention, growth necessity, or compute advantage; it would justify testing the
self-addressing mechanism across scale and later across function-preserving growth. The sequential acquisition
also avoids joint full-data retraining, which keeps the scout aligned with the main constraint.

## Generation-budget ruling

**Keep the fixed absolute budget as the primary causal comparison; do not add a proportional-budget rerun before
reading this scout.** On the shared answerable/threatened intersection at one fixed horizon, both sizes have the
same eligible denominator, so proportional-to-intersection size would be the same experiment up to a constant.
Fixed attempts are the stricter test because 1.5B cannot win by receiving more search opportunities.

Add proportional budget as a second report when comparing different horizons or the per-size full populations,
where eligible `N` changes and fixed sampling can create mechanically vanishing coverage. It should remain a
search-scaling diagnostic, not replace the fixed-budget headline. Report at least:

1. fixed-budget intersection coverage;
2. unique correct intersection propositions per 1,000 generated tokens;
3. per-size full-population coverage as a practical-capability result;
4. generation and acquisition FLOPs/wall time, because a native larger model can gain capability while losing
   compute efficiency.

## Important implementation corrections before accepting a pass

The run can continue, but `s3/scale_scout.py` does **not** currently implement the stated pass contract. Read the
raw JSON and correct these before publishing a binary result:

1. `decide()` computes `deltas_thr` but never uses it for a pass. Lines 139–145 gate on answerable-intersection
   deltas only. An adequately powered threatened-set result can therefore fail while the script prints
   `scale_sensitive`.
2. An `underpowered_threatened` verdict can be overwritten by `scale_sensitive`; line 140 reads the nonexistent
   `verdict_pre` key rather than preserving the verdict set at line 138.
3. The promised “still after token normalization” condition is absent from `decide()`. Moreover,
   `correct_per_1k_tokens` uses correct facts from each model's full answerable population, not the shared
   intersection, so it cannot validate the causal intersection gain.
4. The documented `4x` alternative is not implemented. A relative rule also needs an explicit zero-floor
   convention; otherwise division by zero or a one-hit result can masquerade as a large multiplier.
5. `surfaced_global()` returns raw and correct matches, but `run_size()` discards the raw sets. Consequently the
   scout cannot report the preregistered proposition-target error or enforce its ceiling.
6. `GEN_N=400` is passed separately to L0 and L1, so the implementation spends **800 attempts per model**, not
   400 total across the two history-free levels. This is still matched across sizes and therefore not fatal, but
   the report must say “400 per rung / 800 combined.” If 400 was intended as the total search budget, split it
   between the rungs in the later corrected run.

For this already-running scout, the minimum defensible manual decision is: require the frozen effect on the
shared answerable intersection in both seeds; require the same-direction threatened result when powered; compute
intersection-specific correct propositions per 1,000 generated tokens; and refuse a binary claim if threatened
power is inadequate. A subsequent corrected 3B confirmation should enforce all of those conditions in code.

## If 3B is triggered

Do not change only the 3B optimizer to make it fit without treating that as an acquisition confound. First remove
avoidable residency: historical acquisition can update its working model in place; the final threat write can be
scheduled destructively after caching the pre-write generation/readouts; neutral-anchor teacher logits can be
precomputed; and the unused frozen size can be moved off GPU. Add gradient checkpointing next. If 8-bit Adam is
still necessary, rerun the relevant 0.5B/3B comparison with the same optimizer and verify matched acquisition and
base-capability gates. Otherwise an apparent scale effect could be an optimizer effect.

So the operational ruling is: **let 1.5B finish, use fixed-budget intersection coverage as primary, manually
audit the raw result rather than the current `decision` field, and reserve 3B engineering for a replicated,
nontrivial 1.5B signal.**
