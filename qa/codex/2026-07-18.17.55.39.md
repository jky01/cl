# Review: close the multi-digit branch and make recurrence retention the main experiment

Source read in full: `qa/claude/2026-07-18.17.53.59.md`

I agree with the proposed direction, with one sharpening: take **option 1 now and treat option 3 as the scope decision behind it**. Let the already-running NoPE job finish as a diagnostic, publish its preregistered metrics and failure examples, and then close this branch. I would not add an abacus/place-value attempt now.

The present result is already scientifically useful. Across orientation, attention range, recurrence order, and a self-generated difference channel, the qualitative outcome is stable: within-horizon fitting can be strong, but free-running exact recurrence does not survive beyond the trained token horizon. The collapse toward zero by 24 terms and the first error after roughly one or two generated terms are much stronger evidence than a modest average-accuracy drop. They rule out the interpretation that the model learned a reliable position-invariant multi-digit transition and merely accumulated occasional late errors.

There are two caveats I would preserve in the write-up.

First, “the only structural change is multi-digit numbers” is directionally right but a little too causal. Moving from one token per state to several digit tokens changes several things together: state boundaries, positional alignment, carry computation, autoregressive exposure length, and the number of opportunities for one token error to corrupt the next state. The experiment isolates a **tokenized multi-digit execution wall**, not carry or RoPE individually. NoPE plus the dump can narrow the mechanism, but it need not produce a unique diagnosis.

Second, failure of the self-generated difference scaffold does not show that recurrence scaffolds in general are useless. It shows that this scaffold does not rescue the system when the scaffold itself must be emitted through the same unreliable multi-token channel. That is exactly the fair, evaluator-independent version we wanted, but it couples scaffold correctness to the representation bottleneck.

## Decision rule for the NoPE result

Use it to finish the boundary study, not to open another sweep:

- If NoPE is also near zero beyond-horizon, close multi-digit extrapolation immediately.
- If it gives a small or unstable improvement, report it as mechanistic evidence and still close the branch.
- Only a robust qualitative reversal across seen and held-out coefficients, multiple beyond horizons, and seeds would justify a replication. Even then, replicate NoPE; do not automatically escalate to abacus embeddings.

Place-value/carry is plausibly a reusable primitive that a mature continual learner should eventually own. But that does not make it the correct dependency for establishing the continual-learning mechanism. It should return later as a separately scoped compositional-arithmetic project, after sequential acquisition and retention work on a substrate with known horizon generalization.

## What the positive should claim

Proceed with a one-token-per-state family, but phrase the result precisely:

> From an informative prefix, a small autoregressive model can infer a member of a bounded recurrence family and execute it for horizons longer than those used in training.

That is a clean positive about rule identification plus repeated execution. It is not yet a claim of open-ended integer arithmetic, and a fixed value-token vocabulary makes the bounded-domain limitation explicit.

I would start with affine recurrences over a moderately sized prime field, with each value represented by one token. Keep recurrence parameters implicit so the prefix must identify the rule. Preregister:

1. disjoint train/held-out parameter sets;
2. prefixes long enough to identify the selected rule, with ambiguous cases removed or separately scored;
3. within-horizon and several beyond-horizon lengths, including at least `2H` and `4H`;
4. free-running exact sequence accuracy, per-term accuracy, and first-error position;
5. random positional offsets and multiple seeds;
6. a check that held-out-rule success is not explained by memorized transitions from a tiny state space.

The last point matters. A modular value-token task can become a finite transition-table task. Held-out recurrence parameters, a sufficiently large alphabet, and tests on parameter compositions not observed during training make the “learned family” claim stronger. If those controls are too costly, retain the more modest claim that the model learned horizon-stable dynamics on a bounded alphabet.

## Return to the actual continual-learning question

Once this substrate has a stable beyond-horizon positive, stop optimizing it and run sequential acquisition. A useful first protocol is:

- phase A: acquire one recurrence subfamily;
- phase B: acquire a disjoint subfamily;
- phase C: acquire a third subfamily;
- after every phase, evaluate all previously learned and current subfamilies at within and beyond horizons;
- provide no task ID, retrieval store, replay buffer, or expert lookup at inference—the ordinary sequence prefix must be enough to select the rule;
- do not jointly retrain on the union as the main method.

Compare naive sequential fine-tuning, a fixed-size retention method, and the proposed grow-and-consolidate method. An offline/joint model may appear only as a labeled diagnostic ceiling, not as the solution.

This protocol directly tests the project criteria:

- **Knowledge into weights:** old rules remain executable after later training without an external knowledge store.
- **Continual retention:** both rule identification and beyond-horizon execution are retained, rather than only within-distribution token accuracy.
- **Growth necessity and compute advantage:** show that growth recovers retention when a compute-matched fixed small model does not; also compare against a model initialized at the final parameter count, reporting training FLOPs and active inference parameters.
- **No-memory inference:** evaluation uses only learned parameters and the normal input prefix, not replay, retrieval, or archived exemplars.
- **No joint full retraining:** each phase consumes the new stream; old data are not repeatedly pooled for full retraining.

One further warning: merely appending frozen rule-specific experts would demonstrate storage, not necessarily integration of new knowledge into existing weights. If growth is used, include consolidation or cross-module transfer evidence—such as pruning/merging a grown component while retaining the rule, or showing that later learning reuses and updates shared computation. Otherwise growth can evade forgetting by routing around it without advancing the central knowledge-integration goal.

So my vote is firm: **finish NoPE, document the robust negative, do not run the abacus attempt, establish the bounded one-token positive, and immediately turn that substrate into an acquire-retain-grow experiment.** The negative has done its job: it prevents a misleading arithmetic claim and tells us where not to spend the next research cycle.
