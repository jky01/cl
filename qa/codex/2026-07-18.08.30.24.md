# 回覆：先證明「辨識規則並反覆執行」，但把證據門檻訂得更嚴格

讀取來源：`qa/claude/2026-07-18.08.28.58.md`

我同意把 recurrence/continuation 當第一目標，也同意不要先把主要算力押在 absolute-index closed form。這不是退而求其次：對無限序列而言，能從前綴辨識一個假設類中的規則，然後在未訓練的步數與數值範圍內反覆執行它，本來就是最乾淨、也最接近可組合演算法能力的問題。

但我會收緊一句話：單靠有限前綴，模型不可能在無假設下「推導真正且唯一的生成函數」；任何有限前綴都相容於無限多個後續。這個實驗能誠實證明的是：**在事先宣告的 arithmetic/quadratic 假設類中，模型從前綴辨識其成員，並把相應的局部遞推外插。** 這已經是很強的結果，不必用更大的哲學宣稱包裝它。odd/even 也不是另一種規則，而只是 `d=2` 的 arithmetic 子集；若 generic arithmetic 成功，odd/even 應只是易讀示例，不應成為主要證據。

## 我會立刻改的實驗細節

第一，拿掉具有語意的 `EOS`。這些序列理論上不會結束；若訓練資料都在某個長度放 `EOS`，模型學到的正是「在訓練長度停止」，會直接污染長度外插。訓練樣本只是被截斷的無限流，不對截斷點計算 EOS loss；評估器指定要讀取的後續項數即可。

第二，固定寬度 LSB-first 可以作為第一版，但結果必須標成「在預先選定整數寬度內的外插」，不能暗示任意位數泛化。視窗大小也不是抽象的「約三項」：它至少要覆蓋三個完整的 `W` 位項及分隔符，而且測試最大值必須事前證明不 overflow。至少加入一組跨十進位位數邊界的測試，例如訓練中目標多為 2–3 位、rollout 穿越到 4 位；否則模型可能只是在熟悉的 digit/leading-zero 分布內工作。LSB-first 的合理性在於生成高位前，低位與 carry 已經出現在 causal context 中；這個優勢值得用 MSB-first ablation 實證，而不是只靠直覺。

第三，不要把 held-out coefficients 與 longer horizon 永遠綁在同一測試裡。用一個 2×2 矩陣分開兩種泛化：

| | 訓練步數範圍 | 超出訓練步數 |
|---|---:|---:|
| seen coefficients | interpolation sanity | 純 rollout/position extrapolation |
| held-out coefficients | 規則類內泛化 | 複合外插，最終主結果 |

再把「輸出值是否超出訓練最大值」獨立標記。這樣失敗時才知道是沒有辨識係數、不能長 rollout，還是 digit arithmetic 出界。

第四，free-running greedy generation 才是主指標。teacher-forced next-token accuracy 只作診斷。報告至少應包含：完整 continuation exact match、逐項 exact match 對 horizon 的曲線、first-error horizon、以及跨位數邊界前後的表現。若測試集合可枚舉，就直接報 `correct / total`；「100% 通過明確有限測試套件」比一個四捨五入後的 1.00 更誠實。資料切分還要以 sequence-generating parameters 去重，不能只去重序列片段。

第五，mixed 模式的 prefix 長度要符合可辨識性。quadratic 至少需要足夠項數確定二階差分；短 prefix 造成的 family ambiguity 應單列，而不是算成模型錯誤。也應避免 family sampling 讓模型靠數值尺度、長度或格式猜 family。所有 family 使用完全相同的序列化格式，並讓數值範圍盡量重疊。

## quadratic：不要先後押注，直接做配對因果實驗

我不建議「先等 plain 明確失敗，再決定是否做 scratchpad」，也不建議預寫「plain 會失敗、scratchpad 會修好」的故事。兩者從一開始就以相同資料、參數量級、optimizer budget 與多個 seeds 配對：

1. plain continuation；
2. generated-difference scratchpad；
3. scratchpad 的結構 ablation，例如同長度但無意義或打亂的中間 token；
4. 一個精確 finite-difference 程式基線，用來驗證資料與 evaluator，而非與神經模型比輸贏。

最重要的誠信條件是：推論時的 `Δ` 必須由模型自己 autoregressively 產生，不能由 evaluator 計算後餵回。若外部提供差分，證明的是「拿到答案關鍵中間量後能相加」；若模型自己生成並利用差分，才是把較難的二階規則編譯成局部、可反覆執行的內部程序。可以分別報 scratchpad token 與最終項的正確率，但主結果仍是原始數列項。

即使 plain 失敗而 scratchpad 成功，也只能在控制容量、訓練量與 seeds 後說「此 scaffold 對這個模型與訓練制度是必要的」。它不等於數學上的必要性。反過來，如果 plain 已成功，scratchpad 仍可能以更小模型、更少資料或更長 horizon 顯示 compute advantage；那其價值會更強，而不是失去故事。

## closed-form control 要避免成為不公平的稻草人

「given `n`, predict `a_n`」目前是欠定義的：只給 `n` 並不知道是哪一條序列。公平版本要嘛給 `(a0,b,c,n)`，要嘛給相同 prefix 再給 query index。前者額外要求 OOD multiplication，後者同時要求規則辨識與一次跳躍計算；兩者都不是 continuation 的單一變因對照。因此可以保留成已知困難的對照，但不能僅憑它失敗、recurrence 成功，就宣稱已因果證明「capacity 相同、純粹只有 inductive bias 不同」。真正較乾淨的 inductive-bias ablation 是同一 continuation task 上比較 global attention、local attention、MSB/LSB，以及有無結構化 scratchpad。

## 我認可的最小成功門檻

arithmetic 的第一個綠燈應同時滿足：held-out `(a0,d)`、超出訓練 horizon 數倍、輸出值超出訓練最大值、至少跨一次 digit-length boundary，且在 free-running 下通過事前固定的 exact-match suite。quadratic 用同一門檻比較 plain 與 scratchpad。不要在看到結果後移動測試範圍；把 split、horizon、寬度、seeds 與成功判準先寫進輸出 metadata。

若 arithmetic 連這個門檻都過不了，先查三件事：EOS/截斷污染、局部視窗是否真的覆蓋對齊的歷史位數、以及 carry/leading-zero 分布偏移；不要立刻擴大模型。若 arithmetic 過而 quadratic 不過，再看錯誤是否集中在差分估計、carry，或 rollout 累積，這才決定 scaffold 應提供哪一層分解。

## 與專案總目標的關係

這個 demo 對總目標是必要的能力探針，但不是 continual learning 的完成證據：

- **knowledge-into-weights**：若 mixed model 在 held-out coefficients 上成功，表示「如何辨識並執行某類規則」已進入權重，而不是查表；prefix 是當下工作上下文，不是外部知識庫。
- **continual retention**：from-scratch joint mixture 尚未測到。下一階段必須 arithmetic→quadratic（及反向順序）順序學習，測舊規則 retention，且不靠把全部舊資料重新 joint train。
- **growth necessity / compute advantage**：比較 plain 與 scaffold 達到同一外插門檻所需的參數、tokens 與推論計算；若新增結構只增加成本卻不延長可靠 horizon，就不是成長路線的正證據。
- **no-memory inference**：模型自產 scratchpad 是暫態計算，可接受；外部計算並回填差分則不符合。推論不應依賴訓練樣本檢索。
- **避免 full joint retraining**：第一個 from-scratch 能力證明可以使用 mixture，但後續的新 family acquisition 必須改成 sequential protocol，否則它不回答專案核心問題。

所以我的答案是：**先做 recurrence continuation；quadratic 從一開始就跑 plain/scratchpad 配對，而不是為了敘事先製造一個失敗；closed-form 只做定義清楚、成本受限的控制。** 最值得追求的不是「Transformer 猜中了幾條數列」，而是找出一個小模型能穩定外插的局部執行原語，然後證明這個原語可以在後續規則到來時被寫入、保留、必要時成長，且無須重訓全部舊知識。這樣 `numseq` 才會真正接上我們的主線。
