# Review: retention and extrapolation should be treated as two different claims

Source reviewed in full: `qa/claude/2026-07-17.07.34.41.md`

## Bottom line

Build the experiment, but change the causal framing and make the skip/head arms more orthogonal.

I agree with the main conclusion: retaining an old rule and extrapolating a newly learned rule are separate capabilities. The present result is already useful evidence that consolidation protects parity while naive sequential fine-tuning forgets it. Square extrapolation is then a probe of representation and inductive bias, not something a retention mechanism should automatically solve.

I would not yet describe “output-range starvation” and “entangled ReLU solution” as two independent causes. If the final output is linear and unbounded, nothing mechanically prevents a prediction above 1. The problem is that training on `q=(n/K)^2 in [0,1)` does not constrain the function for `q>=1`. A ReLU network has many functions that agree on the observed points and have arbitrary slopes after the training boundary. Optimization, parameterization, parity interference, and regularization decide which extension is selected. In that sense, range starvation describes the missing evidence, while entanglement/inductive bias describes how the model resolves the resulting underdetermination.

If the model uses a sigmoid, clipping, or another bounded output, then range starvation is a literal architectural obstruction. That distinction should be recorded explicitly. With an ordinary linear regression head, I would use the phrase **unsupported out-of-domain continuation**, not inability to emit large values.

There is also an important interpretive limitation: because the target square value is already supplied as the `q` input feature, this experiment does not test whether the network discovers squaring. It tests whether the network learns and preserves the rule “route this supplied feature to the scalar output under the square task tag.” That is still a valuable primitive for compositional learning, but it is a feature-selection/routing result rather than autonomous rule derivation.

## Answers to the three questions

### 1. Cause and controls

The matched square-alone control is essential and is more informative than the weight-decay arm.

It should use the exact same MLP, input vector, scalar head, optimizer, step budget, initialization distribution, and square examples as the continual experiment; the task tag can simply be held constant. The earlier standalone polynomial-feature result is encouraging, but if its architecture or optimization differs, it does not isolate multi-task sharing.

Add a trivial linear-regression oracle `y = a*q + b` on the same train points. It should extrapolate essentially perfectly. This confirms that the dataset identifies the desired linear coefficient for a model whose hypothesis class exposes that bias directly, and catches scaling or evaluation bugs.

The interpretations would then be:

- Matched square-alone succeeds, but both sequential variants fail: prior-task representation or sequential interference is implicated.
- Matched square-alone and sequential baseline both fail, while the linear oracle succeeds: the main issue is MLP parameterization/optimization, not continual learning.
- Naive succeeds but consolidation fails: the stability constraint itself blocks the required representation.
- Both naive and consolidate fail, as currently observed: this does **not** indict consolidation; the square-alone control is needed to distinguish shared/sequential interference from a generic architecture bias.

Weight decay is a reasonable arm, but its interpretation should be narrower. L2 parameter norm in a multilayer ReLU network is not the same thing as minimum complexity in function space, and ReLU scaling symmetries make “minimum norm prefers `y=q`” especially unsafe. There is no direct raw-input coefficient in the baseline architecture for L2 to select. If weight decay works, the conclusion is “this regularizer and parameterization biased optimization toward a better continuation,” not that a general simplicity prior recovered the true rule. Use a small preregistered decay grid and report all values rather than letting one favorable value stand for the arm.

### 2. Whether square extrapolation is the right metric

Keep it. Extrapolating from targets below 1 to targets as large as 16 is a deliberately severe and revealing test. It is not a fair apples-to-apples comparison with bounded parity, but it need not be. The two rules expose different failure modes.

Do not reduce the result to a single `square_extrap = 0.000`. For square, report:

- MAE or RMSE, normalized by the target range;
- fitted prediction slope and intercept against `q`;
- maximum predicted value;
- performance in nested OOD shells, for example `n/K` in `[1,1.5)`, `[1.5,2)`, `[2,3)`, and `[3,4)`;
- several seeds with mean and spread.

Those measurements distinguish immediate saturation, a merely wrong slope, and a gradual loss of validity. A thresholded “accuracy” can turn all three into zero and erase the mechanism.

A bounded control is useful, but I would not replace square with it. A periodic or thresholded target learned only from bits introduces a different and possibly harder identifiability problem. A cleaner bounded routing control is to expose a bounded feature directly and ask the model to copy it under a task tag—for example `b(q)=q/(1+q)` as both an input feature and target. Then square and bounded-copy both test routing, while only square demands unbounded magnitude. Another cheap scale control is `y=q/16` with the original `q` input: extrapolated targets remain at most 1 even though the input support and required 16-fold continuation are unchanged. Use scale-aware metrics so this is not made artificially easier by the tolerance.

### 3. The honest headline

Yes, with one qualification: square interpolation of `0.671` is partial acquisition, so “retains two rules” is stronger than the evidence warrants. I would write:

> Sequential consolidation preserves the previously learned parity mapping while partially acquiring a second mapping, whereas naive fine-tuning forgets parity. Retention does not imply out-of-domain rule execution; square extrapolation exposes a separate representation and inductive-bias requirement.

Because naive and consolidate both have zero square extrapolation, the current evidence already says the failure is not unique to the consolidation penalty. The matched square-alone experiment will tell us whether it is caused by the shared/sequential setting or by the MLP itself.

## Changes I would make to the four arms

Keep four main arms, but define them so each tests one mechanism:

1. **Baseline:** current shared two-layer ReLU trunk and scalar head.
2. **Weight decay:** identical to baseline except for the preregistered L2/AdamW setting.
3. **Task-gated raw linear skip:** `out = MLP(x,t) + a*q_square + b`, where `q_square = 1[t=square]*q`. This directly tests whether a clean raw-feature route is sufficient while retaining one scalar output.
4. **Separate task heads on the shared trunk:** parity and square heads receive only the shared hidden representation, with no raw-feature skip. This tests output-head interference without also granting the square head privileged access to `q`.

I would not use an ungated `v·features` as the clean skip test. Since `q` is present on parity examples too, learning a global `q` coefficient for square can perturb parity and force the MLP to learn a task-dependent cancellation. That recreates the very entanglement the arm is supposed to remove. It can be retained as a secondary stress test, but not as the decisive linear-channel arm.

The separate-head arm should not also read raw inputs; otherwise “head separation” and “linear feature bypass” are confounded. Report its small parameter increase and the fact that it requires a task ID. The current system already supplies a task tag, so this does not change the inference information assumption, but it does introduce task-proportional parameters.

For every continual arm, measure parity immediately after parity training and after square training, plus square interpolation and the full extrapolation diagnostics. Match seeds and, where feasible, parameter counts. The square-alone control does not need naive/consolidate variants because there is no previous task to preserve.

## What this means for the larger project

- **Knowledge into weights:** positive but limited evidence. Both mappings live in model weights at inference, yet the square computation itself is engineered into the input as `q`; the learned knowledge is chiefly selection/routing.
- **Continual retention:** the strongest current result. Consolidation preserves parity where naive fine-tuning collapses toward chance. Square acquisition is incomplete, so plasticity remains the open side of the trade-off.
- **Growth necessity and compute advantage:** not established by this toy. A successful constant-size shared skip would support reusable fixed-cost structure. Separate heads would instead buy performance with task-linear architectural growth, which may be acceptable as a diagnostic but is not yet the desired small-to-large growth story. Training-cost savings also need an explicit comparator before claiming compute advantage.
- **No-memory inference:** satisfied in the episodic-memory sense if no examples or solver are retrieved at test time. It is still task-aware inference because a task tag is supplied; that limitation should remain visible.
- **No joint full retraining:** the proposed sequential experiment respects the project constraint. Square-alone and linear-oracle runs are diagnostic controls, not joint training as the solution.

My recommendation is therefore **go**, with the gated-skip definition, the matched square-alone and linear-oracle controls, and regression diagnostics added before implementation. The scientifically valuable outcome is not merely whether one arm raises a score; it is locating the boundary between stability, raw-feature accessibility, head interference, and OOD continuation.
