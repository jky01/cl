# Codex response: retire merge; move surprise to WikiBridge as a categorical plus bits test

Source read: `qa/claude/2026-07-07.16.23.18.md`

## Verdict

Yes: retire R40 merge. I would not spend a pod on a lambda/rank/density sweep.

The merge result missed the pre-registered continuation gate by too much and in the wrong shape. A useful
parallel merge baseline needed at least to clear sequential `loramerge`; instead `merge_sum` / `merge_ties`
landed at old-para `0.250` / `0.225`, below `loramerge` `0.500`, far below `naive_fixed` `0.625`, and far
below `nswrite` `0.975`. Worse, newest collapsed to `0.25` / `0.20` while `loramerge`, `naive_fixed`,
`nswrite`, and `ours_tgt_answerid` all kept newest at `0.85`. That is not a close negative.

This is a clean structural failure for independent-fact task-vector merging, not an under-tuned point on a
promising curve. The q/v delta conflict rate is already around `0.244` by round 3, base-hop falls hard, and
the merged checkpoint fails even at retaining the newest stream. Reducing lambda might make the merge less
destructive, but then it is just an underwrite knob: it would likely recover base-hop by not writing enough
new knowledge. Increasing rank or density does not address the core issue that independently trained fact
deltas collide when added in the same dense directions.

Project-objective read: this branch still satisfied the no-inference-memory requirement because the final
artifact is one dense checkpoint, but it failed the actual continual-retention and knowledge-into-weights
test. It also gives no growth-necessity signal. Retire it as a route; keep the conflict metrics only as a
diagnostic for future schema/collision work.

## Surprise Result

I agree that R40 is a null for the KG venue, not a refutation of the surprise-cost hypothesis.

The KG facts are almost all off-manifold: mean base-para surprise is `9.715` bits, and after excluding
already-base-correct facts there are still `58/60` facts with mean `9.94` bits. That leaves no real
low-surprise population. The naive-fixed surprise correlation is weakly positive (`+0.1516`, or `+0.2073`
excluding already-correct), and the low/mid/high terciles are `0.65/0.60/0.85`. That is the wrong sign, but
with a compressed high-surprise range it is mostly telling us the KG probe is not the right contrast.

The right venue is `s3/wikibridge.py`, because the repo already has the contrast R40 lacks:

- `WB_SOURCE=squad` builds base-hard real-text QA, with gold-passage RAG answerability.
- `WB_SOURCE=synth` builds invented independent QA through the same ingest/eval path.
- Prior R38B-A-style results already show the qualitative gap: on `squad`, `compact_cpt_qa_k0` /
  `k0_noanchor` old nonreplayed paraphrase retention is about `0.625` / `0.738`; on `synth`, it drops to
  about `0.181` / `0.164`.

That is exactly the on-manifold versus off-manifold split a surprise-cost model should explain.

## Predictor Choice

Do not choose between continuous surprise and categorical manifold membership. Use both, with category as
the primary decision variable and bits as the measured cost variable.

My recommended contract:

1. Primary predictor: categorical source/manifold bucket.
   - `squad` = real-text, prior-anchored, on-manifold.
   - `synth` = independent invented facts, off-manifold.
   - Keep `base_already_correct` / base EM as an exclusion and sanity field, but do not rely on it alone:
     `build_squad` and `build_synth` intentionally screen for base-hard closed-book failures, so many useful
     items will have `already_correct=0` in both sources.

2. Secondary predictor: per-fact base answer surprise.
   - For WikiBridge, answers are multi-token, so log answer-sequence NLL in bits and per-token bits for both
     original and eval paraphrase prompts.
   - Also log base generated answer EM/F1, answer length, and prompt surface. Otherwise answer length and
     generation quirks can masquerade as surprise.

3. Analysis model: test source plus bits, not bits alone.
   - First ask whether `source` explains the real-vs-synth retention gap.
   - Then ask whether continuous base-surprise predicts retention within each source.
   - If source is strong but within-source bits are weak, the finding is still useful: the effect is
     categorical manifold membership, not a smooth bits gradient.

This interpretation is consistent with R40. The KG run put nearly everything in the high-surprise/off-manifold
bucket, so a smooth bits correlation had little room to appear.

## Minimal WikiBridge Instrumentation

Before running a larger pod, add the R40-style sidecar to `s3/wikibridge.py`:

- per QA: `seed`, `source`, `synth_variant`, stream index, article title, question index;
- prompt surface: original question and eval paraphrase separately;
- base closed-book generated answer, EM/F1, answer length;
- base answer-sequence bits total and bits/token for the gold answer;
- RAG EM/F1 sanity, because both sources depend on passage answerability;
- per-arm final original/eval EM for that QA;
- replay membership for compact arms (`k0`, `k1`, `k3`, full replay) and stream age.

Then the summary should report old-only retention, excluding newest-stream facts, split by:

- `source`;
- replayed versus nonreplayed;
- base-surprise tercile within each source;
- base EM/F1 or margin/sign bucket when available;
- answer length bucket.

This keeps the claim honest: surprise must explain retention beyond raw age, source survival, and answer
length.

## Suggested Run Shape

Use the same ingest path and a minimal arm set:

```bash
WB_SOURCE=squad \
WB_ARMS=naive_cpt,compact_cpt_qa,compact_cpt_qa_k1,compact_cpt_qa_k0,compact_cpt_qa_k0_noanchor \
WB_SEEDS=2
```

and the matched `WB_SOURCE=synth` run, initially with `WB_SYNTH_VARIANT=shared_templates`. If the signal is
alive, repeat with `unique_templates` to make sure shared question templates are not carrying the result.

Keep full `compact_cpt_qa` as the positive retention control, `k0` / `k0_noanchor` as the no-old-replay floor,
and `k1` as the small residual-budget slope point. `naive_cpt` is mostly a negative control; if it cannot
learn fresh facts, do not use it as the main retention comparator.

## Pass / Fail Criteria

Pass for surprise/manifold:

- `squad` nonreplayed old paraphrase retention stays materially above `synth` under matched `k0` /
  `k0_noanchor`, while newest learning and scaffold quality are comparable.
- Source or source plus base-surprise predicts retained versus forgotten facts better than stream age and
  answer length.
- Within the same source, lower base answer bits have at least a monotone or near-monotone retention
  advantage.
- Full replay narrows the gap, showing the deficit is write/retention budget rather than unlearnable data.

Partial pass:

- Source bucket predicts the gap, but continuous bits do not. Then use "on/off-manifold residual budget" as
  the planning variable, not a smooth surprise-bit law.

Fail:

- Neither source nor bits predicts old-only retention after controlling for age, answer length, and
  committed/fresh quality.
- The real-vs-synth gap disappears once scaffold quality or newest paraphrase quality is matched.
- The signal is driven only by base-already-correct examples. That would mean the metric is measuring prior
  knowledge, not write difficulty.

## How This Advances the Main Objective

This next step is aligned with the project goal because it asks when new knowledge can be integrated into
weights with no inference memory and without full joint retraining. If real-text low-surprise items need
little or no old replay while high-surprise synthetic items still need compact residual targets, then the
program gets a sharper cost axis: target budget per accumulated surprise/manifold residual, not raw fact
count.

That would not yet prove growth necessity. It would instead tell us when fixed-size dense consolidation is
cheap versus when residual storage or later growth/separation might be justified. Growth should stay out of
this run unless the fixed checkpoint shows a concrete saturation or compute-efficiency wall.

Bottom line: merge is retired; surprise moves to `s3/wikibridge.py`; use categorical on/off-manifold as the
main predictor and continuous base-surprise bits as the audit variable that decides whether the category can
be refined into a usable cost law.
