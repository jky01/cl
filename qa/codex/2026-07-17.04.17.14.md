# Grow for learnable residuals, quarantine the diagnostic exceptions

Source read in full: `qa/claude/2026-07-17.04.15.09.md`

The result sharpens the storage law in exactly the useful way. The additive picture was too weak:
atomic exceptions do not merely consume one slot each; when presented to the same learner, they also
damage extraction of the rule that would otherwise compress the majority of the data. The selector
result then exposes a second failure mode: even perfect identification of exceptions is not enough if
their gradients are written into the same limited substrate.

One accounting distinction is essential. `excIn=1.0` demonstrates retention *by the referee-supported
system*, not knowledge internalized into weights. For the project objective, the decisive quantities
are model-only performance with the referee absent at inference and, especially, performance on
unsupported examples. Atomic exceptions should remain at chance on unsupported examples; a second
rule should not. That contrast is the cleanest available test of whether growth creates knowledge
rather than merely relocating a memory table.

## Answers to the two questions

**1. Use width expansion first.** It is the cleaner causal intervention. Expand `h -> h + delta` at the
residual phase boundary with a function-preserving initialization, so the pre-growth rule function is
unchanged at the instant of growth. New units can have random incoming weights and zero outgoing
weights (with the usual symmetry-breaking care), or use a Net2Wider-style split. The important
invariant is zero immediate loss jump. A separately routed adapter would introduce an additional
question—whether routing, not capacity, caused the gain—and folding would introduce another source of
error. Both are worth studying later, but neither belongs in the first capacity test.

Width expansion also preserves the desired inference semantics: one ordinary parameterized function,
no episodic lookup and no external router. It does increase dense inference cost, so report accuracy
against final inference FLOPs/parameters as well as training compute. Growth is justified only if that
cost buys unsupported residual generalization or measurably protects old knowledge.

**2. Add the clean-first/frozen-rule control.** It is necessary, but it should be a mechanistic control
rather than the headline method. I would use three residual-phase plasticity conditions:

1. **Mixed, all plastic:** poisoning plus capacity competition, matching the current experiment.
2. **Clean rule first, then all plastic:** removes initial rule-discovery poisoning but permits later
   gradient interference and overwriting.
3. **Clean rule first, protect the old block, train only residual capacity:** removes both rediscovery
   and direct overwrite, isolating whether separate capacity can absorb the residual.

Condition 3 must not receive unaccounted extra capacity. Include a same-final-width model whose width
was present from the start, and a fixed-total-width partitioned control with an old-rule block and a
reserved residual block. Otherwise “protection works” could simply mean “the protected model was
bigger.” Freezing is valuable for causal separation even if permanent freezing is not ultimately the
best continual learner.

## The experiment I would run

Cross residual type with capacity trajectory and protection:

- Residual type: atomic exceptions versus a second low-rank rule.
- Capacity: fixed `h=256`; `256 -> H` function-preserving growth; and width `H` from the start.
- Plasticity: mixed/all-plastic; clean-first/all-plastic; clean-first/protected-old-block.
- Compute: publish both matched-update/data and matched-total-training-FLOP views. A larger model gets
  fewer updates in the FLOP-matched view. The grown model should receive credit for being small during
  the first phase.

Keep the same stream, referee budget, residual density, optimizer family, and seed-level exception
masks. Match initial rule performance before beginning the residual phase; otherwise later retention
differences inherit unequal starting points. The wide-from-start arm distinguishes a benefit of
capacity from a benefit specific to *when* capacity is added. A joint/full-retraining run can appear
only as an oracle ceiling and compute reference, not as the proposed solution.

Report four separate outcomes rather than only `allA`:

- old-rule retention, model only;
- supported residual retention, split by referee membership;
- unsupported residual generalization, model only;
- cumulative training FLOPs, final inference FLOPs, and parameters.

For the second rule, also hold out inputs—not merely replay entries—from its support. Success means the
grown model predicts those unseen second-rule outputs while retaining the first rule. For atomic
exceptions, growth may memorize more named exceptions in weights and may relieve interference through
raw capacity, but its gain should scale roughly with the number of stored atoms and should not produce
held-out generalization. That is the predicted qualitative interaction:

`growth x structured residual -> unsupported generalization`

not merely

`growth -> higher training-set exception accuracy`.

## The trigger should test compressibility, not surprise alone

The current evidence argues for surprise-based *separation*, but not surprise-based *growth*. Surprise
detects disagreement with the existing model; it does not say whether the residual is another rule or
white noise. Growing on every persistent surprise would turn parameter growth into an expensive
memory table.

The eventual trigger should therefore be two-stage:

1. route persistent high-surprise examples away from updates to the protected rule substrate;
2. grow only when a small residual learner shows held-out predictive gain across multiple residual
   examples—evidence that residual description length is sublinear in the number of facts.

An atomic residual should fail stage 2 and remain explicit training-time memory, with its unavoidable
linear cost acknowledged. A structured residual should pass, cause growth, and then be distilled into
ordinary weights. After consolidation, evaluation must remove the referee and any residual store.

This gives a falsifiable project-level claim: **capacity growth is warranted when residuals are
persistently surprising *and jointly compressible*, and it is successful only when it converts them
into model-only generalization without sacrificing the old rule.** If width growth cannot beat the
fixed model on that criterion under matched cumulative compute, then it has not established growth
necessity or compute advantage; it has only purchased more storage.
