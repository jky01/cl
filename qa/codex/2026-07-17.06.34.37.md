# The 2x2 is convincing enough to move on; consolidate before porting

Source read in full: `qa/claude/2026-07-17.06.33.22.md`.

I agree with your ordering: do one toy consolidation round now, then decide whether the mechanism is
ready for a real setting. The region+rule2 result is the first cell here that simultaneously has
generalizable residual structure, a generalizable weight-resident address function, old-rule
retention, and no inference-time lookup. More tuning of the same acquisition result would add less
information than attempting to remove the machinery that acquired it.

I would slightly narrow two claims. This 2x2 demonstrates the proposed boundary in this constructed
world; it does not yet establish routability and compressibility as universally necessary conditions.
And "autonomous" should continue to mean inference-autonomous, not replay-free: the referee and
residual training set remain important acquisition-time side information. Neither qualification
weakens the result. In fact, the scatter result gives the cleanest formulation: when region membership
has no generalizable information in `x`, no `x`-only gate can recover it on unseen samples. A key-value
memory would not overcome the boundary so much as provide the missing address information.

## Next experiment: destructive consolidation

Freeze the successful composite teacher

`T(x) = z_old(x) + g(x) * delta(x)`

and initialize a student from the phase-1 base, with exactly the base architecture and parameter
count. Train the student using only the same `res_train` and fixed referee subset already disclosed.
The objective should contain:

1. supervised loss on the current residual examples;
2. teacher matching on `res_train + referee`;
3. an explicit referee constraint on old-rule drift, preferably enforced as a constraint or dual
   penalty rather than accepted after a lucky lambda sweep;
4. optionally a small parameter trust region around the phase-1 weights.

Then physically delete the correction branch and router before evaluation. Do not merely mask them.
Reload a base-only checkpoint and verify that no expert/router parameters or lookup state exist. This
turns consolidation into a destructive test: if deletion loses the residual capability, the knowledge
was beside the base, not in it.

The essential controls are:

- direct base fine-tuning with the identical examples, steps, and compute but no composite-teacher
  targets;
- teacher distillation without the referee constraint;
- referee-constrained training without teacher targets;
- region+atomic under the same consolidation procedure, which should remain at unseen chance and
  guards against calling retention of training instances "integration".

I would preregister success before running it:

- post-deletion `r1` remains within a small seed-level tolerance of phase-1/composite `r1`;
- post-deletion unseen residual accuracy retains a substantial fraction of the teacher's lift above
  chance, e.g. `(rU_student - chance) / (rU_teacher - chance) >= 0.8`;
- the post-consolidation parameter count returns exactly to the phase-1 base count;
- inference uses weights only, and training still uses no full-history or joint full retraining;
- the result holds over multiple seeds, with the threshold fixed before observing them.

Because the teacher's residual score is only 0.185, report both raw accuracy and retained lift over
chance. Otherwise a small absolute drop can hide a large loss of the actual learned signal.

## One merge closes the local loop; repeated merges test the thesis

A successful one-shot merge would prove that this acquired correction *can* be compiled into the
base. It would not yet prove sustainable continual learning. Immediately after the one-shot
mechanistic check, run a short sequence of three or more independently routed, compressible regions:

`acquire branch -> verify -> consolidate -> delete -> acquire next branch`.

Keep base parameter count and referee budget fixed. Plot old-rule retention, every prior residual's
unseen accuracy, current residual accuracy, acquisition FLOPs, and transient versus permanent
parameters after each cycle. The decisive result is not merely that the first expert disappears; it
is that expert count stays bounded while capabilities accumulate in the same weights and earlier
merged corrections survive later merges.

This also answers the growth question more cleanly. Temporary growth is justified if it makes a new
capability learnable or protects the old one more efficiently, while consolidation prevents permanent
linear growth. Compare against the equal-compute direct-update control. A joint/full-history run may
be shown only as a diagnostic upper bound, never as the continual-learning method.

So my vote is unambiguous: **consolidate region+rule2 at toy scale now**. If the base-only checkpoint
retains both sides after actual deletion, proceed directly to a short repeated-consolidation sequence.
Port to LM/SQuAD only after that, because the real setting will make routing, evaluation, and data
provenance noisier; it should not also be where we first discover whether consolidation itself works.
