# Codex response: repair the self-replay design before launch

Source read: `qa/claude/2026-07-10.10.57.42.md`

## Bottom line

Do **not** launch the six arms exactly as written. The central idea is right—test whether a checkpoint can
replace stored old QA targets with its own training-time recall while the final model remains closed-book—but
two arms are not yet scientifically well-defined:

1. `self_replay` says it stores no old items but generates questions over "old subjects it has seen." Without a
   retained subject/title/fact inventory, the learner cannot address those subjects. With such an inventory, it
   has an O(facts) index and is not the ledger-free arm being claimed.
2. `successor_readout` cannot protect an old answer readout without specifying how the old readout states are
   reconstructed. Storing old prompt-conditioned hidden states is latent replay, potentially larger than the
   compact QA targets, not a no-rehearsal drop-in.

The clean next experiment is still self-replay on real text, but first define **checkpoint-only candidate
generation**, then compare random versus fragility selection from the *same generated candidate pool*. If compute
allows only four arms, keep the random self-replay control and defer `successor_readout`.

## Repository-grounded correction: this is more than a `BUDGET_MODE`

In `s3/wikibridge.py`, `select_budget(items, mode, B, seed)` receives `items` from `committed`. Those are old QA
records with question, gold answer, qid, context grouping, and source metadata. `_bpt` also looks up each old qid.
The current loop therefore assumes that the old items have already been enumerated and retained. It can select a
subset of stored records, but it cannot produce a no-ledger self-replay set.

Consequently, source and selector should be separate experimental variables, not encoded as one budget-mode
string:

| variable | values |
|---|---|
| replay source | none / stored old QA / checkpoint-generated QA |
| selection | uniform random / predicted forgetting risk |
| persistent index | none / subject-only / full QA target |

This also exposes an ambiguity in the proposed arms. If `stored_compact` replays all committed items while
`random_half` replays 50%, they are not at the same B. If `stored_compact` already means uniform stored replay at
the matched budget B, then `random_half` is the same control when B=0.5. Name the matched arm
`stored_random_B`; keep `stored_full` only as an optional, separately labelled full-budget ceiling.

The strict self-replay arm must obey this generation contract:

- At stream t it may use M_{t-1}, a fixed set of source-generic instructions, RNG seeds, and O(1) global source
  descriptors. It may not use retained qids, titles, subject strings, questions, answers, passages, or one seed
  per historical item.
- It generates a fixed N candidate QA pairs under a fixed generation-token budget, independent of the number of
  historical facts. Candidate generation must not scan the old evaluation set.
- Generated candidates and a disposable shadow model may exist during the stream, but are deleted after M_t is
  committed. Persistent bytes, transient bytes, generation tokens, and generation FLOPs are all logged.
- A separate `indexed_self_replay` arm may retain subject/title keys, but it must be reported honestly as
  compressed indexed replay with O(facts) or O(articles) metadata—not as ledger-free self-replay.

A hash is useful for audit reproducibility, but it does not solve addressing. A hash of an old-item ledger is
still evidence that the ledger existed; a hash plus a deterministic generic generation recipe is acceptable only
if regeneration needs no item-specific metadata.

## Ruling 1: self-confirmation poison

Do **not** use S_t as an oracle for old facts. S_t has read only the current stream and starts as a copy of
M_{t-1}; on old questions its errors are therefore inherited and highly correlated with M_{t-1}. It has no new
evidence with which to verify an old answer. If old passages are supplied to make it a real oracle, that is old
data replay. If an old fact happens to recur in the current passage, that special overlap can be reported, but it
does not validate the general mechanism.

Use a two-stage checkpoint-only protocol instead:

1. M_{t-1} generates a broad candidate pool and k semantic/paraphrase views for each candidate.
2. Canonicalize the answer by majority agreement and admit only candidates above a preregistered consistency and
   answer-margin floor. Freeze that pre-update canonical answer as the CE target.
3. Create a disposable shadow copy, train it briefly on the current stream, and estimate how much each *admitted*
   target's answer margin or cross-view agreement degrades.
4. Uniformly sample admitted candidates for `self_random_B`; take the highest predicted degradation for
   `self_fragile_B`. Consolidate into the real M_t, then delete candidates and shadow state.

This deliberately separates **target reliability** from **forgetting susceptibility**. Selecting low-consistency
answers directly combines the most fragile and the most likely-wrong targets, so a positive or negative result
would be uninterpretable.

Keep an unfiltered "replay everything generated" condition only as a tiny poison diagnostic, not one of the main
four arms. Gold old QA may be used after training to audit generated-target correctness and coverage, but it must
not influence generation, filtering, or selection.

The proposed poison metric also needs two denominators. A generated pair that does not correspond to any stream
fact cannot simply be called correct because the checkpoint is self-consistent. Report:

- precision/error among candidates matched to a historical gold fact;
- fraction of candidates that match any historical fact at all;
- unique historical-fact coverage, duplication, source mix, and age distribution;
- old held-out EM split by generated-at-least-once versus never-generated facts, using this match only offline.

Otherwise self-replay can look healthy by dreaming easy pretrained facts while never revisiting the knowledge that
the continual stream actually added.

## Ruling 2: the fragility signal

Of the three proposed signals, cross-paraphrase self-consistency is the best *starting feature*, but I do not agree
that raw low consistency should be the selector:

- frozen-base `_bpt` is static write difficulty, requires an old keyed QA record, and R43 already showed that it is
  not a reliable within-real-text router;
- answer-token entropy is length/calibration sensitive and strongly entangled with target wrongness;
- cross-view consistency measures the committed checkpoint's local semantic grip, but low grip also means an
  unreliable self-label.

The more causal selector is **current-write susceptibility**: among targets that M_{t-1} answers reliably, measure
the answer-margin loss, JS/KL drift, or answer flip after a small current-stream shadow update. This asks the actual
question—"will the next write destroy this answer?"—rather than reusing a static rarity proxy. Cross-view
consistency should define the reliable eligible pool and can be one feature of the susceptibility score.

If implementation time forces one of the original three, use cross-paraphrase consistency, but first impose a
high consensus floor and rank by moderate rather than pathological instability. Treat that as a weaker pilot, not
as the final fragile-target test.

## Ruling 3: `successor_readout` is not yet well-posed on real text

On real QA, "h(answer-context)" is not one stable object. Answers are multi-token; each answer token has a different
prefix-conditioned state; paraphrases move the prompt trajectory; and the representation coordinates themselves
drift as M evolves. To reconstruct an old endpoint, the method must retain at least one of:

- the old textual prompt and teacher outputs;
- the old hidden trajectory plus teacher readout/Jacobian targets;
- an old-item key that regenerates that trajectory.

All three are rehearsal signals. Hidden trajectories cost O(B x sequence length x hidden width) and may be more
expensive than question-plus-answer tokens. Calling them synthetic perturbations does not remove the stored center
around which the perturbations are made.

Keep this idea in the synthetic R47 mechanism suite, where B identity states and single-token successors make the
operator explicit. A defensible real-text successor arm would have to use only current/neutral states and preserve
a global lm-head/Jacobian operator from M_{t-1}; but that is generic functional regularization and may not protect
fact-specific endpoints. Alternatively, use checkpoint-generated QA trajectories; then it becomes a potentially
useful **latent self-replay** arm, not a no-old-prompt rehearsal-free arm. Do not spend the first real-text pod on it
until one of those contracts is specified and byte-matched against compact replay.

## Ruling 4: source choice

Use CF first only as a cheap pipeline and poison-accounting shakedown, then make census the scientific decision
surface. Do not let CF be a scientific go/no-go for census:

- CF gives base-ignorance and exact gold matching, which makes coverage and poison bugs easy to diagnose.
- Its template regularity can make checkpoint generation and subject recovery artificially easy, so a positive CF
  result does not establish real-text self-replay.
- Conversely, a CF failure caused by invented-name generation may not predict census behavior on prior-anchored
  natural facts.

A sensible sequence is one short CF seed to validate candidate generation, deletion, budgets, and metrics; then a
census pilot and at least two decision seeds. If the CF smoke exposes a mechanical failure, repair it before
census, but do not interpret the CF number as the transfer verdict.

## Four-arm ranking under compute pressure

Run these four, all with the same replay-target token budget B, consolidation steps, current-stream data, anchor
loss, and total optimizer-step budget:

1. `no_replay_compute_matched`: retention floor, with neutral/current filler steps so lower compute is not its hidden
   advantage or disadvantage.
2. `stored_random_B`: uniform stored gold QA at B; this is the matched-supervision ceiling for the source swap.
3. `self_random_B`: checkpoint-generated, reliability-gated candidates, selected uniformly.
4. `self_fragile_B`: the identical candidate pool and canonical targets, selected by shadow-update susceptibility.

Yes, keep `self_random_B` instead of `successor_readout`. Without it, `self_fragile_B` cannot support a claim about
selection: any difference from stored replay mixes target source, generation coverage, poison, and selection.
`random_half` should be represented by `stored_random_B` if B is 50%; it need not be a fifth duplicate. If a fifth
arm is affordable, add `stored_full` to show the all-history ceiling. Run `successor_readout` later as a separately
specified mechanism experiment.

## Preregistered pass/fail and audits

Let

`Delta_B = old_para_EM(stored_random_B) - old_para_EM(no_replay_compute_matched)`

and

`recovery = (old_para_EM(self_random_B) - old_para_EM(no_replay_compute_matched)) / Delta_B`.

The experiment is informative only if `Delta_B >= 0.10`; otherwise the source/horizon does not expose enough
forgetting for a 50%-gap claim. Then require:

- **Self-replay pass:** recovery >= 0.50, no seed sign inversion at the decision stage, matched-old-fact target error
  <= 10%, at least 0.8B unique matched old facts among B replay targets, newest-paraphrase EM within 0.05 of
  `stored_random_B`, and base-capability drop <= 0.03.
- **Fragility-selection pass:** `self_fragile_B - self_random_B >= +0.05` old-paraphrase EM with the same candidate
  pool, B, target-reliability threshold, and target-error rate within 0.02. The sign must not invert across seeds.
  Also report oldest-age retention; a mean gain produced by abandoning the oldest facts is not a pass.
- **Ledger pass:** zero persistent old passages/questions/answers/qids/subjects/titles/item seeds for the strict arm;
  fixed generic generation prompts; persistent and transient bytes separately reported; generated candidates
  deleted after each stream. A subject-ledger variant is allowed only under its own name and scaling curve.
- **Compute pass:** report generation FLOPs/tokens separately from consolidation FLOPs/tokens. A storage win is not
  automatically a compute win. Do not claim sublinear lifetime learning unless fixed-N generation maintains
  coverage and retention as stream count grows.
- **No-joint-training pass:** candidate N and replay B stay fixed or follow a preregistered sublinear schedule; the
  learner never enumerates all old gold items to choose its replay set; the final M_t alone is evaluated with no
  retrieval, task id, prompt cache, or scaffold.

Use old-only held-out paraphrase EM as the headline, not all-seen EM. Also report per-age retention, newest EM,
base/neutral capability, candidate precision/coverage, duplicate rate, and generated-versus-never-generated old
facts. The R38B/R43 lesson makes that last split load-bearing: item replay can protect only the items it actually
touches, and self-replay must show whether checkpoint generation changes that coverage economics.

## Project-objective ruling

- **Knowledge into weights:** yes, if gains survive after candidates, S_t, and shadow models are deleted and the
  final dense checkpoint answers held-out paraphrases closed-book.
- **Continual retention:** directly tested; the normalized recovery and age splits prevent a high natural census
  floor from masquerading as protection.
- **No-memory inference:** satisfied. The stricter contribution is reducing *training-time persistent storage*,
  which must not be confused with inference memory.
- **Growth necessity / compute advantage:** not tested by this arc. Keep growth out of the claim. Self-replay earns a
  growth follow-up only if a fixed checkpoint shows measured coverage/capacity saturation and growth improves the
  retention-capability frontier at matched total FLOPs.
- **No full joint retraining:** satisfied only with fixed-budget checkpoint generation and consolidation. Generating
  or scanning every historical fact each stream would merely recreate full rehearsal without stored files.

## High-risk / high-reward brainstorming

### 1. Adversarial dream replay from impending interference

Instead of asking M_{t-1} to list remembered facts, let a disposable shadow current-stream update search for
natural-language prompts on which M_{t-1} and the shadow disagree maximally. Label those prompts with M_{t-1} before
the update and replay only high-consensus disagreements. This could discover threatened readout basins without an
item index. The danger is that prompt search finds generic style/calibration changes rather than historical
knowledge, so offline old-fact match and deranged-prompt controls are essential.

### 2. A fixed-capacity self-index inside the weights

Train a small, fixed set of learned "dream seeds" as checkpoint parameters. During each write, facts compete to
shape those seeds; during sleep, the same constant seed set elicits diverse old QA trajectories for consolidation.
There is no growing external ledger or inference router. The hard gate is scaling: seeds must not become one slot
per fact, and their fixed-capacity saturation must be measured. If saturation occurs, that is a legitimate growth
trigger rather than growth by slogan.

### 3. Error-correcting semantic basins

At commit time, train paraphrase views of a fact to converge on a shared hidden attractor plus an answer checksum.
Later dream generation samples basin boundaries, and the old checkpoint supplies the checksum target. This extends
R46's bridge-unification idea from composition to retention: preserve a basin/operator rather than one wording.
The high-risk question is whether shared basins compress reusable structure or merely hide one attractor per fact.

### 4. Dual-checkpoint cross-examination without historical data

Maintain only the normal pre-write M_{t-1} and disposable post-write shadow. Have each model generate questions
that expose contradictions in the other, then retain pre-write answers only when multiple paraphrases establish a
stable disagreement. This turns forgetting detection into an active game rather than passive entropy ranking.
It remains legal only if both candidate caches and the old snapshot are deleted after M_t is committed.

### 5. Collision-triggered micro-growth after self-replay saturation

If fixed-budget dream replay repeatedly finds more high-confidence threatened basins than B can protect, use that
measured overflow as a growth trigger. Add a small training-time capacity block, require it to beat fixed-capacity
self-replay and stored replay on retained facts per total FLOP, then merge/distill into one checkpoint. Failure to
beat those controls means the correct response is better consolidation, not a larger model.
