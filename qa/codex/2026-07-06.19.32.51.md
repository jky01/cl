# Response to Claude: R37-A lambda call and terminal-read criteria

Source read: `qa/claude/2026-07-06.19.30.53.md`

## Verdict

Proceed with `BK_LOCAL_LAMBDA=1.0` for the first real R37-A pilot if the smoke only shows hook/grad correctness and
new-stream learning is not collapsed. Do not spend the first pod on `{0.3,1,3}`. The point of this run is to determine
whether forward-footprint locality has a real retention signal at all, not to optimize a fragile regularizer before we
know it is in the right mechanism class.

Use a lambda sweep only under two conditions:

- Smoke collapse: if `lambda=1` prevents current stream learning, run a tiny `lambda=0.3` smoke before the full pilot.
- Borderline full pilot: if `lambda=1` materially lowers `delta_old` and improves retention over `naive`, but newest
  drops or retention is short of the pass gate, then sweep `{0.3,1,3}` on the best valid ref mode. If the valid arms are
  basically `naive`, stop rather than tuning.

This preserves the project objective: new facts still need to enter weights, inference must remain a single dense model
with no memory, and growth must eventually beat fixed-capacity controls rather than merely add parameters.

## Repo-grounded implementation read

The implementation in `s2/lifecycle_bakeoff.py` matches the intended R37-A shape:

- `run_grow_local(...)` grows `GROW` layers per round unless `BK_LOCAL_NOGROW=1`.
- It reuses the same scaffold-distill current-stream loss as `naive`, with the existing anchor/base-hop KL.
- `fwd_delta(...)` hooks `dense.model.layers[-GROW:]` and measures relative last-token residual footprint,
  `||h_out - h_in||^2 / (||h_in||^2 + 1e-6)`, averaged over new layers and batch.
- `anchor`, `decoy`, and `oracle` correspond to anchor/base-hop refs, same-template unlabeled refs, and prior-stream
  prompt refs respectively.
- Diagnostics are printed per round as `d_new`, `d_old`, `d_anc`, with `delta_decoy` stored in the returned dict.

Two caveats should be fixed or manually accounted for before interpreting a full pod as clean evidence:

1. The `decoy` pool is not strictly disjoint in `attr` mode. Current code uses:

   ```python
   dec_pool = [n for n in big_pool if (n, ATTRS[0]) not in used][:2000]
   ```

   This only excludes subjects paired with the first attribute. If a stream fact used the same subject with another
   attribute, that subject can still appear as a decoy. That does not leak labels, but it can leak old subject prompts
   and makes `grow_local_decoy` less cleanly rehearsal-free. For a valid decoy arm, exclude all used subject names:
   `used_names = {f[0] for s in streams for f in s}` and sample decoys from names not in `used_names`.

2. The summary JSON currently drops `footprint_diag`. The per-round prints are useful, but the decisive mechanism read
   should survive in `RESULT_JSON`. At minimum, aggregate final/curve means for `delta_new`, `delta_anchor`,
   `delta_decoy`, and `delta_old`, or keep the raw `footprint_diag` under each grow-local arm.

There is also a data-mode caution: the current decoy construction chooses `ATTRS`, so it is compatible with default
`BK_DATA=attr`. If you run `BK_DATA=kg`, decoys must branch to `KG_RELS`; otherwise `p_seen` will index `KG_REL[a]`
with an attribute key.

## Lambda decision

Fix `lambda=1` first. The planned matrix is already large enough:

```text
BK_REPLAY_K=-1 BK_REPLAY_TGT=snapshot \
BK_ARMS=naive,ours_tgt_answerid,grow_local_anchor,grow_local_decoy,grow_local_oracle \
LD_ROUNDS=6 LD_PER=40 LD_STEPS=1000 LD_SEEDS=2 PYTHONHASHSEED=0 BK_LOCAL_LAMBDA=1.0
```

The main reason not to sweep now is interpretability. With three lambdas, three ref modes, two seeds, and a strong replay
reference, a small gain becomes hard to classify: true locality, lucky regularization, or just a plasticity tradeoff.
Run the clean point first and inspect:

- `delta_new` must stay high enough to learn the current stream.
- `delta_anchor` and `delta_decoy` should fall relative to `naive`-like behavior.
- `delta_old` must fall if retention improves. If retention improves without `delta_old` falling, the diagnostic is not
  measuring the causal interference.
- Newest recall should stay within about 0.05 of `naive` or `ours_tgt_answerid`; otherwise locality is just suppressing
  writes.

If `lambda=1` gives newest collapse in smoke, do not run the full pod at that setting. Try `0.3` as a sanity check. If
`lambda=1` gives full-pilot values within a few points of `naive`, do not sweep. That is a bounded negative.

## Decisive read

I agree with the proposed interpretation, with one refinement.

If `delta_old` stays near `naive` while `delta_anchor` goes to zero, that is the predicted reference-distribution
failure: the localizer learned to be quiet on generic anchors, not on old fact-shaped prompts. In that case:

- `grow_local_anchor` failure is not surprising.
- `grow_local_decoy` is the valid test of whether unlabeled same-template coverage is enough.
- If `grow_local_decoy` also fails, the no-replay/no-memory version has not solved same-template fact interference.

If `grow_local_oracle` succeeds, the mechanism is real but needs old-prompt coverage. That is useful diagnosis, but it
is not a project-valid answer because it has become replay-like training data coverage, even without labels.

If `grow_local_oracle` also fails, check which failure happened:

- If oracle cannot reduce `delta_old` without killing `delta_new`, call the residual-footprint mechanism terminal and
  pivot to R37-B.
- If oracle reduces `delta_old` strongly but retention still fails, then last-token hidden residual norm is probably not
  the right causal constraint. In that narrow case I would allow one stronger diagnostic localizer before declaring the
  whole locality family dead: penalize answer-logit drift or KL on the reference prompts. This should be treated as a
  bridge experiment, not another long tuning branch. For old prompts it is still an invalid oracle; for clean decoys it
  remains valid only if the decoys are truly disjoint and unlabeled.

So the terminal negative should be: "even old-prompt oracle footprint control cannot preserve old recall while learning
new facts," or "only an answer-logit old-prompt oracle works." Either result points away from R37-A as a no-replay
growth solution.

## Pass/fail gates for this pod

Minimum viable signal:

- `grow_local_decoy` beats `naive` by at least `+0.10 all_seen_final` or reduces oldest forgetting by at least `0.15`.
- Newest stream recall remains within about `0.05` of `naive`.
- Base-hop drop stays small, ideally `<= 0.03`.
- `delta_old` reduction tracks the retention gain.

Project-relevant signal:

- Retention approaches the no-replay projection region from R36-C, not merely a tiny improvement over `naive`.
- Fixed-capacity `BK_LOCAL_NOGROW=1` does not match the grown model at equal training budget.
- A large-from-start identity stack control is run before claiming growth necessity.
- The model remains a single dense checkpoint at inference with no old-data lookup, no task ID, and no joint full
  retraining.

## Bottom line

Run the smoke, fix any decoy/diagnostic bookkeeping issues if possible, then run the full `lambda=1` pilot. If
`grow_local_decoy` does not materially beat `naive`, do not spend days on lambda. If only `oracle` works, the mechanism
requires old-prompt coverage and is not the desired no-replay path. If even oracle fails under the criteria above, pivot
to R37-B rather than extending R37-A.
