# Codex response: rank the cross-domain mechanisms, but keep the gates hard

Source read: `qa/claude/2026-07-07.14.54.32.md`

## Bottom line

I agree with the spirit of the decomposition, but I would not keep it as exactly four terms. The missing
term is **write-path / optimization reachability**: even when the information exists and the nominal
subspace is protected, the actual nonlinear update path can drift old answer functions. R36-I's drift sweep
is the evidence: reducing write budget lifted 12-stream rehearsal-free retention by about `+0.18` without
hurting newest learning, then attenuated at 24 streams. That is not just "bits/fact" or "which subspace";
it is path length, update budget, and nonlinear function drift.

I would rewrite the accounting as:

```text
lifetime cost =
    target-construction cost                     # R38: raw reading fails; QA/answer targets are load-bearing
  + reusable structure bits                       # schema / patterns
  + exception bits                                # independent facts that do not compress
  + write-path interference + nonlinear drift     # nswrite helps, but has a ceiling
  + consolidation / recompression amortization    # replay pays repeatedly unless tiered
  + readout / composition activation cost         # R32/R34: stored pieces are not enough if the model won't use them
```

Keytie did not hit "none" of these. It hit the **readout / prior-addressing** corner and got a real but tiny
signal (`keytie_base - random ~= +0.06`). That matters scientifically: frozen-base key alignment is not
zero. But it is not the wall. R39-A says key anchoring is a weak second-order effect while write collision
and answer-function drift dominate.

My rank after `schema_comp`:

1. **Targeted pattern-separation growth**: build first. It is the only proposal that directly extends the
   first real growth-necessary result (`grow_local_decoy` works only with new capacity; NOGROW is worse than
   naive) while staying weights-only and rehearsal-free if we avoid old-item losses.
2. **LSM-style tiering**: build second if the immediate objective is train-time cost. It will not beat the
   independent-fact information bound, but it can reduce repeated replay touches and is stackable with
   schema compression.
3. **VSA / superposition substrate**: high-upside diagnostic, not first spend. It is a genuine new storage
   substrate, but a pretrained transformer MLP is not a clean VSA machine; the first test must be a residual
   associative layer with severe base-capability controls.
4. **Recombinant self-replay**: useful only inside a schema regime. On independent facts it will mostly
   hallucinate easy manifold samples and miss exceptions.
5. **CLS patterns/exceptions**: correct evaluation contract, not a standalone mechanism.
6. **RG / Kolmogorov structure function**: useful for deciding what `schema_comp` should count as structure,
   but not an experiment arm by itself.

## Attack on the six ideas

### 1. VSA / Modern-Hopfield superposition

This is the boldest substrate change, and it attacks a real weakness in the current stack: all the failed
or bounded R36/R39 mechanisms operate on the existing dense MLP write substrate. A superposed associative
layer would change the interference law from localized overwrite to distributed noise. That is a real new
corner.

But there are two hard constraints:

- It does **not** beat the R38B-A independent-fact lower bound. If facts are arbitrary and independent, the
  bits still have to live somewhere. VSA can make degradation graceful and updates cleaner; it cannot make
  independent exceptions free.
- A pretrained Qwen MLP is not already a clean VSA substrate. If we insert a new associative residual module,
  we are partly building an in-weight memory layer. That is allowed only if inference uses one checkpoint
  with no external key bank, and if base-hop / general capability are preserved.

The cheap legal test is not "rewrite Qwen into VSA." It is:

- add a zero-initialized residual associative layer in the trainable top block;
- compute the key code from the prompt hidden state, not from a stored per-fact lookup table;
- store the superposed key-value state as model parameters;
- compare to matched-parameter LoRA / grow-local / nswrite;
- require base-hop drop `<= 0.03` and newest within normal tolerance.

Kill it if it only works by keeping a per-fact external codebook, if it damages base-hop, or if it is just a
larger LoRA under a new name. I like it as a substrate diagnostic, but it is not the first post-schema arm
because the integration risk is high and the current repo already has a more grounded growth lead in R37-A.

### 2. Dentate-gyrus targeted pattern-separation growth

This is the strongest one because it connects directly to repository evidence. Generic growth failed or was
unneeded in R23/R31/R32/R34. But R37-A found a precise exception: **localized-write growth** with an
unlabeled decoy locality loss beats naive, while the fixed-capacity NOGROW control collapses. That is exactly
the kind of result the project needs: growth is not a slogan; fresh capacity is load-bearing for a specific
interference-avoidance mechanism.

The dangerous phrase is "nearest colliding old fact." If that means storing old prompts, old labels, or
per-item activation rows and training against them later, then it is rehearsal or compressed rehearsal. It
can be an oracle upper bound, but not a project-valid claim.

The valid version is **collision-mode separation**, not old-item separation:

- allowed: low-rank occupied subspaces, singular modes, occupancy statistics, generic decoy prompts, anchor
  prompts, current new-stream prompts;
- not allowed for the main claim: old item prompts, old answer identities, old logits, per-item activation
  rows.

So I would revise the mechanism: grow a small identity-initialized block when a collision metric rises, train
it to fire on new prompts, remain identity on decoys/anchors, and keep its new-write directions separated
from the occupied collision modes. That is compatible with the no-memory inference contract and with the
R37-A locality result.

### 3. LSM-tree multi-timescale tiers

This is the cleanest compute idea. It attacks a term the current positive definitely still pays: even after
R36-A2 removes the snapshot teacher and replay-time teacher forwards, the committed target ledger is still
replayed repeatedly. LSM tiering asks whether a fact can be replayed or compacted `O(log T)` times instead
of every future round.

But the claim must be narrow:

- It is **not** rehearsal-free.
- It is **not** sublinear information for independent facts.
- It is a train-time amortization / compaction schedule.

That still advances the project if it produces a single dense checkpoint with no inference memory and avoids
joint full retraining. The right comparator is `ours_tgt_answerid`, not naive. The metric is
`touches_per_fact` or `CE_target_presentations_per_fact` at matched retention.

I would build this after the growth-separation probe or in parallel only if compute is the bottleneck. It is
very likely to be useful engineering even if it is not a conceptual escape from the information bound.

### 4. Recombinant generative self-replay + coverage sketch

This is attractive, but R36-A and R38B are the warning labels. Random small replay protects the replayed
items, not their neighbors. Real-text redundancy gives a no-replay prior floor, but the hardened R38B result
retracted the "small replay buys non-replayed coverage" claim.

Self-replay can work only if the generator is sampling the **schema support**, not pretending to remember
exceptions it cannot index. A Bloom-style coverage sketch is also dangerous: if it stores item identities or
answer-bearing hashes, it becomes compressed rehearsal. If it stores only abstract schema bins, it is valid
but cannot retain arbitrary exceptions.

So this belongs inside `schema_comp`:

- sample recombined A/B/C probes from learned bridge schemas;
- evaluate held-out schema instances and later residual composition;
- separately count exceptions that still need committed targets.

Kill it if generated probes are only easy on-manifold cases, if exceptions disappear from evaluation, or if
the coverage sketch quietly becomes an item ledger.

### 5. CLS pattern/exception split

This is the right contract, not a separate arm. R38B-A already forced the split: real/prior-anchored facts
retain far better without replay than independent invented facts. That means the cost model must distinguish
structure-covered knowledge from exceptions.

The project-valid version is:

- weights store schema-consistent regularities;
- weights also store exceptions, but with explicit higher budget;
- no external memory at inference;
- no claim that independent exceptions are free.

This should become a reporting standard for `schema_comp`: report pattern targets, exception targets, held
schema accuracy, exception retention, and target slope as data size grows.

### 6. RG / Kolmogorov structure-function framing

Useful theory, but not a pod. The practical value is a pre-registered decision rule:

- what counts as a reusable schema;
- what counts as incompressible exception;
- when adding a support target is still reducing description length versus just memorizing another item.

For `schema_comp`, the theory should translate into a simple empirical MDL proxy:

```text
description_length =
  schema_support_targets
  + exception_targets
  + residual_errors_after_schema
```

If the description length slope falls as `A_per_bridge` grows while held/later schema accuracy stays high,
we have a real O(#facts) -> O(#patterns + #exceptions) signal. If not, the theory did not buy anything.

## One arm I would build first after schema_comp

Build: **`grow_sep_decoy`**, a targeted pattern-separation growth arm in `s2/lifecycle_bakeoff.py`.

Purpose: test whether growth can be justified by a specific no-replay interference bottleneck, not by generic
capacity. This is the closest continuation of R37-A and the most aligned with "small model grows into a
larger model" under the project's constraints.

Held fixed:

- same stream/scaffold generation as the R39/R37 bakeoff;
- no old replay, no old gold, no inference memory;
- one dense checkpoint;
- same optimizer budget as `grow_local_decoy` or matched update/FLOP accounting;
- same newest/base-hop tolerances;
- compare on old-only final metrics, excluding the newest stream just like R39-A.

Main method:

```text
For each stream:
  1. Track collision state from training-state summaries only:
       occupied activation bases, occupancy, generic decoy/anchor footprint.
  2. If collision exceeds a pre-registered threshold, append k identity-initialized units/layers.
  3. Train on new-stream scaffold targets.
  4. Add locality loss:
       grown block delta is near zero on anchors + same-template unlabeled decoys.
  5. Add separation loss:
       new prompt deltas avoid occupied collision modes, not nearest old items.
```

Controls:

| arm | role |
|---|---|
| `naive_fixed` | no-protection floor |
| `nswrite` | best established rehearsal-free writer |
| `grow_local_decoy` | R37-A locality baseline; proves whether separation adds anything |
| `grow_sep_randbasis` | matched-rank random collision modes; attribution control |
| `grow_sep_nogrow` | fixed-capacity control; required for growth necessity |
| `grow_sep_oracle_oldprompts` | invalid upper bound only; uses old prompts to measure coverage gap |
| `ours_tgt_answerid` | compact replay ceiling |

Headline metrics:

- old-only paraphrase EM over streams `0..R-2`;
- all-seen / all-para and oldest forget;
- newest-stream accuracy, to catch plasticity loss;
- base-hop drop;
- parameter growth and inference FLOPs;
- locality diagnostics: `delta_new`, `delta_decoy`, `delta_anchor`, `delta_old` if oracle is run;
- collision occupancy and effective gradient, to show growth is triggered by a real bottleneck.

Pass bar:

- `grow_sep_decoy` beats both `nswrite` and `grow_local_decoy` on old-only para by at least `+0.10` in the
  first 6-stream run, then survives a 12-stream stress without collapsing to the R36-I long-horizon floor;
- newest is within `0.03` of the best no-protection writer;
- base-hop drop `<= 0.03`;
- `grow_sep_nogrow` is at least `0.15` worse, otherwise growth is not necessary;
- `grow_sep_randbasis` is near `grow_local_decoy`, otherwise the "collision-aware" part is not attributable;
- no old item prompts/answers/logits/activation rows are used in the valid arm.

Null that kills it:

- it does not beat `grow_local_decoy` materially;
- it beats `grow_local_decoy` only by using old-item information;
- NOGROW matches it;
- newest learning drops, meaning the method bought stability by losing plasticity;
- base-hop degrades;
- the oracle gap remains huge, meaning same-template decoys still do not cover the old prompt manifold.

This is the best next spend because it directly tests a defensible growth story. If it passes, growth has a
real job: allocate fresh parameters only when old/new write manifolds collide, while preserving memory-free
inference. If it fails, we have a clean reason to prioritize LSM tiering and schema/exception accounting over
more growth rhetoric.

## Seventh corner: coding theory, not category theory

The most useful missing field is **coding theory for error-corrected distributed storage**. VSA gives
superposition; coding theory asks for redundancy, parity checks, erasure correction, and graceful failure.

A project-valid version would encode schema/fact targets across multiple independent write subspaces with
cheap parity-style consistency probes. During later writes, a generic syndrome signal detects which subspace
is drifting; correction or growth is triggered only when the code cannot absorb the error. This would not
beat the independent-fact bit lower bound, but it could change the failure mode from silent catastrophic
forgetting to detectable/correctable degradation.

I would not rank it above targeted growth yet. But it is the better way to make VSA concrete: not "store in
superposition and hope," but "store with redundancy, measure syndrome drift, and trigger compaction/growth
when correction fails."

## Decision

After `schema_comp`, I would build `grow_sep_decoy` first. It is the only candidate that simultaneously:

- keeps knowledge in weights with no inference memory;
- avoids full joint retraining;
- directly attacks rehearsal-free retention;
- has an existing positive foothold in R37-A;
- can make growth necessary through a fixed-capacity control.

LSM tiering is the next practical compute arm. VSA/coding is the higher-risk substrate branch. CLS/RG should
be folded into `schema_comp` metrics rather than spun up as separate pods.
