# Strategic response: current path, walls, and one wall-moving shot

Source read: `qa/claude/2026-07-09.19.01.37.md`

## Bottom line

I agree with the low-probability judgment for the current mechanism family, but I would sharpen the claim:
the evidence does not say "the project is dead"; it says "item replay plus surprise routing plus generic
growth will not reach the full goal." That family has produced a real engineering result, but it has not
changed the lifetime cost curve enough to justify the ultimate claim.

The right continuation is not more tuning of the same replay/router/growth loop. It is one or two explicit
cost-curve tests: can repeated structure be compressed into weights so marginal rehearsal per book falls, and
can growth become necessary only after the fixed model has exhausted that compression/write-allocation regime?
If those tests fail, the honest deliverable is a strong weights-only replay/self-distill system plus a clear
negative map of why rehearsal-free continual learning remains unsolved.

## Evidence assessment

The engineering win is real. R33 is a clean bakeoff: `ours` reaches all-seen 0.914 and all-para 0.826 over
six streams, with oldest-stream forgetting 0.0, no inference memory, and a single dense checkpoint. Naive,
continued fine-tuning, and LoRA merge all forget badly; external memory preserves old items but violates the
target inference constraint. R38 then bridges to real text: raw CPT essentially fails, while self-quiz plus
replay consolidation gives closed-book para-EM 0.893 versus RAG 0.973. This is exactly knowledge-into-weights,
not RAG, and it is worth banking.

But the same evidence also defines the ceiling. R33/R38 are replay/self-distill wins. They do not prove
sublinear lifetime learning. R43-ladder makes that explicit: full replay beats no replay, and random 0.5 replay
matches full replay in the small natural-text ladder, but surprise-gated replay does not beat random on real
self-contained text. The signal is real as a risk marker - high-bpt old items forget much more - but as a
router it does not produce the hoped-for O(number of exceptions) allocation on unimodal real text.

R38B-A/R40-s3 add the deeper reason: prior-anchored real-text facts can survive zero replay at a useful floor,
while independent/off-manifold facts collapse without maintenance. That is not a routing bug; it is the
exception ledger. If a book mostly reuses existing schemas, cost can be low. If it introduces arbitrary new
names, mappings, or facts, the current family still pays item-like cost.

The growth evidence is also correctly pessimistic. R23/R31/R32/R34 are enough to reject generic growth as a
story at this scale. R32 shows atomic single-step knowledge can be perfectly in weights while latent OOD
two-hop composition is exactly 0.0, even after direct two-hop train pairs fit. R34 shows the reachable
in-distribution composition case saturates with +0 growth and gets no meaningful depth advantage. That means
growth is neither rescuing the hard composition case nor needed for the easy one.

So: you are not giving up too early on the project. You are giving up at the right time on the current
mechanism family as a path to the full goal.

## The composition wall

I would not call R32/R34 fatal to all composition. I would call them fatal to the strongest implicit hope:
"store atomic facts into weights and expect latent no-CoT composition to appear automatically at 0.5B."

R32 is a severe but artificial OOD test: held-out endpoints are new combinations, and the model has no
explicit execution scaffold. It proves that memorized edges are not enough. R34 is the mirror image: when the
bridge surface makes the query in-distribution, +0 already groks fast and saturates near 0.98, so growth has no
headroom. The real-text question sits between those extremes.

My prior for real text:

- Familiar schemas already present in pretraining should transfer better than R32. The base model has many
  latent schemas for biography, geography, causality, institutions, chronology, and narrative events.
- Newly defined schemas, arbitrary synthetic relations, or book-local symbolic systems will not transfer
  reliably unless the system learns an execution procedure or compresses the schema explicitly.
- Therefore real composition is not hopeless, but it will not be solved by more item replay. It needs a
  schema/skill acquisition experiment where the metric is not only "old facts retained" but "marginal targets
  per additional book fall while held-out schema queries improve."

That distinction matters. Composition is probably not one wall; it is two: existing-schema activation and
new-schema acquisition. The current evidence kills automatic new-schema acquisition, not all existing-schema
activation.

## One shot most likely to move a wall

Pick schema-compressibility. It has the best chance of actually changing the cost curve while staying inside
the project constraints.

Why not the other three as the first shot:

- A genuinely rehearsal-free interference mechanism is the deepest prize, but the repo has already killed many
  local variants. `nswrite` remains useful, but R36-I/R39/R40 suggest protection quality and representation
  drift, not a clean missing regularizer, are the issue.
- State-as-weights/TTT is promising only if checkpointed as model parameters and consolidated; otherwise it
  risks becoming external memory by another name. It is worth a later rung, not the next single shot.
- Compression-detector reframing is useful diagnostically, but R43 shows detection alone does not buy much if
  the distribution is unimodal and the selected hard items remain hard to rescue.

Schema-compressibility directly attacks both replay cost and composition. It asks whether the system can store
rules/structures in weights and pay residual cost only for exceptions. That is the smallest claim that still
advances "small model grows into a larger model" honestly: growth becomes justified only if schema compression
works and then a fixed model saturates on residuals/collisions.

## Falsifiable 1-pod test

Run a compact `schema_comp` test on a surface that is neither R32-impossible nor R34-trivially-saturated.
Use repeated schemas with held-out instantiations, and measure the slope of retained targets per added book or
schema instance.

Suggested arms:

- `full_replay`: ceiling.
- `k0`: no replay floor.
- `item_k_matched`: same number of targets as the schema arm, randomly chosen or coverage-matched.
- `schema_commit`: train a compact schema/axiom/executor target plus a small residual exception set.
- `schema_random` or deranged-schema control: same budget, wrong or mismatched schema.
- Optional `nswrite+schema_commit`: only if cost is low; do not let it obscure the main comparison.

Pass criteria:

- Single dense checkpoint, no inference memory, no task id, no full joint historical retraining.
- `schema_commit` reaches at least 90% of `full_replay` old paraphrase retention while using clearly fewer
  item targets, or beats `item_k_matched` by at least +0.15 on held-out schema/composition queries.
- The marginal target slope falls as more instances/books are added: for example, book 2 and book 3 require
  fewer new committed targets per retained fact than book 1.
- Base-hop/general capability does not degrade beyond the existing bakeoff tolerance.
- Deranged schema does not pass; otherwise the gain is just extra supervision or capacity.

Fail criteria:

- `item_k_matched` ties `schema_commit`.
- Gains appear only on supported instances, not held-out schema queries.
- The schema target is effectively a hidden item ledger.
- Old paraphrase retention improves but residual target count stays linear in facts.

If this fails cleanly, I would stop calling schema compression an active path and move to the reframed
deliverable. If it passes, it gives a legitimate next growth trigger: grow only when the fixed model's
schema-compressed residual/collision map saturates and a grown arm beats fixed controls at matched compute.

## Reframing the ultimate goal

The honest ambitious version is:

Continual weights-only learning should acquire reusable schemas, skills, and prior-compatible facts into a
single checkpoint with bounded forgetting, while maintaining an explicit residual ledger for non-compressible
exceptions during training only. Inference remains memory-free. Full joint retraining is not the solution.
Growth is allowed only when fixed-capacity schema compression and residual protection saturate, and only if it
beats matched fixed-capacity or adapter controls on retention, new learning, and compute.

This is not surrender. It replaces "unbounded arbitrary fact memorization with no rehearsal" with a scientific
cost model:

`lifetime cost = reusable structure + exceptions + write interference + recompression`

The project can then claim progress if the reusable-structure term grows sublinearly with books and the
exception term is measured honestly. That is a real small-model-grows story: small models first compress and
reuse structure; growth is justified by observed saturation, not by aspiration.

## What I would do next

I would not run another surprise-router ladder except maybe to tighten R43 with more seeds if needed for the
paper. The next frontier experiment should be schema-compressibility with a hard matched-budget control.

Operationally:

1. Freeze R43 as "surprise is a risk signal, not a reliable router on natural self-contained text."
2. Bank R33/R38 as the engineering result: weights-only replay/self-distill works and beats standard CL
   baselines without inference memory.
3. Run one schema-compression 1-pod test with explicit slope/pass-fail gates.
4. Only after a schema pass, test growth as a residual collision/capacity response.

If schema compression fails, I would reframe immediately and stop presenting the current path as plausibly
solving the full frontier goal. The valuable output would still be strong: a reproducible weights-only
consolidation system, a compute-saving replay result, and a precise negative map of why rehearsal-free
continual learning remains hard.

## High-risk / high-reward brainstorming

1. Schema distillation as "program induction into weights." Let the model induce compact natural-language or
   latent rules from a book, then distill against adversarial generated probes that test the rule, not the
   original examples. The danger is hallucinated schemas; the control is deranged schema plus held-out
   entities/events. The win would be genuine O(number of patterns) maintenance.

2. Collision-to-schema discovery. Instead of treating write collisions only as interference, cluster current
   gradients/collisions within the new stream before any old replay. If collision clusters align with semantic
   schemas above deranged controls, use them to propose shared schema targets. This keeps the mechanism legal:
   no old item access, no inference memory.

3. Checkpointed TTT-state as a fast write substrate, followed by forced consolidation. Allow a fixed-size
   differentiable state that is saved as model parameters, but require a sleep step that compresses it into the
   dense model and frees capacity. Pass only if the final dense checkpoint works after deleting the write
   traces. This avoids TTT degenerating into a per-book cache.

4. MDL-based growth trigger. Track residual description length after schema compression, not loss plateau or
   occupancy. Grow only when residual bits per new book stop falling, collision clusters persist, and fixed
   controls cannot preserve old plus new knowledge at matched compute. This would make growth a measured
   necessity.

5. Learn an execution skill separately from facts. R32 may be an execution failure, not storage failure. Train
   a small explicit executor on schema-agnostic chains, then test whether new book facts can be stored as
   atomic axioms and composed by the executor without item-level endpoint replay. If it passes, the project
   stores axioms, not all derived conclusions.
