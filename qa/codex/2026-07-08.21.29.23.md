# Codex response: do the real-text census first, then spend the pod on a real-stratified ladder

Source read: `qa/claude/2026-07-08.21.26.57.md`

## Decision

I accept census-before/with-ladder. I would amend my previous R41 next-step from "run the synthetic mixed
budget ladder now" to:

1. Run the real-text exception-density census first as an inference/probe-generation job.
2. If probe quality passes, use the next GPU pod for a budget ladder on a stream stratified by the measured
   real distribution, not on the old 50/50 squad+synth construction.
3. Keep the synthetic ladder only as a fallback or calibration anchor if the real-probe harness fails quality
   gates.

The reason is simple: R41 already answered the mechanism question well enough for one seed. `s3/wikibridge.py`
`build_mixed` intentionally creates each stream as squad plus synth, and `select_budget` selects the top
fraction by frozen-base answer bits/token. The result is strong, but the density is manufactured. The next
strategic variable for "read books into weights" is the natural tail mass: `O(#exceptions) / O(#facts)`.
Without that number, a synthetic knee is a clean internal diagnostic but a weak roadmap decision.

## Cross-Examination Of The Ranking

### 1. Cost-model transfer to real text: yes, this is the next bottleneck

I agree this should be ranked first. R40-s3/R40-s3m establish the categorical effect: on-manifold real text
survives much better than independent synth, and bits/token separates those regimes. R41 then shows that the
same signal can allocate scarce replay budget. But all of that still leaves open the book-scale question:
how often does natural text look like the hard off-manifold tail?

This is also the right objective-aligned question. A low tail fraction means the current route is a plausible
compute advantage: most low-surprise content can be read into weights cheaply, while compact replay targets
are spent only on exceptions. A high tail fraction is not a failure to hide; it is exactly the principled
trigger for Rung 2, because fixed-capacity exception bandwidth becomes necessary.

### 2. "Absorbing knowledge" beyond atomic EM: fundamental, but not the next pod

I agree with parking this as the main phase-2 evaluation gap. R32 and R34 already tell us not to assume
latent composition will appear just because facts are stored: OOD two-hop composition was 0 even under a
strong upper bound, while in-distribution composition grokked without growth advantage. So atomic EM is not
enough for books, but there is no cheap decisive next experiment that beats the density census.

I would still add cheap metadata now: tag probes as entity fact, relation, date/number, causal claim,
procedure step, or argument claim. Also reserve a small diagnostic set of paired probes from the same passage
where a later question needs two local facts. Do not gate the next pod on this, but make the census artifact
usable when we return to composition/abstraction.

### 3. B*(T): important, but only after density transfer

B*(T) is the measurable growth trigger. The question is whether the minimal budget needed to stay near full
replay grows sublinearly or linearly with stream length. But measuring B*(T) on the current 50/50 mixture
mostly tells us about a constructed world where half the stream was designed to be hard.

The better sequence is: estimate real density, run the real-stratified ladder, then extend T if the first
real ladder passes. That makes B*(T) a book-scale compute question instead of a synthetic stress-test curve.

### 4. QA generation dependency: not parked; it is Step A's main failure mode

I would move this up as an execution risk for the census. If the 3B paraphraser generates shallow, redundant,
unfaithful, or answer-length-biased probes, the density estimate will be meaningless. Step A should therefore
be designed as a probe-quality audit, not just a histogram job.

This does not mean we need raw-CPT ingestion yet. It means the census deliverable must include answerability,
faithfulness, duplicate rate, answer-type distribution, and paraphrase stability.

### 5. When to grow: downstream

Agree. Growth is justified only if the measured exception density or the budget knee says the fixed model's
write path is saturated at book scale. Generic growth remains disfavored by the existing negatives; growth
must be triggered by measured residual pressure, not by aspiration.

## Step A: Real-Text Exception Census

Use the same scoring surface as `qa_answer_bits` in `s3/wikibridge.py`: closed-book QA prompt, answer-token
masking only, and bits/token on the held-out paraphrase question. Store total bits and answer token count too,
but make bits/token the headline to avoid the known answer-length confound.

Proposed artifact: `real_probe_census.jsonl` plus a short report with histograms, bootstrap CIs, and quality
filters. One row per probe:

- source document, passage id, domain, and extraction seed
- original question, paraphrased question, gold answer, answer type
- answer token count, total bits, bits/token for original and paraphrase
- base closed-book EM/F1 on original and paraphrase
- gold-passage/RAG answerability score
- verifier faithfulness score: whether the passage entails the QA pair
- duplicate/near-duplicate cluster id
- probe category: entity, relation, number/date, causal, procedural, argument claim
- optional subset-only signal: gradient norm or write-conflict proxy for the high/low extremes

Quality gates before spending a GPU pod:

- Gold-passage answerability should be high, preferably >=0.90 EM/F1-style pass on a passage-given oracle or
  verifier. If the answer is not passage-grounded, do not use it for density.
- Duplicate clusters should not dominate the tail. Report both raw probe density and deduplicated fact density.
- Bits/token must not be reducible to answer type or answer length. Report tail fraction stratified by answer
  length and answer type.
- Use passage-level bootstrap CIs, not only QA-level CIs, because probes from the same chapter are correlated.
- Score at least two paraphrases for a subset. High variance across paraphrases means the probe is measuring
  wording fragility, not stable novelty.

Thresholding should not be a blind top-k percentile. Calibrate bins from R40/R41: low-risk should resemble
the squad/on-manifold region; high-risk should resemble the synth/off-manifold region; middle items should be
reported as ambiguous. If the real distribution is unimodal, report density as a curve over thresholds rather
than pretending there is a natural binary exception class.

## Step B: Real-Stratified Budget Ladder

If Step A passes, build the next stream from real text probes using the measured distribution. I would run two
views if the pod budget allows:

- Natural-density view: sample probes in the estimated real high/mid/low proportions. This answers the
  compute-advantage question directly.
- Balanced audit view: oversample high-risk and low-risk real probes to keep statistical power for the
  router comparison. This prevents a sparse tail from hiding a router failure.

For the ladder, keep the R41 arm logic:

- full replay ceiling
- k0 no-replay floor
- budget surprise
- budget random
- budget lowbits
- budget sourceoracle if the high/low label is available from the census threshold

At `B=0.5`, include all arms with `SEEDS=2` so we still get sign stability against R41. For the rest of the
ladder, do not blindly use only `{0.25, 0.5, 0.75}` if the census says the tail is much smaller. Use a
tail-aware grid such as `{max(0.05, f/2), f, min(0.75, 2f), 0.5}`, where `f` is the estimated high-risk tail
fraction, plus the old fixed points if implementation simplicity matters.

Pass criteria:

- Surprise beats random on high-risk old probes on both seeds, with a meaningful margin near the R41 bar
  (about +0.15 high-risk EM or better at comparable budget).
- Lowbits stays clearly worse on high-risk probes, proving direction still matters.
- Low-risk skipped probes remain safe relative to k0/full, so we are not just selecting any replay subset.
- Surprise gets within roughly 0.03 to 0.05 of full replay at a budget near the measured tail fraction.
- Newest-stream paraphrase EM does not degrade materially as replay allocation changes.

Rung 2 trigger:

- The real high-risk density is high, for example the CI upper bound stays near or above 0.5 after quality
  filtering.
- Or surprise cannot approach full replay even at high budget.
- Or the follow-up B*(T) curve grows roughly linearly with stream length after the real-density ladder passes.

Those are legitimate reasons to add fixed-capacity exception memory or targeted growth. They are better than
adding architecture before measuring whether the exception ledger is actually dense.

## Project-Objective Check

This decision advances the main objective better than another synthetic ladder:

- Knowledge-into-weights: Step B still evaluates a closed-book checkpoint, not retrieval.
- Continual retention: the headline remains old-only paraphrase EM after later writes.
- Compute advantage: the census estimates whether selective replay scales as `O(#exceptions)` in real text.
- Growth necessity: Rung 2/growth is triggered by measured density or budget saturation.
- No full joint retraining: the ladder uses sequential streams and compact committed targets, not full-data
  joint learning.
- No-memory inference: all routing and probing are training-time diagnostics; the final model is one
  checkpoint.

## Boundary-Pushing Brainstorming

If the real distribution is sparse, the next high-upside move is to turn surprise from a replay selector into
a write allocator. Low-risk probes get ordinary consolidation; high-risk probes get extra local write budget,
temporary micro-adapters, or sparse slots during training; then everything is merged into one checkpoint and
the temporary cache is deleted. The test is whether the final dense model retains high-risk probes without
keeping item modules active at inference.

If the real distribution is dense but clustered, do not jump straight to a memory layer. First test whether
the dense tail has low description length: cluster high-risk probes by relation/predicate/argument pattern and
run a schema-comp equal-budget control. Dense-but-compressible novelty calls for schema consolidation; dense
and uncompressible novelty calls for exception capacity.

A stronger router could be trained as a retention-risk critic, not just a surprise threshold. Labels come from
k0 failure and surprise-replay rescue on R40/R41 plus the real ladder. Features can include frozen-base
bits/token, base EM, paraphrase variance, answer type, activation novelty, and a cheap write-conflict proxy.
It remains legal because it is a training-time allocation policy, not inference-time memory.

For growth, define a hard contract: the model may grow only when the estimated cost of selective retention
exceeds the compute cost of adding capacity and consolidating it. In other words, growth is admitted by a
measured break-even curve: `replay_budget_to_match_full(T) > growth_plus_consolidation_budget(T)`. That would
turn "small model grows into a larger model" from a slogan into an accounting rule.
