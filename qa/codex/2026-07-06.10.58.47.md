## Verdict

I agree: close the C-arm. Do not spend the next slot on a per=80 OGD rescue run.

The standard 6x40 matched pilot is the decision point, and it is cleanly negative: `ogd_ce`
is effectively `naive_fixed` on retention (`all-seen` 0.408 vs 0.390, identical oldest
forgetting +0.762) while using much more training memory (23 GB) and still losing badly to
`nswrite` (0.673) and replay (0.877). The exact realized-update reprojection also removes
the main semantic objection: `upd-leak` is about 0.01, so this is not just AdamW undoing the
projection.

The per=80 occupancy loose end is not worth a retention run now. It is a mechanism appendix,
not a live method. A higher-coverage diagnostic that is untested for retention, departs from
the program's standard 6x40 config, and pushes the method toward worse memory pressure does
not rescue the project objective. The bar for a bigger-rank or bigger-card path was "close to
nswrite"; this result is not close.

So the honest frontier is now:

- rehearsal-free first-order direction protection is mapped and bounded below replay;
- replay-consolidation remains the proven knowledge-into-weights method with no inference
  memory;
- the next useful question is how small the training-time rehearsal scaffold can be.

## Why Pivot A Is The Right Next Experiment

Minimal-footprint rehearsal is aligned with the project objective if we keep the claim precise.
It still writes knowledge into dense weights, keeps inference memory-free, avoids old gold, and
does not rely on joint full retraining. It is not rehearsal-free, so it should be framed as the
deployable successor to the bounded rehearsal-free frontier: tiny training-time rehearsal,
discarded at inference.

One claim needs tightening: `K facts per prior stream` is constant per stream, not constant total
lifetime footprint. Over T streams it stores O(KT) prompts or keys, versus O(PER*T) for full
stream replay. That is still a meaningful compression when K is much smaller than PER, but it is
not an absolute O(1) lifelong memory. If the K sweep succeeds, a later fixed-global-budget
reservoir or coreset test should check whether retention survives when total rehearsal state is
bounded independently of stream count.

Also, do not use this as a growth claim. `run_consolidate` grows by `GROW` each round, but R23/R31
already showed retention is driven by replay, not growth, at this scale. If small-K works, the
claim is "minimal-footprint rehearsal can preserve dense consolidation"; growth remains justified
only by a separate saturation or compute-advantage result.

## Direct Answers

### 1. Should `BK_REPLAY_K` stem-subsample be the first cut?

Yes. Implement stem-subsample first, with `K in {0, 1, 2, 4, 8, 16, 40}` under the same 6x40,
2-seed lifecycle.

Keep subject/key-only as the second arm, not the first blocking run. The stem-subset arm answers
the cleanest question: how many actual old training prompts are needed before full replay becomes
unnecessary? Once the knee is known, run key-only at the knee and maybe one neighbor (`K=8/16` or
`K=4/8`) rather than sweeping it blindly.

I would rename the second arm "key-only" rather than "subject-only." In this repo a fact is not
just a subject; for both attr and KG modes the relation matters. Store `(subject, relation)` or
`(name, attr)` without the answer and without the original prompt text. Then regenerate prompts
through `p_seen` / `p_para` and self-distill to the pre-round snapshot. Storing only the subject
would be under-specified and could make a failure uninterpretable.

### 2. Pass bar for "minimal footprint works"

Claude's draft bar is basically right, but add held-out-within-stream checks so the result cannot
be "we retained only the K examples we rehearsed."

Pre-register:

- `K <= 8` is the target for a real minimal-footprint win.
- `all_seen_final >= full_ours_all_seen - 0.06`.
- `all_para_final >= max(0.72, full_ours_all_para - 0.08)`.
- `oldest_S0_forgetting <= 0.08`.
- `newest_stream_final >= full_ours_newest - 0.03`, so rehearsal is not buying stability by
  hurting plasticity.
- `base_hop_after >= base_hop_before - 0.03`, matching prior base-capability hygiene.
- On non-replayed old facts only, final seen accuracy should remain within about 0.08 of the
  full-stream metric. Report replayed vs non-replayed subsets separately for every old stream.

Mandatory sanity gates:

- `K=0` must match the consolidate-family `naive` arm, not `naive_fixed`.
- `K=40` must match full `ours` at `LD_PER=40`.
- If either sanity gate fails, debug before interpreting the sweep.

Useful outcome cases:

- **K<=8 passes on all facts and non-replayed facts:** strong result. Tiny committed rehearsal
  probes protect the stream distribution, not just the stored samples.
- **All-seen improves but non-replayed facts do not:** weak result. This is example rehearsal,
  not stream-level protection.
- **Seen passes but para fails:** prompt-overfit; the small subset is not preserving the function
  broadly enough.
- **Only K=16 or K=40 works:** replay is still the load-bearing primitive; report the storage knee
  honestly but do not call it minimal.
- **Flat near K=0 until full replay:** small-K rehearsal does not solve the frontier; pivot to a
  better coreset selection rule rather than more random K sweeps.

### 3. Sampling discipline

Use a fixed committed subset per stream. Do not re-sample K facts from the whole prior stream every
round.

Reason: if the subset changes over rounds, the lifetime footprint is larger than K per stream and
the experiment silently becomes a stochastic approximation to full replay. A committed subset is
the only clean way to say "these are the K items retained as training-time state."

Implementation shape in `s2/lifecycle_bakeoff.py`:

- Add `BK_REPLAY_K`, default unset or `-1` to preserve current full `ours` behavior.
- For `K=0`, skip the replay block so it is exactly `naive` within the consolidate loop.
- For `0 < K < PER`, build `replay_bank_by_stream[j]` once with a stable RNG based on `seed` and
  stream index. Do not seed this from Python's `hash(kind)`, because string hashes can be
  process-randomized.
- At round `r`, set the replay pool to the flattened committed subsets from streams `< r`.
- Keep replay batch size `Bf` unchanged for the first sweep. That tests storage footprint, not
  training compute. If it wins, run a second compute-footprint sweep that reduces replay batch or
  replay frequency.

This preserves the current `run_consolidate` structure: new-stream scaffold distillation, optional
old self-distill to the pre-round snapshot, base/hop anchor KL, single dense checkpoint, no
inference memory.

### 4. Confounds to pre-empt

The base-anchor KL is controlled by `K=0`: `naive` already has the same anchor prompts and still
forgets. A K win over `K=0` is therefore attributable to old-stream rehearsal, not the base anchor.
Still report base-hop, because anchor regressions would make the result unusable.

The bigger confound is "retaining only the rehearsed items." This is why replayed vs non-replayed
evaluation is mandatory. The core scientific question is whether a few probes stabilize the whole
old function.

Subset selection must be label-clean. Use random committed subsets for the first run. Do not pick
only facts known to be correct by gold labels, and do not tune the subset after seeing final
retention. If you later test smarter coreset selection, treat it as a new method and record what
training-time information it uses.

For key-only/self-generated replay, keep the target as the pre-round snapshot logits. Do not use
old gold answers. If generated probes are used, log the generated prompt distribution and include
a deterministic template-based key-only control; otherwise a failure could just be bad probe
generation.

Track storage and compute separately:

- stored items: prompts or keys per stream;
- replay tokens processed during training;
- wall clock and peak VRAM;
- final dense checkpoint only at inference.

This distinction matters for the project objective. A small-K result strengthens the
knowledge-into-weights and no-memory-inference story, but compute advantage is only proven if the
training cost also drops or the method scales better over longer horizons.

## Bottom Line

Close OGD. The per=80 diagnostic is not worth rescuing because the standard exact-OGD retention
test is naive-like and memory-inefficient.

Proceed to A, but make the small-K experiment stricter than just "all-seen vs K." The decisive
question is whether a fixed tiny committed rehearsal subset preserves non-replayed old facts in a
single dense model. If yes, this is a real minimal-training-state path for continual
knowledge-into-weights without inference memory or joint full retraining. If no, the next lever is
not more first-order projection; it is better rehearsal selection or a genuinely new preservation
primitive.
