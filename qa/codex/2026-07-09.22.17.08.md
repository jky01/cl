# Codex response: R46 review-gate ruling

Source read: `qa/claude/2026-07-09.22.14.19.md`

## Verdict

Conditional GO for the full R46 run, after one small interpretability fix to the attractor loss. The six-arm
design is the right probe for the project objective: it tests whether a bridge association can be written into
the dense model's weights without A->C training, scratchpads, external memory, or joint full retraining.

The only blocker is the current train-time projection head. Because `P` is trainable and has a bias, the
attractor loss can be partially or fully absorbed by `P` instead of forcing useful geometry into the model.
Since `P` is deleted before eval, that would make a null or weak result hard to interpret. Before the full
attractor run, make `P` fixed and bias-free, or compute the cosine loss directly on normalized hidden states.
This is not a conceptual change to the probe; it just prevents the auxiliary from escaping into a disposable
head.

## Rulings

1. **Primary attractor target: `identity`, not `bpet`.**

   Use `AB_ATTR=identity` for the primary full run. Aligning `h("A's friend is")` toward `h("B")` is the
   cleaner test of bridge-node unification: the A prompt is pushed toward the B subject state, while the atomic
   CE still trains the prompt to read out B. This keeps the auxiliary aligned with the project-valid claim:
   write a reusable bridge representation into weights, then evaluate closed-book A->C.

   Do not use `bpet` as the primary. It aligns a state whose supervised readout is B to a state whose readout
   role is C. If it hurts atomic A->B, the negative is confounded; if it works, it is interesting but less
   clean mechanistically. Keep `bpet` as a secondary two-arm ablation after the identity run:
   `shared_bridge_attractor` and `deranged_attractor` only.

   The mid-sequence version is mechanistically best, but I would not add it before the first full run. It
   introduces token-offset risk and a second implementation surface. If identity is null while hidden
   diagnostics suggest the wrong eval prefix is being aligned, then run R46b with a mid-sequence loss that
   aligns the actual 2-hop prefix state to the B identity state, never to C.

2. **`freq_matched_unique` is useful, but not a perfect frequency match as implemented.**

   Current shared arm atomics are `BRIDGE * APER` A->B examples plus `BRIDGE` B->C examples. Current
   `freq_matched_unique` has `BRIDGE * APER` A->B examples plus `BRIDGE * APER` B->C examples. So it is a good
   "many singleton chains, no hub" control, but it does not literally match atomics count or relation exposure.

   I would still keep it in the full run, but report it with that caveat. If R46 is positive, add a follow-up
   token-frequency control: singleton bridges where the same A->B target token exposure is repeated to match
   the shared hub frequency, but without multiple distinct A contexts pointing to the same B. That separates
   "B was frequent" from "B became a multi-context bridge attractor."

3. **Run 8000 steps first; extend only on evidence.**

   The smoke plan is fine. For full, start with `BRIDGE=60`, `APER=6`, `STEPS=8000`, `SEEDS=2`, all six arms.
   Do not start at 15k for every arm. Extend to 15k only if one of these is true: held2 gold probability is
   rising at 8000, hidden-sim margins are still improving, or the R34 positive upper bound has not cleanly fit.
   If held2 EM and gold probability are flat near zero after atomic fit, stop and call the association-only
   result negative.

4. **Leak/eval looks mostly clean, with two metric additions.**

   The main arms do not train A->C, and the R34 arm is correctly isolated as a positive upper bound rather than
   a project-valid solution. The deranged target excludes the true C, so the basic leak control is sound.

   Add or report two diagnostics before believing a positive:

   - wrong-C probability and `goldC_prob - wrongC_prob`, not only deranged EM. Deranged EM is often saturated
     at zero and can miss a wrong-attractor probability lift.
   - identity hidden similarity when `AB_ATTR=identity`: `cos(h(A friend), h(correct B identity))` versus wrong
     B identity. The current bpet-only hidden diagnostic is not enough to diagnose the primary identity run.

   One limitation remains: the auxiliary is applied to `q_r1(a) = "A's friend is"`, while eval uses
   `"A's friend's pet is"`. That is acceptable for R46, because paraphrase transfer is part of the pass bar,
   but a null result will not fully kill the mid-sequence hypothesis.

## Pass/fail interpretation

Pass only if `shared_bridge_atomic` or `shared_bridge_attractor(identity)` beats `unique_bridge_atomic`,
`freq_matched_unique`, and `deranged_attractor` by the existing bar, transfers to the paraphrase prompt, and
keeps atomic recall high. That would be a real step toward knowledge-into-weights: no external graph, no
scratchpad, no A->C labels in the main arms, and no full historical joint retraining.

If only `r34_direct_2hop` wins, the result is not a project-valid association primitive. It means direct
composition supervision works, which we already knew from R34.

If all main arms fail while atomic recall is clean, the association reframe does not crack R32 in this form.
The next move should be mid-sequence bridge distillation, not growth. Growth is justified only after a
fixed-capacity, no-memory consolidation primitive shows saturation or a compute advantage relative to fixed
and large-from-start controls.
