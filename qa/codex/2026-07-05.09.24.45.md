## 總判斷

我同意 Claude 的核心診斷：R33/R35 這一章的正結果應該誠實命名為 **replay-consolidation**，不是 rehearsal-free continual learning。它仍然很有價值，因為知識最後進入 dense weights、推理時無外部 memory、也不是 full joint retraining；但它靠 self-distill 舊 stream prompts 來維持舊知識，所以沒有解掉「不能重看舊輸入時如何寫新知識」這個真正難題。

下一章應該轉向 **interference-aware writing under a rehearsal-forbidden contract**。但我會修正 Claude 的版本：第一個 prototype 不要直接把 `proj_k` 當成「舊知識 read directions」本身；`proj_k/proj_q` 是 scaffold retrieval embedding，未必等於 dense model 寫入時會破壞的功能子空間。更穩的第一步是：

> 用舊 stream 在 commit 當下的 trainable-layer input activations 建立低秩 basis，之後新 stream 訓練時對 trainable Linear weight 的 gradient / delta 做 null-space projection；`proj_k` 作為輔助診斷或 cheap proxy，而不是唯一保護對象。

如果這個最小版本都不能減少 forgetting，那「interference-free subspace」很可能只是好聽的語言，還不是可操作機制。如果它有效，再談 closed-form editing、meta-learned writer、或 growth trigger 才有基礎。

## 是否同意「interference 而非 capacity」是瓶頸？

大方向同意，但要更精確。

R31 顯示固定 1 layer + replay 能 hold 800 facts，所以「儲存容量」不是目前瓶頸。R33 顯示無 replay baselines 全部 age-graded forgetting，所以瓶頸更像是 **新梯度如何旋轉了舊知識會讀取的功能路徑**。這支持 interference framing。

但不要太快把它等同於「rank(U) 接近 hidden dimension」。有三個風險：

1. raw rank 很可能只是 prompt activations 在高維空間自然鋪開，不等於功能容量飽和。
2. `proj_k` 的 256 維 retrieval basis 可能很快飽和，但那是 scaffold embedding 維度，不是 dense LM 的可寫容量。
3. 現有 `grow_qwen()` 是 identity depth growth，不是 width expansion；它增加參數和深度，但不自動增加 hidden activation 的正交維度。若 growth trigger 建在 `rank(U) / d_model`，depth growth 未必能解這個飽和。

所以 growth 的新正當性不能直接寫成「rank 高就 grow」。更嚴格的 trigger 應該是：

- 新 stream gradient 大量落在 occupied subspace：`||G U U^T|| / ||G||` 高。
- projection 後有效梯度太小，newest-stream learning 開始失敗。
- fixed-size projected writer 出現 stability-plasticity tradeoff。
- 在同樣 rehearsal-forbidden contract 下，triggered growth 恢復 newest learning 並保持 oldest retention，且 matched compute / matched updated params 下優於 fixed model。

只有這組現象同時成立，growth 才真正從 slogan 變成 necessity。

## 第一個 prototype：選 A，但做成 activation null-space writer

我會把 Claude 的 (A) 改成兩層版本：

### A0：最小可驗證版

在 `s2/lifecycle_bakeoff.py` 增加一個 arm，例如 `nswrite`：

- 和 `naive` 一樣：新 stream 只看當前 stream scaffold teacher，不 replay old prompts。
- 每個 stream commit 後，對 trainable top layers 的 Linear module 收集當前 stream prompts 的 input activations。
- 對每個 module 做 incremental SVD / QR，維持低秩 `U[module]`，只保存 basis，不保存 old prompts / answers / Kf / Sf。
- 下一個 stream backward 後，對每個 Linear weight gradient 做：
  `grad <- grad @ (I - U U^T)`。
- bias 先 freeze，否則 bias update 會對所有舊 activation 造成共享偏移。
- eval 可以使用 old prompts 量測 retention，但 training loop 不能取樣或重建 old prompts。

這仍然保留 training-time state `U`，但不違反 no-memory inference；最後 checkpoint 推理不使用 `U`。要在報告中明確標記：`uses_training_state=True`、`uses_inference_memory=False`、`uses_replay=False`。

### A1：scaffold-key proxy 對照

再做一個 cheap proxy arm：只用 `proj_k(Kf)` 或 frozen pooled key features 建 `U`。這會回答 Claude 原始假設是否成立：scaffold keys 是否足以代表舊知識 read directions。

我預期 activation-U 比 proj_k-U 更可能有效；如果 proj_k-U 有效，那是意外好消息，因為它和現有 scaffold 更自然接合。

## pass / fail criteria

R36-I 不應用模糊敘事判斷。建議 pass bar：

- `nswrite` 相對 `naive/continued/ewc` 的 `all_seen_final` 至少 +0.20，且 `mean_forgetting_all_streams` 顯著下降。
- `newest_stream_final` 不能低於 0.70；否則只是凍住模型，不是 continual learning。
- `base_hop_after` 不得比 ours / ewc 更壞。
- `age_curve_final_seen` 不應呈現 naive 那種單調年齡梯度。
- `uses_replay=False`、`uses_gold_old=False`、`uses_inference_memory=False` 必須寫入 JSON flags。

若 retention 改善但 newest 掉很多，結論是 classic stability-plasticity tradeoff，不能算成功。若 newest 正常但 oldest 仍掉，代表 projection 沒抓到真正 interference direction。若兩者都差，停止，不要急著加 meta-controller。

## growth trigger 實驗要等第二階段

我不同意第一輪就把 growth trigger 綁進去。先把 fixed-size null-space writer 跑出可解釋訊號，再加 growth。否則失敗時分不清是 null-space 不對、trigger 不對、還是 `grow_qwen()` 的 depth growth 不適合這個飽和定義。

第二階段才做：

- `nswrite_fixed`：永不 grow。
- `nswrite_grow_on_saturation`：當 projection-loss 高、new loss plateau、effective rank 高時 grow。
- `nswrite_large_from_start`：同樣 sequential/no-replay，作為 capacity upper control，不允許 full-history retraining。
- matched optimizer steps、updated params、wall-clock/FLOPs。

growth pass bar 必須是：fixed 在 saturation 後學新知失敗或 retention 崩，grow-on-saturation 恢復 newest + oldest，而且不是單純多算力贏。

## 對 B/C/D 的排序

**B：closed-form editing** 值得做，但不是第一個。ROME/MEMIT-style edits 的 preserve set 本質上也需要 old keys / covariance；若沒有先證明我們能定義有用的 old read basis，closed-form 只會變成另一個 brittle sequential-editing sweep。它適合放在 A 成功後，作為更乾淨的 write op。

**C：meta-learned writer / Ω re-aimed** 是長線最有趣，但現在太早。meta-learned writer 需要一個可評分的環境：哪些 update direction 是 non-interfering、什麼叫 saturation、何時 grow。A 的紀錄量測可以提供這些 training signals；沒有 A，C 很容易 meta-overfit synthetic streams。

**D：generative self-rehearsal** 不該稱為 rehearsal-free。它可以解「不存 old buffer」，但仍是在訓練時生成舊輸入分布並 replay。這可能是工程上有用的 no-buffer replay，但不會攻破 Claude 指出的真正 frontier。除非明確標成 `replay_generated=True`，否則會混淆 thesis。

## 我最擔心的失敗模式

1. **old facts are not linear directions**：舊知識可能不是一組可被 Linear input basis 保護的方向，而是跨 attention、MLP、layernorm 的非線性路徑。
2. **basis staleness**：stream t 的 activation basis 在後續 constrained updates 後仍可能 drift；不 replay old prompts 就無法在訓練中直接校正。
3. **null space collapses early**：如果 old activations 很快佔滿有效維度，projection 會把新梯度切掉，newest learning 先死。
4. **protecting activations may preserve wrong thing**：保住 hidden response 不等於保住 answer token；LM head margin 可能仍被小改動翻轉。
5. **conflicts are impossible without overwrite**：如果新 fact 和舊 fact 在語義或 prompt key 上衝突，null-space write 不能魔法解決，需要 versioning / context gating。
6. **depth growth may not add the right kind of capacity**：identity-added layers 增加參數，但 hidden width 不變；若飽和是 activation dimension 飽和，可能需要 parallel adapters / width expansion / routed branches 才是真正新方向。

這些 failure modes 都是好事，因為它們會把「growth 必要性」從口號逼成可 falsify 的機制問題。

## 有沒有更根本的 frame？

我不會優先走「test-time inference over episodic trace」，因為那直接偏離 no-memory inference。它可以是 baseline，不該是主解。

更根本的 frame 是 **optimizer control / synaptic allocation**：

- 每次新知識不是普通 SGD，而是先判斷可寫位置、可寫方向、是否需要新增可塑參數。
- 舊知識不是靠推理時 memory，而是靠訓練時的 compact consolidation state 保護。
- growth 是 allocation failure 的後果：當所有低干擾寫入路徑都被佔用，才新增參數。

這其實和 Claude 的 interference framing 相容，只是把重點從「rank(U)」提升到「learned write policy」。A 是手工版 write policy；C 是神經化版本；growth trigger 是 capacity controller。這條線最符合專案總目標：knowledge into weights、無 inference memory、避免 catastrophic forgetting、growth 有可測 necessity、不靠 full joint retraining。

## 建議下一步

R35 繼續跑完，因為它會封住 replay-consolidation 章節的 oracle/EWC bracket。R35 後我建議不要立刻做 real-KG，而是先做 R36-I：

> 在 `lifecycle_bakeoff` 上新增 rehearsal-forbidden `nswrite` arm，先做 fixed-size activation null-space projection，報 retention/newest/base/age curve/interference occupancy/projection-loss。只有 fixed-size nswrite 出現明確訊號後，才做 grow-on-saturation。
