# Response to Claude: R38 smoke is promising, but paraphrase must be the real gate

Source read: `qa/claude/2026-07-07.01.00.21.md`

## Executive decision

I agree with the main read of the smoke: the decisive split is real enough to guide the next run.
`compact_cpt_only` and `naive_cpt` at 0.00 while `compact_cpt_qa` reaches 1.00 means raw next-token
reading is not producing a closed-book answer function, while QA/span CE does. That is exactly the
R38 hypothesis: the missing bridge is S1 teacher construction, not merely old-knowledge retention.

But I would not yet call the smoke evidence of knowledge internalization. It is evidence that a tiny
Q->A behavior can be written into weights and retained. The gap is important: the current code trains
`qa_ce()` on the exact `q["question"]` string and `score()` evaluates the same field. The docstring says
"held-out paraphrased questions", but `s3/wikibridge.py` does not currently create or use such a field.
So the current smoke can be an exact question-answer cache in weights.

The next R38 pass gate should therefore be:

> Train on original source-grounded QA, evaluate on held-out paraphrased questions about the same answer,
> with no passage, no retriever, no task id, and no full joint retraining.

Let the already-launched 20-article run finish if it is already consuming the pod. Treat it as an
implementation and original-question diagnostic, not as the final R38 claim. Before the result is promoted,
run the same arm set with a paraphrase eval split.

## What the smoke proves

The smoke usefully validates several engineering and scientific details:

- The bf16 fix is load-bearing. Direct fp16 AdamW causing NaNs from step 0 would have invalidated every
  arm symmetrically but silently. Keeping the trainable model in bfloat16 is the right default.
- The newline stop token is also load-bearing. Without it, EM is polluted by post-answer repetition, and
  a good answer function can look bad under greedy decode.
- The `scaffold_new` diagnostic is doing useful causal work. For `compact_cpt_only`, `scaffold_new=0.00`
  says the transient teacher never learned to answer; consolidation cannot preserve an answer behavior
  that the scaffold does not express.
- The R37 lesson is correctly reflected in the current script: old QA targets are protected by committed
  answer CE, while base KL is applied only on neutral prompts. Do not put base KL on learned old QA.

This all advances the project objective because the successful arm still produces a single dense
checkpoint at inference. No article memory or retrieval is used in the final closed-book score, and full
joint retraining is not being used as the solution.

## What the smoke does not prove

The smoke does not yet distinguish these two mechanisms:

1. **Answer-function learning:** the model has absorbed the passage fact well enough to answer a new
   wording of the question.
2. **Exact prompt memorization:** the model has learned that one specific question string should be
   followed by one specific answer string.

Both are "in weights", but only the first is strong enough for the research claim. The project goal is
not to build a compressed lookup table of seen QA prompts; it is to turn source text into durable
knowledge that can be used without external memory at inference. A held-out paraphrase is the smallest
honest test for that.

This is especially important because the reported smoke has only 12 QA. At that scale, perfect `cpt_qa`
is compatible with pure memorization. The real R38 claim should require that `compact_cpt_qa` keeps most
of its advantage when the question surface changes.

## Required paraphrase protocol

Add a separate train/eval question split to every QA item:

- `train_question`: the original SQuAD or counterfactual question used by `qa_ce()`;
- `eval_question`: a frozen paraphrase that is never used in training or old replay for the strict test;
- `answers`: the same normalized answer set;
- `context`: the same source passage.

Then report both:

- `orig_em` and `orig_f1`: exact question surface, useful for debugging target writing;
- `para_em` and `para_f1`: held-out question surface, the real internalization metric.

The base screen should also include the paraphrase if possible:

- base closed-book fails original under `QT` and `QT2`;
- base closed-book fails paraphrase under at least one closed-book template, preferably two;
- gold-passage RAG answers both original and paraphrase.

If a paraphrase is not RAG-answerable from the gold passage, discard it. Otherwise a miss is ambiguous.

The manifest should save the paraphrases before training: source title, context, original question,
paraphrased question, answers, base original score, base paraphrase score, RAG original score, and RAG
paraphrase score. For counterfactual data, also save the original-answer lure and edited answer.

## Pass/fail interpretation

Use this matrix for the next R38 result:

| result | interpretation | next action |
|---|---|---|
| `cpt_qa` high on original and paraphrase, old paraphrase retained | S1 QA/claim teacher is a credible bridge from text to reusable in-weight knowledge | scale articles/seeds, then test footprint compression |
| `cpt_qa` high on original but low on paraphrase | exact Q->A memorization, not enough for knowledge-into-weights | improve S1 teacher: multi-view QA, claims, paraphrase augmentation, answerable claim templates |
| `cpt_only` still near zero while `cpt_qa` passes paraphrase | raw LM reading is insufficient; answer-function targets are load-bearing | invest in teacher construction, not more CPT steps |
| `cpt_qa` passes new paraphrase but old paraphrase decays | S2 compact replay undercovers old behavior | add old multi-view compact targets or replay frequency sweep |
| `cpt_qa` fails both original and paraphrase | teacher/scaffold did not form the answer behavior | debug S1 before any retention or growth discussion |

The pass bar should be stricter than the current original-question table:

- `compact_cpt_qa.para_em >= base.para_em + 25` absolute points;
- `compact_cpt_qa.para_em >= naive_cpt.para_em + 20`;
- old-stream paraphrase retention drop no more than 10-15 points from each stream's post-commit score;
- `compact_cpt_only` reported separately so we know whether raw passage LM loss is doing anything;
- RAG-gold remains an upper-bound answerability control, not a valid project solution.

## Answer to Q1: yes, add held-out paraphrased-question eval

Yes. This should be mandatory before making the R38 claim.

The clean smoke split is exactly why the paraphrase test is needed. If `compact_cpt_qa` remains strong on
held-out paraphrases, then R38 has a credible real-text bridge: passage text was converted into an answer
function, consolidated into weights, and used without inference memory. If it collapses, the result is
still useful but narrower: QA CE writes exact prompt-answer behaviors, and S1 must become a multi-view
teacher rather than a single original-question teacher.

The first paraphrase eval can be small. One held-out paraphrase per QA is enough to separate exact string
memorization from minimal semantic transfer. Later, add multiple paraphrases per fact if the one-view
result is positive.

Do not train on the paraphrase in the strict R38-A internalization run. If strict paraphrase fails, run a
follow-up `compact_cpt_qa_multiview` arm that trains on generated multi-view QA or atomic claims. That
would test whether the missing piece is teacher diversity rather than consolidation.

## Answer to Q2: replay all old QA first, then run the footprint sweep

I agree with replay-all first for the scale run. The reason is experimental isolation.

R38 is currently asking whether real passage text can be transformed into durable closed-book QA. If old
QA replay is capped immediately and the run fails retention, the failure is ambiguous: it could be an S1
teacher problem, an S2 compact target problem, or simply insufficient old coverage. Full committed-answer
replay gives the ceiling and keeps the first R38 decision clean.

This does not mean replay-all is the final scalable solution. Repository history already says the
footprint issue is real:

- R36-A showed that tiny fixed replay subsets mostly protect replayed items, not independent non-replayed
  facts. That argues against assuming a small cap will generalize for free.
- R36-A2 showed that compact answer targets can remove snapshot-teacher and replay-time teacher-forward
  cost, but it did not remove the O(number of facts) coverage requirement.
- R33/R35/R36-EV made replay-consolidation the proven dense-checkpoint retention route, but also made
  rehearsal footprint the next bottleneck.

So for R38:

1. Run the ceiling with all committed old QA, using answer-sequence CE.
2. Log the exact footprint: number of committed QA, answer tokens, replay tokens per stream, replay
   batch/frequency, wall time, and peak VRAM.
3. Only if full replay plus paraphrase eval passes, run a storage/compute sweep.

The follow-up sweep should report replayed and non-replayed old items separately, exactly as in the
R36-A lesson. For R38, the sweep dimensions should be:

- cap old replay to `K` QA per article or per stream;
- compare random selection vs diversity/answer-type selection;
- optionally reduce replay frequency after storage compression works;
- report old original and old paraphrase retention separately.

If the cap preserves only replayed old questions and not non-replayed paraphrases, call it item rehearsal,
not knowledge retention.

## Repository-grounded implementation notes

Current `s3/wikibridge.py` has the right skeleton but needs the paraphrase fields before the final claim:

- `score()` currently always uses `q["question"]`. Add a `question_key` argument or create separate
  `score_orig()` and `score_para()` helpers.
- `qa_ce()` currently trains on `q["question"]`. Keep that for strict original-only training, but do not
  accidentally train on `eval_question` in R38-A.
- `build_squad()` screens base on `QT` and `QT2` for the original question only. Add paraphrase screening
  once paraphrases exist.
- `run_ingest()` commits examples based on original-question correctness. That is acceptable for the
  strict test, but the report must separately show how many committed examples also pass paraphrase at
  post-commit.
- Final `allqa` scoring currently reports only original-question `final_em/final_f1`. Add `final_para_em`
  and `final_para_f1`.
- Per-stream logs should include `scaffold_new_orig`, `scaffold_new_para`, `M_new_orig`, `M_new_para`,
  `old_orig`, and `old_para`.

One subtle point: if old paraphrase retention fails while original-question old retention remains perfect,
do not immediately blame catastrophic forgetting. It may mean the old compact target is too narrow. The
right next arm would be `compact_cpt_qa_multiview_replay`, where each committed fact stores a tiny set of
answer CE views. That is still training-time compact replay and no inference memory, but it changes the
footprint claim.

## R37-A context

The R37-A update is consistent with the R38 design lesson: base anchoring must be separated from learned
old answers. If the clean base-KL split is now retaining in the oracle setting, that removes the earlier
anti-memory confound and supports the rule already encoded in R38: neutral base anchors are for preserving
general base behavior, while learned facts need committed answer targets.

It should not change the R38 priority. R38 is not a growth experiment. Growth should be reintroduced only
when fixed-capacity consolidation saturates or when a grown model shows a real compute/capability
advantage over a fixed model. At this stage the question is teacher construction and compact retention,
not capacity expansion.

## Bottom line

The smoke is a useful positive: `compact_cpt_qa` is the only arm that forms and retains the closed-book
answer behavior, while raw passage CPT fails. But the claim must be tightened before scaling:

1. Keep the current full run as an original-question diagnostic.
2. Add held-out paraphrased-question evaluation immediately.
3. Use replay-all old committed QA for the first paraphrase-gated ceiling.
4. If it passes, run the R36-A-style footprint sweep with replayed vs non-replayed old paraphrase metrics.

That sequence best serves the project objective: new text becomes usable model weights, retention is
measured without inference memory, growth is not invoked prematurely, and full joint retraining remains
outside the solution path.
