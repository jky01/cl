# This is a real positive result—but the support generator is now the central question

Source read in full: `qa/claude/2026-07-20.04.37.46.md`

I agree with the narrow conclusion and would state it firmly:

> On this arith→quad benchmark, growth is not necessary for exact continual performance. A fixed-capacity model can contain both functions, and sequential teacher-assisted consolidation can place both into shared weights while preserving 4×-horizon behavior. The tested frozen-trunk adapter growth mechanism underperforms that consolidation method because it retains A but fails to acquire B.

That is already stronger and more relevant to the project than rescuing the adapter. The result establishes all of the following on the measured distribution:

- **Knowledge into weights:** after consolidation, A and B are executed by one shared model; the teacher is absent at inference.
- **Continual retention:** A remains exact, including the meaningful 4× horizon extrapolation, while B is acquired exactly.
- **Growth necessity:** refuted for this task and model size by the joint oracle plus the successful fixed-capacity sequential arm.
- **No-memory inference:** satisfied; neither task ID nor external module selection nor teacher is needed at deployment.
- **Avoidance of joint full retraining:** satisfied in the literal raw-dataset sense, though not in the stronger “no old-function access during training” sense.
- **Compute advantage:** not yet established. Fixed-capacity inference is likely favorable, but consolidation pays teacher inference and synthetic-old-support training costs.

I would change one phrase consistently: do not call this simply “replay-free consolidation.” It is better described as **teacher-assisted generative functional replay** or **pseudo-rehearsal without stored raw examples**. That is not a cosmetic caveat. The frozen teacher stores the old function in parameters, and the arithmetic-prefix generator provides query access to its support. Together they are a powerful form of phase-B memory. The scientific win remains real—knowledge ends up in the student's shared weights—but the mechanism has not yet solved continual learning when old-support inputs are unavailable or unknown.

## The most important hidden resource is not the teacher; it is the support sampler

The teacher alone cannot preserve A unless we know where to query it. Here, generated arithmetic prefixes encode substantial knowledge about the old domain. In an open-ended stream, retaining one sampler or generative specification per past family could become an ownership table in another form, even if deployment stays memory-free.

So the decisive next question is:

> Can the learner recover or maintain the old input-support distribution without an externally supplied old-family generator whose complexity grows with experience?

This is where the result connects to the long-term objective. If the consolidated network can become the sole teacher for both *targets and support generation* in the next phase, then the method has a plausible recursive path from a small model toward durable cumulative knowledge. If each new phase requires retaining hand-written generators or old-domain metadata, the system integrates functions into weights but has not eliminated growing training-time memory.

## What I would run next, in order

### 1. Replication and causal ablations before broad adapter tuning

First replicate the exact consolidation result across seeds and report worst-case retention/acquisition. In the same run matrix, isolate which resource causes success:

1. teacher + generated A prefixes (current method);
2. teacher queried only on current-B inputs;
3. generated A prefixes with hard analytic labels rather than teacher labels;
4. teacher + progressively smaller fixed budgets of generated A prefixes;
5. teacher-free consolidation regularizers under matched phase-B compute.

The comparison between (1) and (2) tests whether support overlap is enough. The comparison between (1) and (3) separates teacher memory from domain-generator memory. The budget curve in (4) reveals whether the method behaves like ordinary replay with synthetic samples or whether a small number of functional constraints genuinely anchors the shared solution.

### 2. Make the recursive continual test the centerpiece

Add a third structural family C. After A→B consolidation, discard the A teacher and retain only the consolidated AB model. Then learn C while attempting to preserve both A and B. Track exactly what is retained to generate old prefixes. This is more probative than another two-task score: a method that succeeds recursively with constant-size auxiliary state is a candidate continual-learning mechanism; one whose sampler metadata grows per task is not yet.

### 3. Do a bounded adapter diagnostic, not an open-ended rescue sweep

The present statement “the tested growth arm underperforms here” is already valid. A preregistered width/placement envelope is useful only to locate why:

- Can the same frozen-trunk adapter architecture learn quad from the post-A initialization under a generous but bounded budget?
- Can it learn quad when trained as a B-only control?
- Does allowing a small, explicitly measured portion of the trunk to rewrite cross the acquisition boundary?

These controls distinguish insufficient adapter capacity, optimization failure, and frozen-representation insufficiency. Stop once that distinction is clear. Even a successful larger adapter would not restore a growth-necessity claim because the fixed shared model has already succeeded.

### 4. Report cost as a resource vector, not one parameter count

For every arm report:

- persistent training state after each phase (student, teacher, generators, metadata);
- peak and cumulative phase-B FLOPs;
- trainable and total parameters;
- active inference parameters/FLOPs;
- raw-example storage, synthetic-query count, and task/family identity requirements;
- whether auxiliary state grows with the number of learned families.

This could reveal the most attractive result: consolidation may cost more during learning yet dominate at inference by compiling behaviors into one fixed active network. That is a legitimate compute trade, but it should not be called an unconditional compute advantage.

## One limit on the word “knowledge”

Exact 4×-horizon execution is important evidence that the learner retained a functional recurrence rather than a fixed sequence. But held-family generalization of zero means the network has not learned the broader algebraic rule across deltas. I would therefore describe the current achievement as **exact integration of two learned recurrence families**, not yet structural rule induction. The grokking curve is useful, but it is secondary to replication, resource ablation, and the A→B→C recursive test.

My recommendation is to publish the current result internally now as a fixed-capacity/shared-weight win, with the terminology tightened. Run seeds and the sampler/teacher ablations next; then test recursive consolidation. Those experiments directly attack the remaining obstacle to the project goal: not whether two functions fit, but whether knowledge can keep accumulating into weights without an ever-growing shadow memory used to reconstruct the past.
