## Direct Answers

### 1. Was the 0.058 CE smoke a starvation artifact?

Mostly yes.

The decisive evidence is not the random-subspace comparison; that is only a sanity check. The practical evidence is that `collect_Q()` is committed-correct filtered, the smoke collected only `ncol=27`, and a less starved CE basis collected `ncol=80` and moved occupancy from 0.058 to 0.179 with update leak still near zero. That means CE old-loss gradients are not near-orthogonal to the write direction.

So for the go/no-go decision, use 0.179, not 0.058. The fair conclusion is:

- margin-OGD was a real negative for the thin margin objective;
- the first CE smoke was too small to rule out CE-OGD;
- CE-OGD now deserves the full matched pilot;
- final retention, not occupancy alone, decides whether OGD is useful.

### 2. If the pilot is partial, should we try rank 128 on a bigger card?

Not by default.

If the full CE pilot lands "partial but clearly below nswrite", the honest practical conclusion is already strong: flattened OGD helps monotonically with rank, but its global Q basis is training-memory expensive and capped around the commodity 24-32 GB regime. A method that needs a 48 GB card to become competitive on Qwen-0.5B top-layer writing is weak on compute advantage, even though it still satisfies no inference memory.

I would run a rank-128 attempt only if the pilot gives a reason to believe it can change the scientific conclusion. Good triggers:

- `ogd_ce` beats `naive_fixed` by a large margin and is within about 0.05-0.10 all-seen of `nswrite`;
- newest and base-hop remain acceptable, so rank is the plausible limiter rather than plasticity or base damage;
- the result would decide between "rank-limited but promising" and "first-order CE protection is structurally insufficient."

If `ogd_ce` is approximately naive despite `energy-occ` around 0.18, or if it remains far behind `nswrite`, skip rank 128 and pivot. That would be the stronger result: CE-gradient protection intercepts a real fraction of the update, but retention still fails through nonlinear, higher-order, or coverage-limited drift.

## Pilot Interpretation

For the running full pilot, keep the gates you listed:

- `ogd_ce all_seen >= nswrite + 0.05`;
- `ogd_ce oldest_forget <= nswrite - 0.10`;
- `ogd_ce newest >= nswrite - 0.05`;
- base-hop drop no worse than about 0.03.

I would add one lower-bound sanity gate:

- `ogd_ce` should beat `naive_fixed` by at least about +0.15 all-seen or reduce oldest forgetting by at least about 0.15. If it clears occupancy but cannot beat the no-projection floor materially, the mechanism is not translating into retention.

The useful outcome cases are:

- **Pass vs nswrite:** real fixed-size, no-replay, no-inference-memory progress. Next run a longer horizon before making any growth claim.
- **Beats naive but loses to nswrite:** partial positive, but rank/memory inefficient. Report as a bounded OGD result and move to A unless rank-128 is likely to decide the mechanism.
- **Occupancy high but retention naive-like:** strong negative for first-order old CE-gradient protection. Pivot to A.
- **Occupancy low after Q reaches cap:** CE directions still do not cover the damaging write motion. Pivot to A.

## Claim Hygiene

Please keep the OGD metadata explicit. The JSON already includes `uses_commit_answers=true`, but the printed table's `gold` column only reflects `uses_gold_new`, so the table can visually understate the supervision used to build Q.

The accurate phrasing is:

> OGD uses no old replay during later writes and no inference memory, but it builds a low-rank training-state basis from committed old prompts and answer identities at commit time. Only the basis survives.

That distinction matters for the project objective. CE-OGD is still a valid no-inference-memory, knowledge-into-weights arm, but it is less label-clean than `nswrite`, which protects activation directions without old answer gradients.

Also, do not turn OGD occupancy into a growth claim yet. At rank64 the reported `eff-grad=0.906`, so the writer is not plasticity-starved. Growth becomes justified only if we see occupancy high, effective gradient genuinely squeezed, newest learning failing, and a grown/factorized writer restoring plasticity at matched compute. That condition has not appeared here.

## Bottom Line

I agree with launching the full CE pilot. The smoke 0.058 should not have triggered a pivot; the properly collected CE basis is above the pilot gate. The main decision should now be retention versus matched `nswrite` and `naive_fixed`, not another occupancy-only scan.

If CE-OGD wins, it is a serious rehearsal-free weight-writing result. If it only partially helps or fails, do not spend a long sweep rescuing flattened OGD unless the result is close enough that rank 128 could genuinely change the conclusion. Otherwise the clean next move is A: a different preservation primitive, not more first-order answer-gradient tuning.
