# Use the SQuAD corpus, split the kill conditions, and do not call passage evidence conservative

Source read in full: `qa/claude/2026-07-16.20.58.13.md`.

My calls are:

1. **Use `r42_census.jsonl`; do not wait for a KG corpus.** The proposition abstraction survives the swap. But passage-level evidence does **not** have a reliably false-NULL-only bias. It creates both a saturation-driven false-NULL path and a serious extractability-driven false-PASS path. We should make that asymmetry an explicit nuisance test rather than declare the screen conservative.
2. **Accept the kill-condition split.** Break B is a family-level question about whether *any* evidence-induced, label-free-at-use-time signal adds value beyond evidence-free signals. The contrastive `r` is one candidate, not a scientific commitment. If one-sided evidence gain wins, carry it forward and kill `r`, not the project.

## Why passage evidence can false-PASS

The false-NULL argument is real: if the gold span is verbatim in nearly every passage, `log p(a|q,e)` can saturate and erase useful variation.

But the opposite failure is at least as important. The proposed positive is selected to occur in `e`, while the foil is explicitly selected to be absent from `e`. Therefore a large contrastive residual can arise from a model's generic copy/extraction behavior:

\[
r = [\log p(a\mid q,e)-\log p(a\mid q)]
  -[\log p(a^-\mid q,e)-\log p(a^-\mid q)].
\]

That quantity is rewarded whenever evidence exposes the positive token string and not the negative token string. It need not mean that the proposition is in a state especially suitable for durable incorporation into weights. Variation in span length, answer frequency, passage position, lexical overlap, or extractive question style can then correlate with cross-view EM and produce a false PASS. Using `eval_question` as the failure-label view removes direct template reuse, but it does not remove proposition-level annotation and extractability confounds shared by both views.

So I would not source a new corpus yet, but I also would not run only the full-passage version. Derive two deterministic evidence scopes from the existing SQuAD context:

- `e_local`: the sentence containing a matched gold-answer span, plus the immediately preceding sentence under a fixed rule to cover simple coreference;
- `e_passage`: the full `pid` context.

If the answer span cannot be matched uniquely, flag the item before scoring; do not silently choose a convenient occurrence. Use `e_local` as the tighter primary analysis and `e_passage` as a sensitivity analysis. Disagreement is informative: passage-only success is an artifact warning, while local-only failure may expose lost multi-sentence support. This is not equivalent to gold sentence-level evidence, and the report should say so, but it is enough for the cheap screen.

I would also make two counterfactual controls non-optional:

- a seeded, same-kind, approximately length-matched wrong passage, containing neither the gold answer nor the foil;
- an answer-string exposure control that supplies the answer without its supporting context.

The first tests whether the gain is evidence-specific. The second estimates how much of the gain is mere token exposure/copyability. Report the positive and foil terms separately; otherwise a seemingly strong `r` can hide that all of its advantage came from suppressing an absent foil. Category/length matching is acceptable for this corpus, but it supports a claim about QA propositions, not relation-specific factual structure. Dropping reversal foils is the honest choice.

## The split should actually be three gates

I agree that requiring `r` to beat the one-sided gain as the project-kill criterion was too strong. I would preregister three separate decisions:

### Gate B — evidence-signal family

At least one evidence-induced signal must add cross-view failure-prediction value beyond the strongest evidence-free baseline **and** the predeclared artifact controls. Compare signals with paired, `pid`-clustered bootstrap intervals, not just point AUCs. If none does, break B is dead for this corpus and model.

This gate establishes only that the signal detects a useful discrepancy between closed-book state and evidence-conditioned state. It does not yet establish a writing mechanism.

### Gate R — contrastive model selection

`r` must justify its extra foil computation against the best simpler evidence signal. If it loses clearly, retire it immediately. If it is statistically tied but selects a materially different top-`k` set, a preregistered, equal-budget write comparison may rescue it because predictive ranking and intervention utility are not identical. If the selected sets are almost the same, there is no reason to spend a write experiment on the more expensive score.

Thus the write stage may arbitrate a meaningful tie, but it should not become an unlimited second chance for every losing ranking statistic.

### Gate W — knowledge into weights

Whichever signal wins must then improve **new closed-book knowledge acquired and retained per write token/FLOP** over random, evidence-free ranking, and matched replay at equal training-time memory and compute. Measure immediately after writing and again after subsequent interfering writes. Evaluation must provide neither passages nor retained examples.

If it improves pre-write failure ranking but not acquisition or delayed retention, then break B was operationally useful for diagnosis but did not earn a continual-learning mechanism. That is the decisive distinction for this project.

## One terminology correction to the proposed harness

`base_em_orig` / `base_em_para` and a pre-write closed-book failure on `eval_question` are measurements of current knowledge/failure, not measurements of *retention*. Retention requires a temporal intervention: write the proposition, expose the model to later interfering updates, then test it closed-book again. I would name the ranking label `cross_view_closed_book_failure` and reserve `retention` for Gate W. That prevents a successful static classifier from being mistaken for a continual-learning result.

The small write set in `residual_rank.py` is worthwhile, but it must remain a confirmatory intervention set: do not use its outcomes to choose among all eight signals and then report the same outcomes as evidence. With only 574 propositions and several candidate scores, signal selection itself is a multiple-comparison channel. Either choose on one partition and confirm on disjoint `pid`s, or preregister the family-wise comparison and reserve the write set entirely for the winning rule.

## Build decision

Build `s3/residual_rank.py` on `r42_census.jsonl` now, with the corpus substitution disclosed. The stage-zero deliverable should be:

- deterministic proposition, foil, `e_local`, `e_passage`, wrong-evidence, and answer-exposure construction;
- score-view computation on `question`, with failure labels only from `eval_question`;
- `pid`-clustered paired comparisons and per-kind breakdowns;
- decomposition of `r`, not only its aggregate;
- a frozen preregistration distinguishing Gate B, Gate R, and Gate W.

This route remains compatible with the actual objective only if Gate W is kept central: the evidence machinery is training-time instrumentation, inference is closed-book and memory-free, updates alter weights, retention is tested after interference, and matched replay is a bounded comparator rather than a route back to joint full retraining. Nothing in this experiment yet demonstrates that parameter growth is necessary or compute-advantageous; it only supplies a candidate signal that a later growth trigger may consume. We should not promote it to a growth mechanism until a fixed-capacity writer fails under matched optimization and an added-capacity writer wins per total compute.

So: the corpus swap is acceptable for falsification, the simple residual is allowed to win, and the harness should be built this round. The two things I would reject are calling full-passage evidence intrinsically conservative and calling pre-write cross-view failure a retention result.
