# Review: edge accounting is the right next probe, but the present result supports a narrower claim

Source reviewed in full: `qa/claude/2026-07-17.09.33.01.md`.

My short answer to the three questions is:

1. **Yes, but call it a positive mechanism result, not yet a positive extrapolation/MDL result.** Whole-graph gating closed the free-residual loophole and demonstrated that the accounting can force a much smaller active graph. It has not yet shown that the selected graph is a short *adequate explanation*: `sq_ip` fell from 0.894 to 0.753, and OOD remained zero. If `sq_ip` is a higher-is-better ID score, some of the collapse may simply be regularization-induced underfitting. The stronger claim becomes justified only when the compact graph matches the required ID/prequential fit and then extrapolates.
2. **Edge sparsity does not literally encode “choose `n/K`,” but the representation does make that answer exceptionally cheap.** That is acceptable for a support-recovery unit test, provided the claim is scoped honestly. The model is being given a one-coordinate sufficient statistic for magnitude, while the alternative representation distributes the same information over many bits. A generic few-input prior will prefer the former. This tests whether structural accounting can recover a compact rule in a favorable basis; it is not yet evidence of basis-independent rule discovery.
3. **Run the single-task edge experiment first as a unit test, then require the grammar family before any LM move.** I would not burden the first debugging run with the full family, but success on this one square task is only permission to run gate 2, not permission to port.

## The diagnosis is plausible, but it should be tested rather than inferred from module count

The proposed explanation is coherent: one surviving product is not a one-rule graph if each factor can read every input. Nevertheless, the current outcome does not uniquely identify dense bit edges as the cause. `x*x` already exists inside the one-product hypothesis class, so it matters why optimization did not find it.

Before or alongside implementing edge gates, I would add four cheap diagnostic checks:

- Print the learned `A` and `B` coefficients per input, per seed, including deterministic gate values. Do not infer bit use solely from OOD failure.
- Evaluate counterfactually with bits zeroed and with `n/K` zeroed. This establishes which route the fitted product actually depends on.
- Train the same one-product model with only `n/K` available. It should recover ID and extrapolate. If it does not, edge selection is not the principal problem.
- Fit or enumerate the small singleton-support candidates and compare their **ID loss plus the exact proposed structural cost**. In particular, compare `{x} x {x}` with the best bit-supported pair. This separates an objective failure from a hard-concrete optimization failure. If `x*x` is the global coded optimum but SGD misses it, changing the code is not the fix; the gate optimizer is.

That enumeration is unusually valuable here because the graph is tiny. It gives a ground-truth answer to “does the intended MDL objective prefer the intended rule?” before stochastic gates obscure the issue.

## Changes I would make to the edge-level design

The most important change is to gate **every possible computational route**, not just the two product inputs. Otherwise the loophole has merely been moved again. The accounting should include:

- both input-factor edges of every product;
- biases or constant inputs, unless they are explicitly forbidden;
- product-to-readout edges if these are independently trainable;
- residual-module input and output edges, not only the residual module gate;
- any skip, direct readout, normalization-affine, or other bypass that can carry input-dependent information.

A hierarchical cost is the clean semantics: an incident edge exists only when its operator exists. Schematically,

```text
C(G) = sum_o g_o c_o
     + sum_(o,e) g_o g_e c_e
     + C_coefficients
```

This avoids charging edges belonging to a nonexistent operator. But expected products of soft gates can admit fractional solutions, so the scientific readout must not stop at “1.3 active products.” Report at least three objects separately:

1. expected soft-gate cost during training;
2. the deterministic thresholded graph;
3. the thresholded graph frozen and refit on ID data only, followed by the one-time sealed OOD evaluation.

The third is the decisive object. If the soft network extrapolates but the extracted discrete graph does not, graph recovery has not occurred.

I would also be careful with the term MDL. `sum L0 + gamma * L2` is a useful structural sparsity objective, but `gamma` is a coefficient-magnitude prior, not automatically a coefficient-precision code. The product has the scaling symmetry `(cA)(B/c)`, so specify how coefficient cost handles that symmetry. For a strict MDL claim, state the mask prior/code, operator identity cost, input-support identity cost, and coefficient quantization or parameter code. For the present probe, it is fine to call these MDL-inspired surrogates, but grammar-family comparisons will be misleading unless code costs are comparable across different numbers of inputs and primitives.

`beta` and `lambda_e` are also not quite independent conceptually: their product sets the edge price. I would preregister actual code costs or a small ID-only selection rule, rather than letting two continuous knobs become an implicit search. OOD shells should remain sealed exactly as proposed.

## Is the answer being supplied?

Partly, at the representation level—not at the coordinate-selection level.

The selector must discover which coordinate to use, so this is not direct feature labeling. A column permutation should leave the result unchanged. But supplying `n/K` turns the target rule into a two-edge graph, whereas binary magnitude is inherently distributed. Edge sparsity is therefore a prior over rules *in this coordinate system*. That is legitimate if the hypothesis is “local sparse operator composition over semantically meaningful features.” It is not legitimate to generalize the result to arbitrary internal LM representations without showing how such meaningful coordinates arise.

Useful controls are:

- permute input columns: recovery should be invariant;
- add irrelevant continuous and binary decoys: the recovered support should remain stable across seeds;
- add an ID-correlated but OOD-breaking one-coordinate decoy: this is the sharp test, because raw edge count alone may find the wrong rule equally short;
- duplicate `n/K`: either copy is acceptable, and extrapolation should remain intact;
- rotate the inputs: failure is not necessarily disqualifying, but it precisely measures basis dependence and must limit the claim;
- include targets whose correct rule is genuinely dense or nonmultiplicative: the method should abstain, expand, or choose another primitive rather than underfit them into a sparse product.

The correlated one-edge decoy is especially important. Edge MDL can distinguish `x` from a many-bit shortcut by length, but it cannot distinguish two equally short coordinates using length alone. That case reveals what additional invariance, causal intervention, multi-environment evidence, or prequential evidence is actually doing the selection.

## Proposed experimental order and pass condition

Proceed with the four-arm ladder. Treat operator-only versus operator-plus-edge as the main causal contrast. I would preregister the single-task conjunction as:

- compact deterministic graph, ideally exactly one product with supports `{n/K}` and `{n/K}`;
- ID/prequential performance at least matching the acceptable unregularized fit, rather than accepting collapse by underfitting;
- stable recovery over seeds, with individual seed outcomes rather than only mean active counts;
- sealed-shell extrapolation near the prespecified target;
- continual-protocol parity retained;
- counterfactual input ablations consistent with the extracted support.

If it passes, immediately run the small operator-grammar family with compact decoys and nonmultiplicative negative controls. If it fails, use the singleton enumeration to choose the pivot:

- intended graph wins the exact objective -> fix optimization/gate discretization;
- bit or decoy graph wins -> fix the code/prior or add identifying environments;
- intended graph cannot fit even when forced -> fix the implementation or representation;
- sparse graph fits ID but not OOD -> the claimed rule was not actually recovered.

Do not do another broad `beta` sweep after a clean monotonic failure. The branch decision should come from which of those four failure modes occurred.

## Relation to the continual-learning objective

Even a successful edge-MDL square result advances only the **structural rule-recovery** component of the larger goal. Before an LM port, the grammar-family stage should explicitly test the remaining requirements:

- **Knowledge into weights:** the learned rule must reside in ordinary parameters/gates after training, not in retained examples or an external symbolic answer table.
- **Continual retention:** learn rules sequentially and measure all prior rules after every acquisition, without joint full retraining on the union.
- **Growth necessity and compute advantage:** expansion should occur only when reuse cannot encode the new rule adequately; report added parameters and cumulative training compute against a fixed large model and against joint retraining as an upper-bound reference, not as the solution.
- **No-memory inference:** evaluation should require neither replay examples, task IDs, retrieval, nor an external router database. A learned gate embedded in the model is fine; a lookup keyed by task identity is not.
- **No full-union escape hatch:** any consolidation must operate from the current model plus the current stream or a tightly defined training-time summary, not silently reconstruct joint training.

So my recommendation is: **build the edge version, but broaden “edge” to every route, harden and refit the recovered graph, and add the objective-versus-optimizer enumeration.** Count the present result as successful closure of one loophole. Reserve the stronger thesis claim for the conjunction of adequate ID fit, exact support recovery, sealed OOD extrapolation, and then multi-rule continual retention.
