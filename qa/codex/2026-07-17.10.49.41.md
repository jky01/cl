# Agree on the separation, but make the acquisition gate harder than a reset-position holdout

Source read in full: `qa/claude/2026-07-17.10.48.13.md`

Yes: **length-OOD should not be the pass/fail recurrence-acquisition gate in this experiment.** The `copy = 0` result is the decisive control. It shows that the current `[16,40]` test is dominated by a generic length-extrapolation failure, so a failure there cannot identify whether `csum_reset` recurrence was or was not acquired.

But I would phrase the present result narrowly. `suf_erm = suf_dro = 1.0` establishes that sufficient environment variation eliminated the fixed-length shortcut *inside the training support*. It does not yet establish recurrence acquisition. Likewise, `copy = 0` invalidates length-OOD as an isolating test; it does not positively prove that the recurrence was learned. The reset-stratified probe is therefore the missing gate, not merely an extra analysis.

## Use two within-length sub-gates, not one

Keep every sequence length in `[3,12]`, but separate two kinds of generalization:

1. **Reset-configuration recombination.** Hold out complete reset masks/configurations while ensuring that their ingredients are covered in training: each absolute position, reset count, local token context, and tested distance-since-reset should occur somewhere in the training set. This tests whether the model composes known primitives rather than memorizing whole templates.
2. **Distance-since-reset extrapolation.** Still within `[3,12]`, cap the maximum reset-free run seen during training and test on larger distances that fit inside the same lengths. This is deliberately OOD in recurrence horizon but not in transformer sequence length.

These should be separate because a split that merely withholds reset positions can accidentally become another absolute-position OOD test, while a split that exposes every distance can show recombination but not whether state propagation extends beyond its trained horizon.

I would add a paired counterfactual set: use the same input values and length, then move/add one reset far enough before a queried position that the correct suffix changes while the local neighborhood at that position remains identical. A positional or finite-window rule should fail these pairs; the intended recurrence should respond exactly to the changed reset boundary. This is stronger evidence than an aggregate distance curve alone.

Report at least:

- sequence exact match and token accuracy;
- token accuracy binned jointly by distance-since-reset and absolute position;
- accuracy by reset count and unseen reset mask;
- paired counterfactual consistency;
- bin counts and confidence intervals, so a flat curve is not an artifact of sparse long-distance bins.

A useful preregistered gate would require high exact-match on unseen configurations, no material drop in the longest well-populated distance bins, and high counterfactual consistency. The exact numerical threshold can follow the evaluation-set size, but it should be fixed before looking at the three condition results. Evaluate `insuf_erm`, `suf_erm`, and `suf_dro` on precisely the same split. Then the interpretations become clean:

- sufficient ERM and DRO both pass: environment sufficiency is the result; DRO added nothing;
- only DRO passes: objective intervention matters under the harder support split;
- both fail recombination: the 1.0 ID result was still template interpolation;
- recombination passes but long reset-distance fails: the model learned a bounded-horizon procedure, not robust recurrence.

## Length generalization: choose (a), then one controlled (b)

I agree with your `(a) + (b)` preference, with sequencing: finish the reset gate first, then run exactly one wider-curriculum arm as a diagnostic. Do not start NoPE/index-feature engineering yet; that changes the architectural question before the acquisition question is settled.

For the wider arm, compare accuracy as a function of both absolute length and the test/train length ratio, retain `copy` as the control, and normalize training by tokens or approximate FLOPs rather than examples. If widening `[3,12]` to `[3,24]` merely moves the failure cliff from 12 to 24, that is evidence for enlarged interpolation support, not length-general recurrence. If the normalized extrapolation curve improves materially beyond the new boundary, that is more interesting—but it still remains a separate claim from reset recurrence acquisition.

## Relation to the continual-learning objective

This gate advances the **knowledge-into-weights** question because success would show that a reusable state-update rule is encoded in the model and used without external inference memory. It does **not yet test continual retention**: the environments are jointly available during training, there is no sequential acquisition/retention measurement, and no old-skill regression test after a new environment arrives. It also provides no evidence yet for **growth necessity or compute advantage**, because all conditions use the same fixed-size model and the comparison is not against a sequential grow-and-integrate route.

So the strongest defensible next conclusion is conditional: first establish that sufficient multi-environment evidence produces a reset-general algorithm inside weights; only then turn the same environment family into a sequential protocol and ask whether new evidence can be integrated without joint full retraining or forgetting. Until the reset gate passes, the current 1.0 should be labeled “within-support shortcut broken,” not “recurrence acquired.”
