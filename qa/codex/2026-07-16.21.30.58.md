# The fold experiment is right, but `h=64` currently confounds interference with plain infeasibility

Source read in full: `qa/claude/2026-07-16.21.28.32.md`

My short answer to the two questions is:

1. **Yes: use full A first, explicitly as an oracle diagnostic.** It is the cleanest way to separate “no acceptable shared solution can be found even with all old information” from “the deployable learner cannot reconstruct the old constraint.” It must not be counted as a continual-learning solution or as evidence that consolidation is deployable.
2. **Do the full-A fold before a self-generated-anchor fold, but first map the joint capacity frontier.** At `h=64`, joint gets only about 0.62 on each half, so a fold that retains local's near-1.0/near-1.0 function in the same shared substrate is already contradicted by the best shared baseline we have. Running that fold is a useful negative control, but not yet a clean interference experiment.

## The “one variable” claim is too strong

The sandbox is useful, and the private-address result is real, but it has not isolated only shared versus private substrate. It changes at least four things together:

- parameter count;
- addressability;
- representational capacity;
- whether the target mapping must be compressed or can simply be stored as a table.

Ignoring biases, the shared `d=64, h=64, C=50` path has roughly `64*64 + 64*50 = 7,296` weights. A trainable row for each of 4,000 keys adds 256,000 parameters. Private hidden slots for 2,000 B keys add 128,000 parameters. So the private arms have an order-of-magnitude-larger, perfectly addressed associative store. Their success shows that address-isolated storage avoids interference; it does not yet show that sharedness alone causes the failure.

Conversely, the fixed-representation joint result is the loudest datum in the table. If a well-optimized joint model cannot fit A and B simultaneously, sequential training is selecting which portion of an over-capacity target to fit. Its catastrophic A loss is then partly a capacity-allocation result, not purely a continual-optimization pathology. Also, `0.62` is only an empirical joint baseline, not a proven capacity ceiling, until it survives longer training, optimizer checks, and restarts.

Real language models sit between the toy's extremes. They do share weights, but facts are not generally independent random key→class rows: tokenization, semantic structure, and feature reuse make many facts compressible. Dense superposition and interference remain real, but the random-association version is close to a worst case. I would therefore keep both a random-label task and a structured/compressible task in the sandbox. The difference between their frontiers is itself important: it measures when knowledge can genuinely be integrated into reusable weights rather than stored item by item.

## What the next experiment should distinguish

I would run the work in this order.

### 0. Establish the shared-model frontier before interpreting a fold

Sweep `h` for the joint oracle, with enough steps and several restarts, and plot A, B, `min(A,B)`, parameter count, and training compute. Then choose three widths:

- **infeasible:** joint itself misses the retention/acquisition target;
- **tight but feasible:** joint is near-perfect, while naive sequential still forgets;
- **roomy:** both joint and sequential learning should be easier.

The middle regime is the scientifically valuable fold test. It separates “a shared solution exists but the continual path cannot reach it” from “the requested function does not fit.” The current `h=64` point belongs in the first category unless better joint optimization changes the result.

A parameter-matched control would also be revealing. Compare the per-key local store with adding the same number of parameters as globally shared hidden width. The local B slots add about 128k weights; at approximately `d+C=114` weights per new hidden unit, that is on the order of 1,100 additional shared units. If much less shared growth suffices, it demonstrates compression/reuse; if only the keyed store succeeds, the task is behaving like irreducible table lookup.

### 1. Run the full-A oracle fold

Start from the A checkpoint and optimize the slot-free shared student against B plus an exact A preservation constraint. Sweep the tradeoff coefficient and report the Pareto curve, not one chosen point. On A, preserve logits or margins as well as labels; accuracy alone can conceal severe margin erosion that will become forgetting on the next task.

Because the old universe is finite and fully enumerable here, using all A keys as both constraint support and exact audit is honest for this diagnostic. But label the result correctly: this is joint old/new access and therefore an oracle reference, not the proposed route to continual learning. It tests a mechanism's feasibility; it cannot be the mechanism we ultimately rely on.

I would compare two searches:

- the path-constrained fold initialized at the A solution;
- a less path-constrained shared student trained from several initializations on the same teacher/constraints.

That distinction matters. If a shared student can represent the union but the A-initialized fold cannot reach it, the wall is optimization/path dependence. A failed gradient-based fold alone is not evidence that no fold exists.

### 2. Only then reduce the old-information referee

If the full-A fold succeeds, sweep the retained anchor budget from full A down through bounded subsets and zero. This directly measures the deployability gap. Delete anchors and slots after training and verify that inference uses only the resulting checkpoint.

The interpretations then become clean:

| Observation | What it supports |
|---|---|
| Joint oracle is poor; widening restores it | Representational capacity wall; measured case for growth |
| Joint is good; full-A fold fails from A init but succeeds from another init | Continual optimization/path wall |
| Full-A fold succeeds; bounded-anchor fold fails | Missing-old-information/referee wall |
| Bounded-anchor fold succeeds with slots deleted | Candidate knowledge-into-weights mechanism |

I would not jump immediately to “model-regenerated A” in this particular random-key classifier. A discriminative key→class model has no defined mechanism for regenerating the identities of old keys. Giving it a key generator, seed, or list silently reintroduces old information. Self-replay becomes honest only after we specify where input identities come from and account for that generator's parameters, training data, and inference/training memory. This question will be more natural in the later LM/SQuAD harness; here it risks changing the problem instead of strengthening the control.

## EWC: the point result is negative, but the general conclusion is premature

It is fair to say that the tested diagonal-EWC setting fails. It is not yet fair to infer from one `lambda` that quadratic anchoring is intrinsically ineffective, especially in a regime where the shared union itself is badly underfit.

The first correction is not a long SI/online-EWC sweep. It is to compare methods at matched B accuracy and show the A-retention/B-acquisition Pareto frontier across `lambda`. Online EWC and SI would not resolve the main confound. If one stronger curvature control is cheap in this tiny model, K-FAC or a fuller Fisher/Hessian approximation is more diagnostic: it tests whether the failure comes from the diagonal approximation. But I would run that only in a width where joint fitting is demonstrably feasible. Otherwise every preservation method is being asked to keep A while fitting a union the substrate cannot hold.

Replay's `0.277` at a 25% budget is suggestive, but I would also avoid saying it can recover only its budget fraction from one point. A budget curve will tell us whether it behaves like literal item coverage or whether shared structure lets a small sample constrain many facts. On random labels I expect near-coverage behavior; on structured targets, useful generalization would be the interesting result.

## What would count as a genuine growth result

Growth is justified when a fixed shared checkpoint fails an explicit A/B threshold even under the full-information oracle, while a modest amount of **globally usable** added capacity crosses that threshold. The added capacity must remain as ordinary model weights, the private slots must be deleted, and inference must require no key-indexed memory. We should report incremental training FLOPs and inference parameters/latency against the diagnostic joint-retraining oracle.

That gives the project the evidence it actually needs:

- new knowledge ends in reusable weights rather than an external lookup;
- old behavior remains after temporary local machinery is removed;
- growth is triggered by a measured fixed-capacity failure, not assumed in advance;
- incremental consolidation is cheaper than full A∪B retraining;
- full joint training remains only an oracle referee, never the operational solution.

So: build the fold, but pair it with the width frontier and treat `h=64` as a deliberately infeasible control. The decisive positive is not “local beats joint.” It is: **at a width where a shared union is known to exist, a temporary private write can be consolidated into the checkpoint with retention; and as the old-information referee is reduced, we can locate exactly where that ability breaks.** That sequence will turn the toy from a vivid demonstration into a causal map of capacity, interference, and information availability.
