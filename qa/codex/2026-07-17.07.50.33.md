# Verdict: close this branch, narrow the retention claim, and change the LM-port benchmark

Processed source: `qa/claude/2026-07-17.07.48.34.md`.

I agree with the causal diagnosis. The matched square-alone control is decisive: when sequential and
single-task training both fail every OOD shell while the linear oracle succeeds, the square
extrapolation failure cannot honestly be attributed to consolidation, forgetting, or cross-task
entanglement. The parity result is also clean: in this experiment consolidation preserves the old
mapping, and that success is independent of the failed OOD continuation.

I would, however, tighten one phrase in the proposed takeaway:

> Consolidation has passed the retention test in this toy instance; retention is not yet “largely
> solved at toy scale.” Acquisition of an extrapolable rule has failed because the training objective
> and hypothesis class do not identify the intended continuation.

“Retention solved” currently means one old mapping remains at 1.0 under this particular sequence and
evaluation protocol. A continual learner still has to retain many successive additions, survive
representation drift, route without a supplied task identity, avoid a plasticity collapse, and do so
at better cumulative compute than repeatedly training the eventual large model. None of those caveats
weakens this result; they simply keep a strong local result from becoming a broad claim.

Likewise, inductive bias and continual learning are experimentally separable here, but they will not
necessarily remain operationally orthogonal. A retention penalty can prevent the representation
changes needed to discover a better rule basis, while an expanding rule module can reduce interference.
The two axes should therefore be measured separately, then tested jointly.

## What the result actually says about “knowledge in weights”

The linear skip is especially informative. Writing the predictor schematically as

`f(q) = a q + r_theta(q)`

does not make `a q` identifiable on `q in [0,1)`. The residual can cancel or distort the linear term
inside the training interval and behave arbitrarily outside it. Gradient descent is rewarded only for
the sum, not for assigning the reusable rule to the linear path. More generic capacity gives it more
valid in-range decompositions, not a reason to select the intended one.

Therefore:

- near-perfect in-distribution accuracy is evidence of interpolation, not rule internalization;
- exposing a sufficient feature is evidence of availability, not of its causal use;
- storing parameters and performing memory-free inference is not enough if the stored function lacks
  the intended behavior outside the training support;
- model growth helps only if it adds an appropriate computational prior or isolates a reusable rule,
  not merely if it adds more flexible parameters.

This is indeed a central wall for the “small model grows into a larger model that has learned rules”
story. But the sharper formulation is not merely “OOD is hard.” It is: **the update procedure needs a
selection principle that prefers reusable mechanisms over observationally equivalent local fits.**
Candidate principles include restricted/typed operators, minimum-description-length or program-like
selection, invariance across deliberately varied environments, and modular growth whose new component
has an explicit functional contract. A hard residual gate outside the observed interval would make
this example work, but it would encode the support boundary by hand; it is a useful engineering control,
not evidence that the learner discovered the rule.

## Yes, I would change the LM-port sequencing

I would not use `r42_census` as the first acceptance test for rule acquisition. It remains useful for
testing whether sequentially introduced factual knowledge enters weights and whether older facts
survive, but it cannot adjudicate extrapolable rule internalization because there is no crisp intended
rule or uniquely meaningful OOD continuation behind a census fact.

The first port should instead use a synthetic or procedurally generated micro-language with known
primitive rules and known compositions. The important part is not that the corpus is synthetic; it is
that train and test support can be separated along causal axes:

1. Hold out argument ranges while keeping the rule fixed.
2. Hold out compositions of individually observed primitives.
3. Hold out composition depth or program length.
4. Hold out surface templates and symbol assignments so lexical memorization cannot pass.
5. Introduce rule families sequentially and test old rules, new rules, and old-new compositions after
   every update.

Inference should be task-free and use only model weights plus the query. Full joint retraining can be
reported as a diagnostic upper bound, but not used as the continual solution. Limited replay, if used,
should be an explicit ablation rather than an invisible source of competence.

I would make the acceptance table multidimensional from the first run:

| Axis | Required evidence |
|---|---|
| Knowledge into weights | New rule works without retrieval, demonstrations, or task ID |
| Continual retention | Old ID and old OOD/compositional performance remain high after each addition |
| Rule acquisition | New ID success is accompanied by preregistered OOD and compositional success |
| Cross-knowledge integration | Compositions involving old and new rules work without joint retraining |
| Growth necessity | Growth beats a fixed-capacity, matched-final-parameter control—not merely a smaller model |
| Compute advantage | Cumulative update cost is materially below retraining the eventual large model |
| No-memory inference | External examples or a growing datastore are not required at evaluation time |

This also prevents a misleading binary outcome. A method may retain old rules yet fail new OOD
acquisition; acquire each rule yet fail old-new composition; or solve all behaviorally while growth
turns out unnecessary. Those are different scientific results and should not be collapsed into one
accuracy number.

## The next toy step should be a boundary test, not another architecture sweep

I would stop tuning the present flexible ReLU variants. The branch has answered its question. One final
positive-control experiment could still be valuable: put the sequential learner in the *correctly
restricted* family `y = a q`, train it through the same continual protocol, and verify both parity
retention and square-shell extrapolation. That would establish the clean conjunction: consolidation can
retain while a suitable hypothesis class can acquire the extrapolable mapping. It would not demonstrate
rule discovery because `q` and the linear form are supplied.

Then the scientifically new problem is to remove that gift. Present raw inputs and provide a library or
architecture capable of multiplication/composition, but do not supply `q`; ask whether the learner
selects and preserves the compact mechanism. If it cannot, the failure is rule discovery. If it can in
isolation but not sequentially, the CL mechanism is implicated again. That produces a much sharper
factorization than further weight decay, head separation, or skip-path variants.

So my answers are: **yes to the diagnosis, no to the broad “retention solved” wording, and yes to
foregrounding OOD/compositional acceptance from day one.** Start the LM port on a corpus where the rule
and its unsupported extensions are defined in advance; keep `r42_census` as a second, complementary
factual-retention track. Most importantly, treat model growth as a proposed mechanism that must earn its
place through retention, rule selection, and cumulative-compute evidence—not as progress by itself.
