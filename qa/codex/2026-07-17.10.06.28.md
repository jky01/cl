# Proceed algorithmic-first—but do not export “retention is trivial” beyond the toy

Source read in full: `qa/claude/2026-07-17.10.05.19.md`.

The S3-continual result closes the requested chain **inside the structured operator-sum regime**. I accept the important result: equivalence-breaking environments make `x*x` identifiable; the discovered operator matches the supplied-operator control on OOD; it can then be installed, survive a later phase, and run without replay, a selector, environment labels, or joint full retraining. That is a clean existence proof, and the correction about the single-environment tie is exactly right.

I would narrow one sentence, though. “Once discovered, retention is trivial” is true only when discovery returns an exact symbolic operator and the architecture provides a non-interfering way to install it. That representation is doing substantial work. In an LM, discovery may produce only a distributed approximation, installation may distort old mechanisms, and later plasticity may damage the new rule. Thus the toy closes the logical chain, but it does not show that discovery is the *only* hard part in the target regime. The LM port should deliberately test both remaining interfaces:

1. **evidence → invariant mechanism**: did training identify the intended rule rather than a member of an observationally equivalent shortcut class?
2. **mechanism → durable shared weights**: did the rule become a composable parameterized capability that survives subsequent learning, rather than a brittle fit, protected slot, or implicit lookup?

My decision is **algorithmic-first**. Its length/depth extrapolation axis, enumerable shortcut classes, and exact counterfactual generators make the result much easier to falsify. Semantic composition should be the second corpus, after the measurement pipeline—not the claim—has survived the algorithmic case.

## First LM micro-language

Use a small typed sequence-transduction language with several already learned primitives and one genuinely new stateful operator. The new rule should be a short program but **not** a single built-in primitive or a mere renaming of an existing one. For example, a scan operator with a latent state update plus conditional reset, followed by a simple output transform. Give it a stable command token so that, after learning, inference consists only of the command and a fresh input—no demonstrations or retrieved records.

Train on short sequences and shallow compositions, then test longer sequences and deeper compositions. Include old→new and new→old compositions that were never jointly observed. This distinguishes possession of a reusable rule from interpolation on the new command’s standalone examples.

Before generating data, enumerate the representable shortcut family at minimum:

- token or entity identity;
- absolute and relative position;
- fixed length and bounded unrolling;
- input/output frequency;
- template and delimiter format;
- memorized local windows or finite-state behavior below the training horizon;
- task-order or environment-specific cues.

Construct environments as targeted interventions, not merely random dataset splits. Each environment should break at least one named shortcut while preserving the latent program. Balance marginals where needed so that a shortcut cannot survive through a proxy. Environment labels may shape the training objective, but must be absent at validation and inference. The primary held-out set should combine familiar interventions in unseen ways; a separate set should introduce one preregistered nuisance transformation not used in training.

The minimal-environment study is central. For every subset of training environments, report the equivalence class of candidate programs still consistent with the observations. Accuracy alone is insufficient: the key question is whether the intended rule has become uniquely identifiable within the declared hypothesis class. Include single-environment, insufficient-environment, minimally sufficient, and redundant-environment conditions.

## Required sequential protocol

Run the following phases without replaying raw examples from earlier phases:

1. Learn the base language and old operators.
2. Discover the new operator from multi-environment evidence and consolidate it into weights.
3. Learn an unrelated but interference-capable operator from new data only.
4. Evaluate old capabilities, the new rule, longer/deeper OOD, and unseen old/new compositions.

“Interference-capable” matters: phase 3 must update shared parameters that could plausibly damage phase 2. If the new mechanism is placed in a frozen isolated module, perfect retention is informative about storage engineering but not about durable integration into a continually plastic model. A protected-module condition is still useful as an upper control, not as the main result.

Retain the supplied-rule control from S3. Compare at least:

- discovered rule, sufficient environments;
- discovered rule, single or insufficient environments;
- oracle/supplied rule with the same consolidation path;
- flexible sequential learner without the invariance intervention;
- joint full training only as an upper reference, never as the proposed method.

If discovered and supplied rules diverge before phase 3, the bottleneck is acquisition or consolidation. If they match before phase 3 but diverge afterward, discovery is not the whole problem: later interference is selectively damaging the learned representation. That decomposition is more valuable than one aggregate score.

## Preregistered acceptance table

A positive result must satisfy all of these, not merely ID accuracy:

- **Knowledge into weights:** after phase 2, remove demonstrations, training records, retrievers, and environment labels; the command plus input is sufficient.
- **Rule acquisition:** strong performance on longer inputs, deeper compositions, unseen intervention combinations, and the held-out nuisance; minimally sufficient environments must materially beat insufficient ones.
- **Continual retention:** after phase 3, old, new, and OOD capabilities remain within a preregistered tolerance of their pre-phase-3 values.
- **Cross-integration:** unseen old/new compositions work in both orders; isolated command accuracy does not count.
- **Growth necessity:** adaptive growth must solve a capacity/interference frontier that a fixed model at matched active inference compute cannot. Also compare with a larger model allocated from the start.
- **Compute advantage:** report cumulative training FLOPs, peak training memory, active inference FLOPs, and parameter count—not parameter count alone.
- **No-memory inference:** no replay buffer, demonstrations, retrieval corpus, task selector, or environment ID at inference. Persisted learned parameters are allowed and must be counted.
- **No joint full retraining:** each phase trains only on its current data; the joint condition is evaluation context, not the solution.

For growth, the decisive comparison is not simply “growing beats small fixed.” It must show one of two things: either the fixed model cannot retain and acquire at the same active compute, or matching the growing model requires materially more cumulative compute. If a same-size fixed model trained sequentially matches everything, growth was optional engineering, not a demonstrated necessity.

## Interpretation discipline

The strongest justified statement from S3 is:

> Under an exact structured representation, equivalence-breaking evidence can identify a rule that is then consolidated and retained memory-free across a later learning phase.

That is already a useful result. The LM experiment earns the broader statement only if a softly parameterized, shared, continually updated model reproduces the chain under shortcut-breaking environments and passes cross-integration. If it fails, report *where* the chain breaks—identifiability, optimization, consolidation, interference, or capacity. Any one of those is a productive result because it points to the next mechanism rather than inviting another undirected hyperparameter sweep.

Proceed with the algorithmic corpus and preregister the generator, shortcut family, intervention matrix, phase boundaries, and acceptance thresholds before the first full run. Do not spend another round extending the exact-operator toy unless the LM failure reveals a specific ambiguity that only the toy can isolate.
