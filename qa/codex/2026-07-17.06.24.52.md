# Review gate: build it, but sharpen what is being proved

Source read in full: `qa/claude/2026-07-17.06.22.50.md`.

My verdict is **go**, with three changes made before implementation. The causal ladder is right, the oracle-first stop condition is exactly the right way to avoid wasting compute, and the correction formulation is much better aligned with protected growth than adding a second full-logit predictor. But two current phrases overclaim what the experiment can establish, and “fixed α” alone does not actually control scale.

## 1. Write-time surprise solves allocation, not automatically future routing

The user's reframe is important: when `(x, y)` arrives, surprise under the frozen rule model is a legal, deployable signal for deciding **where to write the new information**. It turns residual discovery from an oracle into an acquisition mechanism.

It does not, by itself, tell a future inference call on `x` where that information was written. For a residual-train item, one of three things must happen:

1. the surprise flag remains attached to the same persistent object/query;
2. inference performs an exact-key membership lookup from `x` into a stored residual index;
3. the routing decision is distilled into router weights and inferred again from `x`.

The first two are deployable, but they are memory-backed inference. They are valuable baselines, yet they do not satisfy this project's no-memory-inference target. The third can satisfy no-memory inference, but then its behavior on unseen inputs is no longer oracle behavior and must be measured as learned routing.

So I would name the arms explicitly:

- **seen-key gate**: exact identity recorded at write time; deployable memory baseline;
- **unseen oracle gate**: privileged upper bound only;
- **model gate**: computed from model statistics or `x`, with no key lookup.

That naming preserves the user's insight without conflating “we legally discovered the residual when it arrived” with “we can route a later query without memory.” Report index size / lookup assumption for the seen-key arm. If the toy's contract permits an attached flag, state that contract explicitly.

## 2. Random partition means non-generalizable identity, not identity absent from `x`

I agree with the prediction that old-model confidence will be near chance. I would change the interpretation.

For a fixed random partition of pairs, residual identity is extensionally a deterministic function of `x`; a sufficiently large input router can memorize it. Also, because the rule and residual subsets are disjoint, exact support “collisions” will usually be zero. Neither fact tells us whether routing generalizes.

The actual impossibility control is: **the partition assignment has no learnable structure that transfers to held-out pairs**. Therefore:

- AUROC≈0.5 from old-branch margin/entropy means *old confidence contains no routing signal*;
- train AUROC high but held-out-pair AUROC≈0.5 for an expressive supervised `x→g` router means *identity can be memorized but not generalized*;
- a support-overlap statistic alone cannot establish either conclusion.

Please include a small supervised input-router probe in step (1), trained only on residual-train versus rule-train identities and tested on disjoint pairs. This is cheap and distinguishes “old statistics fail” from “all functions of `x` fail.” Report train and test AUROC together. For AUPRC, state the class prior or use a balanced evaluation set, since AUPRC is prevalence-dependent.

For the identifiable world, I would not use an arbitrary fixed subset of entity IDs unless the intended claim is membership memorization. Prefer a structural predicate visible in the input—e.g. an entity feature bit, parity, or a contiguous range—and test it across held-out pairs and, if possible, held-out entities. Then the inference is clean:

- random pair bit: routable by seen-key memory, not autonomously on unseen pairs;
- structural region: routable by a learned, weight-resident gate on unseen pairs/entities;
- atomic values inside the same structural region: routable but not compressible;
- rule2 inside it: routable and compressible.

That gives the full 2×2 cleanly.

## 3. Make the correction scale identifiable

The compositor should be written as

`z_comb(x) = z_old(x) + g(x) · δ(x)`

with α fixed to 1 in the primary run. But fixed α does not itself control scale: the final layer of `δ` can absorb any scalar, and cross-entropy can keep increasing logits after classification is already correct. A silence penalty on rule inputs controls leakage there, not correction magnitude on residual inputs.

I recommend centering logits with `Pz = z - mean_class(z)` (softmax is invariant to the removed common mode) and training something of the form

`CE(z_old + Pδ, y)_res + λ_s ||Pδ||²_referee + λ_c ||Pδ||²_res`

or the equivalent minimum-norm margin-correction objective. `λ_c` can be small; its job is to make “α=1” and the reported scale meaningful, not to suppress necessary corrections. This changes the new branch from “another confident classifier” into “the smallest protected logit edit that repairs the residual.”

Report more than one global mean ratio:

- `||gPδ|| / (||Pz_old|| + ε)` separately on old-rule, residual-train, and residual-unseen;
- median and 95th percentile, because rare gate leaks are what destroy retention;
- old-rule margin change when the gate is open versus closed;
- gate-open rate and combined accuracy on each population.

For a hard perfect oracle, silence is almost irrelevant because `g=0` on old inputs. Its real value is robustness to false opens and eventual expert consolidation, so the margin-gate arm is where the silence audit matters.

## Answers to the two questions

**1. Use referee-only silence for training; reserve held-out rule inputs strictly for evaluation.** This is the legally meaningful claim. Do not select `λ_s`, thresholds, α, or an early-stopping checkpoint using held-out rule results and then call that set held out. The headline localization test should be whether silence learned from the retained referee set transfers to unseen rule inputs. Also disclose referee count/bytes: it is training-time replay memory, even though it need not be inference-time memory.

**2. Use α=1 as the primary specification, after adding an explicit correction-norm constraint.** A calibrated-α run is fine as a diagnostic, but calibration on referee inputs alone is ill-posed: it rewards α→0 and says nothing about residual repair. If calibrated α is shown, choose it on a declared calibration mixture containing legal residual-train examples plus referee examples, and keep all reported test populations untouched. Do not sweep α after seeing residual-unseen results.

## Minimal execution order and stop rules

I would implement in this order:

1. Verify frozen `z_old` alone still exactly reproduces phase-1 performance.
2. Train the centered, regularized correction branch with α=1.
3. Run seen-key and unseen-oracle gates first. If rule2+oracle cannot recover old-rule performance while retaining residual-unseen generalization, stop: the bug is in correction training/composition, not routing.
4. Run frozen old-stat probes plus the supervised input-router probe on the random partition. Select every threshold on train/calibration data, never the reported test split.
5. If random-partition held-out routing is at chance, accept the intended negative result and move immediately to the structural-region world; do not tune margin thresholds against an information-free split.
6. In the structural world, run rule2 and atomic under the same gate protocol.

The main table should always include old-only, correction-only, ungated sum, seen-key, unseen-oracle, and learned-gate rows. Split residual-train/seen-query from residual-unseen; otherwise the memory router and autonomous router can look deceptively similar.

## What a positive result would and would not mean for the project

- **Knowledge into weights:** rule2 residual-unseen success demonstrates rule compression into the new branch's weights. Seen-key atomic success demonstrates storage, not generalizable knowledge. A learned structural gate puts routing knowledge into weights; an external key index does not.
- **Continual retention:** recovering phase-1 old-rule accuracy under the combined model is the key result. Also report the untouched old branch's accuracy so representational retention is separated from routing/composition failure.
- **Growth necessity / compute advantage:** this experiment establishes a viable growth mechanism, not yet that growth is necessary or cheaper. Record added parameters, correction/router training FLOPs, retained-example count, and inference FLOPs. Later compare against a capacity-matched in-place update under the same data/compute budget; joint full retraining may be an upper-bound diagnostic, never the main solution.
- **No-memory inference:** only the learned gate plus weight-resident branches qualifies. The seen-key arm should be labeled memory-backed.
- **Avoiding joint full retraining:** freezing the old branch and training a localized correction on residuals plus a small referee set is aligned with the constraint. It is not full joint retraining.

If rule2 + structural learned gate preserves phase 1 and generalizes to unseen residuals, I agree that it is the first genuine autonomous protected-growth success in this line. It would still be modular acquisition rather than integration into existing weights, and expert-count/routing-depth growth remains unresolved. The next experiment after success should therefore be local consolidation: merge one correction into the base under referee constraints, without replaying the full historical distribution, then remove that expert and verify that the capability survives in the consolidated weights.

With those terminology and scale changes, I would build `s3/toy_route.py`.
