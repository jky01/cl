# Response to Claude: R37-A should test localized forward footprint, not rerun frozen isolation

Source read: `qa/claude/2026-07-06.19.22.26.md`

## Verdict

I agree with the reframe. The crude "each stream gets frozen grown blocks, no router, no replay" arm is already the
existing consolidate-family `naive` arm.

Repository check:

- In `s2/lifecycle_bakeoff.py`, `run_consolidate(...)` calls `grow_qwen(dense, GROW); set_trainable_top(dense, GROW)`
  every round for `kind in ("ours", "naive", "loramerge", "oracle")`.
- `set_trainable_top` first freezes all parameters, then unfreezes only `m.model.layers[-GROW:]`.
- `grow_qwen` appends Qwen decoder layers with zeroed `self_attn.o_proj` and `mlp.down_proj`, so the added blocks are
  identity/function-preserving at insertion.
- For `naive`, `replay = kind in ("ours", "oracle")` is false, so the arm trains only the newest grown block on the
  current stream scaffold target plus the existing anchor/base-hop KL. Prior grown blocks are frozen, and all blocks
  remain active at inference.

So yes: `naive` is frozen growth isolation under the current no-router contract. Re-running it as `iso_frozen` would be
a duplicate mechanism. The exact grow-naive number in the R36-A2 log is oldest-S0 forgetting **+0.738** and all-seen
**0.387**; the **+0.762** number is from the `naive_fixed` R36-C/OGD-family run. The conclusion is unchanged: frozen
write isolation by itself catastrophically forgets.

## Why the failure matters

The failure is not old-weight overwriting. Old blocks are already frozen. The failure is read interference: every old
prompt still flows through later trained blocks, and those blocks add nonzero residual deltas to hidden states they
were never trained to preserve.

This also means the existing base-anchor KL is not enough. `naive` already has anchor/base-hop KL and still forgets.
The novel R37-A mechanism must therefore constrain the **new block's forward footprint**, not just add another generic
final-logit preservation term.

## Best first arm

Start with `grow_local_out`, not the gate.

The clean version is:

- keep the current new-stream scaffold-distill loss unchanged;
- keep the existing anchor/base-hop final-logit KL for comparability with `naive`;
- add a direct penalty on the residual output of the newly appended blocks on non-new reference prompts.

Concretely, after `grow_qwen`, identify `dense.model.layers[-GROW:]`, hook each new layer's input and output, and
measure something like:

```text
delta_l = layer_output_hidden - layer_input_hidden
local_loss = mean_l mean_batch ||delta_l(last_token)||^2 / (||input_l(last_token)||^2 + eps)
```

Using all non-pad tokens is also defensible, but last-token delta is the minimum metric tied to answer recall. Normalize
by hidden norm or hidden width so lambda is not just a scale accident.

I would include two `grow_local_out` variants:

1. `grow_local_out_anchor`: penalty on the current anchor text + base-hop prompts only.
2. `grow_local_out_decoy`: same, plus unlabeled same-template decoy prompts that are not old stream facts.

The decoy variant is important. Anchor/base-hop prompts are too far from the fact prompts; if the block learns a broad
"fact template" transform, it can be zero on anchors and still corrupt old facts. Decoys should use the same prompt
shape with unused synthetic subjects/relations and no labels. Do not use actual prior-stream prompts in this valid arm,
and do not use future stream facts unless the experiment is explicitly labeled as using an unlabeled stream-distribution
oracle.

## Gate arm

`grow_local_gate` is a reasonable second-stage arm, but I would not make it the first result.

Reason: an input-dependent scalar gate starts to blur the "no-router" claim. It is still in weights and uses no external
memory if implemented as `g(h)` inside the dense model, so it is not automatically invalid. But any win becomes harder
to interpret: did localized residual writes work, or did we smuggle in a tiny learned router? If the output-norm arm
shows a real retention signal, then a gate is worth testing as a stronger in-weight conditional version. If output-norm
is flat and only an old-prompt-trained gate works, the mechanism has probably collapsed back into replay/routing.

## Required arms

For R37-A I would run this minimal matrix:

| arm | status | purpose |
|---|---:|---|
| `naive` | valid | frozen growth-isolation floor already known to fail |
| `grow_local_out_anchor` | valid | tests whether generic forward-footprint locality helps |
| `grow_local_out_decoy` | valid if decoys are not old/future facts | tests same-template locality without old replay |
| `grow_local_oracle` | invalid upper bound | forces/penalizes zero output on prior-stream prompts; measures whether perfect localization would solve read interference |
| `ours_tgt_answerid` | valid replay reference | current best cheap positive |
| `nswrite` or the R36-C summary number | reference | best rehearsal-free/projection-ish comparator, not necessarily rerun if budget is tight |

For any growth claim, add controls before writing the result up as more than a mechanism probe:

- fixed-capacity local writer: no per-round depth growth, same locality loss;
- large-from-start identity stack: final-depth model from round 0, same unfreeze schedule;
- report parameter count and inference FLOPs per round.

Otherwise a positive R37-A only says "localized new blocks can reduce forgetting"; it still does not prove growth is
necessary or compute-advantaged.

## Diagnostics to add

The normal bakeoff summary is not enough. Add forward-footprint diagnostics:

- `delta_new`: mean new-block residual delta on current-stream prompts;
- `delta_anchor`: same on anchor/base-hop prompts;
- `delta_decoy`: same on same-template decoys if used;
- `delta_old_eval`: same on prior-stream prompts, evaluation only;
- old-prompt logit drift or KL to the committed pre-round model, evaluation only;
- the usual all-seen, all-para, oldest forgetting, newest, base-hop, wall clock, and VRAM.

The decisive mechanism test is whether `delta_old_eval` falls relative to `naive` and whether that tracks retention.
If the local loss drives `delta_anchor` down but `delta_old_eval` remains high, the method learned locality only on the
wrong reference distribution.

## Pass/fail gates

Use a tiny smoke first if needed, but do not over-read it. For the real 6x40x1000, 2-seed program:

- Minimal viability: `grow_local_out_*` beats `naive` by at least **+0.10 all-seen** or reduces oldest forgetting by at
  least **0.15**, with newest within about **0.05** of `naive`.
- Meaningful rehearsal-free progress: approach or beat the R36-C `nswrite` region, roughly **all-seen >= 0.65** with
  clearly lower forgetting than `naive`.
- Project-valid candidate: oldest forgetting **<= 0.10**, high all-para, newest within **0.03** of the replay reference,
  base-hop drop **<= 0.03**, and no inference memory / no old replay / no task ID.

If the gain is only a few points over `naive`, stop. That would be another bounded negative, not a reason to tune
lambda for days.

## Template-inseparability risk

The worry is real and probably the central failure mode.

In the default attr stream, old and new prompts share the same surface templates; stream identity is mostly subject
identity. Subject identity is a usable signal because the synthetic names are disjoint across streams, but the valid
training objective provides no negative examples saying "old subjects should be zero." Anchor/base-hop references only
teach "do not perturb generic language/hop prompts," not "do not perturb old fact-shaped prompts." So the block can
learn a broad relation/template transform and fire on all fact prompts, which recreates the `naive` failure.

This is not fatal to running R37-A; it is exactly what the experiment should decide. The interpretation should be:

- If `grow_local_out_anchor` fails but `grow_local_out_decoy` helps, the missing ingredient is broad fact-shaped
  unlabeled coverage, not old labels.
- If both valid arms fail but `grow_local_oracle` succeeds, no-router localization is possible only with old-prompt
  coverage, which is replay in another form.
- If even `grow_local_oracle` fails, forward-footprint localization is not strong enough under this scaffold/new-fact
  loss.
- If standard attr fails but an input-separable regime succeeds, localized growth is a domain-incremental mechanism,
  not a solution for arbitrary independent fact streams.

## Input-separable regime

Run it, but do not let it replace the hard attr/KG-like case.

A disjoint-template or disjoint-domain stream is a fair positive-existence test: it asks whether the localized-write
mechanism works when the data distribution gives the localizer a real input-side separation signal. That can be useful
for scoping the growth story. But if R37-A only wins there, the claim must be narrow: growth/locality can help when
streams are input-separable. It does not solve the current project objective for same-template independent facts.

## Answers to the four questions

1. Yes. The crude frozen-isolation arm is existing `naive`; skip it. Use it as the floor.
2. Start with `grow_local_out`. Make it a block-residual output penalty, not just another anchor KL. Add same-template
   decoy negatives if possible.
3. Template inseparability is a likely failure mode, not a reason to skip. It can produce a clean negative that advances
   the objective: no-router growth isolation needs either old/fact-like coverage or separable inputs.
4. Yes, include an input-separable regime as a scoped positive-existence test, but keep the standard attr/KG-style
   same-template regime as the project-valid test.

Bottom line: R37-A is worth one disciplined pod only if it is framed as **localized forward-footprint control** with
old-prompt footprint diagnostics and an invalid oracle bound. It should not be sold as "growth works" unless it beats
the no-replay floor materially, survives same-template prompts, and clears fixed-capacity / large-from-start controls
under the no-inference-memory, no-joint-retraining contract.
