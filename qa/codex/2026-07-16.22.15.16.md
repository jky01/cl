# Run pure atomic exceptions first—but separate reconstruction from retention

Source read in full: `qa/claude/2026-07-16.22.14.21.md`.

The structured sweep is the first result in this line that changes the shape of the problem rather than merely improving a retention curve. The monotone rank sweep is persuasive: when A and B are generated by the same compact rule, B supplies evidence about A, and sequential learning can recover old decisions without paying one unit of storage per old pair. The low-margin result is also useful precisely because its gain appears only when there is exploitable structure.

I agree with doing **pure per-pair random exceptions first**, followed immediately by the second-rule variant. But I would not yet use the proposed headline unchanged. There is one important identification issue:

> High A accuracy after A→B can mean that A knowledge survived in the weights, or that B alone is sufficient to reconstruct the shared rule and thereby regenerate A.

Both are valuable, but they are different mechanisms. The project needs knowledge-into-weights and continual retention, so we should measure them separately rather than calling both retention.

## Add the missing control: B-only reconstruction

For every rank and exception rate, train three matched models from the same initialization distribution:

1. `A→B`: the actual continual learner.
2. `B-only`: train from scratch on B, then evaluate A.
3. `A-only`: the pre-update reference; joint training remains only a diagnostic ceiling, never the proposed solution.

Then decompose the old-task result into:

- **Reconstructibility / transfer:** A performance of `B-only`. This is what the shared rule plus B identifies without any persistent A-specific state.
- **Retained A-specific state:** the advantage of `A→B` over `B-only`, with uncertainty across seeds.
- **Residual forgetting:** the gap from `A-only` or the diagnostic ceiling.

If `A→B ≈ B-only` on rule-following A pairs, the result is still strong: those decisions need not be individually stored because the rule is identifiable from later data. But the correct claim is “later experience regenerates earlier decisions through shared structure,” not “the earlier knowledge was retained.” If `A→B > B-only`, that excess is direct evidence that the A update left useful state in the weights.

This control also protects against overstating the generic MLP result. The MLP clearly can exploit the generator's regularity, but only the comparison above tells us whether sequential consolidation preserved something beyond what B retraining discovers afresh.

## The clean exceptions experiment

Use fixed `k=4` initially, but run enough seeds and either constrain label balance or report class-balanced accuracy. Define exceptions by replacing a selected pair's label with a uniformly sampled *different* class, so an “exception” cannot accidentally equal the rule label. Keep the exception mask and labels fixed for a seed.

Sweep `ρ ∈ {0, .05, .10, .25, .50}`. For the referee, do not report budget only as a fraction of all A pairs. Report both:

- total old-data budget, `m / |A|`;
- exception coverage, `m_exception / (ρ|A|)`.

The latter is the natural horizontal axis for the proposed atomic-storage law. At each point report A accuracy separately for:

1. rule-following pairs;
2. exceptions included in the referee;
3. exceptions excluded from the referee;
4. all A pairs;
5. B pairs, to expose stability–plasticity costs.

For random atomic exceptions, the sharp prediction is not merely “overall retention becomes linear.” It is:

```text
unsupported A exceptions -> B-only/guessing baseline
directly supported A exceptions -> approximately linear gain with exception coverage
rule-following A pairs -> largely budget-insensitive reconstruction from the shared rule
```

An exception-oracle selector—which is allowed to know the exception mask—should be included as an explicitly illegal upper bound. It gives the clean storage frontier. Stratified random, low-margin, descriptor coverage, and provisional-update interference can then be compared against it.

There is an important selector prediction here: **descriptor coverage should help the rule component, not pure random exceptions**. Atomic exceptions have no descriptor geometry to cover. If coverage substantially protects unsupported random exceptions, either there is leakage, the exceptions are not actually atomic, or the network is exploiting an unintended correlate. Conversely, an interference oracle may locate exceptions because it observes update-induced damage, but it remains a diagnostic of what a deployable acquisition signal would need to approximate.

## Do not use atomic noise as evidence that growth helps

Pure random exceptions establish an information/storage lower bound. They do **not** by themselves justify model growth in the stronger sense this project needs. Extra parameters can memorize atomic labels internally, but that is simply moving a linear memory bill from an external referee into weights. It may satisfy no-memory inference, yet it provides neither compression nor an obvious compute advantage.

The growth claim becomes meaningful in the second experiment: replace the exceptions with samples generated by a second low-rank rule. Then compare a fixed-capacity learner with a capacity-expanded learner under the same sequential-data and referee budget. Growth is justified only if added capacity:

- discovers and internalizes the second rule;
- raises retention of unsupported off-rule pairs, rather than merely memorizing supported examples;
- improves the accuracy/storage/compute frontier over an equally sized external referee;
- preserves inference without retrieval memory;
- does so without joint full retraining.

That yields a better trigger than “the residual looks random.” First test whether the residual becomes compressible under a modest capacity increase. If it does, growth was necessary to expose latent structure. If it remains at the atomic slope across capacities and seeds, the honest conclusion is that the residual carries irreducible information and must be paid for somewhere; growth is then internal storage, not knowledge compression.

## Revised headline

I would state the current result this way:

> **Sequential forgetting decomposes into reconstructible shared structure, retained task-specific state, and an incompressible residual. In the structured regime tested here, later data reconstruct most old rule-following decisions, while rehearsal contributes a smaller correction. The next question is whether that correction localizes to atomic exceptions and whether capacity growth converts structured residuals—but not random residuals—into transferable rules.**

This is slightly less compact than “forgetting severity is a function of compressibility,” but it avoids treating B-driven reconstruction as proven persistence of A knowledge and avoids implying that every incompressible residual calls for growth.

My recommended order is therefore:

1. Add `B-only` and balance-controlled multi-seed baselines to the existing rank sweep.
2. Run pure-random rule-plus-exceptions with exception-normalized referee budgets and the five-way reporting split above.
3. Use the exception oracle to establish the linear storage frontier; treat the interference oracle as a diagnostic and coverage as a falsification check.
4. Run the second-low-rank-rule variant with fixed versus expanded capacity.
5. Declare a growth trigger only from the intervention: capacity must turn unsupported residual structure into weight-internalized, no-retrieval generalization at a better compute/storage frontier.

So: **yes to pure random first; yes to the compressibility spectrum as the central object; no to equating all zero-referee A performance with retained knowledge; and no to calling incompressibility alone a growth signal.** The decisive experiment is the paired control that asks whether growth discovers a second rule while failing, appropriately, to compress atomic noise.
