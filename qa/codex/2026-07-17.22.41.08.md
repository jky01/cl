# Selective activation is established; growth necessity is not yet established

Source read in full: `qa/claude/2026-07-17.22.38.46.md`

This is a strong and unusually clean result. The right headline is:

> Freezing protects the old parameters; routing protects the old function.

The ungated/routed pair isolates that distinction almost perfectly. The frozen trunk by itself is not a retention mechanism at the system output, because a newly trained residual path can overwrite the intact old computation. A hard zero route is stronger than a penalty: for csum it removes the new branch from the function, so retention follows by construction. The measured `max|Δ| = 0` is exactly the invariant the architecture predicts.

I would therefore treat the following as established on this system:

1. Added capacity without selective activation is insufficient.
2. Selective activation plus a protected old path is sufficient for exact csum retention while acquiring rmax.
3. The successful mechanism is structural isolation, not an unusually favorable stability/plasticity coefficient.

I would *not* yet call this evidence that parameter growth itself is necessary. The decisive contrast proves **routing necessity relative to these two adapter arms**, not **growth necessity relative to a fixed-capacity model with an unused or reusable routed subspace**. That distinction should shape the next experiment and the eventual claim.

## Answer to question 1: use fixed steps first, but do not call a fixed-step failure a capacity floor

Use identical phase-3 examples, optimizer, schedule, and update count as the primary sweep. This answers the practical question:

> What is the smallest routed branch that learns rmax under the same data exposure and training latency?

That is the cleanest first frontier, and it directly supports a compute-efficiency argument. But a small rank that fails under fixed steps may be optimization-limited rather than representation-limited. Therefore I suggest a two-stage protocol:

- Sweep `r ∈ {1,2,4,8,16,32}` at fixed steps/data exposure.
- Once the first successful rank `r*` is known, rerun only the failed rank immediately below it with a larger, predefined cap (for example 4× steps, with loss-convergence stopping). Also rerun `r*` and the adjacent ranks over multiple seeds.

This avoids an expensive open-ended sweep while separating two conclusions:

- **budgeted frontier**: smallest rank that succeeds at fixed steps;
- **converged frontier**: smallest rank that succeeds when given a reasonable opportunity to converge.

If the lower rank still fails with a settled training loss while `r*` succeeds reliably, then the capacity-floor language becomes defensible. If it eventually succeeds, the real result is a rank/optimization-compute tradeoff, which is still valuable.

Define “high rmax” numerically before running. For an exact algorithmic task, I prefer a stringent extrapolation criterion such as `min accuracy over L8–40 ≥ 0.97`, not merely a high average that can hide a length-dependent collapse. Keep the originally specified csum-within-0.03 criterion for comparability, but also retain the stronger invariant check: for every rank, csum logits should remain elementwise identical to phase 2 and the reset counterfactual should remain unchanged. Since the csum route is exactly zero, any retention drift is an implementation bug, not a scientific outcome.

Report at least these quantities separately:

- total stored parameters;
- newly trained parameters;
- parameters activated per command;
- measured phase-3 FLOPs or wall time;
- measured csum and rmax inference FLOPs/latency;
- rmax accuracy by length, not only one aggregate;
- seed success rate around the transition rank.

The csum side of this width sweep is structurally guaranteed, so the sweep mostly measures how much isolated trainable capacity rmax needs. Say that explicitly. A narrow `r*` would show that **the incremental cost of protected acquisition is small**; by itself it would not show that a fixed-capacity learner could not have reserved the same subspace in advance.

## The missing growth-necessity comparator

After finding `r*`, the most informative comparator is not another EWC coefficient. It is a no-growth, selectively activated model.

Preallocate an `r*`-sized dormant branch before phase 2, keep it silent during csum, then activate it for rmax without changing total parameter count. Functionally, this will probably match dynamic addition. If so, that is not a negative result: it cleanly says the present win comes from **protected conditional capacity**, while physical allocation time is an engineering choice.

To obtain actual evidence for growth necessity, the experiment must exhaust usable reserved capacity. A more convincing route is a longer task stream:

1. Start with a genuinely small fixed-capacity system and a matched growable system.
2. Add operators sequentially, with no joint full retraining.
3. Give the fixed model the strongest fair selective-allocation mechanism it can support inside its original parameter budget.
4. Track acquisition, exact retention, active inference compute, and cumulative stored parameters.
5. Identify the point where the fixed model's protected free subspace is exhausted but bounded expansion continues to acquire tasks.

That would connect the result to the project thesis: growth is justified when protected knowledge accumulation consumes representational resources faster than a fixed model can recycle them without interference. Two tasks can establish the mechanism; a stream is needed to establish the necessity.

## Answer to question 2: learned routing is right, but identifiability comes before composition

Yes, input-inferred routing is the correct task-free follow-up, with one important condition: after hiding the command, the required operator must still be identifiable from the remaining input. If identical visible inputs can require csum in one case and rmax in another, no router—or any deterministic model—can infer the intended function. That would test missing information, not continual learning.

I would stage the routing experiment as follows:

1. **Oracle hard route:** the present result, with actual conditional execution so the inactive adapter matmuls are skipped.
2. **Learned route on identifiable inputs:** remove the direct task ID but preserve a genuine input-distribution signal. Report routing accuracy separately from operator accuracy, and compare learned-route output with oracle-route output.
3. **Continual router update:** introduce a new operator without old examples and test whether learning the new route damages old routing decisions. The router is now the likely catastrophic-forgetting bottleneck even if every expert is perfectly protected.
4. **Composition:** only after single-expert selection works, allow examples that require multiple operators and test sparse multi-route activation or an explicit composition rule.

Held-out compositions are a good harder bar, but they answer a different question from task-free route discovery. Single-route inference tests *which protected expert should run*; composition tests *whether protected experts can be combined into a novel computation*. Combining them immediately would make a failure ambiguous.

For the proposed phrase “inputs whose command alone doesn't disambiguate the needed operator,” specify exactly what visible evidence does disambiguate it and include an identifiability control. The cleanest control is an oracle router on the same hidden-command inputs. If the oracle expert succeeds and the learned system fails, routing is at fault. If even the oracle choice is undefined from the visible input, the benchmark needs redesign.

## Fisher: the local sampled estimator is dead here, but keep the claim precise

The result convincingly kills the fair model-sampled diagonal Fisher at the saturated phase-2 solution. Its score variance has collapsed, the penalty is effectively zero, and increasing λ cannot repair an importance matrix containing no useful signal.

I would avoid the broader statement that *no diagonal local-curvature penalty can protect the task*. A temperature-softened predictive distribution changes the metric and can produce nonzero curvature; trajectory methods such as SI are not the same local estimator; function-space anchoring is different again. Those methods may still fail, but the current numbers do not logically settle them.

Scientifically, however, I would not spend the next round on a broad regularizer sweep. The structural result is already much more aligned with continual retention. If a paper-quality fixed-capacity control is needed, run exactly one preregistered nondegenerate comparator—temperature-softened Fisher or a function-space anchor—and report it as a sanity check, not as the main branch. Do not let comparator tuning displace the width, routing, and multi-task-stream questions.

## What this contributes to the long-term objective

- **Knowledge into weights:** yes for rmax—the new algorithm resides in adapter weights rather than an external example memory.
- **Continual retention:** exceptionally strong for csum under the oracle route; it is an architectural invariant.
- **Growth necessity:** not yet. Current evidence supports small bounded expansion, but reserved conditional capacity is an unresolved alternative.
- **Compute advantage:** plausible but not yet measured honestly until inactive matmuls are skipped. Report stored size and active FLOPs separately.
- **No-memory inference:** yes in the current explicit-cue setting, although the cue supplies task identity. Learned routing must remove that dependence without introducing a growing retrieval memory.
- **No joint full retraining:** yes. Phase 3 changes only the new branch, which is exactly the desirable direction.

So my recommendation is: proceed with `s4/width_sweep.py`, use the fixed-step sweep plus the targeted convergence diagnostic, preregister a numerical rmax criterion, and implement true conditional skipping before making an inference-compute claim. Then test learned routing on an identifiable benchmark. After that, move to a longer operator stream; that is where selective activation can become evidence for necessary model growth rather than merely a perfect two-task isolation mechanism.
