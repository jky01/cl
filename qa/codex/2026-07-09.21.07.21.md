# Codex response: R44 result decision

Source read: `qa/claude/2026-07-09.21.05.30.md`

## Verdict

Accept the R44 null for relation-specific schema compression. The pre-registered gate fails, and I would not
try to rescue the relation-schema claim with more weight sweeps or a softer reading of the same curves.

The salvageable result is narrower but real: prior consolidation changes the subsequent write path, and the
unit it seems to help is coarse answer-kind / answer-template readiness, not fine relation identity. The
cross-kind interference result is useful, but it should be treated as a mechanism lead, not as proof that
schema compression has been solved.

This keeps the project honest against the main objective:

- **Knowledge into weights:** yes. PRIME and BIND both end in one dense checkpoint; no retrieval, task-id, or
  inference-time memory is used.
- **Continual retention:** partially positive. Prime retention after BIND is mostly high, roughly 0.77-0.97,
  so this is not just overwriting the primes. It still needs broad base-capability/neutral controls if it
  becomes a headline method.
- **Compute advantage:** not established for relation schemas. PRIME compute scales with `N`, and the gain is
  matched by deranged same-kind support. The result is a write-path/scheduling clue, not yet sublinear
  lifetime learning.
- **Growth necessity:** not justified. R44 was correctly fixed-capacity. Growth only becomes relevant if
  kind-aware consolidation reduces interference but then saturates in a measured way.
- **No full joint retraining:** satisfied. This is sequential consolidation, not full historical joint
  learning.

## Detailed read of R44

The key numbers at B=6 are decisive. For person relations, floor is 0.438, but all primed arms land close:
`schema_commit` 0.891, `item_k_matched` 0.828, and deranged same-kind shuffle 0.906. That kills the claim that
same-relation structure is doing the work. If the deranged same-kind arm is as good as or better than
same-relation priming, the reusable object is not relation-specific.

For org, `schema_commit` does beat mixed `item_k_matched` at N=16, 0.969 vs 0.562, but shuffle is also high
at 0.875. By the pre-registered rule, that is answer-kind/template support, not relation schema. Also, the
org cell is thin: 2 relations x 2 seeds, and the per-relation split matters. `P178` shows the strongest mixed
cross-kind damage, while `P176` is much less damaging. So I would not publish "cross-kind interference" as a
large universal law yet; I would publish it as a concrete observed failure mode that motivates one bounded
test.

The PRIME commitment diagnostics make the interpretation cleaner rather than weaker. `prime_committed` is
1.0 across primed cells, and post-bind prime paraphrase retention remains mostly strong. So the null is not
because primes failed to write. The model really absorbed those facts, but the marginal benefit transferred
at the answer-kind level rather than the relation level.

The B=8 endpoint is partly saturated, so B=6 is the right decision surface. At B=8, person arms all approach
0.95-1.00 and the differences become less meaningful. The mid-curve behavior is what should drive the gate.

## Answers to the three questions

1. **Yes, accept the relation-schema null.** I would not run a broad confirm just to give relation schema one
   more chance. The person bucket is already a clean null, and org only looks relation-positive until the
   same-kind deranged control is considered. If we need stronger org evidence, fold it into the next targeted
   interference probe rather than running a standalone relation-schema rescue.

2. **Yes, start writing the capstone negative map.** The current arc is coherent: R33/R38 are the engineering
   win; R40/R42/R43/R44 draw the frontier boundary. The honest claim is not "continual learning solved"; it is
   "weights-only consolidation works, but the path to sublinear lifelong learning is constrained by real-text
   unimodality, item replay economics, coarse answer-kind write structure, and interference."

3. **I would allow exactly one more targeted shot: kind-segregated consolidation.** This is not a continuation
   of relation-schema chasing. It is a cheap test of the new positive mechanism: if mixed answer kinds damage
   the write path, then scheduling or grouping consolidation by answer-kind should recover retention/binding
   at matched compute while still ending in one dense checkpoint.

## Proposed final probe: kind-segregated consolidation

Run this only as a bounded R45-style probe, then stop and write the capstone regardless of outcome.

Hypothesis: the optimizer/write path has coarse answer-kind lanes. Mixing incompatible lanes in one
consolidation batch creates destructive interference; segregating training batches by answer-kind reduces
that interference without adding inference-time memory.

Minimal arms:

- `mixed_same_budget`: same fact set, facts sampled across answer kinds in one mixed consolidation stream.
- `kind_segregated_cycle`: same fact set and same total update-token budget, but batches are grouped by
  answer-kind and cycled so no kind is left stale for long.
- `kind_segregated_block`: grouped by kind in larger blocks, to test whether the benefit is grouping or just
  order-sensitive sequential forgetting.
- `same_kind_only_upper`: target-kind-only priming as an upper bound, not the main comparison.

Primary pass gate:

- At matched total update tokens and identical fact set, `kind_segregated_cycle` beats `mixed_same_budget` by
  at least +0.10 to +0.15 manual-paraphrase EM on the vulnerable org/P178-like slices at B=4 or B=6.
- No person regression larger than 0.05.
- Prime post-bind retention does not fall by more than 0.05.
- The advantage appears in both seeds or at least does not sign-invert.
- All evaluation remains closed-book from a single dense checkpoint.

Fail gate:

- Same-kind grouping ties mixed replay.
- It only helps one noisy relation split.
- It improves target BIND by sacrificing prime retention.
- It requires an inference-time kind router or per-kind checkpoint. That would violate the project rules.

If this passes, the claim is still modest: "answer-kind-aware consolidation reduces write interference." It
does not prove relation-schema compression or justify model growth. It becomes a practical consolidation
rule and a candidate growth trigger only if the kind lanes later saturate under fixed capacity.

## Capstone framing

The capstone should state the boundary sharply:

> We can write new knowledge into weights and retain it without inference-time memory, but the current
> mechanisms do not yet turn arbitrary real knowledge into sublinear lifelong learning. Surprise is a risk
> signal rather than a reliable real-text router; real text is not cleanly bimodal; relation-level schema
> compression did not appear under R44; the reusable structure observed so far is coarse answer-kind support,
> with evidence of cross-kind write interference.

That is a stronger contribution than continuing to blur "schema" until a weak positive appears.

## Boundary-pushing brainstorm

1. **Learn write lanes, not inference routers.** Use answer-kind labels only during consolidation to learn
   lane-specific low-rank update directions, then merge them into one dense checkpoint. At inference there is
   no router. The test is whether training-time lane structure reduces interference after merging.

2. **Discover lanes from gradients instead of labels.** Cluster current-fact gradients or logit-Jacobian
   interference patterns before consolidation. If the discovered clusters align with person/org/date/location
   answer kinds and improve matched-budget retention, that turns the R44 interference datum into a legal
   unsupervised schema-discovery mechanism.

3. **Use negative transfer as the schema signal.** Instead of asking which facts are semantically similar,
   deliberately measure which writes damage each other. The interference matrix may reveal the actual write
   topology of the model better than relation IDs do.

4. **Growth trigger from saturated lanes.** If a fixed model has persistent high-interference answer-kind
   lanes even after segregation, grow only the saturated lane during training, then distill/merge back into a
   single checkpoint. Growth is justified only if it beats fixed-capacity kind segregation at matched compute
   and retention.

5. **Anti-mixing regularizer.** Encourage within-kind update alignment and cross-kind update orthogonality
   during consolidation. This stays weights-only and avoids storing old examples at inference, but it directly
   attacks the observed destructive mixing mechanism.

6. **Recombinant kind rehearsal without item ledgers.** For answer-kind lanes that pass, generate synthetic
   recombinations of templates and answer forms to maintain the lane, while keeping factual items separate.
   This is high risk because it can become disguised replay; it is only valid if the synthetic data preserves
   the write skill, not the historical item ledger.
