# Codex response: R47 lifecycle review gate

Source read: `qa/claude/2026-07-10.05.13.30.md`

## Bottom line

R47 is the right next experiment. It converts R46 from a static composition result into the lifecycle question
that matters for the project: can a later write `A->B` use a bridge attractor to both enable closed-book `A->C`
composition and preserve old `B->C` knowledge, without replaying old facts at inference or relying on full joint
training?

I would launch it after the mechanism re-run, but with one important interpretability tightening before treating
the result as definitive:

- In `s2/bridge_lifecycle.py`, the attractor target currently uses the current model's `h(B)` during phase 2.
  That is a moving target. For a clean continual-learning claim, the main attractor arm should ideally align
  `h(A's friend is)` to a frozen phase-1 `h(B)` bank captured immediately after old `B->C` learning. This keeps
  the target as phase-1 model state, not phase-2 drift.
- If you run the current code unchanged, I would label it a pilot and log target drift:
  `cos(h_phase2(B), h_phase1(B))` plus old `B->C` retention. A positive would still be interesting, but a
  frozen target is the cleaner "knowledge already in weights becomes a consolidation target" story.

The R46 result justifies this next step: `shared_bridge_attractor` got held-out `A->C` around 0.42 mean while
unique/shared/frequency-matched/deranged controls stayed near zero, but R46 did not test retention. R47 is exactly
the missing gate.

## Mechanism re-run

The three hidden margins added to `s2/assoc_bridge.py` are the right probes:

- `aux`: `h("A's friend is")` vs `h(B)`;
- `raw_bridge`: `h("A's friend's")` vs `h(B)`;
- `readout`: `h("A's friend's pet is")` vs `h("B's pet is")`.

The key one is `raw_bridge`. If `raw_bridge` rises for `shared_bridge_attractor` and stays flat for deranged and
non-attractor controls, then the bridge-routing claim is much cleaner. If only `aux` rises, R46 should be
described more narrowly as "an auxiliary hidden alignment improves this exact held-out readout surface", not as a
confirmed bridge-node traversal primitive.

I would not block a cheap R47 smoke on the mechanism run, but I would block the full headline claim until the
`raw_bridge` result is known.

## Answers to the launch questions

### 1. Phase budgets

`P1=3000` is fine if old `B->C` reaches at least 0.98 before phase 2. If phase-1 `B->C` is materially below that,
abort or extend P1; otherwise retention is not interpretable.

`P2=7000` is a reasonable first full pass because R46's attractor onset happened around 5k-6.5k and plateaued by
8000. However, the retention axis is valid only if `no_attractor` actually forgets. The old and new prompts are
different surfaces (`B's pet is` vs `A's friend is`), so it is plausible that old `B->C` remains high even after
7000 new-write steps. If `no_attractor` old `B->C` drop is less than about 0.10 from its P1 value, call the run
"composition lifecycle, retention stress inconclusive", not a retention win.

Adaptive rule:

- Keep `P2=7000` for the first real run.
- If `no_attractor` old `B->C` remains above 0.90-0.95 with little drop, rerun a stress setting with longer P2
  such as 12000-15000, or a stronger phase-2 write setting, but apply the same horizon to all comparable arms.
- If attractor `A->C` and `gold_minus_wrong` are still rising in the last 2-3 eval windows while deranged and
  no-attractor stay flat, extend the comparable lifecycle arms together, not just the attractor arm.

Do not over-tune the replay ratio yet. `replay_old` and `distill_old` are baselines with old-data access; the
important comparison is whether attractor gets a better no-old-fact-data Pareto point than `no_attractor`, and
how far it is from the old-data baselines.

### 2. Fairness of the retention comparison

Aligning to `h(B)` is not old-data replay in the same sense as `replay_old` or `distill_old`, as long as the
attractor arm never touches old `B->C` prompts or C targets during phase 2. The B identity is already part of the
new `A->B` label space; using it as an identity state is fair.

The honest phrasing is:

> The attractor uses phase-1 model state and current bridge identities, but no old `B->C` examples, no old C
> labels, and no inference-time memory.

That distinction matters. If `h(B)` contains phase-1 successor information, that is not a flaw; it is exactly the
knowledge-into-weights path being tested. The model is using its own weights as the carrier. But to make this
defensible, freeze the phase-1 `h(B)` target bank if possible. A frozen bank created at the phase boundary and
deleted after training is a train-time consolidation target, not an inference memory.

By contrast:

- `replay_old` is old-data replay because it trains on `B->C` prompts and labels in phase 2.
- `distill_old` is old-data access because it revisits `B->C` prompts, even if the target is phase-1 logits.
- `direct_2hop` is an upper bound only, not project-valid, because it trains the target `A->C` behavior.

### 3. The right headline and pass gate

Yes, the main headline should be the 2-axis Pareto cell:

> attractor beats `no_attractor` on both held-out `A->C` composition and old `B->C` retention, while keeping
> `A->B` high, without replaying old `B->C` data.

Score the axes separately first, then make the joint claim only if both pass.

Suggested gates:

- Phase-1 old `B->C`: `bc_after_p1 >= 0.98`.
- Phase-2 new `A->B`: final `AB >= 0.95`; otherwise composition/retention tradeoffs are undertrained.
- Composition: attractor `A->C` EM and `gold_minus_wrong` clearly exceed `no_attractor` and
  `deranged_attractor`; use at least +0.15 to +0.20 EM as the practical bar, or call it weak.
- Retention: attractor old `B->C` final retention exceeds `no_attractor` by at least about +0.10, or recovers at
  least half of the no-attractor drop from P1.
- Mechanism: `raw_bridge` margin is positive and higher than `no_attractor`/`deranged_attractor`; `aux` alone is
  not enough for the bridge-routing wording.

Matching replay/distill is a stronger secondary claim, not the minimum gate. Because replay/distill touch old
data in phase 2, the key project-valid result is not "attractor beats replay"; it is "attractor moves the
composition-retention frontier without old fact replay." If it approaches replay/distill retention while also
adding `A->C`, that is a real result.

### 4. Ways a spurious gain could slip through

Main risks I see in the current structure:

1. Moving-target `h(B)`: if the target is computed from the current model during phase 2, the target can drift
   along with the model. Freeze or log phase-1 target drift.

2. No visible forgetting: if `no_attractor` retains old `B->C` near ceiling, R47 cannot prove retention benefit.
   It can still test lifecycle composition, but not forgetting prevention.

3. Deranged conflict: `deranged_attractor` trains correct `A->B` CE while aligning hidden states to wrong B. If
   this simply harms `A->B`, its failure is less diagnostic. Require final `A->B` high before interpreting the
   deranged control.

4. Exact-surface retention: old `B->C` retention is currently exact-prompt recall. That is acceptable as a first
   synthetic gate, but the claim should remain narrow. If adding a cheap paraphrase of `B->C` is feasible, log it;
   if not, do not overstate semantic retention.

5. EM-only interpretation: keep `gold_minus_wrong`. R46 showed EM can be step-like; the probability margin is
   better for detecting weak but real routing.

6. Seed variability: R46 had 0.62 vs 0.23 for the positive arm. Two seeds are enough for a launch decision; a
   headline result should probably get a third seed if the effect is borderline or asymmetric across axes.

## Launch ruling

Launch R47 after the mechanism re-run if either:

- `raw_bridge` confirms the R46 bridge-routing interpretation; or
- you explicitly downgrade the R47 label to "lifecycle test of the aux-hidden-alignment primitive."

For the definitive run, I prefer:

```bash
BL_P1=3000 BL_P2=7000 BL_EVAL=500 BL_SEEDS=2 \
BL_ARMS=no_attractor,attractor,deranged_attractor,replay_old,distill_old,direct_2hop \
python -m s2.bridge_lifecycle
```

But I would add the frozen phase-1 `h(B)` target or at least target-drift logging before spending the full pod
budget. The frozen-target version is the cleaner project-objective experiment: old knowledge is in the weights,
new knowledge is written into the weights, no old fact examples are replayed, and inference remains one dense
checkpoint.

## Project-objective read

- Knowledge-into-weights: strong alignment if final `A->C` emerges in the checkpoint without A->C labels or
  inference memory.
- Continual retention: R47 directly tests it, but only if `no_attractor` exhibits measurable old `B->C`
  forgetting.
- Growth necessity / compute advantage: still not tested. Growth remains out of scope until fixed-capacity bridge
  unification saturates or becomes less compute-efficient than a justified grown variant.
- No-memory inference: satisfied by the current eval design.
- No full joint retraining: satisfied for the attractor arm; replay/distill/direct are baselines or upper bounds,
  not the proposed solution.

## High-risk / high-reward directions

1. **Frozen successor-state consolidation.** After old learning, store a temporary compressed bank of frozen
   identity/successor hidden states, train new facts to attach to those states, then delete the bank. This is
   not an inference memory; it is a training-time bridge from old weights to new weights.

2. **Attractor saturation as the legal growth trigger.** Scale bridge count and A-per-bridge until `raw_bridge`
   margins collapse or old retention falls. Only then test growth, and require a grown bridge-basin model to
   beat fixed-capacity at matched compute or matched retention.

3. **Unsupervised bridge discovery.** Instead of giving the correct B attractor target, mine current-current
   collision clusters from new A states and old subject identity basins. Pass only if discovered clusters recover
   correct bridge structure above deranged clusters without old fact replay.

4. **Successor-feature target without endpoint labels.** Align A states not just to `h(B)`, but to a small
   endpoint-masked successor feature of B. The model would inherit "how B behaves" without seeing C during phase
   2.

5. **Multi-hop lifecycle ladder.** If R47 passes, extend from old `B->C` plus new `A->B` to old `C->D` plus new
   `A->B`, evaluating held-out `A->D`. This is risky, but it distinguishes shallow two-hop surface transfer from
   a reusable internal graph traversal primitive.
