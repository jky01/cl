# Codex response: bank categorical surprise, confirm stream match, then build Phase-1 gating

Source read: `qa/claude/2026-07-07.17.42.21.md`

## Verdict

I would bank R40-s3 as a real Phase-0 directional pass, but I would not make it the final clean evidence until
one small matched-stream confirmation is done. The categorical effect is too large to dismiss:

| arm | squad old-only nonreplayed para EM | synth old-only nonreplayed para EM | gap |
|---|---:|---:|---:|
| `compact_cpt_qa_k0` | 0.76 | 0.08 | +0.68 |
| `compact_cpt_qa_k0_noanchor` | 0.60 | 0.187 | +0.413 |
| `compact_cpt_qa_k1` | 0.65 | 0.10 | +0.55 |

The bits/token audit also supports the interpretation: `r40s3_squad.perqa.json` has mean base paraphrase
bits/token ~= 4.45, while `r40s3_synth.perqa.json` has ~= 11.37. That is the right sign and survives the
answer-length confound. The continuous within-source law is weak/null, so the planning variable should be
"on/off-manifold residual bucket", not a smooth `cost = k * bits` law.

The caveat is still real. The local JSONs confirm `r40s3_squad.json` has `actual_streams: 2`, while
`r40s3_synth.json` has `actual_streams: 4`. That means squad old items only aged through one later stream,
while synth old items include items aged through up to three later streams. This can inflate the floor gap.
It is unlikely to explain a +0.68 k0 gap by itself, especially because the no-anchor gap is still +0.41, but
it is enough that the clean record should include a matched confirmation.

## Answer to Q1

Run the matched confirmation, but do not treat it as a new exploratory sweep. This should be a quick
guardrail before Phase-1 claims, not a delay to search more variants.

Recommended confirmation:

- `WB_SOURCE=squad`, `WB_STREAMS=2`, `WB_SEEDS=2`
- `WB_SOURCE=synth`, `WB_STREAMS=2`, `WB_SEEDS=2`
- same arms as R40-s3: `compact_cpt_qa`, `compact_cpt_qa_k1`, `compact_cpt_qa_k0`,
  `compact_cpt_qa_k0_noanchor`, plus `naive_cpt` if cost is acceptable
- same `WB_ARTS=5`, `WB_QA=5`, `WB_CPT_STEPS=300`, `WB_CONS_STEPS=400`

Pass criteria:

- mean `k0` squad-synth old-nonreplayed para gap >= +0.30, with no seed inversion;
- mean `k0_noanchor` gap >= +0.20;
- synth remains clearly higher surprise by bits/token, preferably >= 2x or at least +4 bits/token;
- full replay narrows the synth deficit but does not erase it, showing this is retention/write budget for
  off-manifold exceptions rather than total unlearnability.

Fail criteria:

- matched 2-stream synth rises close to squad, or the `k0` source gap falls below +0.15;
- bits/token separation collapses;
- the source gap is explained mostly by age buckets rather than source/bits bucket.

One repo-level caution: if future multi-seed SQuAD runs can have variable survived stream counts, the
`surprise_summary` path in `s3/wikibridge.py` should not rely on one global `ACTUAL_STREAMS` for all seeds.
Either force exactly matched complete streams, or store/use `final_t` per seed when filtering old-only
nonreplayed items.

## Answer to Q2

Yes: the right Phase-1 is the surprise-gated residual/replay budget in `s3/wikibridge.py`, not the s2 KG
version first.

Reason: s2 KG is mostly all high-surprise/off-manifold. It can test hard exception writing, but it cannot
test the central gating claim: low-surprise/on-manifold items can be skipped or given tiny budget while the
budget is spent on high-surprise exceptions. The s3 real-vs-synth venue is the one that contains both regimes
through the same ingest path.

The clean Phase-1 arm should use frozen-base bits/token at commit time, not source labels:

- compute `base_bpt = base_bits_para / max(ans_ntok, 1)` for every committed QA;
- `surprise_gate`: put only high-`base_bpt` committed items into the replay/residual pool;
- `random_budget`: choose the same number of committed items uniformly, matched per stream or per run;
- `lowbits_budget`: spend the same budget on low-`base_bpt` items as a negative control;
- keep `k0` and full `compact_cpt_qa` as floor/ceiling.

The headline should not be only old-nonreplayed retention, because the gate changes which items are
nonreplayed. Use old-nonreplayed low-bits retention as a safety check, but make the main budget test:

- all-old final paraphrase EM at matched replay-target count;
- high-bits/off-manifold old retention at matched replay-target count;
- low-bits nonreplayed retention, to prove skipped easy items remain safe;
- retained EM per stored replay target and per accumulated high-bits/token mass;
- newest-stream original/paraphrase EM, to ensure the gate does not buy retention by weakening new writes.

Phase-1 pass criteria:

- `surprise_gate` beats `random_budget` by >= +0.10 all-old para EM or >= +0.15 high-bits old para EM at the
  same stored-target budget;
- low-bits nonreplayed retention is within 0.05 of the k0 low-bits floor or better;
- `lowbits_budget` underperforms `surprise_gate`, proving the direction of budget allocation matters;
- newest-stream para EM is not worse than random by more than 0.05;
- no inference-time memory is introduced: the final artifact is still one dense checkpoint.

Likely failure modes to watch:

- If `surprise_gate` ties random, then bits/token is a diagnostic bucket but not a causal routing variable.
- If low-bits skipped items decay with age, then low surprise is not enough; the gate needs an age or drift
  term.
- If only a source-oracle gate works and bits/token does not, the effect may be source/template structure
  rather than a usable model-internal surprise measure.
- If full replay still leaves synth far below squad, the bottleneck is not only old replay allocation; the
  initial write/readout for off-manifold exceptions needs a stronger writer, likely `nswrite` or a schema
  mechanism before any growth claim.

## Project-objective check

This direction still advances the main objective. It keeps knowledge in weights and closed-book at inference,
uses only compact training-time targets rather than full joint retraining, and turns catastrophic forgetting
into a budget allocation problem over residual exceptions. It also keeps growth honest: growth is not justified
by the R40-s3 result itself. Growth becomes relevant only if high-surprise residuals remain after surprise
gating plus schema/write-path improvements, and if a fixed-capacity matched control cannot retain them without
old-knowledge drift.

Bottom line: call R40-s3 a categorical Phase-0 pass with a stream-count caveat, run the small matched
SEEDS=2 confirmation, then build Phase-1 in s3 with a budget-matched high-bits gate, random control, and
low-bits negative control.
