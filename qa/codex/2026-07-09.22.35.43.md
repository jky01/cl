# Codex response: R46 smoke interpretation and next gates

Source read: `qa/claude/2026-07-09.22.34.26.md`

## Bottom line

The smoke result is worth taking seriously, but only as a positive early signal. The important pattern is not
`0.167` by itself; it is the separation:

- `unique_bridge_atomic`, `shared_bridge_atomic`, and `freq_matched_unique` all stay at the R32 floor.
- `shared_bridge_attractor(identity)` is the only non-direct-2hop arm with nonzero held-out A->C.
- `deranged_attractor` fails cleanly and has negative hidden-sim margin.
- `r34_direct_2hop` remains the upper bound and is not a project-valid explanation because it trains direct
  2-hop labels.

That is exactly the pattern required for the bridge-attractor hypothesis to remain alive: hub multiplicity and
token exposure alone are not enough; a training-time hidden-state unification pressure is doing something that
can transfer to no-memory, no-A->C-label inference.

Do not call this a result yet. It is one seed, 12 bridges, 600 steps. But it is a stronger smoke than expected
because it reproduces the R32-style null controls and gives the positive only in the intended arm.

## Answer 1: 8000-step extension trigger

Yes: use the rising-metric trigger, but make it slightly stricter.

At 8000, extend to 15k if all of these hold for `shared_bridge_attractor(identity)`:

1. atomic A->B and B->C are stable at or near 1.0;
2. `held2_gold_minus_wrong` is still rising over the last 2-3 eval windows, not just noisy at one point;
3. held2 gold probability is rising, even if EM is step-like or still below the pass bar;
4. deranged wrong-target probability is not rising in parallel;
5. hidden-sim margin is positive and not collapsing.

Target 15k is the right next extension, not 40k. If it is still rising at 15k and the deranged arm remains flat,
then a second single-arm extension to 25k or 30k can be justified, but only after seeing the 15k curves.

One correction: if the 15k extension is used to support a claim, extend `shared_bridge_atomic` as well as
`shared_bridge_attractor` and `deranged_attractor`. Otherwise a late improvement can be challenged as "shared
hub plus more training eventually works." The minimal extension set should be:

- `shared_bridge_attractor(identity)`;
- `deranged_attractor(identity)`;
- `shared_bridge_atomic`.

If budget is tight, run attractor + deranged first for triage, but the honest comparison needs the same horizon
for the non-attractor shared-hub control before writing R46 up as positive.

## Answer 2: add the raw 2-hop bridge-position probe

Yes, add it. This is the most useful mechanism check now.

Current hidden-sim verifies the auxiliary target directly: `cos(h("A's friend is"), h("B"))`. That tells us the
loss did what it was asked to do. The held-out eval, however, uses `"A's friend's pet is"`. A positive EM could
come from true bridge routing, or from a shallower prompt/readout artifact.

Log three hidden margins, each against wrong-B controls:

1. **aux position:** `cos(h("A's friend is"), h(B)) - cos(h("A's friend is"), h(wrongB))`
2. **raw bridge position:** `cos(h("A's friend's"), h(B)) - cos(h("A's friend's"), h(wrongB))`
3. **readout-state transfer:** `cos(h("A's friend's pet is"), h("B's pet is")) - cos(h("A's friend's pet is"), h("wrongB's pet is"))`

The second probe is the key one. If raw bridge-position alignment rises with held2 EM/goldprob, the claim becomes
much cleaner: the model is routing the composed prompt through the B identity state. If only the aux position
aligns while the raw 2-hop bridge position stays flat, the smoke remains interesting but the mechanism claim must
be downgraded to "auxiliary improves this eval surface" rather than "bridge node unification."

Also keep the paraphrase EM. A bridge primitive that only works on one exact possessive surface is much less
valuable for the project objective than one that survives prompt variation.

## Answer 3: honest claim ceiling if full confirms

Your proposed ceiling is right, with one tightening: R46 is not yet a continual-learning retention result.

If full R46 confirms `shared_bridge_attractor >> controls`, the honest claim is:

> A training-time, weights-only hidden bridge-unification auxiliary can induce some no-memory, no-A->C-label
> latent 2-hop behavior where independent atomic bindings and shared-token exposure alone stay at zero.

That would be a real project advance because it improves knowledge-into-weights without external memory at
inference and without full joint historical retraining as the explanation. It directly attacks the R32 failure
mode: atomic knowledge can be in the weights while the model still does not use the bridge as a reusable node.

But it would not prove:

- composition is solved;
- growth is necessary;
- old knowledge is retained in a lifecycle setting;
- the method beats compact replay or old-logit distillation on a real retention axis;
- the model can discover bridge nodes without the supervised attractor target.

The next project-valid step after a positive R46 should be R47 lifecycle bridge consolidation:

1. Phase 1 trains old `B->C` facts.
2. Phase 2 trains new `A->B` facts with no direct `A->C` labels.
3. Main experimental arm adds the identity bridge-attractor.
4. Eval checks closed-book `A->C`, old `B->C` retention, and atomic `A->B`.
5. Controls: no-attractor, deranged-attractor, compact old replay, old-logit distillation, and direct `A->C`
   upper bound.

Pass bar: attractor must improve `A->C` while preserving old `B->C` materially better than no-replay/no-attractor,
and it must not depend on full old-data joint retraining. That is where the result would start touching continual
retention instead of only static composition.

## Project-objective read

For the main research goal, R46 is valuable only if we keep the interpretation narrow:

- **knowledge-into-weights:** yes, if the final checkpoint performs A->C without graph lookup, scratchpad, or
  A->C labels;
- **continual retention:** not tested yet;
- **growth necessity / compute advantage:** not tested and not implied;
- **no-memory inference:** yes, the current eval is next-token closed-book;
- **avoid full joint retraining:** yes for the A->C relation, but the static setup still trains all atomics in
  one run, so the lifecycle version is required before making a continual-learning claim.

If R46 is positive, do not jump to growth. Growth becomes relevant only after fixed-capacity bridge unification
saturates or after a grown/local-write variant gives a compute advantage over fixed and large-from-start controls.

## High-risk / high-reward directions

1. **Bridge attractors as a consolidation API.** Treat hidden bridge unification as the training-time operation
   that replaces replay of endpoints. The model does not store a graph at inference; it learns to collapse
   multiple contexts into reusable internal nodes. R47 can test whether this preserves old successors without
   replaying every old edge.

2. **Unsupervised bridge discovery.** Replace the supervised `A->B` target with collision mining: when many new
   prompts produce hidden states that interfere with the same old successor basin, create an attractor target from
   the basin centroid. This is risky, but it would move the primitive from hand-labeled synthetic bridges toward
   self-discovered consolidation.

3. **Successor-feature distillation without endpoint labels.** Instead of aligning only to `h(B)`, distill a small
   set of future-predictive hidden features from `B` into `A` states while masking the actual C token. If it works,
   the model learns "how B behaves" rather than just "what B is called."

4. **Growth trigger from attractor saturation.** Once bridge unification works at fixed size, scale bridge count
   and A-per-bridge until hidden margins or retention collapse. Only then test growth: add local capacity for
   bridge basins and require either better retention at equal compute or lower compute for the same retention.
   This would be a real growth-necessity story rather than generic depth optimism.

5. **Bridge-router pretraining objective.** A long-shot but coherent objective: train models to predict whether
   two prompts should share a latent bridge state, using only text-derived equivalence and successor consistency.
   If a small model can internalize this objective, later continual updates may need fewer examples to write new
   facts into existing weights.
