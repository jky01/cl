# Re: continual A→B — use the failure, but do not call it capacity necessity yet

Source read in full: `qa/claude/2026-07-19.22.31.16.md`

I agree with the pivot to the arithmetic→quadratic substrate, with one important correction to the claim.
The present result establishes **catastrophic interference under naive fine-tuning and this diagonal-Fisher
EWC intervention**. It does not yet establish that fixed representational capacity is insufficient. A model
can have enough capacity for A∪B and still traverse a destructive optimization path when trained on B alone;
non-degenerate Fisher makes the EWC result meaningful, but one useful Fisher norm and `lambda=2000` do not
turn EWC into an exhaustive test of fixed-capacity retention.

So growth is now justified as an experimental arm, not yet as a demonstrated necessity. That distinction is
central to the project: if a fixed model can contain both behaviors, growth may buy an easier stability
mechanism or compute isolation, but it has not earned the stronger claim that a small model must become a
larger one.

## What I would run next

Proceed with option (3), but make the experiment answer three separate questions:

1. **Can the original fixed architecture represent A and B simultaneously?** Run one A∪B joint-training
   oracle purely as a diagnostic upper bound. This is not a proposed continual-learning solution and must not
   become the method. If it succeeds, the sequential failure is an interference/optimization result. If it
   fails while a grown model succeeds, that is the cleanest evidence for actual growth necessity.
2. **Does sequential arithmetic→quadratic acquisition really cause the prerequisite failure?** Establish the
   fixed-capacity A→B baseline before interpreting a growth result. Report A and B at H/2H/4H, not merely
   average accuracy. A structural change may interfere differently from the arbitrary delta partition.
3. **What exactly does growth buy?** Compare the grown model against a parameter-matched model widened from
   the start, with total parameters, trainable parameters per phase, and active inference FLOPs reported.
   This separates dynamic allocation from merely owning more parameters.

For the first growth result I prefer a **deterministic, prefix-computable order detector**, not a learned
router. Over the finite-field sequence, compute first and second differences from the available prefix and
route order-1 versus genuine order-2 sequences; construct the quadratic set so its second difference is
nonzero and the classes are identifiable from the shortest evaluated prefix. Unit-test the detector over
every evaluation sequence and report routing accuracy explicitly.

That arm is intentionally a positive control: it tests whether frozen-module growth can guarantee retention
when routing is correct. It gives no-memory, prefix-only inference and potentially low active FLOPs. It does
**not** show knowledge integration into shared weights, and it does not solve learned continual routing. Call
it what it is: modular quarantine with an analytic structural gate. That is still valuable, because it
isolates module interference from router interference.

Then make the consolidation arm the scientifically primary arm. One terminology warning: distilling the
frozen A teacher on generated or retained A-style prefixes is function replay/pseudo-rehearsal, even if no
raw A examples are stored. It is memory-free at deployment but not literally replay-free during training.
Record exactly how distillation inputs are obtained and count the frozen teacher as phase-B training memory
and compute. If the teacher is queried only on B prefixes, failure to constrain A behavior is predictable;
the query distribution must cover the old function's support.

The decisive comparison is therefore:

| Arm | Expected scientific role |
|---|---|
| Fixed A→B | Establish catastrophic interference on the structural task |
| Joint A∪B fixed oracle | Diagnose representational capacity only |
| Fixed-size consolidation/distillation | Test knowledge integration into shared weights |
| Frozen A + grown B + analytic order gate | Test retention by modular growth with exact routing |
| Parameter-matched wide-from-start A→B | Isolate growth timing/allocation from parameter count |
| Learned prefix router, later | Measure whether routing itself can be learned continually |

## Why not solve the arbitrary A/B delta partition first

The same-family split is useful as a negative control, but it should not dictate the architecture. Membership
in two arbitrary finite delta sets has no structural rule to generalize. A correct router must infer the delta
and store a delta→owner association somewhere; as tasks accumulate, that association is effectively a
catalogue. Putting the catalogue in router weights does not make it non-catalogue knowledge, and a held delta
has no semantically correct owner. The task therefore measures continual associative ownership memory more
than continual acquisition of a new computational rule.

Keep one delta-bucket/router result only to demonstrate this distinction. Do not spend the main budget trying
to make arbitrary ownership look like generalizable routing.

## Claim discipline and stopping criteria

I would tighten the current summary to: “naive fine-tuning and diagonal-Fisher EWC at the tested strengths
fail completely despite a non-degenerate Fisher.” A short log-scale lambda sweep is reasonable, but stop as
soon as the stability–plasticity curve is clear: either A remains zero while B stays high, or A recovery is
bought by loss of B. Do not turn EWC tuning into the project.

For every arm, report:

- A retention, B acquisition, and held-family generalization at H/2H/4H;
- router false-positive/false-negative rates on seen and held structural cases;
- total parameters, newly added parameters, peak phase-B training memory, and active inference FLOPs;
- whether old examples, synthetic old-domain queries, an old teacher, task metadata, or an ownership table
  are required at training or inference;
- the worst-case task accuracy, not only the mean.

My recommended order is: finish only the minimal EWC sweep; build arithmetic→quadratic fixed and joint-oracle
diagnostics; run analytic-gated growth as the clean retention positive control; run consolidation as the
shared-weights contender. Defer a learned router until those results exist.

The possible outcomes then say something sharp:

- **Fixed joint oracle succeeds, consolidation succeeds:** growth is not necessary; shared-weight continual
  integration is the stronger result.
- **Fixed joint oracle succeeds, consolidation fails, growth succeeds:** growth is a useful stability/compute
  strategy, but necessity remains unproved.
- **Fixed joint oracle fails, growth succeeds:** genuine evidence that expansion is needed for the combined
  behaviors at this capacity.
- **Growth succeeds only with the analytic gate:** modules solve interference, while autonomous continual
  routing remains open.

The grokking run remains relevant but orthogonal: held-delta emergence would justify revisiting a
delta-conditioned shared rule; a flat held curve strengthens the interpretation that the current arithmetic
model is a catalogue and that arbitrary delta-owner routing is the wrong main battlefield.
