# Codex response: ontology reframe after R44

Source read: `qa/claude/2026-07-09.21.49.28.md`

## Verdict

I buy the synthesis as a productive reframe, but not as a full explanation yet. The strongest part is not
"R44 used atemporal triples, therefore no schema could exist." That is too forgiving to the failed hypothesis.
The stronger claim is:

> R44 did contain invariants, but the only invariant that matched Qwen2.5-0.5B's actual write/read geometry was
> coarse answer-kind. Relation ID was a human database coordinate, not a usable write coordinate for this model
> under this training protocol.

That distinction matters. If we say "triples had no invariant," then every schema failure can be dismissed as
the wrong dataset. If we say "the invariant existed but was not aligned with the model's write topology," then
we get a concrete next target: discover the model's write topology and consolidate in those coordinates.

R44's evidence supports that narrower target. In `docs/cloud_results/r44_ladder.json` and `FINDINGS.md`, at
B=6, person relations show `schema_commit` 0.891, `item_k_matched` 0.828, and same-kind shuffle 0.906. Org
shows `schema_commit` 0.969, `item_k_matched` 0.562, and same-kind shuffle 0.875. PRIME commitment was real,
and prime retention after BIND was mostly high, so the null is not "the primes never entered weights." The
write happened; transfer occurred at answer-kind/output-path level, not relation level.

## Where the synthesis overreaches

### 1. "Atemporal triples had no invariant" is too strong

A triple family has several invariants:

- relation text or predicate identity;
- subject/object role structure;
- answer type;
- prompt form;
- entity familiarity and lexical distribution;
- output-token pathway.

R44 tested whether the relation-specific invariant had marginal binding value beyond matched item replay and
same-kind derangement. It failed. That does not mean the dataset had no invariant. It means relation identity
was not the invariant the model could exploit.

The answer-kind result is not a trivial nuisance. It is a direct measurement of a real macrostate: "this update
prepares the model to answer with a person/org-like name." That is coarse, but it is exactly the kind of
coarse-grained variable your entropy/RG framing would predict to survive first.

### 2. Structured temporal data may help, but only for a narrower reason

I agree that temporally/causally structured data could behave differently from isolated triples. But the reason
is not "time" by itself. It helps only when the past contains a latent state that reduces future prediction
loss. A revolution narrative, a chemical reaction, or a character arc gives repeated evidence for a hidden
process; a bag of unrelated facts does not.

So the falsifiable version is:

> If episodes share a latent process, then consolidating the predictive state of that process should improve
> held-out future queries at lower marginal update budget than compact item replay.

The controls must be brutal:

- same facts, shuffled temporal order;
- same answer-kind distribution without causal order;
- same number of item targets;
- future queries whose answers are not present in the supports;
- one final dense checkpoint, no retained episode memory at inference.

If the structured arm wins only because it has more coherent prose, more repeated labels, or easier answer
kinds, then this is just compact replay on a nicer corpus.

### 3. Predictive information is operationalizable, but not as literal MI

I would not try to estimate `I(past; future)` directly at this scale. It will become a slogan or a noisy
estimator. The cheap operational proxy is future loss reduction:

`score(unit) = Delta future_probe_loss - lambda * write_cost - mu * old_drift`

Where `unit` can be a fact, cluster, summary, latent code, or generated training target. This converts the
retention objective into a measurable selection rule:

- train or simulate a small candidate consolidation from prefix information;
- measure reduction in held-out suffix QA/logloss;
- penalize target-token/update budget;
- penalize forgetting on old probes;
- keep only units with positive net predictive value.

This fixes R43's failure mode. R43 used static write-time surprise; it knew what was hard now, not what would
matter later. The future-loss objective asks whether a candidate update earns its maintenance cost.

The danger is benchmark leakage: "future" must be registered before selection. Otherwise the system just
learns the evaluation distribution.

### 4. SAE/concept-code is plausible but too heavy as the next decisive tool

The discovered-code idea is directionally right, especially because R44 showed relation labels are not enough.
But a full SAE/dictionary-learning codebook can easily become a second research program before it answers this
one.

The cheaper version is to discover concepts from write interference:

- collect per-item gradient or logit-Jacobian signatures during current-stream training;
- build an interference matrix: which writes help, tie, or damage other writes;
- cluster the matrix;
- use clusters only during training for batching, shared targets, or low-rank consolidation;
- delete cluster metadata and evaluate one dense checkpoint.

If those clusters rediscover answer-kind, that validates R44 mechanistically. If they find finer units than
answer-kind and those units compress, that is a real step toward autonomous concept discovery.

## My wall-mover

The real wall-mover is not "temporal data" alone and not "SAE concepts" alone. It is:

> predictive-sufficient consolidation in model-discovered write coordinates.

This combines the two provocations without romanticizing either:

- the unit is discovered from the model's own update/interference geometry, not imposed relation IDs;
- the retention objective is future predictive value, not static surprise;
- all scaffolding is training-time only;
- the final state is one dense checkpoint;
- growth is disallowed unless fixed-capacity predictive consolidation saturates.

A compact decision probe could look like this:

1. Build small temporally structured episode families with a latent process and held-out future queries.
2. Build matched bag-of-facts and answer-kind controls.
3. Derive candidate consolidation units from current-stream interference clusters or prefix-to-future loss
   reduction, not human relation labels.
4. Train equal-budget arms: compact item replay, answer-kind batching, predictive-unit consolidation, and
   deranged predictive-unit consolidation.
5. Pass only if predictive-unit consolidation beats item replay and answer-kind batching on held-out future
   queries, while old retention stays within a small delta and inference uses one dense checkpoint.

This would genuinely move the project objective. It tests knowledge-into-weights, retention, compute advantage,
and no-memory inference in one frame. It still does not justify growth unless the fixed model's predictive-unit
curve saturates.

## Steelman against all of this

The opposing case is strong:

- R44 may already have found the actual usable unit at 0.5B: output type. Finer "concepts" may be real in
  larger models but not reachable here with tiny QA fine-tunes.
- Temporal structure may just make data more redundant, not reveal a new consolidation mechanism. Compact replay
  on structured data may match every fancy predictive unit.
- Predictive-information scoring needs a future distribution. In real lifelong learning, that distribution is
  unknown, drifting, and easy to overfit in experiments.
- Discovered-code methods add machinery and compute before proving they reduce lifetime target count.
- R43 already showed a sobering baseline: random@0.5 matched full replay on old paraphrase EM. Any proposed
  mechanism must beat that boring constant-factor result, not just beat k0.

If that steelman wins, the honest next move is the capstone negative map: weights-only consolidation works
impressively in R33/R38-style engineering regimes, but sublinear lifelong learning did not emerge from surprise
routing, generic growth, relation schema compression, or current composition probes.

## Project-objective check

- **Knowledge into weights:** any next probe must end with a single closed-book checkpoint. Temporary concept
  codes, clusters, summaries, or future probes are legal only as training-time scaffolding.
- **Continual retention:** old-only paraphrase EM and base capability controls remain headline metrics, not
  secondary diagnostics.
- **Compute advantage:** the target is lower marginal write/maintenance budget than compact item replay and
  random subsampling, not just higher EM than k0.
- **Growth necessity:** growth remains illegal as a claim until fixed-capacity predictive consolidation shows
  measured saturation or persistent collision that a grown arm resolves at matched compute.
- **No full joint retraining:** the system can use sequential consolidation and registered future probes, but
  cannot solve the problem by replaying all historical data as the main method.

## Boundary-pushing brainstorm

1. **Write-topology atlas.** Before inventing new schemas, map the model's interference graph: every current
   fact gets a vector of help/hurt effects on every other fact. Treat clusters in that graph as the discovered
   concept space. This is more directly relevant than semantic labels because it measures the geometry that
   actually governs forgetting.

2. **Predictive half-life tiers.** Give every learned unit a measured half-life: how fast it decays under later
   unrelated streams, and how much future loss it prevents. Consolidate high-value short-half-life units first;
   let low-value units decay. This is the non-mystical version of memory as active maintenance.

3. **Split/merge concept codebook.** Start with coarse answer-kind clusters. Split a cluster only when internal
   writes destructively interfere; merge clusters only when cross-cluster writes help each other. This makes the
   codebook plastic without needing a full SAE upfront.

4. **Anti-causal control as the decisive temporal test.** If a temporal consolidation method works, reverse or
   shuffle episode order while preserving facts and answer kinds. A true predictive-state method should lose
   its advantage; compact replay should not care much.

5. **Successor-feature memory for text.** Instead of storing facts, learn features that predict what questions
   the current passage will make answerable later. Consolidate those successor features into weights, then test
   closed-book future probes. This is a clean bridge from predictive information to an implementable target.

6. **Growth as adding a timescale, not width.** If fixed consolidation saturates, add a new training-time tier
   with a different retention half-life, then distill or merge it into one checkpoint. Growth is justified only
   if a new timescale lowers total maintenance cost while preserving old knowledge.

7. **Schema hallucination audit.** For every generated/predictive schema target, create adversarial exceptions
   where the schema is almost true but wrong. If consolidation overwrites exceptions, it is not learning a
   useful invariant; it is averaging facts into a false rule.

8. **Negative-transfer curriculum.** Intentionally present fact pairs that damage each other, then train the
   system to propose a shared abstraction, a separation, or a growth request. The goal is not to avoid
   interference but to use interference as the self-supervised signal for representation reorganization.
