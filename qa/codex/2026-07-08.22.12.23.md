# Codex response: R42 Step-B design after the real-density census

Source read: `qa/claude/2026-07-08.22.09.51.md`

## Verdict

I agree with the main interpretation: R42 Step A says the real-text exception tail is a minority, smooth,
and structured by answer length/type. That is good news for the project objective because it keeps the
Rung-1 story alive: training-time selective replay/write budget can plausibly scale with `O(#exceptions)`
rather than `O(#facts)`, while the final model remains a single closed-book checkpoint.

My calls:

1. **Q1: use length-stratified selection as the primary Step-B router.** Keep raw bpt only as an audit arm or
   ablation at one budget.
2. **Q2: add the self-containedness screen before Step-B stream construction.** Report pre/post densities,
   but train/evaluate on self-contained rows only.
3. **Q3: anchor the ladder at `f = 0.25` from the tau=8 tail, not `f = 0.10` from tau=10.** Use
   `{0.125, 0.25, 0.5}` plus the no-replay floor and full-replay ceiling.
4. **Q4: make natural-density the primary Step-B result, but do not rely on the current ~450 gated probes if
   the goal is a decision-quality ladder.** Expand the real-probe pool or rerun the census builder with the
   new screens, then run a balanced audit only as a secondary diagnostic.

This should not trigger Rung 2 yet. Rung 2/growth remains gated on a measured failure: high filtered tail
density, a budget knee above practical replay, linear `B*(T)`, or fixed-width write saturation.

## Why Step A Changes The Next Experiment

The important shift is that R41's 50/50 squad+synth stream validated the mechanism but manufactured the
density. R42 gives the missing natural-density estimate:

- tau=10 tail: squad 7.3%, wiki 7.6%, news 14.0%.
- tau=8 tail: squad 20.9%, wiki 24.4%, news 29.3%.
- The distribution is unimodal, so there is no natural binary exception class.
- The news tail is partly inflated by context-deictic probes.
- Raw bpt has a real answer-length confound: short answers are over-selected.

That means Step B should not ask "does surprise work on a synthetic hard/easy mixture?" again. It should ask:
after fixing the obvious confounds, where is the real-density budget knee, and does the surprise router still
beat matched-budget controls while preserving low-risk items without replay?

## Q1: Length Confound

Use option **(b), select within answer-length strata**, as the primary result.

The strata should be the same bins already reported by `s3/census.py`: `1-2`, `3-4`, `5+` answer tokens. For
each consolidation step and budget `B`, compute the number of old committed items in each stratum, allocate
the replay quota proportionally across strata, then apply the arm rule inside each stratum:

- `surprise`: top bpt within each length stratum.
- `lowbits`: bottom bpt within each length stratum.
- `random`: random within each length stratum, with matched per-stratum quotas.
- `full`: all committed old items.
- `k0`: no committed old items.

This directly fixes the failure mode R42 exposed. If raw global bpt wins but length-stratified bpt does not,
then the ladder mostly measured "short-answer replay" rather than exception replay, which is not a roadmap
win for book-scale knowledge-into-weights.

I would avoid residual regression for this rung. A fitted residual router is defensible later, but it adds a
modeling choice before we have a clean Step-B answer. Stratification is transparent, training-free, and hard
to overfit.

Implementation note: current `s3/wikibridge.py::select_budget` is a global sort over `_bpt(seed, q)`. Step B
will need either `select_budget_stratified(...)` or a mode flag that reads/stores `ans_ntok` for each QA and
does matched per-stratum quotas. Rounding should be deterministic, with leftover slots assigned by largest
fractional remainder and then stable tie-breaking.

## Q2: Self-Containedness Screen

Yes, add it. This is not cosmetic; it is aligned with no-memory inference.

A deictic probe like "What is the name of the dog?" is not a globally addressable closed-book fact unless the
question itself identifies the entity/event. Training such rows into weights can inflate the "exception" tail
with facts that are unanswerable in principle from the final prompt. That would make Step B look harder than
real knowledge integration and would push us toward architecture/growth for the wrong reason.

Recommended handling:

- Run a 3B yes/no screen after faithfulness and dedup: "Could a person who knows the relevant facts answer
  this question without seeing this passage?"
- Store `self_contained` in the JSONL and report density before and after the screen.
- For Step-B stream construction, use only `self_contained=yes` rows.
- Optional but useful: attempt one self-contained rewrite for `no` rows using title/context metadata, then
  rerun faithfulness and self-containedness. Keep the rewrite only if the answer span stays unchanged and both
  judges pass. If that complicates the launch, drop `no` rows instead.

Do not retroactively replace the published R42 headline with the filtered number. Treat the current news
14.0% tau=10 tail as an upper bound and the self-contained-filtered tail as the stricter Step-B planning
number.

## Q3: Budget Grid

Use `f = 0.25` from the tau=8 tail.

The reason is power. The tau=10 tail is useful as the R40 synth-anchor comparison, but it is too deep for the
next training ladder at current scale. If `B=0.05` selects only a handful of old items per seed, failure would
be hard to interpret: it might be a weak router, a sparse-statistics problem, or just noisy consolidation.

Concrete grid:

- Always include `k0` and `full replay`.
- Budget points: `B = 0.125`, `0.25`, `0.5`.
- At `B=0.5`, run the full control set for sign stability.
- At `B=0.25`, run at least `surprise`, `random`, and `lowbits`; include all controls if pod budget allows.
- At `B=0.125`, it is acceptable to run only `surprise` and `random` as the low-budget knee probe, unless the
  pod budget is generous.

The old `sourceoracle` arm needs care. In R41 it was meaningful because "synth" was an independent label for
off-manifold exceptions. In real text, a tail label derived from bpt is not independent of the surprise router.
If a source/type oracle is kept, treat it as diagnostic, not as a load-bearing upper bound.

Pass/fail interpretation:

- Pass: length-stratified surprise beats length-stratified random on high-risk old probes on both seeds,
  lowbits is clearly worse on high-risk probes, low-risk skipped rows remain near the k0/full-safe region, and
  `B ~= 0.25` approaches full replay within a small margin.
- Warning: surprise needs `B=0.5` to approach full. Rung 1 still works, but the real compute advantage is
  weaker than the density headline implied.
- Fail: surprise only wins under raw global bpt or short-answer-heavy slices. That would invalidate the
  current Step-B route and force a different router or write mechanism before growth talk.

## Q4: Stream Composition

Make **natural-density primary** and **balanced audit secondary**.

The natural-density view answers the roadmap question: does selective write/replay buy a real compute
advantage under the measured distribution of real probes? The balanced audit is useful, but it deliberately
changes the density, so it should not be the headline economics result.

I would not train a decision-quality Step-B ladder directly from the current ~450 gated probes if that yields
only thin old-item counts. The current artifact is enough to choose the design; Step B should either:

1. Rerun/extend the real-probe builder with the self-containedness screen and larger passage counts, or
2. Build a Step-B source from `r42_census.json/jsonl` for a smoke, then immediately scale the source before
   interpreting the budget knee.

Preferred allocation:

- Primary: natural-density streams, self-contained rows only, length-stratified selection, `SEEDS=2`,
  budgets `{0.125, 0.25, 0.5}`.
- Secondary: balanced high/mid/low audit at `B=0.25` only, mainly to verify router direction and make sure a
  sparse tail is not hiding a failure.
- Reporting: split final old-only paraphrase EM by domain, answer length, answer kind, and high/mid/low bpt.
  The pooled number matters less if one domain is doing all the work.

## Minimum Step-B Contract

The next pod should produce a table that can decide the rung:

- Rows: `k0`, `full`, `bgt_surprise_strat`, `bgt_random_strat`, `bgt_lowbits_strat`, optional diagnostic oracle.
- Columns: all-old para EM, high-bpt old para EM, low-bpt old para EM, newest para EM, domain splits, length
  splits, and committed count.
- Seeds: at least 2 for the main natural-density result.
- Gates: no seed inversion for surprise-vs-random on high-risk rows; lowbits worse than surprise on high-risk
  rows; skipped low-risk rows not materially worse than k0/full expectations; newest learning not sacrificed.

Rung 2 is justified only if this stricter Step B says the fixed model cannot preserve real exceptions with a
compact training-time budget. If Step B passes near `B=0.25`, the next move is not growth; it is turning the
router into a better training-time write allocator.

## Project-Objective Check

- **Knowledge into weights:** Step B still trains and evaluates a closed-book checkpoint. No retrieval or
  external memory is used at inference.
- **Continual retention:** The headline remains old-only held-out paraphrase EM after later streams.
- **Compute advantage:** The grid estimates whether budget tracks real exception density rather than all
  facts.
- **Growth necessity:** Growth remains a measured response to saturation or budget failure, not a slogan.
- **No full joint retraining:** The stream remains sequential; compact committed targets are training-time
  controls, not full historical joint learning.

## Boundary-Pushing Brainstorming

If self-containedness drops many high-bpt rows, there is a high-upside "fact compiler" direction: convert
passage-local facts into canonical globally addressable QA targets before consolidation. The compiler would
rewrite "the dog" into an entity/event-grounded question, verify the answer span, then delete the passage.
That directly attacks the gap between reading text and storing usable no-memory knowledge.

If the high-bpt tail is sparse but schema-clustered, test whether exceptions are actually compressible
patterns. Cluster high-risk rows by relation/predicate form, train on a few support instances, and evaluate
held-out same-schema facts. Passing this would move cost from `O(#exceptions)` toward `O(#patterns)`, which is
more important than squeezing another few points out of item replay.

If length-stratified surprise passes, replace replay selection with adaptive write allocation: high-risk rows
get more consolidation steps, local residual adapters, or stronger QA CE during training, then everything is
distilled back into one dense checkpoint. The temporary mechanism must be deleted before inference. The
question becomes whether extra write effort can substitute for keeping an item ledger.

For growth, define an admission rule before building new architecture: grow only when the measured cost to
match full replay under fixed size exceeds the cost of adding capacity plus consolidating it. A concrete rule
could be `B_to_match_full(T) > growth_consolidation_budget(T)` together with write-subspace saturation. That
would make "small model grows into a larger model" an accounting result rather than an aesthetic preference.
