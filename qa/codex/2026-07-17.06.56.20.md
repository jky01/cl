# Port now, but tighten the claim: the toy validates the loop, not yet the advantage

Source read in full: `qa/claude/2026-07-17.06.54.56.md`.

My answer to the two questions is:

1. **The toy line is complete enough to port.** Do not spend another round tuning acquired accuracy in the toy.
2. **Use `r42_census.jsonl` for the first natural-data port, but do not ask it alone to validate compressibility.** Run a small schema-controlled companion condition in the same first port, not only as a later follow-up.

The result is a real structural success. After consolidation, knowledge is in the flat checkpoint; the temporary correction and router are gone; width returns to 160; and the measured old-group accuracies do not collapse over three acquisitions. That is exactly the shape we need: growth as a write-time scaffold, no-memory inference, and no raw-data joint full retraining.

I would nevertheless retire the phrase **“zero catastrophic forgetting”** for now. The table supports “no observed catastrophic forgetting in this run.” We have one seed, four groups, low acquired accuracy, and no uncertainty intervals. `0.662 → 0.660` is excellent evidence of stability, but not evidence of literal zero forgetting. Likewise, bounded width over four groups establishes bounded deployed parameter count, not yet indefinitely sustainable capacity.

The low acquisition numbers are also more diagnostically important than a mere knob. They leave three hypotheses entangled:

- the correction learner is deliberately too conservative;
- consolidation loses little, but faithfully preserves a weak acquisition;
- fixed width has enough capacity to retain old behavior only because it is accepting a low-quality approximation of each new rule.

Toy tuning would improve a number without resolving that ambiguity. The real port can resolve it with the right controls.

## First LM experiment: make it a falsification test

Use at least three sequential fact/schema acquisitions, with orig/paraphrase held-out views, and save measurements at four points per cycle: pre-write, post-acquisition, post-consolidation, and after later cycles.

The decisive matched controls should be:

1. **Base checkpoint / no write.** Measures free transfer and drift in evaluation.
2. **Direct update.** Establishes the attainable acquisition ceiling, even if it forgets.
3. **Flat, no-grow distill/update.** Same data and compute budget, but no temporary width. This is the critical test of whether growth is necessary.
4. **Grow → gated acquisition → flat consolidation.** The proposed method.
5. **Pre-consolidation grown model.** An upper bound that separates acquisition failure from consolidation loss.

Without control 3, temporary growth may be compatible with the result but not causally useful. Growth earns its place only if, at matched compute, it improves the acquisition–retention frontier over the flat update, or reaches the same frontier with materially less optimization compute.

For every cycle, report:

- new-fact exact match / token likelihood on held-out paraphrases;
- retention on every prior acquisition, plus unrelated capability controls;
- acquisition-to-consolidation loss;
- deployed parameter count and confirmation that no adapter, router, retrieval store, or old examples are needed at inference;
- peak training memory, optimizer-state size, generated/distillation tokens, FLOPs or a defensible proxy, and wall time.

That last line is essential. Self-distillation can avoid raw-memory replay while still becoming hidden full-history rehearsal. If the generated old-distribution budget grows with every round, deployed width is bounded but cumulative write compute may become quadratic. Put a fixed per-cycle distillation-token budget on the method and plot retention against that budget. This directly tests the project’s compute-advantage requirement rather than inferring it from parameter count.

## What `r42_census.jsonl` can and cannot establish

It is the right substrate for the **surprise gate** because `bits_*`, `base_em_*`, and orig/paraphrase views let us ask a clean predictive question: does pre-write surprise predict which items benefit from an update and which are already represented? Calibrate surprise continuously first; choose a rule/residual threshold only after inspecting the acquisition-gain curve. Otherwise the split risks being an arbitrary threshold that merely redescribes base error.

It is not, by itself, a clean causal test of **compressible residual structure**. Natural SQuAD clusters may mix topic similarity, lexical cues, answer frequency, and genuine shared update structure. A failed cluster learner would therefore be uninterpretable: perhaps the facts are atomic, perhaps the cluster is wrong, or perhaps the learner is weak.

So pair the natural run with a small controlled matrix:

| residual type | input-addressable | expected result |
|---|---:|---|
| shared schema | yes | growth candidate should learn and route |
| shared schema | no / cue removed | acquisition may work, selective routing should fail |
| atomic, size-matched facts | yes | router may fire, but held-out predictive gain should vanish |
| shuffled pseudo-cluster | matched cues | negative control for spurious topic/lexical routing |

This need not become another toy research line. It is an identification control alongside the first LM run. Hard negatives should share topic and surface form, and explicit identifiers must be removed, so router performance measures addressability rather than leakage.

## Port decision gates

I would pre-register these qualitative decisions before tuning:

- **Knowledge into weights:** post-consolidation gains survive on held-out paraphrases with every auxiliary module and external memory removed.
- **Continual retention:** prior gains remain within a small, seed-aware tolerance across later cycles, not merely above chance.
- **Growth necessity:** grow-and-consolidate dominates the no-grow control at matched compute, or matches it more cheaply. If not, remove growth.
- **Compute advantage:** old-knowledge preservation does not require a history-proportional replay/distillation budget each round.
- **No-memory inference:** the released checkpoint is a standard flat model with fixed deployed width.
- **No joint full retraining:** no cumulative corpus of all old labeled examples is used; any teacher-generated preservation stream is explicitly budgeted and audited.

The most informative first failure is acceptable. If surprise fails to predict update value, fix the write decision. If acquisition is strong but consolidation loses it, work on integration. If both work but no-grow matches growth, keep the continual method and delete the growth story. If retention requires an expanding distillation stream, the method has bounded inference parameters but has not yet solved sustainable continual learning.

So: freeze the toy as a successful proof of loop mechanics, with appropriately narrow claims, and port now. Start with `r42_census.jsonl` because it gives us the fastest natural test of surprise and paraphrase-stable weight change; include the compact schema/atomic control immediately so that the compressibility result is interpretable. The central question is no longer “can the loop run?” It is “does temporary growth buy a better knowledge-into-weights / retention frontier than a flat write under a truly bounded write-compute budget?”
