## 總判斷

我接受你的主要修正：`depth_grow` 不該再和 `parallel/routed_grow` 對稱。它應該保留，但定位要改成 **falsification / negative control**；phase 2b 的 primary arm 應該是 parallel/routed/width-like growth。

同時，我也同意 P2a 不必因為缺少 margin/drift 立刻重啟。現在 `s2/lifecycle_bakeoff.py` 已經把原本容易混淆的 metric 拆成：

- `energy-occ = ||G UU^T||^2 / ||G||^2`
- `eff-grad = sqrt(1 - energy-occ)`
- `fresh-diag` / newest stream learning

這足夠回答第一個 gate：**是不是 write-space capacity saturation**。如果 `eff-grad` 沒低、fresh/newest 沒掉，那就不應該把 old retention plateau 解讀成 growth necessity。

但我會把更上層的研究方向改得更精準：

> growth 不應該是第一原語；更高階的原語應該是 learned write-placement / allocation policy。growth 是當固定權重內已沒有低干擾 placement 時，allocator 才允許使用的動作。

這比「遇到 saturation 就 grow」更符合專案總目標：新知識仍進入 weights、inference 不依賴外部 memory、避免 catastrophic forgetting，而且 growth 有必要性門檻，不是口號。

## 1. depth argument：我接受你的 framing，但保留 depth 作反證控制

你對 `grow_qwen()` 的批評是成立的，尤其 repo 目前的 growth 是 identity depth growth：

- `s0/qwen_grow.py` 深拷貝最後一層 Qwen decoder layer；
- 將 `self_attn.o_proj` 與 `mlp.down_proj` zero-init，使新增 layer 初始為 residual identity；
- hidden width / residual stream dimension 沒變；
- 在 `s2/lifecycle_bakeoff.py` 的既有 runner 中，growth 本質上是多幾個 residual-path Linear/MLP/attention module，不是新增一個與舊 residual read directions 隔離的 channel。

因此如果 P2a 的 failure 真的是「old-activation input directions 佔滿可寫空間」，depth 的確不是最對症的新增 capacity。它增加參數與可選 layer，但沒有新增未佔用的 input dimension；新增 layer 的 output 仍回到同一個 residual stream，LM head 仍讀同一個 `d_model` 空間。這會讓它更像「多一個會干擾舊 readout 的寫入位置」，而不是低干擾新通道。

我之前的 hedge 保留了一個可能性：新增 depth 也許能在 LM head 前形成更可分的 intermediate representation。但現在我會把這點降權。它是值得測的反證，不是 primary hypothesis。

所以 phase 2b arm 應改成：

1. `nswrite_fixed`：failure baseline。
2. `nswrite_parallel_or_routed_grow`：primary rescue arm，新增隔離、zero-init、gated output 的 write channel。
3. `nswrite_depth_grow`：falsification control；若它救得動，代表我的 width/channel 假說不完整。
4. `nswrite_large_from_start`：capacity upper control，避免把 trigger/optimizer 工程問題誤判成 growth 無效。

機制讀數也應該跟著改：不要只報 final all-seen，要量新 module 的 gradient/write 是否仍投到既有 `U` 佔用方向。若 `depth_grow` 的新梯度仍高 energy-occupied，而 parallel/routed branch 的新梯度有效避開既有 `U`，那就能直接支持「需要的是隔離寫入通道，不是盲目加深」。

## 2. P2a as-running 是否有效：有效，不要 kill；但要預先定義非 capacity 分流

我同意你現在的判準：

> capacity saturation requires `effective_grad -> small` and `fresh/newest -> drops`.

這個 gate 對「是否因為沒有可寫梯度而需要 growth」已經足夠。原因很簡單：如果 `eff-grad` 還在 0.25 以上，而且 fresh/newest 仍接近 0.97，固定模型仍能把新知識寫進權重；此時就算 old retention 掉，也不是「小模型寫不進新知識，所以必須長大」。

我會把 P2a 結果分成四格：

- **A. eff-grad 低 + newest 掉 + old retention 掉**：乾淨 capacity wall，進 phase 2b growth rescue。
- **B. eff-grad 不低 + newest 高 + old retention 掉**：不是 growth necessity；優先看 margin/basis/placement。
- **C. eff-grad 低 + newest 還高 + old retention 掉**：可能是 projection 仍有足夠可用方向但保護錯功能；要補 margin/drift，不急著 grow。
- **D. nswrite 到 24 streams 仍高於 floor 且 newest 不掉**：強正結果，但結論是 fixed interference-aware writing 比預期更 scalable；growth 仍未被證明必要。

所以我不同意現在 kill P2a。它正在回答最重要的二元問題：**這是不是 capacity gate**。margin/drift 是下一層 disambiguation，不是這輪是否有效的前提。

但我也會把 follow-up 寫死，避免 P2a 出現 B/C 時又被過度解讀：

- 若 old retention plateau 低但 newest 高：立刻補 eval-only `gold_margin_commit/final` 與 `margin_flip_rate`。
- 若 margin collapse 明顯：轉向 margin-aware / readout-aware writer。
- 若 within-block input/output drift 大：轉向 basis refresh 或 local module-wise protection。
- 只有 eff-grad/newest gate 成立時，才把 2b 寫成 growth necessity test。

## 3. growth-on-saturation vs learned placement-policy：我認為 placement-policy ceiling 更高

我的 honest read：**learned placement-policy 是更高 ceiling 的方向；growth-on-saturation 是它的一個動作，不應該是唯一答案。**

原因有三個。

第一，`nswrite` 現在是全域 union-null-space writer。它把所有舊 stream 的 protected input directions 合成一個 global `U`，再把新梯度投到 complement。這很乾淨、可歸因，但也很 blunt：它不問「這個新 fact 實際會干擾哪些舊 facts」，而是把所有舊方向都一起保護。長 horizon 下，這很容易把可寫方向消耗在過度保守的全域 constraint 上。

第二，continual learning 的核心不是「參數夠不夠」，而是「把新知識寫在哪裡才不破壞舊功能」。如果 fixed model 中仍存在低干擾 placement，直接 grow 反而會掩蓋真正問題。專案要證明小模型逐步長大，最強說法應該是：

> 先用 learned placement 在既有權重內尋找低干擾寫入；只有當 placement policy 找不到合格位置，才分配新參數。

這樣 growth necessity 會更硬：不是因為我們想讓模型變大，而是因為 allocator 在固定容量內無法滿足 retention/plasticity constraints。

第三，placement-policy 可以同時服務 no-memory inference 與 knowledge-into-weights。只要 policy 的輸出是「更新哪些 weights / branches / adapters」，而不是 inference 時查外部 memory，新知識最後仍在 checkpoint 內。訓練時保留 activation bases、risk scores、或 routing statistics 可以接受；它們是 optimizer state，不是 inference dependency。

所以我會這樣排序：

1. **P2a 照跑完**：先分類是 capacity wall 還是非-capacity plateau。
2. **若是 capacity wall**：跑 2b，但 primary 是 `parallel/routed_grow`，depth 是 falsification control。
3. **若不是 capacity wall**：不要硬跑 growth；優先做 placement-policy fixed-capacity arm。
4. **即使跑 2b，也加一個 fixed-capacity placement control**，避免把「nswrite 太 blunt」誤判成「必須 grow」。

## 4. 具體 placement-policy pilot

我建議下一個非-growth arm 不要做太大，可以先做 `nswrite_selective` 或 `slotwrite_fixed`。

### `nswrite_selective`

目標：驗證「fact-specific / stream-specific protection」是否能在固定參數下勝過 global union `U`。

做法：

- 每個舊 stream/fact 保留 low-rank activation basis summary，而不是只保留一個合併後的 global `U`。
- 訓練新 stream 時，用新 batch activation 與舊 summaries 的相似度、或預估 gradient projection energy，選出 top-risk protected bases。
- 只對 top-risk subset 做 projection，而不是對全體舊 bases 做 union-null projection。

判準：

- matched newest learning 下，`nswrite_selective` 的 all-seen / age curve 高於 `nswrite`。
- effective-grad 不只是變大；old retention 也要更好，否則只是少保護。
- `nswrite_rand_selective` 或 shuffled-risk control 不能接近它，避免變成 generic weaker projection。

這個 arm 直接測你的 claim：「global null-space projection 太 blunt，應該 fact-specific placement」。

### `slotwrite_fixed`

目標：把 placement-policy 做得更像未來的 growth allocator，但先不增加總參數。

做法：

- 預先放一組固定數量的 zero-init gated adapters / low-rank branches。
- 每個新 stream 根據 interference score 選 slot/branch 寫入。
- slot 數固定，不能每輪新增，避免把正結果歸因於容量增加。
- inference gate 必須是模型內部 gate 或 prompt-feature gate，不能查外部 memory。

判準：

- 若 `slotwrite_fixed` 明顯贏 global `nswrite`，說明下一步應是 learned allocation。
- 若 fixed slots 用完後出現 eff-grad/newest failure，再開 `slotwrite_grow`，growth necessity 會更乾淨。

這條線會把「小模型長大」改成可檢驗的 compute/capacity decision：固定 slot 仍夠就不 grow；slot exhausted 才 grow。

## 5. 對三個 concrete asks 的直接回答

1. **我接受 depth-is-ill-suited 到足以改 2b framing。** `parallel/routed` 是 primary arm；`depth` 是 falsification control，不再對稱。若 depth 贏，代表 residual-depth 仍能創造有效分離；若 depth 輸、parallel 贏，專案 claim 會更精確。

2. **我同意 effective-grad + fresh/newest 已能回答 capacity gate。** P2a as-running 有效，不必重啟。但如果結果是 retention 低、newest 高，就不能進 growth claim；必須補 margin/drift 或直接轉 placement-policy。

3. **我認為 learned placement-policy ceiling 高於單純 growth-on-saturation。** 最好的 thesis 不是「固定模型不行就變大」，而是「模型學會把知識寫到低干擾位置；只有沒有位置時才長出新 capacity」。這更能同時滿足 knowledge-into-weights、continual retention、no-memory inference、no full joint retraining，以及 growth necessity。

## 下一步決策

P2a 跑完後我會用這個 decision table：

- `eff-grad < 0.20~0.25` 且 `newest < 0.80`：做 2b，primary=`parallel/routed_grow`，control=`depth_grow`。
- `eff-grad >= 0.25` 且 `newest` 高但 all-seen 低：不要 grow，先做 `nswrite_selective` / margin-aware writer。
- `nswrite` 到 24 streams 仍穩：更新 claim 為 rehearsal-free interference-aware writing scales further than expected；growth 還未必要。
- `nswrite_rand` 接近 `nswrite`：basis attribution broken，先修 attribution，不進 growth。

這樣才不會回到過去的錯誤：用 growth 口號解釋所有 failure。現在的主線應該是 **write placement first, growth only when placement fails under measurable capacity constraints**。
