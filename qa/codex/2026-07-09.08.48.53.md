## Code sanity check

### `select_budget`

The core quota logic is sound:

- strata are answer-token bins `1-2`, `3-4`, `5+`;
- quotas are proportional to stratum size;
- leftover slots use largest fractional remainder;
- `surprise`, `lowbits`, and `random` are applied within each stratum;
- `*raw` modes correctly fall back to the old global-sort behavior.

No blocking fix needed before census-XL.

Small fixes I would make before the training ladder:

- Add an explicit mode guard. Right now any unknown non-random mode silently behaves like `lowbits`.
- Log the actual `nb` selected each stream/arm. The caller uses Python `round`, so `.5` cases are banker's
  rounded. That can matter at `B=0.125` when counts are small.
- Include `mode` in the random seed string for cleaner audit separation, e.g. `f"{seed}:{mode}:budget:{bi}"`.
- For equal `_bpt` ties, consider stable tie-breaking by `qid` instead of committed-list order. Not urgent,
  but it removes a subtle age/order artifact.

### `build_census`

The filtering rule is aligned with the project objective: train only on non-duplicate, faithful-or-human,
self-contained probes, and keep final evaluation closed-book on the census paraphrase. Also, skipping the
base-hard screen is correct for the natural-density view; base EM was already essentially zero in R42, and
unlearnable rows can fail to commit rather than being pre-filtered away.

Non-blocking issues to fix or at least account for before the ladder:

- `r42_census.jsonl` has no `self_contained` field, so this builder will yield zero rows if pointed at R42.
  Use the new R43 artifact only.
- `len(qs) >= min(QA_PER, 3)` makes `QA_PER` a cap, not a guarantee. With `QA_PER=4`, 3-QA articles can enter.
  That is acceptable for density preservation, but ladder sizing must use actual total QA and actual committed
  old count, not `STREAMS * ARTS * QA_PER`.
- `qs[:QA_PER]` takes the first probes in JSONL order. I would seeded-shuffle or seeded-sample within each
  passage before truncating, otherwise probe-generator ordering can leak into the stream.
- The printed domain mix counts all usable `arts`, not just the returned `arts[:nstream * ARTS]`. For the
  natural-density headline, print the used-stream domain mix.
- Keep `WB_LM_MAXLEN=384` for the Step-B ladder. The default 256 can truncate census passages.
- `s3/census.py` now reports post-self-contained tails, but its `strat_len` / `strat_kind` summaries are still
  over pre-self-contained `ok` rows. For Step-B interpretation, compute length/type confounds on `ok_sc` from
  the JSONL before deciding the final ladder table.

## Census-XL size

`120/domain` and `8 probes/passage` is enough for the next decision-quality census. R42 had 446 gated probes
before the self-contained screen; XL is roughly 4x the raw opportunity count after scaling passages and probes.
That should be enough to estimate post-screen density and passage-level survival.

If the post-screen yield is thin, increase passages before increasing probes. Step B needs enough passages
with several usable probes, and more passages also improves the passage-bootstrap estimate. More probes per
same passage helps article survival, but it gives less independence.

Required census-XL report before ladder:

- `n_gated`, `n_sc`, and `sc_rate` by domain;
- passage counts with `>=3`, `>=4`, and `>=5` self-contained probes;
- post-screen bpt tails by domain;
- post-screen length/type confound tables;
- base closed-book and gold-passage RAG EM after the screen.

## Ladder sizing correction

The current tentative target `STREAMS=6, ARTS=3, QA_PER=4` gives at most 72 QA total. Before the final stream,
there are only 60 old candidate QA. If commit rate is ~0.8, the old committed pool is ~48, so `B=0.125`
selects about 6 items, not the desired 7-8. To get `B=0.125` above the interpretability floor, require
measured old committed count `>=60`, not just total QA `>=60`.

Practical sizing rule:

1. Run census-XL.
2. Build the candidate stream.
3. Run a cheap two-arm pilot, `compact_cpt_qa_k0` and `compact_cpt_qa`, on one seed.
4. Use the observed committed-old count to set `STREAMS/ARTS/QA_PER`.

If yield allows, prefer one of:

- `STREAMS=6, ARTS=3, QA_PER=5` for 90 nominal QA and 75 old candidates before the last stream;
- `STREAMS=7, ARTS=3, QA_PER=4` for 84 nominal QA and 72 old candidates;
- or keep variable-QA articles but explicitly require `old_committed >=60` before interpreting `B=0.125`.

Also adjust the wall-clock estimate. R41 was ~490s per training arm/seed for 3 streams. A 6-stream run likely
costs closer to 900-1000s per arm/seed because CPT and consolidation steps are per stream. The listed ladder
is 10 training arms, not 11, but at 2 seeds this can still be ~5-6h rather than 3-3.5h. Base/RAG diagnostic
arms are cheap and should not be counted like training arms.

`surpriseraw@0.25` is useful, but lower priority than the stratified controls. The per-QA sidecar can audit
the length distribution of raw-vs-stratified selection offline, but it cannot fully simulate the retention
effect of actually replaying raw-selected items. My recommendation: run `surpriseraw@0.25` on one seed if the
main result is clean, and only run the seed pair if the stratified result is ambiguous or raw selection appears
materially different.

Do not use `sourceoracle` as a headline arm on census. There is no independent synth/source oracle in real
text; a bpt-derived oracle would be circular.

## Natural-density primary

Yes: keep natural-density as primary and defer the balanced high/low audit unless the ladder is ambiguous.
That is the view that answers the compute-advantage question: can selective training-time replay scale with
real exception density while final inference remains one closed-book checkpoint?

The balanced audit is still useful later if the natural tail is too sparse to diagnose router direction, but
it should not become the headline economics result.

## Pass/fail criteria

Pass:

- length-stratified `surprise@0.25` beats matched `random@0.25` on old-only held-out paraphrase EM on both
  seeds;
- `lowbits@0.25` is worse than surprise, especially on high-bpt old rows;
- `surprise` approaches full replay within ~0.03-0.05 at a budget near the measured tail fraction;
- newest-stream paraphrase EM is not sacrificed;
- the result survives domain, answer-length, and answer-kind splits.

Warning:

- surprise only closes the gap at `B=0.5`;
- the win exists only in raw global bpt and disappears after length stratification;
- full replay itself has low commit/retention, meaning Step B is measuring poor probe/write quality rather
  than replay allocation.

Fail:

- stratified surprise is not better than random;
- lowbits is not worse;
- skipped low-risk rows decay like high-risk rows;
- the budget needed to approach full replay is so high that compute advantage over broad replay disappears.
