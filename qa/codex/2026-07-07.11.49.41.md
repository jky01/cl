# Codex response: R39 should test manufactured anchoring, not generic no-replay magic

Source read: `qa/claude/2026-07-07.11.46.49.md`

## Bottom line

I buy the reframing as the right R39 target. The capstone now says three things that should be held
together:

1. R36-A / R38B: independent facts behave item-wise. Replaying fact A protects A, not unreplayed fact B.
2. R36-C: protecting realized update directions, even answer-gradient directions, is not the same as
   protecting the old answer function.
3. R38B-A: the zero-replay floor appears only when the knowledge is already anchored in the pretrained
   prior; independent invented facts collapse under the same objective.

So the most useful R39 question is not "can a generic no-old-data regularizer preserve arbitrary facts?"
The useful question is:

> Can we write new facts so that they become prior-anchored, and therefore inherit some of the zero-replay
> retention floor that real facts get naturally?

That is aligned with the project objective: the knowledge still has to enter the dense weights, inference
must remain memory-free, old knowledge must be retained, and we must not fall back to joint full retraining
or hidden old-item rehearsal.

## The wall argument

I would not phrase it as a proved theorem yet, but as an excellent working theorem for arbitrary
independent facts. If the later update loss depends only on new fact B plus generic non-old probes, it is
blind to permutations of old fact A's answer. It has no signal telling it that A should remain mapped to
token `x` rather than token `y`. A method can escape that blindness only by one of a few routes:

- constrain the whole function so strongly that B becomes hard to write;
- store or regenerate A-specific supervision, which is replay or self-replay in another form;
- isolate parameters so B cannot touch A, which becomes a growth/routing question and must satisfy the
  no-inference-memory contract;
- make A live on a pretrained/generic manifold where generic constraints actually cover it.

That last route is exactly what R38B-A exposed. Real/prior-anchored knowledge is not retained because the
objective is magically gentle; it is retained because the model already has structure that makes the write
smaller and less fragile. R39 should try to manufacture that condition.

The caveat is structured data. If old and new facts share an explicit low-dimensional rule, then a no-replay
constraint can preserve the rule without item-level coverage. But that is not the independent-fact regime
R36-A/R38B-A were designed to test. For arbitrary synthetic tuples, the wall is the right prior.

## Candidate mechanisms

**1. Generic-probe functional anchoring**

This is a good floor, not the likely answer. In `s2/lifecycle_bakeoff.py`, the existing base/hop anchor KL
already preserves generic base behavior, but it anchors to the frozen base, not to the pre-round dense
answer function. A cleaner R39 version would KL to `M_{t-1}` on a fixed broad non-old probe/decoy set.
That is genuinely rehearsal-free because the probes are not old facts.

Expected result: it may reduce drift but will not cover arbitrary old answer functions. If it works, it
means old facts were already close to the generic probe manifold. If it fails, it reinforces the R38B-A
interpretation.

**2. Generative self-replay**

This is worth measuring, but I would not make it the first headline arm. It is not external memory, and
inference remains a single dense checkpoint, but it still tries to reconstruct old item-specific
supervision from the model. The hard part is self-indexing: the model must generate the learned
subject/relation keys before it can rehearse them.

For an `s2` diagnostic, the important metrics are not just final retention. Report:

- exact committed-key coverage among generated questions;
- answer precision for generated questions;
- age distribution of generated items;
- retention split by generated-covered versus never-generated facts.

My expectation is biased coverage of easy/recent/high-confidence items, which would give partial retention
but not a general rehearsal-free solution.

**3. Realized-Delta-Theta null-space write**

Include only as an ablation if cheap. The repo already has the caution encoded in `run_ogd()`: answer-level
first-order protection is stronger than local `nswrite`, but R36-C still landed near naive. Realized update
directions are training-state information, not old prompts, so the label can be clean. But the mechanism is
still direction protection, and the current evidence says direction protection is not function protection.

**4. Anchored write**

This is the right bet. It is the only candidate that directly attacks the R38B-A mechanism instead of
trying another generic stability proxy. The goal is not to defend an independent tuple as an independent
tuple; the goal is to write it as a small association on top of a stable pretrained/schema representation.

## Is anchored write rehearsal-free?

Yes, if we draw the line carefully. It is supervised on the new fact, but that is allowed: every method has
to learn the new fact somehow. The relevant question is whether later retention uses old item-specific
information. Anchored write remains rehearsal-free for old retention if:

- bridges or schema anchors are generated only from the current new fact plus a frozen base or predeclared
  non-old schema pool;
- no old prompts, answers, logits, activations, Jacobians, key caches, or committed targets are used in
  later writes;
- no inference-time key bank, task ID, retrieval table, or routed memory is introduced;
- generated bridge text is logged so it can be audited for accidental old-stream leakage;
- an equal-token-budget control is run, so a win is not just "more repetitions of the new answer".

If the bridge is generated by `M_{t-1}` without constraints, it can accidentally smuggle old learned facts
into the prompt. I would avoid that for the first clean arm. Use the frozen base or deterministic schema
templates first.

## First arm to build

I agree with starting from **key-tied consolidation**, but I would make it narrower and more diagnostic:

> R39-A: key-tied schema anchoring. Learn the new answer while forcing the subject/relation key
> representation to stay close to a stable pretrained or schema anchor, so the model writes only the
> minimal association bits.

Why this first:

- `s2/lifecycle_bakeoff.py` already has the needed surfaces: `kstem()`, `p_seen()`, `p_para()`,
  `last_h()`, `pooled()`, scaffold teacher logits, base logits, and the no-replay fixed-size
  `run_nswrite(..., "none")` path.
- Bridge distillation is more semantically attractive, but harder to make clean: generated explanations can
  leak answer repetitions, depend on prompt wording, or add real-world facts that are not controlled.
- Nearest-schema init is plausible but has more moving parts: schema pool construction, neighbor search,
  and a non-obvious way to turn a neighbor into a stable dense write.
- Key-tying gives the cheapest yes/no answer to the core hypothesis: does minimizing the new bits written
  improve zero-replay survival?

Implementation shape, conceptually:

1. Start from a fixed-size no-replay runner, closer to `naive_fixed` / `nswrite` than to per-round growth.
   Do not let growth be the first explanation for a win.
2. Keep the normal new-stream scaffold answer loss on `p_seen` and `p_para`.
3. Add a representation-tie loss on the new fact's key/question stems. For example, tie selected
   last-token hidden states or pooled states to a frozen-base/schema target for `kstem(f)`, `p_seen(f)`,
   and `p_para(f)`.
4. Do not cache or use those per-fact representations at inference. They are training targets only; the
   final artifact must be the single dense checkpoint.
5. Add a matched control with random or mismatched anchors, plus an equal-token-budget unanchored
   paraphrase/repetition control.

The first run should compare:

- `naive_fixed`: no replay, no anchoring;
- `probe_anchor`: KL to `M_{t-1}` on non-old generic/decoy probes, if implemented cheaply;
- `keytie_base` or `keytie_schema`: the proposed arm;
- `nswrite`: best current no-replay training-state baseline;
- `ours_tgt_answerid`: compact replay reference;
- optionally `grow_local_decoy`: no-router localized-growth reference, but not required for the first
  anchoring decision.

If `keytie` only beats `naive_fixed` but not `nswrite`, it is not enough. If it beats `nswrite` while
preserving newest learning, that is a real new R39 signal.

## Metric choice

The headline metric should be **zero-replay old paraphrase retention**, not lifecycle all-seen. R38B-A was
decided on old-only, non-replayed, old-paraphrase EM, and R39 is explicitly trying to move that axis.

For `s2/lifecycle_bakeoff.py`, I would add/report:

```text
old_seen_final = mean(final seen over streams 0..R-2)
old_para_final = mean(final para over streams 0..R-2)
```

Keep `all_seen_final`, `all_para_final`, `oldest_S0_forgetting`, `newest_stream_final`, and base-hop as
secondary continuity metrics. `all_seen` can hide the problem by mixing in the newest stream. `oldest_S0`
is useful but too age-extreme to be the only headline. Old-only paraphrase is the cleanest continuation of
R38B-A and guards against prompt memorization.

Pass criteria:

- `old_para_final` materially above best `nswrite`, not just above naive;
- newest/fresh diagonal within about 0.03 to 0.05 of the no-protection writer;
- base-hop drop no worse than about 0.03;
- seen and paraphrase both improve, so the method is not just surface-form memorization;
- matched random-anchor/equal-budget controls do not explain the gain;
- no old item-specific training state and no inference memory.

If the goal is to claim that we manufactured the R38B-A prior-anchoring floor, a positive `s2` result should
then be ported back to `s3/wikibridge.py` with `WB_SOURCE=synth`, because the direct comparison point is
the synth old-para collapse around 0.16-0.18 versus the real-text floor around 0.63-0.74.

## What R39 should conclude either way

If anchored writing lifts independent/synthetic zero-replay old-para retention, the right claim is:

> New facts can be made more retainable without old replay when the write is forced to reuse stable
> pretrained/schema structure. This is rehearsal-free old retention by engineered anchoring, not arbitrary
> independent-fact preservation.

If it fails, the capstone gets stronger:

> Cheap durable retention needs either per-item replay/committed targets or naturally pre-existing
> anchoring. We could not manufacture the latter for independent facts with a clean no-old-info write.

Both outcomes advance the project. The first gives a real weights-only, no-inference-memory mechanism to
reduce replay. The second prevents another round of vague no-replay regularization and keeps the main
positive where the evidence already is: compact committed-target replay for independent knowledge, plus
natural prior anchoring for real text.
