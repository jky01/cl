# R50 re-rank: pivot to shadow query search, but narrow the mechanism claim

Source read: `qa/claude/2026-07-10.18.18.23.md`

## Bottom line

I agree with the strategic pivot, with one important correction: the hardened probe supports
**proposition-preserving paraphrase robustness plus entity-cued proposition-selection drift**. It does **not** yet
establish `decoding_competition`, and it does not prove that unrestricted tomography can find the right
proposition without an old key.

My re-rank is:

1. **R50-A: checkpoint-only shadow query search as a discovery-only feasibility test.** This is now the most
   principled research shot because it directly targets the observed failure: find a threatened address rather
   than ask the checkpoint to volunteer an old fact from its high-prior generation distribution.
2. **Compressed cue-ledger as the engineering ceiling and cost curve.** R48 has already shown that stored gold
   cues beat self-generation. Do not spend another pod merely reproducing `stored_random_B > self`; test how many
   persistent bits are actually load-bearing.
3. **Structured multiview as a query-policy intervention, not an encoding intervention.** Keep it alive, but
   promote it only if it improves checkpoint-only proposition enumeration after later writes. Merely making
   `(entity, relation) -> question` work when both fields are externally supplied does not solve self-addressing.

Thus: **yes, pivot R50 from multiview encoding to shadow query search first**, but make Stage A a no-training
coverage test with hidden historical gold used only for audit. Search earns a retention run only if it discovers
correct threatened propositions under a genuinely history-free proposal contract.

## What the hardened result really establishes

The overturn is material. Across 60 final-answerable facts out of 172 old facts, audited-equivalent paraphrases
have high ordinary retrieval accuracy: `para` EM is 0.833 over 102 rows and `short` EM is 0.860 over 57 rows.
Changed entity-generated questions behave very differently, and the wrong-entity control moves in the intended
direction. This is strong evidence against the scout's blanket claim that learned facts occupy a literal-string
basin.

The qualitative examples are particularly useful. Once a question actually asks who designed the
Peirce-Nichols House, the checkpoint returns Samuel McIntire under rewording. In contrast, "Sir Richard Branson
was what?" asks another plausible proposition and the checkpoint answers that new proposition. That is best
described as an **address-selection failure**: the model can answer an addressed proposition but does not preserve
which relation it intended to ask about when generating a question from an entity.

That result should be banked, but only at the following scope:

- It applies to the selected final-answerable population: 32/90 and 28/82 old facts, about 35% overall. It says
  nothing about facts that were no longer reachable even under the full held-out question.
- The 25 equivalent failure rows represent only 20 unique facts, with 13 unique failures in seed 0 and 7 in seed
  1. That remains below the previously requested per-seed decision-grade population.
- The self-generated evidence is only 11 lexically admitted rows, all from seed 0: 10 judged changed and one
  equivalent. It is a revealing mechanism trace, but not yet a two-seed estimate of self-question drift.
- The same 3B model generates and judges the variants, with no `ambiguous` state or independent audit. There is a
  visible false-positive example in the saved rows: "What city does the headquarters of the BBC News channel lie
  in?" is accepted as equivalent to a question whose gold is the building `Broadcasting House`; both models
  reasonably answer `London`. That row is semantic drift, not a decoding miss.
- Paraphrases are generated from the original acquisition question, not stratified by frozen lexical distance
  from the held-out evaluation question. High EM therefore demonstrates useful rewording robustness, but not yet
  a calibrated far-paraphrase basin.

Most importantly, the emitted `decoding_competition` label is not supported by its own intended discriminator.
Only 1 of 25 equivalent failures has `winner_is_base_lure=1`, a rate of 0.04. The classifier assigns the label
solely because pooled failure lift exceeds half of a pooled full-query mean; it does not require a base lure or
token-level competition. The rows also omit base full-query log-probability, so paired
`lift(variant) / lift(full)` cannot be computed per fact from the artifact. The defensible conclusion is therefore
**retained learned support under many equivalent prompts despite occasional wrong greedy answers**, not a proven
base-prior decoding mechanism.

This distinction matters for R50: it removes the motivation for broad multiview encoding, but it does not motivate
a lure-margin loss either. The novel bottleneck is selecting the old proposition to query.

## Cue-ledger ruling: valid engineering floor, not the frontier mechanism

R48 already contains the relevant causal comparison at matched replay budget: `stored_random_B` old-only
paraphrase EM is 0.435, versus 0.293 for passive random self-replay and 0.355 for fragile self-replay. The bare
no-replay floor is 0.376, so off-target self-replay is not merely weak; it can add interference. Repeating that
comparison would confirm a known result.

The useful next ledger experiment is a **persistent-bit ablation curve**:

1. full question plus answer;
2. full question, with the checkpoint regenerating its committed answer before replay;
3. entity plus relation plus stored answer;
4. entity plus relation, with the answer regenerated;
5. shared relation template plus entity identifier;
6. entity only and a fixed generic query instruction.

Match consolidation tokens and report old retention, newest acquisition, neutral/base capability, persistent
bytes, replay tokens, and retention gain per persistent byte. Separate cue bytes from answer bytes; otherwise a
"tiny stub" result may still hide an O(facts) answer ledger.

A shared relation template can reduce constants, but it does not generally make arbitrary facts sublinear. Every
independent subject-relation proposition still needs to be identified, so the entity/relation incidence list is
O(number of facts) unless subjects and relations are derivable from already-shared structure. A sublinear claim is
earned only if bytes per accumulated surprise fall as streams grow, or if one stored schema cue reliably protects
many independently audited facts. The ledger is compatible with one-checkpoint, no-memory **inference** because it
can be discarded after consolidation, but it remains external historical memory during learning. It is therefore
an honest deployment baseline, not the desired checkpoint-only continual mechanism.

## R50-A: the decisive shadow-tomography probe

The result raises tomography from speculative to well-motivated, but paraphrase existence is not searchability.
The known equivalent questions prove that good addresses exist near a historical question. They do not prove that
a history-free optimizer can locate those tiny regions in the enormous prompt space. Shadow disagreement may
also maximize on adversarial nonsense, generic pretrained behavior, or a different proposition about the same
entity.

Freeze this Stage A contract:

- Inputs available to search: `M_prev`, the disposable 60-step current-write shadow `S`, the frozen generic base
  `B`, and fixed generic prompts. No old question, answer, qid, title, subject, entity, relation, or historical
  embedding may enter proposal or ranking.
- For a candidate natural question `q`, let `a = greedy(M_prev, q)`. Rank using a preregistered combination of:
  loss of `a` under the shadow, high and stable commitment of `M_prev` to `a`, positive acquired lift over `B`,
  natural-question likelihood, and diversity from already selected candidates. Use two independently generated
  paraphrases to require answer consistency. The base and shadow are training-time auditors and are discarded.
- Do not call `M_prev(q) == a` a proposition gate; that is tautological because `a` came from `M_prev`. The gate
  only says the behavior is self-consistent. Whether `q` addresses a true old acquired proposition must remain a
  hidden offline audit against historical facts.
- Save every proposal, objective component, answer, paraphrase-consistency result, and hidden audit match. Report
  unique-fact coverage rather than candidate-row coverage.

Use at least these matched proposal controls:

| arm | What it isolates |
|---|---|
| passive checkpoint generation | R48/R49 coverage floor |
| shadow-disagreement tomography | proposed mechanism |
| same search with an unmodified copy or wrong-stream shadow | whether real impending damage is load-bearing |
| confidence/base-lift search without shadow disagreement | whether search merely finds salient acquired facts |
| stored full-question oracle | addressability ceiling, audit only |

Increase the number of eligible threatened facts before ruling; R49a's 9 and 7 threatened facts were explicitly
underpowered even though the shadow proxy was excellent (`pooled Spearman=0.973`). Pre-register Stage A as a pass
only if, in each seed, tomography reaches at least 25% correct coverage of unique answerable threatened facts,
beats passive coverage by at least 4x, has at most 20% proposition-target error among admitted candidates, and
loses at least half its coverage under the wrong-shadow control. These are mechanism gates, not tuned promotion
thresholds.

If Stage A passes, run Stage B with four consolidation arms: compute-matched no replay, passive self-replay,
tomography replay, and stored-cue replay. Proposal, scoring, and consolidation FLOPs must be separately reported.
Tomography passes retention only if both seeds improve old-only held-out paraphrase EM by at least 0.05 over the
compute-matched floor, recover at least 30% of the stored-cue gap, do not lose the newest stream beyond a frozen
tolerance, and preserve neutral/base evaluations. Evaluate covered, uncovered, and never-proposed old facts
separately to detect narrow protection or collateral forgetting. Final evaluation uses ordinary greedy decoding
from one checkpoint, with all prompts, base models, shadows, and candidate pools discarded. This remains
sequential consolidation, not joint full-history retraining.

If Stage A fails, do not train tomography harder blindly. The result would mean disagreement predicts *which
known facts* are vulnerable but cannot invert the checkpoint into a usable address without historical keys. That
would promote compressed ledger or an in-weights query index rather than another search sweep.

## Where structured multiview still fits

Teaching `(entity, relation) -> canonical question` is useful only if it changes the model's autonomous query
policy. If relation is supplied at replay time, the experiment has simply moved the ledger from a natural-language
question to a structured key. The hard case is one entity with many relations: from an entity-only or generic
seed, the model must enumerate distinct learned propositions without collapsing onto the highest-prior relation.

A later matched test should construct 1/4/8-relation-per-entity strata and compare single-view acquisition with
equal-token structured multiview acquisition. After later streams, provide no historical relation labels and
measure unique proposition coverage, relation precision, duplicates, answer correctness, and downstream
self-replay retention. Promotion requires a seed-robust increase in autonomous correct proposition coverage—not
just higher EM when the correct `(entity, relation)` key is handed to the model—without reducing ordinary QA,
newest learning, or base capability.

Storing such an index in weights is not conceptually disqualifying; knowledge and its usable address both belong
in weights under the project objective. It is better than a ledger if the checkpoint can enumerate it, retain it,
and use it with lower lifetime cost. It is merely a lossy ledger imitation if it needs the same per-fact external
keys or drifts before it protects later streams.

## Project-level decision

Bank the mechanism as **cued proposition access is often robust; autonomous proposition selection is the current
wall**. Do not bank `decoding_competition`, rehearsal-free retention, or growth. R50-A attacks knowledge access
without adding inference memory; R50-B, if earned, tests whether discovered behaviors can be consolidated back
into the same weights. Growth remains off-path until fixed-size query search/query indexing reaches a reproducible
capacity or interference saturation point and a grown model beats both fixed-size and large-from-start controls at
matched lifetime compute. No result here licenses full-history joint training.

## Boundary-pushing, high-risk/high-reward brainstorming

### Invert the shadow through a soft prompt, then discretize the address

Instead of sampling questions, optimize a short continuous prefix to maximize
`log p_M(a|z) - log p_S(a|z)` while jointly optimizing a stable answer `a`. Decode or distill the soft prefix into
several natural questions and retain it only when those questions agree under `M_prev`. This tests whether the
address basin is geometrically reachable even when discrete autoregressive proposal cannot enter it. The decisive
controls are wrong shadows, soft-prefix length, naturalization failure, and hidden-gold proposition precision.

### Build a fixed enumerable neural address space

At acquisition, assign propositions to a shared, deterministic code space and train both `code -> question` and
`question -> code`, then fold both directions into the checkpoint. Replay enumerates the fixed codebook rather
than storing per-fact cues. This could turn self-replay into scanning a reusable address lattice whose metadata
does not grow with facts; collision rate and empty-slot compute become the price. The dangerous failure is that
code assignments themselves require an external ledger or are overwritten across streams. A convincing result
would show stable code occupancy and fact recovery after later writes with only a fixed seed list.

### Use an ensemble of counterfactual shadows as a functional CT scan

Create several cheap shadows from different plausible next writes. Generic fragile behavior will vary
inconsistently, while a genuine acquired proposition boundary may produce a coherent low-rank disagreement
signature. Search for prompts whose answer is stable in `M_prev` but predictably damaged across the shadow
ensemble, then replay only consensus discoveries. If this sharply improves hidden proposition precision over one
shadow at matched FLOPs, it would turn tomography from adversarial prompt mining into a reusable map of the
checkpoint's fragile knowledge geometry.
