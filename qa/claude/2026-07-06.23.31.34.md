## The oracle paradox — a clue I don't fully understand

R37-A oracle forces the grown block to ≈identity on old prompts (`delta_old`→0.001) yet **destroys** old
recall (0.177, worst of all). Retention is **non-monotone** in footprint: decoy(0.054) > anchor(0.078) >
oracle(0.001). newest is identical (0.887) everywhere, so it's not plasticity.

**Q2.** What is this telling us about WHERE interference lives? My reading: old-fact recall *depends on the
later blocks' contribution* — they're not inert on old prompts — so "protect by making the writer silent
on old inputs" is self-defeating; the old answer is a *distributed* computation, not a localized store.
If that's right, then **every** "protect a subspace / freeze a region / zero a footprint" method is doomed
for the same reason (R36-C input-direction, R37-A output-footprint) — the invariant we must preserve is the
**end-to-end answer function**, which only replay (or gold) actually optimizes. Is that the deep unifying
explanation for the whole R36–R37 bound? Or am I over-reading a synthetic quirk?

## Genuinely-novel mechanisms we have NOT tried — which have real prior?

I want your ranking + any I'm missing. Candidates for "a method not yet discovered":
1. **Learned writer / learned optimizer** — meta-learn an update rule that minimizes measured interference
   (train the writer across streams to preserve old answers without replay). High-risk, but it's the one
   that directly optimizes the end-to-end invariant rather than a proxy.
2. **Robust modular routing that provably doesn't forget** — the router-forgetting recursion killed naive
   MoE-growth. But is there a *non-learned* or *frozen-after-commit* routing (hash/locality-sensitive, or
   a router trained once and frozen) that sidesteps the recursion? Or content-addressable routing where the
   "key" is a frozen function of input, not a learned-and-drifting one?
3. **Function-space / dual formulation** — operate on the model's input→output *function* (e.g. a stored
   set of old (input, committed-logit) constraints enforced as hard equality via a projection at *write*
   time) rather than parameter space. But that's basically compact replay (R36-A2) in disguise — is there
   a version that's genuinely not replay?
4. **Test-time / inference-time mechanisms** — we banned inference memory, but is there a *parametric*
   inference-time adaptation (fast weights, in-context-to-weights) that stays "single dense checkpoint"?
5. **Sparse/mixture write with orthogonal *feature* allocation** (not parameter freezing) — allocate each
   stream a disjoint set of *features/directions* in activation space via a fixed random or learned code,
   so writes are feature-orthogonal by construction. Different from OGD (gradient) and R37-A (footprint).

**Q3.** Rank these by prior of beating replay's *necessity* (not just beating naive). Kill the ones that
secretly reduce to replay/routing. Add any genuinely-different primitive we haven't named.
