## Why I think this is achievable AND where our own line says it will break

We already have a directly relevant positive: `s4/scratchpad.py` (interleaved local step + local-window
attn) length-extrapolates the `csum_reset` recurrence to L40=0.95. Number sequences are recurrences:
- arithmetic a_n = a_0 + d·n  => order-1 recurrence (constant 1st difference). Should extrapolate like csum.
- quadratic a_n = a_0 + b·n + c·n² => order-2 recurrence (constant 2nd difference). Harder; may need the
  1st-difference sequence exposed as a scratchpad to make the step local.

And the honest wall from the toy line (`toy_quadratic`, `posrand`): absolute-position closed-form
(given n, predict a_n) does NOT extrapolate OOD; only a LOCAL RECURRENCE rolled forward does. So I will
frame and measure two views explicitly:
1. **recurrence/continuation view** (given the prefix terms, predict the next terms) — expected to
   extrapolate; this is the sense in which it "learns the generating function".
2. **closed-form-from-index view** (given n, predict a_n) — expected to fail OOD; reported as the control
   that shows the difference is inductive-bias, not capacity.

## Concrete design (`s4/numseq.py`)

- **Representation**: each integer as fixed-width base-10 digits, **LSB-first** (units first) to keep carry
  local (helps the local-window extrapolation the way interleaving helped csum). Vocab = {0..9, SEP, BOS,
  EOS, PAD} (all-positive families first; add a sign token only if we later need decreasing sequences).
- **Serialization**: `BOS d(a_0) SEP d(a_1) SEP ... d(a_{L-1}) EOS`, next-token LM loss on all digits.
- **Model**: small from-scratch transformer (d≈128, 4 layers, 4 heads, rotary), with an optional
  **local-window** covering ~3 terms so the order-≤2 recurrence is position-invariant => extrapolable.
- **Families / splits**: arithmetic(a_0,d) and quadratic(a_0,b,c≥1) with coefficients sampled in a TRAIN
  range; test on (a) more terms than trained (L_test>L_train => larger n & larger values never seen) and
  (b) HELD-OUT coefficients. Both are true extrapolation (function generalization, not memorization).
- **Eval**: feed the first k terms, autoregressively generate the remaining digits, exact-match the
  untrained-range terms. Report per-family, in-range vs beyond-range term accuracy, plus the closed-form
  control.
- **If quadratic plain fails**: add a **difference scratchpad** — emit Δ_i = a_i−a_{i-1} between terms so
  the model executes the constant-2nd-difference step locally (honest label: scaffold supplies the step
  decomposition, as with csum; still autonomous continuation once trained).

## Two modes, and the "self-derive which function" question

- **per-family**: one model per family (cleanest extrapolation proof).
- **mixed / in-context**: ONE model trained on all families; given a prefix it must INFER which function
  and continue. This best matches the user's "小模型自行推導" (self-derives the continuation) — the prefix
  is the only signal for which rule applies. I plan to report per-family first (is extrapolation even
  there?), then mixed (can it identify-and-roll-forward from the prefix alone?).
