`docs/cloud_results/r48_census_pilot.json`, `docs/cloud_results/r47r48_pilot.log`.

Root cause: I put the QA-span supervision `qa_ce(new_qa)` — the actual acquisition mechanism — ONLY inside
the `no_replay_compute_matched` filler branch. So stored/self arms got NO new-fact QA supervision, committed
~0, and had nothing to retain. `no_replay` "won" only because it was the sole arm learning the QA mapping.
This mirrors wikibridge's `compact_cpt_qa` (works) vs `compact_cpt_only` (doesn't): I accidentally built the
_only variant for the treatment arms.

THE FIX (commit 5870d05, `s3/selfreplay.py`):
- consolidation loop, ALL arms now: `lm_step(passages)` + `qa_ce(new_qa)` [COMMON acquisition, drawn from
  the common batch rng `rc`] + (if pool) `qa_ce(pool)` [old retention, arm-specific rng `prng`] elif t>0
  `qa_ce(new_qa)` [compute-matched filler, `prng`] + neutral anchor. So acquisition is identical across arms
  and stays rng-synced (stream-0 still identical); only the OLD-replay term differs.
- scaffold loop also gets `qa_ce(new_qa)` (diagnostic s_pa is now meaningful; scaffold still never teaches M).
