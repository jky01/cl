## The observation that reorders phase 2: nswrite has NOT saturated to failure

Your growth trigger requires **occupancy high AND effective gradient low AND newest-learning
plateau, simultaneously**. But at 6 streams only the first holds: occupancy is 0.92, yet **newest is
still 0.975 and the model keeps writing new streams fine.** The residual forgetting (S0 → 0.56) is
imperfect protection, *not* a capacity wall — the writer isn't yet failing to learn. So if I ran
"grow vs fixed" now, fixed nswrite still works → I'd be back in an R32-style 0-vs-0-of-necessity
(nothing for growth to rescue). **Growth necessity is not yet demonstrable because saturation-to-
failure hasn't happened.**

So phase 2 must be two stages:

**Phase 2a — drive nswrite to actual failure (no growth).** Extend the horizon until fixed nswrite
*breaks*: more streams (12–24), and/or larger per-stream rank so U fills the module input dims. The
signature to hunt: occupancy → ~1, **effective gradient ratio ||G(I−UUᵀ)||/||G|| → small**, and then
**either newest_stream_final drops (can't write) or retention collapses (can't protect)**. Report the
occupancy + effective-grad + newest curves vs stream index. If nswrite *never* breaks (stays dominant
to 24 streams), that's itself a strong result — fixed low-rank interference-aware writing scales
further than expected, and growth stays unjustified. Only if it breaks do we have a saturation point.

**Phase 2b — at the failure point, test whether growth restores it, and WHICH kind.** Only here run:
`nswrite_fixed` (breaks), `nswrite_grow_on_saturation` (add capacity when the 2a signature fires),
`nswrite_large_from_start` (capacity upper control), matched updated-params / wall-clock. And the real
prize you flagged: **depth (`grow_qwen`) vs width/parallel-adapter/routed growth.** My hypothesis:
since saturation is in *per-module input-activation* dimensions, identity depth growth won't add
writable directions (new layers start as identity, contributing no new orthogonal input basis to the
readout), whereas a **parallel adapter / new routed branch** adds genuinely fresh input dimensions the
projection hasn't occupied. If that holds, the project's "小→大" becomes precise: *grow by allocating
new low-interference write branches at saturation, then consolidate* — not by deepening one residual path.

## Two additions I want in phase 2a (cheap, they explain the residual forgetting)

Per your failure-mode list, the residual S0→0.56 forgetting has two candidate causes; measuring them
now tells us whether nswrite's ceiling is a basis-staleness problem or a margin problem:
1. **per-layer old-activation drift** (eval-only old prompts): block-entry drift should be ≈0 (frozen
   lower stack — validates the friendly-setting hypothesis); within-block drift ≠ 0 explains residual
   forgetting via propagation.
2. **answer-margin preservation** (eval-only): logit(gold)−max_other on committed-correct old facts.
   If hidden drift is small but margin collapses → protecting the input basis doesn't protect the
   token, and the fix is a **margin-aware / readout-space** writer (→ your B, closed-form editing),
   not more null-space rank.
