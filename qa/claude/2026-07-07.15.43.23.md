## What I verified in the code
- Answers are SINGLE tokens (`one_tok(v)`), so surprise on the gold answer = `-log2 P_base(gold | prompt)` =
  clean per-fact CE in bits. No multi-token complication.
- `eval_all` uses `recall(m, facts, p_seen/p_para)` = argmax==gold. Per-fact retention is just the
  un-aggregated version of `recall`.
- `run_loramerge` (line 555) trains a LoRA on the EVOLVING dense each round and `merge_and_unload`s it in —
  that's the sequential-drift arm that failed R33/R35. The new parallel arms must train each stream on a
  FRESH frozen base and combine deltas only at eval. Confirmed they are genuinely different.

## Part A — parallel-merge arms: `merge_sum`, `merge_ties`  (new `run_mergeparallel(seed, streams, scaffolds, mode)`)
```
base = load_frozen()                                   # kept as the delta reference
deltas = []                                            # per-stream {weight_name: ΔW_r on CPU}
for r in ROUNDS:
    fresh = load_frozen(); peft_m = get_peft_model(fresh, cfg=<same q_proj/v_proj LoRA as loramerge>)
    train peft_m on stream r ONLY, IDENTICAL loss to run_loramerge (teacher CE+KL from scaffolds[r])
    merged = peft_m.merge_and_unload()
    Δ_r = { name: (merged.sd()[name] - base.sd()[name]).cpu()                # exact delta from merge
            for name in target q_proj/v_proj weights }
    deltas.append(Δ_r); del fresh, peft_m, merged; empty_cache()
    # eval at round r: combine deltas[0..r] into a fresh base copy
    dense = load_frozen()
    for name: dense.sd()[name] += LAMBDA * combine(mode, [Δ_j[name] for j in 0..r])
    seen,para,h = eval_all(dense, streams, r); record; del dense
```
- `combine("sum", Δs)` = `Σ_j Δ_j`  (task-vector arithmetic sum).
- `combine("ties", Δs)` per weight `name`, coordinate-wise across the r+1 deltas:
  1. **trim**: keep each Δ_j's top-`BK_TIES_DENSITY` (default 0.2) by |magnitude|, zero the rest;
  2. **elect sign**: `γ = sign(Σ_j trim(Δ_j))` per coordinate;
  3. **disjoint mean**: average only the trimmed entries whose sign matches `γ` (mean over agreeing count,
     not over r+1).
- `LAMBDA = BK_MERGE_LAMBDA` (default 1.0 for ties; sum I'll sweep {0.3, 0.5, 1.0} — task arithmetic
  typically wants <1 for sum). flags: `uses_replay=False, uses_inference_memory=False, single_dense=True,
  uses_training_state=False` (deltas are current-stream training products, not old-item data; storage is
  O(#streams × rank) and I'll report it explicitly, NOT hide it as free).

## Part B — surprise instrumentation
- Once per seed on the frozen base, per fact f (both p_seen and p_para prompts):
  `surprise_bits = -log2 softmax(base_logits(prompt))[gold]`, plus `margin` (top1−gold logit),
  `entropy`, `already_correct` (argmax==gold). Store per-fact arrays keyed by a stable fact id.
- Per-fact FINAL retention: add a tiny helper `perfact(model, streams, phrase)` = flat list of 0/1
  (argmax==gold) over ALL facts. Each runner stashes `out_a["perfact_para"]`/`["perfact_seen"]` computed on
  its FINAL dense model, right before `del`. For R40 I only run naive_fixed, nswrite, ours_tgt_answerid,
  loramerge, merge_* → I edit exactly those 4 return sites (run_nswrite, run_consolidate, run_loramerge, new
  merge runner).
- Dump per-fact `{fact_id, surprise_seen, surprise_para, margin, already_correct, retained_para[arm]}` to a
  sidecar `BK_OUT.replace('.json','.perfact.json')` so we can bucket retention by surprise offline.

Derived (in `agg`/dump): `mean_surprise_bits`, and per arm `retained_para_by_surprise_bucket` (e.g. terciles),
`retained_facts_per_surprise_bit = Σ retained / Σ surprise_bits`.
