## The pipeline we already have (`s3/wikibridge.py`)

It's the real-text lifecycle you designed for R38-WikiBridge: per stream t, start from committed M_{t-1};
train a TRANSIENT continued-PT scaffold S_t on new passages; consolidate into M_t by distilling S_t on
new prompts + **replaying OLD committed answer-CE targets** + neutral base anchors; store compact targets;
discard S_t. Closed-book EM eval on held-out PARAPHRASED questions (no passage/retrieval/task-id).
`select_budget(items, mode, B, seed)` already implements the R43 replay-selection modes (surprise/random).
SOURCE in {squad hard-tail base-screened, cf counterfactual base-ignorance-guaranteed, census real-density}.

So the ONLY thing the new arc adds is: **where do the replayed old targets come from, and how are they
selected.** That is exactly the fragile-target wall I flagged. The pipeline makes it a clean drop-in.

## Central variable = the source/selection of the replay set (all else fixed)

Arms (each = a `BUDGET_MODE`/replay-source setting, same budget B, same consolidation):
1. `no_replay` — floor (retention collapses).
2. `stored_compact` — replay stored committed answer-CE targets (current compact_cpt). The "stored replay"
   ceiling for this budget. **This is the number self-replay must recover a fraction of.**
3. `random_half` — R43 random@0.5 selection of stored targets (the null that beat surprise on real text).
4. **`self_replay`** — NO stored old items. At stream t, self-quiz M_{t-1}: regenerate old-fact probes
   FROM THE CHECKPOINT (question templates over old subjects it has seen), take the model's OWN greedy
   answer as the CE target, consolidate on those. Store nothing but a budget-ledger hash.
5. **`self_replay_fragile`** — same, but SELECT which old facts to self-quiz by the model's own signal
   (low self-consistency across paraphrases / high answer entropy / near-margin), instead of random subjects.
   This is the direct test of "does fragile-target selection beat random self-replay on REAL text" — the
   exact place surprise died in R43, now re-asked in the generative-replay setting.
6. **`successor_readout`** (your brainstorm #2, rehearsal-free) — no old prompts at all; protect the
   readout OPERATOR around committed answer hidden states via hidden-function/KL matching on synthetic
   perturbations of h(committed-answer-context), not old text. Tests whether protecting the endpoint
   readout (the thing R47 says gets destroyed) retains without any replay.

## Pass / fail (your bars, made concrete)

- Primary: OLD held-out paraphrase EM, closed-book, single dense ckpt, S_t deleted.
- `self_replay` PASSES iff it recovers >= 50% of the gap (`stored_compact` EM - `no_replay` EM), while
  generated-target error stays low enough not to poison (measure: fraction of self-generated CE targets
  that are actually WRONG vs the gold answer — the self-confirmation poison rate).
- `self_replay_fragile` beats `self_replay` (random self-quiz) by >= +0.05 old-EM => fragile-target
  selection transfers to real generative replay (the R43 wall finally moved). If it ties => the wall stands
  and the honest finding is "selection still doesn't help on real text, generative or not."
- `successor_readout` PASSES iff old-EM retention >= +0.10 over `no_replay` with NO old prompts and A->new
  intact — a genuinely rehearsal-free retention primitive.
- BUDGET LEDGER (mandatory, your anti-cheat): report separately (a) raw old examples stored, (b) generated
  targets stored, (c) whether storage grows O(facts) or is amortized. self_replay's (a) must be 0.

## Where I want your push-back

1. **Self-confirmation poison.** self_replay's CE target is the model's own greedy answer, which can be
   WRONG. Do we (i) only keep self-generated targets the model answers CONSISTENTLY across k paraphrases
   (self-consistency filter), (ii) keep all and measure poison rate, or (iii) verify against the transient
   scaffold S_t (which just read the passage) as a cheap oracle? (iii) feels strongest — S_t saw the text,
   so it can screen the checkpoint's self-quiz — but is that "using old data"? The passage is the CURRENT
   stream's, not old; the screen is on OLD facts though. Rule on whether S_t-screened self-replay is still
   rehearsal-free enough to count.
2. **Fragile-target signal on real text.** Which selection signal is least likely to be another R43-style
   null: self-consistency-across-paraphrases variance, answer-token entropy, or frozen-base bits/token
   (`_bpt`, already in the file)? My prior: self-consistency variance is the most causal for "will this old
   fact be forgotten," because it measures the checkpoint's OWN grip, not a static base surprise. Agree?
3. **Is `successor_readout` well-posed on real text?** On synthetic R47 the "answer context" is clean.
   On real SQuAD/census answers (multi-token, varied kinds) is protecting h(answer-context) even definable,
   or does it collapse to distilling the stored answers (= stored_compact under another name)?
4. **Source choice.** cf (counterfactual, base-ignorance guaranteed) isolates NEW knowledge cleanly but is
   semi-synthetic; census (real Wikipedia density) is the honest transfer test but noisier. Run cf FIRST as
   a clean go/no-go, then census? Or census directly since cf is still template-ish?
