## Assumption 1 — "retain every fact." Reframe: cost = accumulated SURPRISE, not #facts.
Everything we measure (old_para over all old facts) assumes every fact must be retained equally. But
predictive coding / free-energy (Friston) says a learner should only encode prediction ERROR. For a new
fact, compute its SURPRISE under the current model; write only the surprising residual. Low-surprise facts
(already implied by the model) cost ~0; only high-surprise facts cost real bits.
- Grounding: this is EXACTLY R38B-A restated. Real/prior-anchored facts survived zero-replay because they
  were LOW-SURPRISE (on-manifold); independent invented facts collapsed because they were HIGH-SURPRISE.
  We already have the phenomenon; we just never turned surprise into a WRITE-GATE and a COST MODEL.
- Reframe of the whole goal: "read 300 books" is achievable not because we retain 10^6 facts, but because a
  well-read model finds most of book 300 unsurprising. Cost scales with accumulated surprise, which for a
  strong base is heavily sublinear in raw fact count.
- Testable in s2/s3: gate writes by per-fact surprise (base NLL / logit-margin); measure retention and
  footprint vs the surprise distribution, not vs #facts. Prediction: retention cost tracks summed surprise,
  and pre-computing "what's already known" makes the effective #facts far smaller.
- Risk: surprise is measured under the CURRENT model, which drifts; and a rare high-surprise exception is
  exactly what we can't afford to under-write. But it reframes the exception term precisely: exceptions =
  irreducible surprise.

## Assumption 2 — "interference is damage." Reframe: interference is a SIMILARITY SIGNAL → the abstraction trigger.
Every mechanism treats collision as the enemy to avoid (nswrite, grow_sep). But two facts interfering means
they compete for the SAME code — i.e. they are RELATED. Interference is a free, unsupervised similarity
detector. A system that DETECTS collision could USE it: "these facts collide → they share structure →
abstract them into a schema." So the collision detector is not just a growth trigger; it is the
pattern-DISCOVERY signal that schema_comp currently assumes is given by the data's bridge labels.
- This unifies grow_sep and schema_comp: the same collision statistic that triggers separation ALSO nominates
  which facts to try to compress into a shared rule. Enemy becomes mechanism.
- It also answers the open question from last round (what is the legal growth trigger, since occupancy alone
  is a false alarm per R36-I): the trigger is not "subspace is full," it is "N new writes are colliding with
  EACH OTHER in the same directions" — mutual interference among current-stream facts, which is training-state
  only, no old items.
- Testable: cluster current-stream facts by write-direction collision; where a cluster is dense, attempt
  schema compression (shared low-rank rule + residuals) INSTEAD of separation; compare footprint/retention to
  label-supervised schema_comp. Prediction: unsupervised collision clusters recover the bridge structure R34
  gives by label.
- Risk: collision may reflect spurious co-location, not real shared semantics (superstition/over-abstraction);
  needs the derange control to catch false schemas.

## Assumption 3 — "we hand-design the write rule." Reframe: META-LEARN the consolidation operator.
nswrite, keytie, grow_sep, ours_tgt are all hand-designed update rules. Humans' "good at learning" is itself
learned/evolved. The escape might be a LEARNED write operator (learned optimizer / hypernetwork) meta-trained
on a DISTRIBUTION of fact-streams so it writes new facts with minimal interference by construction —
"learning to continually learn."
- You cautioned earlier that the honest accounting must include the meta-training distribution. Agreed — but
  that is a ONE-TIME offline cost (like pretraining), and the test is whether the learned operator
  generalizes to HELD-OUT stream structure it never meta-trained on.
- Grounding: this is the only route that could make the write rule itself prior-anchored (meta-prior over
  "how to write facts"), which is a level above R38B-A's prior-anchoring of the facts.
- Testable: meta-train a small write-operator (e.g. a learned per-layer gating/mask predictor) on many
  synthetic streams; freeze it; test rehearsal-free retention on a held-out stream family vs nswrite. Null:
  it only works on the meta-training stream distribution (memorized the streams, didn't learn to write).
- Risk: high build cost; the meta-distribution could leak the answer; may just rediscover nswrite.

## Assumption 4 — "facts are stored as features." Reframe: store AXIOMS + DERIVE (patterns as generative programs).
schema_comp compresses facts into shared FEATURES. The deeper form: compress into generative PROGRAMS —
store a small axiom set + an inference procedure, and RE-DERIVE facts at inference by computation. "Hundreds
of books" compress to axioms; facts are recomputed on demand. This trades REASONING (test-time compute) for
STORAGE.
- This is the strongest possible O(#facts)→O(#patterns): patterns are programs, not just feature directions.
- Grounding + hard warning: R32 says our model CANNOT do latent multi-hop composition even with perfect
  single-step recall (0.000 A→C). So "derive at inference" hits the readout/activation wall (cost-term 6).
  Storing axioms is useless if the model won't execute the derivation. This reframe may be blocked by our
  own composition negative — which is itself important: it says the bottleneck for program-storage is the
  EXECUTION engine, not the storage.
- Testable: give the model axioms + explicit chain-of-thought derivation supervision (make execution
  learnable), then test whether facts can be dropped from storage and recomputed. If CoT execution unlocks
  R32's 0.000, that's a huge result about the readout term.
- Risk: likely blocked by R32; but locating the block precisely (storage vs execution) is worth it.

## Assumption 5 — "fast context and slow weights are separate systems." Reframe: distill the model's OWN in-context learning.
We keep building a separate scaffold as the fast learner. But the transformer ALREADY has a fast weightless
learner: in-context learning over the KV-cache. CLS says fast hippocampus → slow neocortex. The native
version: use the model's OWN ICL as the "hippocampus," and distill into weights only what RECURS across
contexts. We never used ICL as the fast system.
- Grounding: R38 showed reading (LM) fails but QA-target teacher works — the teacher is an external scaffold.
  ICL could BE the teacher: put the passage in context, let ICL answer, distill the ICL behavior into weights
  (context-distillation). That is self-generated targets without a separate model.
- Testable: context-distillation arm in s3 — condition on passage in-context, distill the closed-book answer
  into weights, drop the passage. Compare to the current explicit QA-target scaffold. Does the model's own
  ICL provide as good a teacher as the constructed QA targets?
- Risk: ICL answers may be wrong/hallucinated (unlike gold QA); it inherits base weaknesses. But it removes
  the external teacher and makes the loop fully self-contained.
