# First LM gate: multi-env breaks the within-range shortcut (ID 0.095→1.0), but the length-OOD axis is dominated by the transformer length-generalization wall (copy also 0). Need the reset-stratified probe you specified.

Source: `qa/claude/2026-07-17.10.48.13.md`. Files: `s4/train_gate.py`, result
`docs/cloud_results/lm_gate1.txt`. First cheap gate ran (3 conditions × 4000 steps, ~1.8M-param rotary
decoder, local RTX 2070).

```
condition   all-ops ID[3,12]   csum_reset OOD[16,40]
insuf_erm   0.095              0.000     (E0 fixed len 8 -> only len-8 works = fixed-length shortcut)
suf_erm     1.000              0.000     (E_len+E_reset+E_alpha+E_tmpl, len [3,12])
suf_dro     1.000              0.000
```

## Two findings

1. **Environment sufficiency works for the within-range shortcut — the toy conclusion holds at LM
   scale.** insuf_erm memorizes length-8 (ID 0.095 = the ~1/10 of the [3,12] eval that is length 8);
   sufficient multi-env training drives ID to **1.000 for all ops including csum_reset**. So multi-env
   evidence broke the fixed-length/position shortcut exactly as the identifiability analysis predicts.
   group-DRO ≡ ERM here (both already 1.0 in-range), so no objective-intervention signal at this point.

2. **The length-OOD axis is confounded by length generalization and does not isolate recurrence
   acquisition.** OOD[16,40] = 0.000 for **every op, including `copy`**. Copy is the identity; its OOD
   failure cannot be about the reset recurrence. So OOD-by-length is dominated by the well-known
   transformer length-generalization wall (rotary is defined at all positions, but the model still did
   not learn to *continue* the mapping beyond trained lengths), which masks whether `csum_reset`'s
   recurrence was acquired. My gate conflated environment-sufficiency with length-extrapolation.

## The fix I propose (your reset-stratified probe, made central)

Length extrapolation is a real but *separate* wall; I don't want it to swallow the identifiability
result. So I'll isolate recurrence acquisition with a WITHIN-training-length probe, exactly the
reset-position / distance-since-reset stratification you asked for:

- Keep evaluation lengths inside [3,12] (no length extrapolation), but hold out RESET CONFIGURATIONS:
  train with resets in one set of positions/counts, test on unseen reset positions and larger
  distance-since-reset within the same lengths. csum_reset accuracy stratified by distance-since-reset
  tests whether the model runs the *recurrence* (state accumulates correctly over unseen distances)
  vs a local/positional shortcut — with zero length extrapolation.
- Report accuracy vs distance-since-reset; a model that learned the recurrence stays flat, a shortcut
  decays with distance.

Then length generalization becomes its own, separately-reported axis (a graded sweep 12→14→16→…→40),
not the pass/fail gate. That keeps "did multi-env identify the recurrence" clean from "can the
transformer extrapolate length."
