Executing the bridge you designed. Building it as a NEW script `s3/wikibridge.py` (real-text ingestion is

## Decision 1 — data source (the base-ignorance problem is the crux)

Your spec wants real passages, base-screened low, RAG-answerable high. Options:

- **(a) SQuAD v1.1 subset** (HF `squad`): real Wikipedia passages + human short-answer QA (extractive,
  multi-token spans). Pro: zero QA-generation, clean answerable spans, on HF. Con: famous Wikipedia →
  base model may already know many answers → after base-screen only the hard-detail tail survives; I'd
  over-select 60–80 QA and keep those with base EM ≈ 0.
- **(b) Counterfactual-edited real passages** (knowledge-editing style: take real passages, flip a
  specific entity/date/number, ask about the flipped fact). Pro: **guarantees base-ignorance** (the
  counterfactual can't be pre-known) and stays real-text-shaped. Con: half-synthetic; but it directly
  tests "can new/contradictory info from text be written into weights over the base prior" — arguably the
  MORE relevant production case (updating a model with new/changed facts).
- **(c) Recent/obscure articles** (post-cutoff or long-tail): truly base-unknown. Con: harder to source
  reproducibly on the pod without a curated file.

My lean: **(a) SQuAD-hard-tail as the primary** (cleanest "real text → closed-book recall"), **plus a
small (b) counterfactual arm** as the base-ignorance-guaranteed control (so a null result can't be blamed
on "base already knew"). Reproducible via HF `datasets`, deterministic subset by seed. Do you agree, or do
you want (b) as primary because it removes the base-leakage confound entirely?

## Decision 2 — harness design (`s3/wikibridge.py`)

Contract preserved: sequential streams, transient continued-PT scaffold, compact old targets, single dense
inference, no retrieval/task-id at test.

- **Streams**: 4 streams × 5 articles = 20; each article = passage text + its QA set. `make_streams(seed)`
  deterministic subset.
- **Scaffold `S_t` (per stream)**: start from committed `M_{t-1}`; continued-PT (next-token LM loss) on the
  new stream's passage chunks + (for the `_qa` arm) source-grounded QA prompts (question → answer-span CE).
  Transient — discarded after consolidation.
- **Consolidate `M_t`**: distill new-stream targets from `S_t` + replay **compact old committed targets**
  (per-QA answer-sequence: stored answer token-ids per question, multi-token CE — the R36-A2 `answerid`
  generalized to sequences) + base-capability anchor KL on **neutral** prompts only (never on old QA).
- **Committed targets**: after each stream commits, store per-question `(question_prompt, answer_token_ids)`
  from `M_t` (committed-correct only). Old replay = teacher-force answer CE on these. This is compact
  (ids only) and multi-token, no snapshot teacher needed (R36-A2 result carried over).
- **Arms**: `base_no_ingest`, `rag_article` (concat passage in-context → answerability upper bound),
  `naive_cpt` (sequential continued-PT, no old replay), `compact_cpt_only` (scaffold=LM-only + old compact
  targets), `compact_cpt_qa` (scaffold=LM+QA + old compact targets). Optional `joint_all` ceiling.
- **Eval**: closed-book QA (normalized EM/F1) on held-out **paraphrased** questions per stream (final +
  per-stream-post-commit for the retention curve); base-capability slice (small held-out LM ppl or a
  fixed MCQA slice) for no-regression; RAG only as upper bound.
- **Model**: Qwen2.5-0.5B first. Single 5090/4090.

## Decisions I've defaulted (flag if wrong)

- Answer generation at eval: greedy decode up to answer length, normalized EM + token-F1 (SQuAD-style).
- Retention target for old QA: **committed answer-id sequence CE** (not full passage-logit replay) — per
  your "closed-book answer behavior, not reproduce every token." Passage-LM replay deferred.
- base-anchor: a fixed neutral prompt set (general text) for capability preservation — NOT old QA prompts
  (the R37-A base-KL-on-old-prompts confound lesson applies here too).
- Pre-registered pass bars: exactly yours (new QA `compact_cpt_qa` ≥ base +25; old-QA retention drop
  ≤10–15; beat `naive_cpt` all-stream by ≥+20; base-capability ≤5% ppl / ≤2–3pt MCQA; decisive read =
  `cpt_only` vs `cpt_qa`).
