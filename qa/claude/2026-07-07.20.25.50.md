## PART A — the first-principles spine (this round's core; attack it first)

**Thesis: continual learning on a transformer is an ADDRESSING problem, not a capacity or plasticity problem.**

Derivation:
1. Stability-plasticity is a dilemma ONLY because representations are entangled/superposed: one param serves
   many mappings, so editing one perturbs others.
2. Therefore the real problem is not "store without forgetting" but "decide, per new fact, the right DEGREE
   of parameter sharing" — share when on-manifold (generalize/compress), isolate when off-manifold (avoid
   interference). That decision signal is exactly the R40-s3 surprise/manifold variable.
3. Capacity is NOT binding: 0.5B × 2 bits/param ≈ 1e9 bits ≈ ~1e7 facts of headroom, yet we wall out at
   ~1e2–1e3 facts (nswrite saturates, merge collapses at 3 streams). We hit walls 4–5 orders of magnitude
   below capacity. So the binding constraint is **write-addressing (write to empty space without disturbing
   occupied space) + read-addressing (retrieve what was written)** — not storage, not plasticity.
4. Every failed method (keytie, merge, EWC, OGD, generic growth) tried to solve CL WITHOUT addressing.
   nswrite is crude write-addressing (avoid occupied directions) with no read-addressing, and it saturates.

**Saturation is fundamental, not a bug.** In fixed d-dim θ-space you can pack ~d mutually-non-interfering
(orthogonal) writes before the null space is exhausted (Gardner-bound flavor). Three escapes only:
- (a) grow d — but only "smart" growth connected to the interfering circuit AND readable (generic growth
  failed R23/31/32/34; R37-A localized worked);
- (b) graceful interference — high-d random superposition (VSA): retrieval SNR ∝ √(d/k), degrades gracefully,
  never "runs out", just gets noisier — fundamentally different from hard null-space saturation;
- (c) consolidate-to-free-space — re-express many specific writes as one rule + small residuals, freeing the
  null-space dims the specifics occupied. The ONLY indefinitely-sustainable route, but needs structure.

**CLS convergence (derived from constraints, not biology-worship).** A sustainable CL system MUST have four
components: (1) fast, high-capacity, non-interfering write buffer; (2) slow, shared, compressed store; (3)
consolidation moving compressible structure fast→slow, freeing fast capacity; (4) a routing signal (per-write
and per-read). We have validated THREE: slow store (dense), consolidation (replay-distill + schema_comp we
designed), routing (surprise, R40-s3). **The ONLY missing primitive is #1: a fast, non-interfering,
addressable write layer.** So the whole program collapses to ONE testable primitive.

## PART B — architecture primitives (last round; feasibility as the #1 buffer)

1. **TTT / Titans / DeltaNet** — hidden state IS inner weights updated by online gradient steps in the
   forward pass. Titans gates its long-term memory write by SURPRISE (gradient norm) + a forget gate. This is
   independent external convergence with R40-s3. Feasible test: add a small Titans-style surprise-gated memory
   residual module to Qwen; does it retain off-manifold exceptions better than dense FT?
2. **Product-Key Memory** — huge sparse addressable memory, few slots retrieved per token, single forward
   pass, fixed capacity. Native "write to an empty slot" primitive.
3. **Modern Hopfield / Sparse Distributed Memory (Kanerva)** — exponential capacity, retrieval by energy min;
   adding a well-separated minimum barely moves existing ones. A different STORAGE LAW (non-interfering by
   construction), addable as a residual layer.
4. **VSA / random near-orthogonal (Johnson-Lindenstrauss)** — force new writes into random near-orthogonal
   subspaces; graceful √ degradation, no hard saturation.
5. **Gradient routing / sparse subnet allocation** — allocate disjoint subnets by masking gradients (not
   inference-time routing), merge to dense. "Growth without growth."

## PART C — the definitional question I need you to RULE

Is a **fixed-capacity, jointly-trained, content-addressed memory LAYER** (PKM / Hopfield / SDM / TTT-state)
an "external memory" (forbidden) or "a layer" (allowed)?

My argument for ALLOWED: attention IS content-addressed memory over the context; an associative memory layer
is the identical operation over a fixed learned KV set. It's a parametric layer, fixed capacity, single
forward pass, no task-id, no growing item DB. The forbidden thing is a GROWING retrieval database of raw items
indexed at inference (RAG). If attention-over-context is allowed (it's the base model), attention-over-a-
learned-KV-memory is the same op. Do you accept this line, or is there a principled reason a learned KV
memory layer violates "knowledge in weights, no inference memory"? This decision gates whether we can build
the #1 buffer at all, vs being restricted to pure-dense manifold-expansion.

## PART D — the feasibility LADDER (rank it; pick the rung)

Ordered by feasibility, NOT novelty:
- **Rung 1 (zero new architecture): surprise-gated compact-replay budget** (your Phase-1). on-manifold → dense
  only (already retained); off-manifold exceptions → O(#exceptions) compact committed targets (8 bytes/fact).
  If the exception tail is sparse, this may already make "read books" tractable with NO new architecture.
- **Rung 2 (add a layer): fixed-capacity content-addressed associative memory for exceptions**, surprise-
  routed at write (gate) and read (uncertainty). Needed only if exceptions are dense or we want zero replay.
- **Rung 3 (change substrate): TTT/Titans, local/predictive-coding update rules, VSA superposition.** Highest
  risk/reward; only if Rung 2 also walls.

My recommendation: **climb, don't leap.** Rung 1 first — it uses all validated components and, crucially, it
MEASURES the exception-tail density (retained-per-exception, how many compact targets survive), which is the
number that tells us whether Rung 2/3 is even needed. First-principles says the exception density is the
decision variable, and Rung 1 measures it cheaply.
