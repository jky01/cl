# Is the self-addressing wall Qwen/base-specific? Worth an instruct/family scout before R50-A? Challenge me.

User question I'm routing to you: is the "can't self-address its own newly-written facts" wall a Qwen limitation,
and would other open models have a chance? Bring your own view + push back on mine. Context: R48/R49a/margin/
R50-scale all used **base Qwen2.5** (0.5B, 1.5B) as BOTH the knowledge holder AND the self-generator.

## My analysis
**Likely GENERAL (model choice won't save it):**
- Reversal-curse (Berglund 2023) reproduces across GPT-3/LLaMA: gradient-descent acquisition encodes the trained
  direction (Q→A) but not the inverse/generation direction. Our self-addressing failure is a cousin — we trained
  QA-span CE (Q→A), never "generate a question about this fact," so the model doesn't.
- The 1−exp(−B/N)+prior-skew coverage scaling you flagged is model-agnostic: any model's free-generation
  distribution is dominated by high-prior pretraining, so low-prior tail facts are rarely sampled.

**But one UNCONTROLLED confound that could partly explain it:**
- We used BASE models as the self-generator. "Generate a trivia question about your knowledge" is exactly the
  instruct-tuned behavior. A base model few-shot-prompted may be a WEAK GENERATOR (regurgitates high-frequency
  patterns) — so the failure could be "base can't follow the generation instruction well," NOT "the fact isn't
  self-addressable." This is the single most likely place we're over-stating the pessimism.
- Different families (Llama-3.2, Gemma-2, OLMo) have different pretrained priors → different reachable sub-facts.

**Model-agnostic escape:** R50-A tomography does NOT need the model to volunteer facts — it SEARCHES for a query
that elicits the fact. So even if no model self-addresses, R50-A's premise holds.

## The specific probe I'm considering (cheap, same tokenizer)
Re-run the R50 addressability audit with **Qwen2.5-1.5B-Instruct** as the acquirer+self-generator (Qwen2.5 shares
the tokenizer, so my wb helpers work unchanged). Question: does an instruct model self-generate proposition-
preserving questions about its OWN newly-acquired facts materially better than base (cov_ans > 0)? A family test
(Llama-3.2-1B / Gemma-2-2B) is also possible but needs tokenizer parameterization (more work).

## Where I want you to push
1. **Is the instruct confound real and worth a pod, or a distraction?** Steelman BOTH: (a) instruct is exactly the
   right generation mode and base-only results overstate the wall — so we MUST control it before trusting the
   pessimism; (b) instruct-tuning changes the OUTPUT POLICY, not whether the newly-written fact is in the
   generative support — since acquisition is standard CE on top of instruct weights, the reversal-curse-style
   direction gap persists and instruct will ALSO be ~0 on tail facts. Which is more likely, and does the answer
   change if the instruct model is prompted with an explicit "list facts you just learned about X" chat turn?
2. **Confounds in an instruct scout:** acquiring on instruct may degrade instruction-following (CE on QA span can
   damage chat behavior). And instruct models may self-generate MORE fluent questions that are still NOT the
   acquired proposition (higher raw coverage, same or worse CORRECT coverage). How do I keep the comparison to
   base clean — same acquisition objective, same proposition-equivalence audit, report correct-not-raw coverage?
3. **Ordering vs R50-A:** given R50-A is model-agnostic and you already ranked it #1, is the instruct/family scout
   worth doing FIRST (de-risk "our pessimism is a base-model artifact") or is it a lower-value detour that a
   nonzero R50-A result would moot anyway? I lean: one cheap instruct scout FIRST, because if instruct self-
   addresses even weakly, it reframes the whole problem (the fix is generation-mode, not search) and changes R50-A.
4. Is there a decisive CHEAP variant I'm missing — e.g. keep the base ACQUIRER (our real setup) but use an
   instruct model ONLY as the generator, prompted to elicit the base's facts? That separates "who holds the
   knowledge" from "who poses the query," which is closer to a realistic self-replay pipeline than switching the
   whole model to instruct.

My lean: run ONE cheap Qwen2.5-Instruct addressability scout before R50-A to kill the base-model confound, keep
family (Llama/Gemma) as a follow-up only if instruct moves the needle. Push back if you think reversal-curse
makes this a near-certain 0 and the pod is better spent on R50-A directly.
