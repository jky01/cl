## Proposed experiment: `s4/stream.py` — an operator stream that can exhaust the interference-free subspace

To saturate a reserved budget I need many genuinely-interfering operators (microlang only has ~5 natural
ones, and the width sweep says each needs r≈1–2, so 5 operators would never exhaust a reasonable budget).
I propose a **parametrized operator family** giving arbitrarily many distinct, mutually-interfering
stateful maps that all share the same machinery:

  op_c(x): running state s; on RESET token s←0 else s←(s + f_c(x_i)) mod V; emit s.
  index c ∈ {0..T-1} picks a distinct per-operator digit permutation f_c (a fixed random bijection on the
  V symbols). Same recurrence & reset structure as csum_reset (so they interfere in the SAME substrate),
  but each c is a different function → learning c'=k must not destroy c=j. Command token = the operator id.

Models, each learning operators c=0,1,...,T-1 SEQUENTIALLY (new operator's data only, no replay, no joint
retrain), retention measured on ALL earlier operators after each step (algorithm-level: L8–40 + cf):

  A. naive          : fixed trunk, sequential FT                         (overwrite baseline)
  B. fixed-budget    : frozen trunk + ONE reserved adapter of total size R, **routing-partitioned** across
                       operators (op c writes only its slice R/T; the strongest fair selective allocation a
                       fixed budget supports — your directive). Saturates when R/T < r* ≈ r-floor.
  C. growth          : frozen trunk + a NEW r-slot per operator (total params grow linearly ~ T·r)
  D. reserved==growth: frozen trunk + T disjoint r-slots preallocated up front (equals C's final size but
                       fixed from t=0) — the control that says "if you KNEW T, reserved = growth".

Growth-necessity signal = the crossover T* where B's per-operator share R/T drops below the floor and its
old-operator retention falls, while C keeps acquiring at bounded incremental cost and retains all. D
pins down that the win over B is the interference-free ISOLATION, and the win over "just preallocate" is
only the unknown-T provisioning argument (which I'll state as engineering, not necessity). I'll report,
per step: acquisition of the new op, exact retention of every old op, cumulative stored params, and active
inference FLOPs — so B (cheap, saturating) vs C (growing, retaining) is a real Pareto curve, not a slogan.
