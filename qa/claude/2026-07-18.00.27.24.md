## Two families, same interfering recurrence substrate as csum

Both stay in the reset-recurrence substrate so they interfere in the SAME machinery csum/rmax used:
- **Permutation (incompressible stress):** `s_i = (s_{i-1} + π_c(x_i)) mod V`, reset→0; π_c a random
  bijection per operator id c. Command encodes c. Each op ~ log2(V!) unrelated bits => expect ~linear
  storage; this is the negative control / accounting test.
- **Affine (compressible / integration):** `s_i = (a·s_{i-1} + x_i + b) mod V`, reset→0; command encodes
  (a,b). csum = (a=1,b=0). Shares one affine-recurrence generator across all surface operators. Since the
  command CARRIES (a,b), a fully integrated learner needs ZERO new stored params per operator (apply the
  shared rule with the given a,b), whereas the permutation map cannot be computed from its index c.
  Marginal-stored-params-per-operator is thus the direct integration metric: ~const for permutations,
  ->0 for affine iff the learner discovers the generator. Slot allocation alone CANNOT integrate (slots
  are isolated), so the affine family also needs a **parametric-adapter arm** that reads (a,b) — I'll add
  that arm in the affine run to give integration a mechanism to succeed or fail against.
