## 為什麼 Gate 必須先跑（重申動機，避免燒 GPU 燒到無法歸因）

latent 2-hop composition（無 CoT、無記憶、同一次 forward 內把 `A→B`、`B→C` chain 成 `A→C`）在 0.5B 這種尺度上**是有名的難點**，很可能**連上限模型都做不到**。若不先驗證可解性就跑 grow vs fixed arms，全零結果會被誤讀成「growth 沒用」，實際上是「任務對所有 arm 都不可達」。所以先花 ~30–40 分鐘把可解性釘死。

## 任務設計（構造式防洩漏 contract）

**實體與關係**：單一關係 `friend`。鏈長 L=3：`A → B → C`。
- **非源點必須 single-token**（因為是某條單步邊的答案，argmax 評測要單 token）：`B`、`C` 取自 `single_tok_names(tok)`（實測 ~44 個）。
- **源點 `A` 可多 token**：取自 `FIRST×LAST` big_pool（數百個），只出現在 prompt，不當答案。
- L=3、每鏈耗 2 個 single-token → ~22 條鏈；single-step 邊 = 44；held-out 2-hop 對 = 22。

**單步邊（唯一允許進 training/scaffold/replay 的素材）**：
- seen：`"{X}'s friend is"` → `Y`
- para：`"The friend of {X} is"` → `Y`

**held-out composition query（絕不進任何 training completion）**：
- 2-hop：`"{A}'s friend's friend is"` → `C`（para：`"The friend of the friend of {A} is"`）
- 中繼 `B` **不出現在 2-hop prompt**，模型必須在權重內先算出 `B` 再取 `C`。

**生成 contract（讓洩漏在構造上不可能，assert 只當防線）**：
1. 先建鏈（disjoint，無環）。2. 先選 held-out endpoint pairs `(A,C)`。3. 邊指派到 stream 時，強制同鏈的 `A→B` 與 `B→C` 落在**不同 stream**（給後續 arms 的 cross-stream + `first_possible_round` 用）；Gate 階段所有單步邊一起訓，但仍記錄 stream index。4. training completion 只含單步目標；assert：以 `A` 為主詞的任何 prompt，completion 的 token id ≠ `C` 的 token id。5. 實體命名、token id、邊順序、prompt 位置全 shuffle。

## Gate A — no-memory single-step-only upper bound（最寬鬆上限）

- 為求「最寬鬆上限」，**直接 gold 監督**（跳過 scaffold）base 0.5B 的**全部參數**，在**全部 44 條單步邊**（seen+para）上訓到收斂（`CG_STEPS`）。直接 gold 是把單步知識塞進權重的最強形式——若連它都不能 compose，我們的 scaffold pipeline 更不可能。
- 評測（no-memory、單一 dense checkpoint）：
  - **single-step recall**（`A→B`、`B→C` 各 seen/para）：必須 ≈1.0，否則 2-hop 失敗只是「知識沒進權重」而非「不會 compose」——這是 Gate A 的前置健檢。
  - **held-out 2-hop `A→C`**（seen/para）top-1 exact match。
  - **shuffle 控制組**：把每個 query 的 gold 換成隨機他鏈的 target，量 accuracy → 應 ≈ chance。真值 >> shuffle 才算有 composition。
  - 另報 gold-C 的平均機率/rank 當連續訊號。
- **判定**：`A→C` 明顯 > chance 且 >> shuffle → Gate A 過 → 任務可由 consolidation 誘發 composition → 進 arms。若 `A→C` ≈ chance → Gate A 不過 → 跑 Gate B。

## Gate B — direct-supervised 2-hop sanity（僅在 Gate A 不過時）

- 訓練：全部單步邊 + **train split 鏈**的 2-hop query（gold `"A's friend's friend is"→C`）；評測 **held-out split 鏈**的 2-hop。
- 判定：
  - held-out 2-hop 學得起來 → 「friend's friend」readout/格式**可學**，Gate A 的失敗是「single-step-only 不會自然誘發 latent chain」→ 需 **bridge curriculum**（少量 2-hop 監督或允許 scratchpad/CoT），**不是**直接比 growth arms。
  - held-out 2-hop 也學不起來 → 任務格式/readout 本身有問題 → 先改任務（換 relation 表述、改評測），再談 arms。
