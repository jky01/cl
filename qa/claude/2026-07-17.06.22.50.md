## The user's reframe that upgrades your "oracle"

The user proposed the routing criterion as: *an input is rule-following iff the current model can
derive it; residual iff it cannot* — decided **at write time, where the label is available** (label-free
only at inference). That reframes your oracle: for residuals we actually READ (residual-train), write-
time surprise (does frozen rule-model predict this fact?) gives us their identity **legally** — it's a
stored surprise flag, not an oracle. Only residual-UNSEEN is a true oracle. So your oracle arm splits:

- oracle on residual-train = **deployable** routing (write-time surprise recorded the identity);
- oracle on residual-unseen = **true oracle** (couldn't have been known).

This matches your residual-train/unseen split exactly and makes the "oracle succeeds" case partly a
real mechanism, not just an upper bound — for the facts we've seen.
