`s0/` implements Step 0 of the neuromodulated continual-learning architecture (spec in `reference/3.md` §11.4): an amortized, no-gradient fact-capsule memory around a FROZEN proxy transformer. Goal of Step 0 = store ONE new (subject,relation,object) fact and read it back. Runs on CPU via `.venv/bin/python -m s0.run [--smoke]`.

**RESULT (2026-06-30, SOLVED): Step-0 gate fully passes.** N_facts=1 capsule exact-match **1.000 + locality 1.000** at smoke scale; **0.969 / 0.984** at d=128/60-vocab. Multi-fact emerged for free (nf=4 ≈0.52, nf=16 ≈0.32, locality stays ~0.92–1.0). The fix that did it: **token-level (subject,relation) retrieval keys + cross-batch InfoNCE** (see the contrastive-collapse story below). Before this, storage worked but locality was stuck ~0.1–0.6 for ~12 experiments.

Key debugging findings (each cost a long CPU run to establish; don't re-derive):
- **Write path failed only due to LR.** At lr=2e-3 the attention-pool FactEncoder + WriteNet stack diverges instantly and sits at chance; at **lr=1e-3 + grad-clip 1.0** it reaches 0.96. Earlier "object not in v" probes were this divergence, not a capacity limit. Added a `z_f→v` residual skip in `WriteNet` as insurance.
- **Read/inject path is sound** — answer-loss-only reaches acc 1.0 at N_facts=1; the gate opens itself (no deadlock).
- **Mixing N_facts=1..4 during training COLLAPSES even N_facts=1** (unlearned multi-slot retrieval poisons the shared read path). So Step 0 trains `max_facts=1`; multi-fact retrieval is Step 1. `run.py` default/smoke now set max_facts=1.
- **Locality mechanism**: injection gate `g = g_content(H_ans,R) · relevance(conf)`, where conf = top key-match score and relevance = σ(20·(conf−thr)) with FIXED steep slope + LEARNABLE threshold. A `margin` loss (matched query score >0.7, unrelated <0.1, IN-EPISODE negative only — cross-batch negatives collapse) separates conf. Locality metric compares the read vs the no-injection read `lm_head(inject_ln(H_ans))` (NOT raw core — that double-counts the inject_ln).
- **LOCALITY ROOT CAUSE FOUND (GPU session 2026-06-30): retrieval contrastive collapse.** Scaling the core did NOT help (it made locality worse: a better core makes the <ans> hidden MORE subject-invariant by the random-binding design). Decisive isolation results:
  - The learned-query **attention-pool encoders (FactEncoder/QueryEncoder) COLLAPSE under contrastive** (matched & random query·key identical; retr@1 stuck at chance for both hinge AND 128-neg InfoNCE). They train fine under supervised CE (so storage/v path is OK) but not contrastive.
  - **Subject identity is washed out** of pooled query hidden (linear probe: subject 0.11, relation 0.67) — mean-pool dilutes it.
  - **FIX (validated, retr@1=0.914):** build retrieval key/query from the SUBJECT and RELATION **token hidden states**, gathered by token-id range (see `s0/diag_tokret.py`), + InfoNCE. Mean-pool InfoNCE only reached 0.41; token-gather hits 0.91.
- **DONE — the rebuild worked.** `capsule.py` now has `gather_sr()` + `SRKeyEncoder`; `CapsuleMemory.key_enc`/`query_enc` build k_sem (statement S,R tokens) and q_sem (query S,R tokens); `WriteNet` no longer makes k_sem (owns v/addr/aux only); `train.py` uses cross-batch InfoNCE (`retrieve` λ=1.0), margin loss removed. Relevance gate (fixed slope 20 + learnable thr) + warmup kept. Result above.
- **STEP 1 (multi-fact) now also works** via a CURRICULUM that ramps episode size 1->max_facts over the first 70% of training (in `train_omega0`). Without it, training directly on max_facts=16 collapses to chance (ans loss never gets traction). With it, d=128/60-vocab/omega8000: nf=1 **1.00**, nf=4 0.98, nf=8 0.94, nf=16 0.87, nf=32 0.76 (extrapolates past training), locality 0.94–1.0 throughout. run.py defaults now max_facts=16/omega8000.
- **STEP 2 (conflict versioning, §27.10) DONE.** Non-destructive update: write a conflicting (s,r) as o_before@time=0 then o_now@time=1; a now/before query routes to the right version. Mechanism: slot gains a `time` field (SlotLayout.d_time); read derives `c_target` from the query's now/before token via `ctx_enc`, biases retrieval toward the slot whose time matches (`ver_weight=0.5`), with a sharp read softmax (`read_temp=0.1`) so the selected version isn't blended. `train_omega0` has a `_conflict_loss` sub-batch each step (lam conflict=1.0). Result (smoke): now-acc 1.00, before-acc 0.97, routing-fail 0.00, and no regression (nf=1 1.0/1.0, nf=16 0.76). `eval_conflict` in train.py, reported by run.py. World gained now/before tokens + `render_query_versioned` + `sample_conflict_episode`.
- **STEP 3A (capacity / occupancy allocation) DONE.** Diagnosed that the recall drop under load was OVERWRITES, not retrieval: `rec|surv` is flat ~0.87 regardless of N, recall ≈ survival×0.87, and the content-addressed product-key allocator collided (birthday) even below capacity. Fix: `CapsuleMemory.write` now places into a FREE slot (read scans all slots by k_sem, so slot index is free to choose; no differentiable loss depends on it), with FIFO (oldest-time) eviction when full. Result: survival=1.000 for N≤n_mem, and it ALSO fixed multi-fact (nf=16 0.76→1.000, since within-episode collisions are gone). Over capacity, survival=n_mem/N (FIFO). The product-key allocator + balance loss are now vestigial (balance λ=0).
- **STEP 4 (commit gate / validate-and-rollback, §27.18/§27.21.5) DONE.** Admission control: `write(trust=...)` computes `g_commit = sigmoid(commit_net([trust, conflict]))` where conflict = max k_sem sim to an occupied slot; g_commit is stored as the slot's `alloc` (soft presence), and read replaced the hard alloc mask with a `commit_weight*log(alloc)` bias (alloc~1 → 0, so trusted writes unchanged; alloc~0 empty/rejected → suppressed). `_safety_loss` (lam safety=1.0): write reliable (trust=1) then a CONFLICTING unreliable (trust=0) update; the reliable value must still be recalled, plus direct BCE so g_commit→1 for reliable, →0 for unreliable. Result: reliable-recall-after-attack 1.00, admission g reliable 1.00 / unreliable 0.00, no regression. Gate generalizes: trust drives admission; trust=1 conflicting writes are still admitted (legit versioned updates, Step 2 still 1.0/1.0).
- **STEP 5 (lifelong forgetting, the headline claim) DONE.** `eval_lifelong`: learn 8 sessions × 6 facts in order, recall EACH session at the end. Capsule = **1.00 flat across all session ages (zero catastrophic forgetting)**; the sequential-LoRA rival (`_seq_lora_recall`, one adapter fine-tuned session-by-session) fails (~0.02). Fixing this caught a latent bug: version routing was applied to PLAIN queries (default c_target=1 penalised old-time slots below the relevance threshold → false forgetting); now the version bias is gated by `has_ctx` (only when the query carries now/before). NB the smoke d=64 core is too weak for LoRA to show a clean decay-with-age curve (it fails uniformly); the contrast is cleaner on the bigger model.
- **s0 now demonstrates the full thesis**: single+multi-fact write/read, locality, conflict versioning, capacity (zero within-bound forgetting), trust-gated admission, and lifelong zero-forgetting vs a parametric rival. ~5 commits (473b941 → ...).
- **GROWTH operator (`core.grow_deeper`) added + de-risked** — toward the user's "small model → continually grow into a big model" goal. Appends identity-initialised blocks (attn out-proj + mlp final linear zeroed → block(x)=x): mid-run L=2→4 gave max|Δhidden|=**0.00e+00**, recall delta 0.0000 (zero-forgetting growth); width unchanged so memory modules' interface intact; after unfreezing new layers + continued training recall holds ~0.97. PROVES "growth doesn't hurt"; does NOT yet prove "growth helps" (needs a task that saturates the small core). Deepening chosen over widening because widening changes d_model and breaks every module that reads hidden states.
- **GROWTH IMPROVES CAPABILITY — validated** (`s0/diag_grow_hops.py`). Depth-sensitive task = in-context K-hop chain traversal (shuffled edges, follow r to chain end; each hop ~needs a layer). L=2 saturates (K2 0.52, K3 0.33). grow_deeper L=2→4 + continued training breaks through (K2 0.98, K3 0.73, K4 0.42) while K1 stays 1.00 (no forgetting). The decisive control: L=2 trained for 2× steps stays plateaued (0.53/0.34) → the gain is from added DEPTH, not more compute. So both halves of the small→large thesis hold: growth doesn't forget (hidden Δ=0.00) AND growth adds capability that in-place training can't.
- **AUTONOMOUS small→large loop — validated** (`s0/diag_autogrow.py`). A plateau-triggered controller (loss barely improving while high-K still failing = capacity bottleneck → `grow_deeper(2)`, rebuild optimizer) grows the core BY ITSELF from L=2→4→6 on the K-hop task. K2 climbs 0.46 (fixed-L=2, stuck even after 16 chunks) → 0.96 (auto-grown); K1 stays 1.00 (no forgetting). Honest bound: K3+ stays low even at L=6 (K3 0.45, K4 0.30) — harder hops need still more depth/training; the closed LOOP is proven, the hard task isn't fully solved. Trigger is a heuristic (placeholder for §27 SleepGate/CapacityNet learned gate).
- **The small→large thesis is now demonstrated end-to-end in sandbox:** continual learning w/o forgetting (memory), function-preserving growth w/o forgetting, growth adds capability in-place training can't, and an autonomous saturation→growth controller. 9 commits.
- **NEURAL growth trigger — validated with honest caveats** (`core.GrowableCore`, `s0/diag_neurogrow.py`). Replaced the heuristic plateau trigger with learned per-layer gates: n_base always-on blocks + n_grow GatedBlocks behind a sigmoid gate (init ~0 = identity); loss = task CE + λ·grow_gate_penalty. The gate is cost-sensitive: λ=0.5 → gates exactly 0, capability = true L=2 (K3 0.31); λ=0.02 → capability K3 0.97. So the trigger is now fully differentiable/loss-driven, no hand threshold. CAVEATS (point to the clean fix): (1) L1-on-gate is GAMEABLE — the net keeps the gate scalar ~0.01 but up-scales block weights, so the gate value under-reports usage (must measure usage by ABLATION, not gate value). (2) Ablation showed the grow blocks only net-add ~0.12 at K3 (0.96→0.84) while base-2 alone reached 0.84 (vs 0.33 standalone) — i.e. part of the gain is overparameterized-optimization easing, not inference-time depth. Clean next: penalize the gated-contribution NORM (ungameable) instead of the gate scalar.
- **Norm-cost attempt — done, honest MIXED result.** `grow_gate_penalty` now returns the summed RELATIVE residual contribution of the grow blocks (`_last_grow_cost` from hidden()), which is ungameable. Outcome: the λ=0.5 run FULLY SOLVED K-hop (K5 0.97 vs L=2's 0.18) and ablation confirms the grow blocks are essential (K3 0.99→0.46) at tiny contribution norm (~0.01) → growth delivers capability efficiently and ablation is a faithful usage check. BUT the cost magnitude is NOT a clean monotonic "how-deep" dial: the smaller-λ (0.05) run did WORSE (counter-intuitive; single-seed, likely optimisation variance), and a tiny-norm contribution can still be essential. CONCLUSION: the neural growth MECHANISM + ablation-faithful verification hold; a clean cost-controlled growth DIAL remains OPEN (needs multi-seed / scheduling / a different controller — a real research point, not a tuning fix).
